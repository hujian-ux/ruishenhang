现状与痛点

秋冬新品季，赵晴手上有 180 个候选商品。关键词工具按热度排序，第一名是「智能保温杯」——但 300 条竞品差评里，42% 在抱怨 App 连不上。热门不等于能赚钱，低竞争也可能是没人要。

工具各给一半答案，拼起来靠人脑

关键词工具给热度、卖家精灵给销量、供应商给 MOQ、认证机构给费用——五个工具五个页面，最后凭感觉拍板。

高频
评论是选品金矿，但没人真读

300 条差评躺在导出文件里，多数选品只看评分和销量。高频抱怨里藏着差异化机会，也藏着伪需求信号。

高价值被忽略
热门赛道 = 高广告成本 + 高退货

热度第一的词往往 CPC 最贵、同质化最重、退货率最高。选品报告里写「市场巨大」，上线后给广告打工。

成本浪费
供应链约束总在选定后才发现

MOQ 5,000、认证 6,800 EUR、体积重超标——这些在立项后才暴露时，调研费用已经沉没。

高风险

选品不是找热搜，是把需求、竞争、利润、供应链、合规和退货风险放在同一张证据卡里。

WorkBuddy 的解决与价值

差别不在快，在于有人把散在五个页面里的东西拼到了一起，并且强制每个结论附上证据来源。

传统做法

关键词工具导出热搜榜，按销量排序 → 挑前 20 名找供应商问价，凭毛利率拍板 → 评论只看星级分布，不读原文 → 认证和 MOQ 等打样时再说。热度第一的品最先被选中，也最先亏钱。

WorkBuddy 做法

先定经营约束（客单价 15-49 / 认证周期 ≤9 周 / 首单现金 ≤45,000 / 头程 ≤4.2 / 退货 ≤10%），再筛候选 → 六维评分每维绑证据 → 300 条差评原文聚类，区分「可整改机会」与「伪需求」→ 打样 / 调研 / 放弃三档队列，淘汰原因写清红线编号与实测值。

三个核心价值
01把六维评分变成可复核的证据卡

需求/竞争/利润/供应链/合规/退货每维 0-5 分，每一维都必须能指到一个文件里的一个字段。加权分公式写死，任何人都能复算，不再是「我觉得这个能做」。

02让差评原文替你判断需求真伪

抱怨指向可整改的结构参数（容量虚标 47 条、折叠处漏水 38 条）＝差异化机会；抱怨指向核心卖点本身（126 条骂 App 连不上）＝伪需求，整个细分否决。这是热度榜永远给不出的答案。

03把供应链约束提到立项之前

认证周期、MOQ 现金占用、体积重头程在筛选阶段就参与打分。周期超上市窗口的硬否决（钱解决不了），费用高低的移交立项裁决——不再等打样完才发现调研费白花。

方案定位

不是替你决定做哪个品，而是把「五个工具的半份答案 + 300 条没人读的差评」变成一张每行都带红线编号和证据文件的验证表。专利与商标核查、认证可行性、打样与立项决定仍然属于人——本场景全部输出中不出现「可立项」结论。

解决方案的工作流程

从三份素材到一张 21 行的选品证据卡，共 5 步，每步都有正式产出。

01先定经营约束

客单价 15-49 USD、认证周期 ≤9 周、首单现金 ≤45,000、头程 ≤4.2、退货 ≤10%，五条红线先立后筛。

02硬筛 180 → 18

逐条跑 R1-R5 + 集中度 ≥0.55 红海规则，命中即否决并写明红线编号与实测值。

03差评聚类提机会

300 条差评按抱怨主题聚类，区分「可整改机会」与「核心卖点伪需求」两类结论。

04六维评分绑证据

18 个候选逐维 0-5 分，每维指向具体文件字段，按固定权重算加权分。

05三档队列与移交

打样 / 调研 / 放弃三档；软约束项（认证费、现金临界）逐项写明移交立项裁决。

案例基本介绍

脱敏构造、逻辑可核验的案例，与本场景库 PD-02 / PD-03 / PD-04 同一案例链——本场景筛出的 5 个打样候选，正是下一场景立项会上要测算的那 5 个。

脱敏案例：海拓生活科技 · 秋冬新品季选品

180 个候选经六维初筛剩 18 个，深度验证后得到 5 个打样候选（HT-K09、HT-L10、HT-P11、HT-M12、HT-S15）。7 个被淘汰的原因逐条留证据：认证周期超 9 周窗口 3 个、MOQ 现金占用超 45,000 USD 2 个、体积重导致头程超 4.2 USD 2 个。最关键的一条结论来自差评原文——关键词热度第一（12.84 万）的「智能蓝牙保温杯」被排除，因为 300 条差评里 126 条（42%）抱怨 App 连不上，用户要的不是智能，这是伪需求而非能力缺口。同一批差评里，容量虚标 47 条与折叠处漏水 38 条则直接指向 HT-K09 的差异化点。

请基于我上传的三份素材，为「海拓生活科技 · 秋冬新品季」做选品机会发现与多维验证，输出一张可复核的选品机会验证表。

【输入 1 · 经营约束】经营约束.md
- 硬红线 R1 客单价 15-49 USD / R2 认证周期 ≤9 周 / R3 首单采购现金 ≤45,000 USD / R4 头程单件 ≤4.2 USD / R5 退货率 ≤10%
- 六维权重：需求.25 竞争.20 利润.20 供应链.15 合规.10 退货.10
- 财务现金上限 38,000 USD（PD-02 立项口径，不用于本次筛选）

【输入 2 · 候选商品池】候选商品池.csv（180 行）
- 含建议售价、采购价、月搜索量、竞品数、头部集中度、平均评分、CPC、MOQ、首单采购现金、认证要求/费用/周期、体积重、头程单件、退货率参考

【输入 3 · 竞品差评样本】竞品差评样本300条.csv（300 行）
- 含竞品ASIN、星级、抱怨聚类、映射机会点、评论原文

【执行要求】
1. 先读约束再看货：把 R1-R5 写成显式判定表，不要先看候选再定标准。
2. 硬筛 180 → 18：逐条跑 R1-R5，并追加「头部集中度 ≥0.55 视为红海」「平均评分 <3.8 必须回差评原文判断是机会还是伪需求」两条规则。命中即标注阶段=初筛否决，写明红线编号与实测值。
3. 差评聚类：按抱怨主题聚类并给出条数与占比。区分三种情况——
 · 抱怨指向可整改的结构/参数 → 机会，写进对应候选的机会信号
 · 抱怨指向产品核心卖点本身 → 伪需求，该候选及所属细分整体否决
 · 抱怨分散、单聚类占比 <5% → 标注「差评未定位」，需求维度不给满分
4. 六维评分：对 18 个候选逐维打 0-5 分，每一维都必须能指到具体文件的具体字段；按权重算加权分（保留 2 位小数）。
5. 三档队列：
 · 打样 = 加权分 ≥3.4 且无红线；落在软约束区的项（认证费金额、现金 38,000-45,000、退货 8%-10%）必须逐项写「移交 PD-02 立项裁决」
 · 调研 = 无红线但差异化路径未定 / 需求规模不足 / 与主推品重叠，写明「补什么才能重评」
 · 放弃 = 命中任一红线，写明红线编号 + 实测值 + 证据文件

【输出格式】CSV，20 列，列名与顺序固定：
阶段, 候选编号, 品名, 六维加权分, 需求, 竞争, 利润, 供应链, 合规, 退货, 机会信号（证据）, 关键风险, 首单采购现金USD, 认证费EUR, 认证周期周, 头程单件USD, 验证结论, 结论依据（红线编号/理由）, 证据来源, 下一步动作

【硬性约束】
- 不允许出现「可立项」字样。专利/商标核查、认证可行性、打样与立项决定属于人工，AI 只能输出「打样候选 / 待人工核查」。
- 结论依据不允许写「综合判断」，必须含红线编号或明确理由。
- 证据来源必须指向真实文件名 + 可溯字段（如「竞品差评样本300条.csv 的 App连接失败聚类 126 条」）。
- 认证的周期与费用分开处理：周期超窗口是硬否决，费用高低移交立项裁决。
- 不写任何效率百分比或效果承诺。

【生成后自检，逐条回答】
1. 每行结论依据是否都含红线编号或明确理由？
2. 每行证据来源是否指向真实文件与可溯字段？
3. 「打样」项的软约束是否都写了移交去向？
4. 淘汰原因分布是否与漏斗一致？（本季应为：认证周期 3 / MOQ 现金 2 / 体积重 2）
5. 是否没有任何一行出现「可立项」？
自检全过再输出 CSV。

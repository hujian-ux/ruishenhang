# AI选品机会发现与多维验证

## 一、这个 Skill 解决什么

选品的真实困难不是「找不到热搜」，而是**答案被切成五份放在五个页面里**：

- 关键词工具给热度，不给竞争强度
- 卖家精灵给销量，不给退货率
- 供应商给 MOQ，不告诉你 MOQ 会锁掉多少现金
- 认证机构给费用，不告诉你周期赶不上上市窗口
- 差评导出文件躺在硬盘里，从来没人读原文

结果是：**热度第一名往往是最差的选择**。本 Skill 的核心动作，是把这五份答案拼到同一张表上，并强制每个结论附证据来源。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 新品季开季，手上有几十到几百个候选 | 主用场景：批量初筛 + 深度验证 |
| 关键词工具排名第一的品要不要做 | 需要用差评原文判断需求真伪，而非看热度 |
| 老板问「为什么不做那个热门品」 | 需要逐条淘汰理由与证据留档 |
| 立项会前需要一份可复核的候选清单 | 输出直接作为 PD-02 全口径立项的输入 |

**不适用**：已定点供应商后的比价（→ PD-03 供应商询价与样品对比）；已进入财务测算的立项（→ PD-02 新品全口径利润立项）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `经营约束.md` | 必需 | 客单价带宽、认证周期上限、首单现金上限、头程上限、退货率上限、六维权重 |
| 2 | `候选商品池.csv` | 必需 | 候选编号、品名、建议售价USD、采购价CNY/USD、月搜索量、竞品数、头部集中度、平均评分、CPC、MOQ、首单采购现金USD、认证要求/费用/周期、体积重、头程单件USD、退货率参考 |
| 3 | `竞品差评样本300条.csv` | 必需 | 评论ID、竞品ASIN、星级、抱怨聚类、映射机会点、评论原文 |

> 缺 3（差评原文）时，本 Skill **必须拒绝输出「需求」维度的分数**，只能标注「需求真伪未验证」。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`选品机会验证表.csv`，字段固定为 20 列：

```
阶段, 候选编号, 品名, 六维加权分, 需求, 竞争, 利润, 供应链, 合规, 退货,
机会信号（证据）, 关键风险, 首单采购现金USD, 认证费EUR, 认证周期周, 头程单件USD,
验证结论, 结论依据（红线编号/理由）, 证据来源, 下一步动作
```

- `阶段` ∈ {初筛否决, 深度验证}
- `验证结论` ∈ {打样, 调研, 放弃, 初筛否决}
- `结论依据` 必须包含红线编号（R1–R5）或明确理由，**不允许写「综合判断」**
- `证据来源` 必须指向具体文件名 + 可溯字段（如「竞品差评样本300条.csv 的 App连接失败聚类 126 条」）

## 五、工作流程（workflow）

### STEP 1 · 读约束，先立规矩再看货

从 `经营约束.md` 读入 5 条硬红线与 6 维权重，写成显式判定表。**顺序不可颠倒**——先看候选再定标准，等于给结论找理由。

```
R1 客单价带宽 15–49 USD
R2 认证周期 ≤ 9 周（上市窗口）
R3 首单采购现金 ≤ 45,000 USD（= 财务上限 38,000 × 1.2 谈判空间）
R4 头程单件 ≤ 4.2 USD（体积重 × 1.35）
R5 退货率参考 ≤ 10%
权重：需求.25 竞争.20 利润.20 供应链.15 合规.10 退货.10
```

### STEP 2 · 硬筛：180 → 18

对每个候选逐条跑 R1–R5，并追加两条初筛规则：

- 头部集中度 ≥ 0.55 → 红海，除非差评聚类给出明确差异化点
- 平均评分 < 3.8 时，**必须去差评原文判断**是「产品普遍做不好」（机会）还是「需求本身伪」（陷阱）

命中即 `阶段=初筛否决`，并写明红线编号与实测值。

### STEP 3 · 差评聚类与机会提取

对差评样本按抱怨主题聚类，输出「聚类 / 条数 / 占比 / 可否整改 / 映射到哪个候选」。判定规则：

| 差评特征 | 判定 | 处理 |
| --- | --- | --- |
| 高频抱怨指向**可整改的结构/参数**（漏水、容量虚标、异味） | **机会** | 写进对应候选的「机会信号」 |
| 高频抱怨指向**产品的核心卖点本身**（如「智能」=App 连不上） | **伪需求** | 该候选及所属细分整体否决 |
| 抱怨分散无主线、单聚类占比 < 5% | 信息不足 | 标注「差评未定位」，需求维度不给满分 |

> 本季关键结论就出在这一步：热度第一的智能保温杯，300 条差评里 126 条（**42%**）在骂 App 连不上——用户要的不是智能，这是伪需求，不是能力缺口。

### STEP 4 · 六维评分与证据绑定

对通过硬筛的 18 个候选逐维打 0–5 分，**每一维都必须能指到一个文件里的一个字段**。计算加权分：

```
加权分 = 需求×0.25 + 竞争×0.20 + 利润×0.20 + 供应链×0.15 + 合规×0.10 + 退货×0.10
```

### STEP 5 · 三档队列与软约束移交

| 结论 | 判定条件 | 附加动作 |
| --- | --- | --- |
| 打样 | 加权分 ≥ 3.4 且无 R1–R5 红线 | 落在软约束区的项（认证费金额、现金 38k–45k、退货 8%–10%）**必须逐项写「移交 PD-02 立项裁决」** |
| 调研 | 无红线，但差异化路径未定 / 需求规模不足 / 与主推品重叠 | 写明「补什么才能重评」 |
| 放弃 | 命中任一红线 | 写明红线编号 + 实测值 + 证据文件 |

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出：

1. 每行 `结论依据` 是否含红线编号或明确理由？
2. 每行 `证据来源` 是否指向真实文件名与可溯字段？
3. 「打样」项的软约束是否都写了移交去向？
4. 淘汰项原因分布是否与漏斗声明一致（本季：认证周期 3 / MOQ 现金 2 / 体积重 2）？
5. 是否**没有**任何一行出现「可立项」字样？

## 六、关键规则（不可协商）

1. **AI 不出「可立项」结论。** 专利与商标核查、认证可行性判断、打样与立项的最终决定属于人。AI 只能输出「打样候选 / 需人工核查」。
2. **热度不是需求。** 需求维度的分数必须有差评原文佐证，否则只能标注「需求真伪未验证」。
3. **认证的周期和费用是两件事。** 周期超窗口是硬红线（钱解决不了），费用高低是立项财务裁决（→ PD-02）。混为一谈会误杀好品。
4. **两道现金口径不可混用。** PD-01 用 45,000（含 20% MOQ 谈判空间）做筛选，PD-02 用财务上限 38,000 做最终裁决。
5. **淘汰必须留证据。** 「感觉不行」不是理由；每个放弃项要写清红线编号、实测值、证据文件，供事后复盘。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（赵晴 / 财务） |
| --- | --- |
| 多源数据归一到同一张表 | 专利 / 商标核查确认 |
| 六维评分与证据绑定 | 认证成本与可行性判断 |
| 差评聚类与机会 / 伪需求识别 | 打样与立项的最终决定 |
| 三档队列与淘汰依据整理 | 市场假设的确认 |

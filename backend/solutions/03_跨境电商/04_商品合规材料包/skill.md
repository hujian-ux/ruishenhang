  - 步骤2 完整性检查：以「目标市场 × 类目 × 要求项」为矩阵，用台账的「满足要求编号」回填，逐项判定齐备或异常

  - 步骤4 有效期核算：按核验基准日算剩余天数，90 天内到期标「即将到期」，已过期标「已过期」并立即停用
  - 步骤5 宣称审核：逐条宣称判定（绝对化用语 / 医疗功效无支撑 / 依赖要求未齐备需限定 / 参数需报告支撑 / 通过），并给出建议表述

关键规则:
  - 型号逐字核对：销售型号、送测型号、证书覆盖型号三者必须完全一致（含后缀与大小写）。不一致即标「型号冲突」，澄清前该报告不得用于任何申报——包括平台资质上传、符合性声明引用与海关申报。
  - 「测试未完成」等同「缺失」：报告已开单但项目未跑完，不能作为申报依据。
  - 「声明」不等于「认证」：CE、FCC SDoC、REACH SVHC 都是符合性声明（自我声明），详情页不得写成"通过 XX 认证"。
  - 责任人义务互不顶替：GPSR 欧盟责任人、电池法规责任人、英国责任人是三个独立义务。
  - 有效期按到期日排序，不按文件名排序；90 天预警，到期前完成换版或续期。
  - 宣称不得超出证据范围：认证宣称受证书覆盖型号约束；功效/医疗表述须有资质与检测支撑；参数须与报告实测值一致并注明依据；全站禁用绝对化用语。
  - 放行判定按 SKU × 市场分别出结论：存在缺失/过期/未完成/冲突任一 → 暂缓上市；仅有即将到期 → 有条件放行并挂盯办；全齐备 → 按期上市。同一 SKU 不同市场结论可以不同。
  - 费用类处置给方案不做决策：型号覆盖声明与重新送测各自列出费用与周期，检测与认证费用审批由人负责。

# 商品合规材料包 · Skill 定义

## 1. 能力定位

文件看着都齐了，直到有人发现测试报告上的型号和要卖的型号不一样。

商品合规材料涉及检测报告、证书、标签、说明书、责任人信息，分布在供应商邮件、实验室系统和采购文件夹里。上市前一周问供应商"证书都有吧"，对方回"都有"；证书 PDF 存进文件夹就算完成合规；没人逐字核对型号、有效期、适用标准——直到平台抽查。

本 Skill 做四件机器擅长、人容易漏的事：

1. **三方映射**：SKU—型号—文件一一对应，先暴露空档。
2. **逐项核对**：按目标市场与类目要求矩阵回填，问题分四级。
3. **冲突识别**：型号后缀、责任人、标准版本交叉核验。
4. **档案与任务**：逐 SKU 档案目录 + 补齐任务，提交前有人签字。

## 2. 输入

| 文件 | 内容 |
| --- | --- |
| `SKU型号主数据.csv` | 销售型号与送测型号必须分列——这是型号冲突检测的前提 |
| `合规证书台账.csv` | 每份文件的覆盖型号、有效期、适用标准版本、`满足要求编号`、状态 |
| `目标市场合规要求.csv` | 市场 × 类目的强制要求项、法规依据、验收标准、适用 SKU |
| `详情页宣称清单.csv` | 页面上每一条宣称的原文、类型、涉及市场 |

> `满足要求编号` 是台账与要求矩阵的连接键。台账维护时必须填，否则该文件在核验中等同不存在。

## 3. 输出

`商品合规材料包.md`，11 个部分：

1. 核验概要（四级统计 + 逐 SKU × 市场放行判定）
2. SKU—型号—文件三方映射
3. 类目资质清单（逐 SKU 逐要求项）
4. 完整性检查 · 缺失 / 测试未完成 / 型号冲突 / 即将到期 / 已过期
5. 型号冲突专项（星标素材 + 两个处置方案带费用与周期）
6. 成分标注与标签合规（限用物质、材质标注、责任人、电池标识）
7. 详情页宣称合规清单（宣称 → 依赖要求 → 判定 → 原因 → 建议表述）
8. 逐 SKU 档案目录（提交包目录树）
9. 补齐任务清单（谁、何时、拿什么验收、预计费用）
10. 审核要点（提交前必看 7 条）
11. 人工审批边界

## 4. 工作流（6 步）

```
① 三方映射 → ② 完整性检查 → ③ 冲突识别 → ④ 有效期核算 → ⑤ 宣称审核 → ⑥ 档案与任务
   空档先暴露    市场×类目矩阵    型号/责任人/标准   90天预警        判定+建议表述     目录树+补齐+放行
```

## 5. 四级问题分类

| 级别 | 触发条件 | 处置 |
| --- | --- | --- |
| 缺失 | 无任何文件对应该要求，或文件状态为「缺失」 | 不得申报，进补齐任务 |
| 测试未完成 | 报告已开单但项目未跑完 | 等同缺失，不得申报 |
| 型号冲突 | 文件覆盖型号 ≠ 销售型号 | 澄清前不得用于任何申报 |
| 即将到期 | 有效期在 90 天内 | 有条件放行 + 到期前换版/续期 |
| 已过期 | 有效期已过基准日 | 立即停止使用 |

## 6. 宣称审核判定优先级

```
医疗/功效无支撑（不通过）
  > 绝对化用语（不通过）
    > 依赖要求未齐备（需限定）
      > 参数宣称（需报告支撑）
        > 通过
```

绝对化词库：绝对、100%、永不、无隐患、高达、完全、彻底、零风险、最长、最
医疗功效词库：缓解、治疗、理疗、消肿、医用、除菌率、杀菌率

每条不通过或需限定的宣称必须给出**可直接替换的建议表述**，而不是只说"删掉"。

## 7. 放行判定

按 **SKU × 目标市场** 逐格出结论，同一 SKU 不同市场结论可以不同——这是本 Skill 最实用的输出：一个市场暂缓不必拖累其他市场按期上市。

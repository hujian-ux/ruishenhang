  - 证据文件台账.csv（字段：证据编号, 文件名, 证据类型, 出具方, 签发日期, 有效期至, 关联SKU, 关联型号, 持有人, 所在系统, 文件状态, 可24小时内取得, 对应指控编号, 星标）
  - 账号绩效指标.csv（字段：指标代码, 指标名称, 统计口径, 平台阈值, 当前值, 单位, 是否超标, 统计窗口, 数据来源）

  - 账号申诉证据包.md（案件基本信息 / 时间线 / 指控拆解 / 指控—证据映射 / 证据缺口 / 绩效核对 / POA 三段式 / 时限 SLA / 方案代价对比 / 人工边界）
workflow:
  - 步骤1 时间线还原：把投诉、页面改动、下架通知、Case 往来按时间排序，标出自相矛盾处（如"页面改动晚于首起投诉"、"安全投诉被按常规退货结案"），矛盾必须先暴露再写材料
  - 步骤2 指控拆解：把平台通知里的每一项指控独立编号（A1/A2/A3…），逐项写"平台指控原文要点 / 我方定性 / 需要证明的事"，禁止把多项指控合并回答
  - 步骤3 证据映射：读取证据台账，按"对应指控编号"把每份文件挂到指控上，并判定证明力——关联型号与销售型号一致=直接；型号不一致=间接（须限定表述）；文件状态非已归档=缺口不可引用
  - 步骤4 缺口识别：把"未取得/待导出/待供应商提供"的证据单列成缺口清单，每项给出责任人、取得方式、目标时点与预计费用，明写而不掩盖
  - 步骤5 POA 三段式：按根因（Root Cause）/ 纠正（Corrective）/ 预防（Preventive）成文，每条后括注支撑证据编号，逐条通过表述红线自检
  - 步骤6 时限 SLA 与方案：按平台时限（如 72 小时）倒排节点表；给出至少两个提交方案（窄口径 vs 完整申诉），各自带外部支出、停售天数、停售损失与合计代价
关键规则:
  - 一条主张 = 一条证据编号。没有证据编号支撑的主张，不许写进 POA。
  - 认证主体不得外扩：元件级认证只能支撑"所用元件持第三方认证"，不能推导"整机安全无隐患"。整机认证未确认前，POA 全文禁止出现"产品合规""整机安全"类表述。
  - 缺口必须明写，包括责任人、取得方式、目标时点。掩盖缺口是被驳回的主因之一。
  - 根因写"具体谁在什么时间做了什么导致什么"，不写"我们已修改页面"（那是纠正）；预防写可验证动作（SOP 编号、培训签到、审批留痕），不写"加强管理"。
  - 禁用情绪化与立场性表述：良心卖家、恶意投诉、我们很委屈、客户不讲理、绝对安全、百分百安全、加强管理。生成后必须逐词扫描。
  - 时间线不得自相矛盾，与平台 Case 记录的日期顺序必须一致。
  - 商业影响必须量化：停售日损失 = 近 30 天销售额 ÷ 30；库存货值 = 在仓件数 × 到仓单价。
  - 高风险动作一律人工：事实陈述最终确认、法律责任与承诺表述（法务）、检测费用审批、最终提交按钮。

# 账号申诉证据包 · Skill 定义

## 1. 能力定位

能写申诉信的人不少，能把发票、合同、物流和整改记录串成证据链的不多。POA 正文两小时能写完，但发票在财务、合同在采购、物流凭证在供应链、整改记录在运营——凑齐往往已过截止时间。

本 Skill 不代写"漂亮的申诉信"，而是做三件平台真正在看的事：

1. **把事实排成一条不矛盾的时间线**——平台审核只看材料，不听解释；时间线一乱，整份材料失信。
2. **把每条主张挂到具体证据编号上**——上一轮被驳回的理由是"证据与主张不对应"，不是没证据。
3. **把拿不到的证据明写成缺口**——并据此决定申诉口径，避免主张超出证据范围。

## 2. 输入

| 文件 | 内容 |
| --- | --- |
| `平台绩效通知与Case往来.md` | 平台通知原文、指控编号（A1/A2/A3）、事件时间线、上轮驳回记录、页面表述现状对照 |
| `证据文件台账.csv` | 每份证据的编号、类型、出具方、有效期、关联 SKU 与型号、持有人、所在系统、文件状态、能否 24 小时内取得、对应指控 |
| `账号绩效指标.csv` | ODR、安全投诉数、政策违规通知、A-to-z 索赔率等指标的阈值与当前值 |

## 3. 输出

`账号申诉证据包.md`，10 个部分：

1. 案件基本信息与商业影响（含停售日损失、库存货值）
2. 事件时间线还原（矛盾点先暴露）
3. 平台指控拆解（逐项定性 + 需证明的事）
4. 指控—证据映射表（含证明力判定与星标素材）
5. 证据缺口清单（责任人 / 取得方式 / 目标时点 / 费用）
6. 账号绩效指标核对（超标项与承接关系）
7. 申诉陈述 · POA 三段式草稿 + 表述红线自检
8. 时限 SLA 倒排表
9. 两个提交方案与代价对比
10. 人工审批边界

## 4. 工作流（6 步）

```
① 时间线还原 → ② 指控拆解 → ③ 证据映射 → ④ 缺口识别 → ⑤ POA 三段式 → ⑥ 时限 SLA 与方案
   矛盾先暴露     逐项配证据     判定证明力     明写不掩盖      红线自检        代价可比
```

## 5. 证明力判定规则（步骤 3 的核心）

| 条件 | 判定 | 后果 |
| --- | --- | --- |
| 关联型号 == 销售型号，文件状态 = 已归档 | 直接 | 可直接引用支撑主张 |
| 关联型号 != 销售型号（如元件型号），文件状态 = 已归档 | 间接 | 只能支撑限定表述，须明确认证对象 |
| 文件状态 = 未取得 / 待导出 / 待供应商提供 | 缺口 | 不可引用，进缺口清单 |

**星标素材**：能改变申诉口径的证据要标星。例如供应商回传的元件 UL 认证证书——它证明问题在页面表述而非产品本体，同时暴露"整机认证未确认"这一缺口，直接决定本轮采用窄口径申诉。

## 6. POA 三段式写作规范

| 段 | 要写什么 | 不许写什么 |
| --- | --- | --- |
| 根因 Root Cause | 具体谁、在什么时间、做了什么、导致什么后果，可追溯到证据 | "我们已经修改了页面"（这是纠正）、"客户误用"、"平台误判" |
| 纠正 Corrective | 已完成的动作 + 完成时间 + 留证方式（截图/记录/报告编号） | "已重视""已排查"这类无留证动作 |
| 预防 Preventive | 制度化动作：SOP 编号与版本、审批流留痕、培训签到人数、系统卡点 | "加强管理""提高意识""严格要求" |

## 7. 时限管理

- 收到通知即为 T+0，按平台给的小时数（24 / 48 / 72）倒排。
- 每个节点写清动作、责任人、状态（已完成 / 进行中 / 待办 / 硬约束）。
- 无法在时限内取得的证据（如需 8 个工作日的检测报告），不得作为本轮提交前置条件，改为复审阶段并行推进。

## 8. 方案代价计算

```
停售损失 = 近30天销售额 ÷ 30 × 预计停售天数
合计代价 = 停售损失 + 外部支出（检测费/认证费/服务费）
```

至少给两个方案：**窄口径申诉**（时限内提交、外部支出为 0、口径受限）与**完整申诉**（等检测报告、口径完整、超时限）。让业务方按金额和时限决策，而不是按感觉。

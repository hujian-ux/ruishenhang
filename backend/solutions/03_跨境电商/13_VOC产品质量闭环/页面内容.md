现状与痛点

HT-H03 加湿器近 90 天：差评 214 条、退货 163 单、工单 96 件，几乎全写着「质量不好」，仓库 Disposition 也标 Defective——看起来是板上钉钉的质量问题。

Disposition 不等于根因

仓库按外观与功能检查结果标 Defective，客户按使用体验退货——两套语言说的是两件事。Defective 里混着「已开封无法复原」，按它追责供应商就是冤案。

高频误判
差评、退货、工单在三个系统里

评论在平台后台、退货在 FBA 报告、工单在客服系统，没人每月把三类数据按 SKU 对齐看一遍——同一个问题重复三个月才被发现。

结构性盲区
Listing 误导造成的退货，质量部门背锅

尺寸图、参数表、场景照造成的预期差，最终计入「质量退货」：供应商被罚款、产品被误判，真正该改的那张图没人改。

责任错位
整改没有闭环，问题换皮重来

客服知道尺寸有问题，运营不知道；运营改了图，没人告诉客服话术要换——下个月同类工单继续来。

组织失忆

你们仓库退货表的备注栏，客服和产品部看过吗？61% 写的是 too small / not as expected——产品没坏。

WorkBuddy 的解决与价值

差别不在快，在于有人把散在多处的东西拼到了一起：三类 VOC 按 SKU / 日期 / 语言对齐，用客户原话推翻仓库标签，再把结论落成有岗位、有验收、有截止的 CAPA。

现在的做法

差评归类靠客服月底手工翻；Disposition 是什么就按什么定责；质量问题找供应商，描述问题没人认领；改完没有验收，下月同样的问题再来。

WorkBuddy 的做法

三类数据按 SKU / 日期 / 语言对齐；问题聚类占比必须算平（尺寸 61% / 噪音 19% / 漏水 11% / 其他 9%）；星标素材用仓库备注栏的 too small 推翻 Defective 标签；双路径归因把 CAPA 派到岗位。

三个核心价值
01把误判从质量账上摘出来

163 单退货里 122 单被标 Defective，其中 71 单属尺寸类、仓库自己写着「通电正常、无渗漏」。这 71 单索赔可撤销，供应商与质量月报同步更正。

02让钱说话，让图被改

尺寸类退货 99 单 × 18.4 USD = 1,821.6 USD，占四类退货损失 3,078.9 USD 的 59.2%。金额一摆出来，改五点描述这种零成本动作 48 小时内就能上线。

03双路径归因让整改真闭环

每个主题都要回答「为什么发生」和「为什么没被拦住」——前者改内容，后者补流程（Listing 尺寸完整性审校项、VOC 月度对齐例会），下个月才不会换皮重来。

方案定位

不是替品质部门做检验判定，而是把「三源对齐 + 聚类算平 + 星标取证 + 双路径归因 + CAPA 派工」做成可复跑的流水线。产品根因认定、Listing 修改确认、供应商索赔决定，一律交回人做。

解决方案的工作流程

五步，每步都有正式产出；占比算不平、证据编号写不出来，流程不允许往下走。

01三源数据对齐

差评 / 退货 / 工单按 SKU、日期、语言统一到同一时间窗，三源不去重，报出分量与合并条数。

02问题聚类算平

用客户原话打主题标签而非平台原因码，条数之和必须等于合并条数，占比之和必须 100.0%。

03星标素材取证

交叉核对 Disposition 与退货备注，逐条列出矛盾的 return_id；按 Listing 版本切分找拐点。

04双路径归因

为什么发生 + 为什么没被拦住分开追，并判定「产品失效」还是「描述性预期差」。

05CAPA 派工验收

改图 / 改描述 / 改话术 / 加质检项各有责任岗位、验收标准与截止日，零成本动作排在最前。

脱敏案例：海拓生活科技 · HT-H03 加湿器

近 90 天（2025-12-16 ~ 2026-03-15）差评 214 条、退货 163 单、工单 96 件，VOC 合并 473 条。聚类结果：尺寸误解 288 条（61%）、噪音 90 条（19%）、漏水 52 条（11%）、其他 43 条（9%），条数与占比双向算平。星标素材来自没人翻的地方——退货表 warehouse_note 栏：71 单被标 Defective 的尺寸类退货，仓库自己写着「通电正常、功能测试通过、无渗漏」，客户备注写 too small。再按 Listing 版本切分，尺寸类差评 130 条中有 66 条挤在 v2.3 改图后的 14 天里，日均 4.71 条 vs 其余时段 0.84 条。产品从没变，变的是那张移除了参照物、只标 φ168mm 外径的主图。

提示词
TRAINING PROMPT · 复制即用
请按「VOC产品质量闭环」技能，处理 SKU HT-H03（海拓生活科技 · 家用桌面加湿器）近 90 天（2025-12-16 ~ 2026-03-15）的 VOC 数据，输出可派工的 CAPA 闭环表。

【输入 1 · 差评明细.csv】214 行
字段：review_id, sku, review_date, marketplace, language, star_rating, review_title, review_body, verified_purchase, listing_version, theme_tag

【输入 2 · FBA退货报告.csv】163 行
字段：return_id, order_id, sku, return_date, marketplace, quantity, platform_reason_code, customer_comment, warehouse_disposition, warehouse_note, unit_loss_usd, theme_tag

【输入 3 · 客服工单.csv】96 行
字段：ticket_id, sku, created_date, marketplace, channel, subject, customer_verbatim, first_reply_hours, resolution, linked_order_id, theme_tag

【输入 4 · 产品与Listing档案.md】
含：三维规格基准（外径 φ168mm / 含底座总宽 205mm / 含盖总高 286mm）、Listing v2.1/v2.2/v2.3 变更记录与上线日期、Disposition 口径对照、责任岗位对照表

【输出要求 · 按 5 段】
1. 三源对齐：报出 差评/退货/工单 条数与 VOC 合并条数，说明时间窗与「不去重」口径
2. 问题聚类：尺寸误解 / 噪音 / 漏水 / 其他 四类的条数与占比 —— 占比之和必须 = 100.0%，四类条数之和必须 = VOC 合并条数
3. 星标素材：列出 warehouse_disposition = Defective 且 customer_comment 含 "too small" / "not as expected" 的真实 return_id，报出误判单数与占全部 Defective 的比例，并结合 warehouse_note 说明「通电正常/无渗漏」为何不构成质量失效证据；同时按 Listing v2.3 上线日（2026-01-18）切分尺寸类差评，给出上线后 14 天日均 vs 其余时段日均的倍数
4. 双路径归因：每个主题分别写「为什么发生」与「为什么没被拦住」，并判定根因类型（产品失效 / 描述性预期差），描述性预期差一律不得向供应商索赔
5. CAPA 闭环表（CSV）：序号, 问题主题, VOC合并条数, 占比, 退货单数, 单均损失USD, 损失金额USD, 星标证据编号, 发生原因_为什么发生, 流出原因_为什么没被拦住, 根因判定, CAPA编号, CAPA动作, 动作类型, 责任岗位, 验收标准, 目标完成日, 状态 —— 主题级指标只在该主题首行填写，末行为合计校验行

【硬规则】
- 金额只从退货表算：主题损失 = 该主题退货单数 × 该主题单均损失
- 零成本动作（改五点描述文字）必须排在改图之前，并给 48 小时内截止
- 尺寸图未上线前，不得出现「已解决」结论；结案条件写成上线后 30 天占比目标
- 不承诺效率百分比，只报可复算的条数、占比、金额、日期
- 产品根因认定 / Listing 修改确认 / 供应商索赔决定，标注为「需人工审批」

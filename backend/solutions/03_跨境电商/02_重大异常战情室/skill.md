# 重大异常战情室（MG-02）

## 适用时机
- GPSR 限期下架、封号、召回等重大异常发生，群里同时有 5 个版本说法，事实比谣言跑得慢。
- 运营、客服、采购、财务各看自己一段，没有人把碎片拼成一条时间线，老板在群里挨个问。
- 需要对外发口径，但虚假陈述风险敞口必须写清楚，且须法务/老板确认。

## 输入（inputs）
- `下架SKU清单.csv`：SKU / 品类 / 德国站月销售额USD / FBA库存件数 / 下架原因线索。
- `客户舆情记录.csv`：客户ID / 国家 / 首问时间 / 核心诉求 / 是否提及平台投诉 / 风险等级。
- `异常事件时间线.csv`：时间 / 事件类型 / 来源 / 描述。

## 工作流程（workflow）
1. **时间线**：通知、整改、抽检、下架、客诉，按时间排成一条所有人认可的主线。
2. **统一事实**：下架几个、涉及多少销售和库存，群里只认这一版，杜绝多版本。
3. **影响分级**：销售 / 库存 / 客户舆情 / 账号健康四级分开估、分开派人。
4. **对外口径**：给两个版本各带风险敞口，法务确认前不群发；虚假陈述风险写清楚。
5. **升级与归档**：L1 现场 → L2 老板审批 → L3 法务/平台 → L4 复盘归档，避免组织失忆。

## 输出（outputs）
- 异常事件时间线（统一版）。
- 影响四级分级表（含处置负责人）。
- 对外口径两版（各带风险）。
- 升级路径表与复盘归档要求。
- 重大异常战情室看板 `.md`（见 `重大异常战情室看板.md`）。

## 关键规则 / 提示词要点
- 事实优先：所有数字来自输入表，不编造；统一事实版本前不下结论。
- 舆情比下架更急：先安抚客户再处理恢复，话术不承诺具体恢复日期、不虚构原因。
- 根因未确认前不能对外发统一口径；对外口径最终确认由法务/老板负责。
- 高风险动作（与平台/监管沟通、恢复销售决定）一律人工决策。

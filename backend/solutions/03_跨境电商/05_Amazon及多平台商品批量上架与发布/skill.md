# Amazon及多平台商品批量上架与发布校验

## 适用时机
- ERP / 刊登工具批量上架后收到平台回执（如 Amazon Listings Items API 的创建/校验/错误回执），报出大量字段错误需要归因。
- 多变体 SKU（如颜色/尺寸变体）首次上架，父子体关系容易挂错。
- 历史旧 ERP 把颜色变体建成独立 SKU，与新主数据「父子体」规则冲突，需要定位根因。
- 类目错选导致搜索流量错配、发布动作缺乏审批与回执闭环。

## 输入（Inputs）
- `商品上架主数据.csv`：每行一个 SKU，含 父SKU / 产品系列 / 颜色 / 变体主题 / 提交类目节点 / 推荐类目节点 / 主图尺寸 / 附图数量 / 证书状态 / 变体关系状态 / 归属站点。
- `旧ERP_SKU映射表.csv`（星标素材）：旧系统 SKU 规则 vs 新主数据父子体要求，用于暴露变体规则冲突根源。
- 平台 Schema 要求：类目节点、必填属性、枚举值、图片规格（主图≥1000x1000px、纯白底、占比≥85% 等）。

## 输出（Outputs）
- **上架校验与批次发布计划.csv**（预期交付物）：
  - 摘要区：回执字段错误总数、三类归口（图片/类目/变体）、字段级展开数、发布策略、星标素材、历史代价参考。
  - 明细表：序号 / SKU / 错误类别 / 字段 / 平台要求 / 当前值 / 问题描述 / 严重度 / 修正建议 / 责任方 / 发布批次。
- 修正对照表：每条错误 → 平台要求 → 当前值 → 修正动作，供运营一键核对。

## 工作流程（Workflow）
1. **主数据校验**：发布前先过必填字段、图片规格（尺寸/分辨率/白底/占比）、证书状态；不通过则拦截，不进入发布队列。
2. **Schema 映射**：产品类型、属性、枚举值与目标平台类目要求逐项对齐；类目节点与必填属性联动检查。
3. **错误归因**：回执错误按「图片 / 类目 / 变体」三类归口，每条定位到具体 SKU 与字段，引用旧 ERP 映射表判定变体根因（颜色是否被建成独立 SKU）。
4. **修正对照**：为每条错误生成「平台要求 vs 当前值 vs 修正建议」，标注责任方（AI 自动修正 / 人工确认）。
5. **分批发布**：无争议项（图片规格、类目属性）AI 修正后先发；争议项（变体父子体）待人工确认后重试，回执全程留痕，形成闭环。

## 关键规则与提示词要点
- **变体映射未确认前，不批量发布**：先发无争议 SKU，保留争议 SKU 进入重试队列。
- **错误分类口径**：图片类=主图/附图尺寸与质量；类目类=类目节点与随类目必填属性；变体类=父SKU关联、变体主题、子体关系、库存/价格联动。
- **历史代价提示**：错类目不立刻报错但搜索流量分配全错（案例 HT-K02 曾 7 天损失约 1,900 USD 销售额），类目必须人工确认。
- **人工边界（AI 负责 / 人负责）**：
  - AI 负责：主数据与 Schema 校验、错误分类归因、修正对照表生成、发布批次与重试队列编排。
  - 人负责：变体关系最终确认、类目选择确认、正式发布按钮。
- **高风险动作一律人工审批**：任何改写类目、父子体结构的操作需运营确认后再执行。

## 使用方式
1. 在 WorkBuddy 左侧「专家·技能·连接器」点击「添加技能 → 上传技能」，导入本 Skill 包（`03_技能包/Amazon及多平台商品批量上架与发布/` 文件夹或 Skill 包 zip），并在「已安装」列表启用。
2. 上传 `商品上架主数据.csv` 与 `旧ERP_SKU映射表.csv`。
3. 发送主提示词（见 `主提示词.md`），由 Skill 驱动校验与归因。
4. 核对交付物：42 字段错误是否三类归口、修正对照是否可照做、分批计划是否「先发3无争议 + 重试3争议」。

> 真实性说明：Listings Items API 的创建/校验/错误回执机制来自 Amazon 官方文档；错误类型来自铺货实务；案例数据为脱敏构造，不承诺效率百分比，高风险动作一律人工审批。

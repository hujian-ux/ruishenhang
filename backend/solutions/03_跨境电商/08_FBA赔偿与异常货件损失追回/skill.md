# Skill · FBA 赔偿与异常货件损失追回

## 适用时机
- 平台自动赔偿已到账，但你想确认「赔得足不足、漏没漏」；
- 月底/季末对账，发现库存事件报告里的丢损数量和赔偿明细对不上；
- 准备向 Amazon Seller Central 提交 reimbursement / 索赔申诉；
- 担心索赔时效窗口（FBA 丢损索赔有明确时效，过期归零）。

## 输入（inputs）
1. `库存事件报告.csv` —— 平台导出的库存事件（Lost / Damaged / Disposed / Inbound 差异），含事件号、SKU、数量、发生时间。
2. `FBA赔偿明细.csv` —— 平台已自动赔偿明细，含事件号、SKU、赔偿金额（平台估算成本口径）、赔付时间。
3. `货件接收记录.csv` —— 货件入仓接收记录，含 SKU、应收/实收数量、差异件数。
4. `采购发票成本.md / .csv` —— 真实制造成本（采购发票写明的单位成本），用于核对平台默认估算成本。

> 三张表「事件号 + SKU」对不上是常态，Skill 必须先做对齐再核对。

## 工作流程（workflow）
1. **三方匹配**：以「事件号 + SKU」为主键，把库存事件、赔偿明细、货件接收记录逐笔对齐；无法匹配的先单列「待澄清」。
2. **分类**：每笔标记为 `已赔足额` / `漏赔`(应赔未赔) / `少赔`(已赔但按平台估算成本低于发票成本) / `无需赔`(正常流转、无丢损)。
3. **成本核对**：制造成本以**采购发票**为准，平台默认估算成本与发票差异单列，「少赔」= (发票成本 − 平台估算成本) × 丢损件数。
4. **金额计算**：漏赔合计 + 少赔差额合计 = 可追回总额；每笔金额可复算、可溯源。
5. **案件提交**：组织案件包（事件号 + SKU + 丢损件数 + 发票成本证明 + 应赔金额），证据最齐、时效最临期的优先提交。

## 输出（outputs）
- `FBA赔偿与异常货件损失追回_案件分析.csv` —— 84 行（示例）：每行含分类、平台估算成本、发票成本、平台已赔、应赔、漏赔/少赔差额、时效状态、证据状态、提交优先级。
- 索赔案件包清单（优先提交顺序）+ 时效预警（临期标红，仅提示不代提交）。

## 关键规则 / 提示
- **自动赔偿 ≠ 足额赔偿**：Amazon FBA 按制造成本赔丢损，默认用平台估算成本，估算往往低于真实采购价，差额不逐笔核就白白流失（政策 2025-03 起按制造成本口径）。
- **成本以发票为准**：平台估算成本（如 ¥52/件）低于采购发票（如 ¥68/件）时，差额逐笔追；发票扫描件上传前，对应案件不得提交。
- **有时效**：丢损索赔有时效窗口，超期归零；时效临期案件优先提。
- **人工边界（硬性）**：
  - AI 负责：三方匹配与分类、成本差异逐笔计算、案件包组织、时效预警；
  - 人负责：制造成本申报确认、索赔提交、与平台的争议沟通。
- **不承诺效率百分比**，高风险动作（提交索赔、与平台争议）一律人工审批。

## 验收自检（生成后逐条回答）
1. 84 条库存事件是否 = 31 已赔 + 7 漏赔 + 4 少赔 + 42 无需赔（算式配平）？
2. 漏赔 7 笔合计是否 = 1,486 USD？少赔 4 笔差额合计是否 ≈ 728 USD？可追回是否 ≈ 2,214 USD？
3. 4 笔少赔是否均标记「需发票扫描件，未上传不得提交」？
4. 时效临期的案件是否排在最前提交？
5. 是否全程无任何「已替你提交索赔」「平台会自动赔够」等误导表述？

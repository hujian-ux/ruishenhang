# 海外客户分级开发与跟进台账

## 一、这个 Skill 解决什么

海外客户开发的真实困难不是「不认识客户」，而是**每个客户的往来记录散在不同的人、不同的渠道、不同的备忘里**：

- 触达前不知道这个客户此前联系过没有，重复开发信发出去尴尬又低效
- 谁是重点客户、谁在流失，全靠老销售的脑子记，人一休假就断线
- 不同等级的客户用同一套话术、同一个频率跟进，大客户嫌慢、小客户嫌烦
- 跟进到哪一步了没有统一台账，交接时只能口头补课

本 Skill 的核心动作，是把 30 条散落的往来记录按规则归集分级，让每一条分级结论都能回溯到规则编号与实测值，并给每一级客户配上确定的跟进节奏。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 客户信息分散在多个渠道，需要统一建台账 | 主用场景：归集 + 分级 + 定节奏 |
| 开发新客户前，需要先核查历史触达避免重复 | 输入文件的跟进事项列即历史核查底稿 |
| 季度/半年度客户盘点，需要区分重点与流失风险 | 分级结果直接给出 A/B/C 分布与金额占比 |
| 销售交接或团队协作，需要统一的客户视图 | 台账即交接底稿，逐行对应客户 |

**不适用**：单一客户的深度背调报告（本 Skill 只做分级与节奏，不做企业征信调查）；已成交订单的跟单执行（→ 跟单交付类场景）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `海外客户往来记录.csv` | 必需 | 客户编号、客户名称、区域、最近订单日期、年采购额USD、沟通渠道、跟进事项 |
| 2 | `分级与跟进规则.md` | 必需 | 基准日、GA1/GB1/GB2/GC1 分级规则、各等级跟进节奏与建议动作、判定依据书写规范 |

> 缺 2（规则文件）时，本 Skill **必须拒绝输出分级结论**——没有先立的规则，分级就退化成主观印象。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`客户分级与跟进台账.csv`，字段固定为 7 列：

```
客户编号, 客户名称, 区域, 等级, 判定依据, 下次跟进日期, 建议动作
```

- `等级` ∈ {A, B, C}
- `判定依据` 必须包含规则编号（GA1/GB1/GB2/GC1）+ 年采购额实测值 + 订单间隔天数实测值，**不允许写「综合评估」「经验判断」**
- `下次跟进日期` 只按等级节奏计算（A +14 天 / B +30 天 / C +90 天，基于基准日 2026-06-30）
- 行数 = 输入行数（30 行），逐行对应，不允许合并或遗漏客户

## 五、工作流程（workflow）

### STEP 1 · 归集往来记录

把邮件、WhatsApp、视频会议纪要与个人备忘里的客户往来记录归集到 `海外客户往来记录.csv`，每个客户一行，字段齐全才算归集完成。

### STEP 2 · 先立规则再看客户

从 `分级与跟进规则.md` 读入基准日与 GA1/GB1/GB2/GC1 四条规则，写成显式判定表。**顺序不可颠倒**——先看客户再定标准，等于给结论找理由。

```
GA1  年采购额 ≥200,000 USD 且最近订单距基准日 ≤90 天      → A
GB1  年采购额 ≥200,000 USD 且最近订单距基准日 >90 天      → B
GB2  60,000 ≤ 年采购额 <200,000 且订单距基准日 ≤180 天     → B
GC1  其余（金额 <60,000，或 60,000–200,000 但订单 >180 天） → C
```

### STEP 3 · 逐行分级并写判定依据

对每个客户计算间隔天数 = 基准日 − 最近订单日期，按 GA1→GB1→GB2→GC1 顺序判定，命中即定级。判定依据必须写成可复算格式（规则编号 + 两个实测值）。

### STEP 4 · 匹配跟进节奏与建议动作

| 等级 | 节奏 | 下次跟进日期 | 建议动作 |
| --- | --- | --- | --- |
| A | 每 14 天 | 基准日 + 14 天 = 2026-07-14 | 发送新品样册并预约视频会议，逐条推进在手事项 |
| B | 每 30 天 | 基准日 + 30 天 = 2026-07-30 | 发送品类报价更新与组合采购方案 |
| C | 每 90 天 | 基准日 + 90 天 = 2026-09-28 | 发送电子版产品目录与区域市场动态，观察复激活信号 |

### STEP 5 · 触达前历史核查

触达任何客户前，先读台账的跟进事项列：已有待办事项的客户从待办续起，无事项的客户按等级建议动作发起首触。**避免重复联系**。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出：

1. 台账行数是否 = 往来记录行数（30 行）？
2. 每行判定依据是否都含规则编号与两个实测值？
3. 分级分布是否可复算（本批：A 8 / B 12 / C 10）？
4. 下次跟进日期是否严格按等级节奏计算？
5. 是否没有任何一行出现「综合评估」「经验判断」？

## 六、关键规则（不可协商）

1. **规则先立、数据后判。** 分级结论只能引用规则文件的四条编号，不得临时新增或放宽规则。
2. **判定依据必须可复算。** 金额与间隔天数都要写实测值，任何人拿同一份输入都能得出同一等级。
3. **跟进节奏不由个人偏好决定。** A/B/C 的 14/30/90 天节奏写在规则里，提前或延后都要有书面理由。
4. **触达前必查历史。** 跟进事项列就是重复触达的防线，绕过核查直接开发视为违规。
5. **分级不等于放弃。** C 级是「观察复激活信号」，不是删除；降级与淘汰客户属于人的决策。
6. **不承诺转化率。** 输出中不写「提升 X% 成交率」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（海外销售岗） |
| --- | --- |
| 多渠道往来记录归一与格式校验 | 客户深度背调与信用判断 |
| 按规则分级并绑定判定依据 | 分级规则的制定与季度修订 |
| 跟进节奏与建议动作生成 | 关键客户的谈判与让价决策 |
| 台账统一维护与历史核查底稿 | 客户降级、保留与淘汰的最终决定 |

## 八、下游衔接

- A 级客户在手事项 → 跟单交付与单证加工场景（订单执行链路）
- C 级客户复激活信号 → 本场景下一轮台账更新
- 多语言样册与目录发送 → 产品内容目录与视觉方案批量加工（MED-10）


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规则再分级：把四条规则写成显式判定表，不要先看客户数据再定标准。
2. 逐行分级：对 30 个客户逐个计算间隔天数与规则命中，判定依据必须写成「年采购额实测值 + 间隔天数实测值 + 规则编号」的格式，可复算。
3. 匹配节奏：下次跟进日期严格按等级节奏计算，建议动作按等级映射：A 发新品样册并约视频会议 / B 发品类报价更新与组合方案 / C 发电子目录与区域市场动态。
4. 历史核查标注：跟进事项列已有待办的客户，在建议动作前保留原待办表述，避免重复触达。
5. 统计汇总：分级完成后给出 A/B/C 家数分布、A 级年采购额合计及其占 30 家合计的百分比（保留 1 位小数）。

### 硬性约束

【硬性约束】
- 判定依据必须含规则编号与两个实测值，不允许写「综合评估」「经验判断」。
- 不允许新增、放宽或临时修改分级规则；规则缺漏时先问人，不要自行补规则。
- 客户降级、保留与淘汰的最终结论属于人工，AI 只输出分级与建议动作。
- 不写任何转化率承诺或效率百分比。

### 生成后自检

【生成后自检，逐条回答】
1. 台账行数是否 = 30，与输入逐行对应？
2. 每行判定依据是否都含规则编号 + 金额实测值 + 间隔实测值？
3. 分级分布是否与本批数据一致（应为 A 8 家 / B 12 家 / C 10 家）？
4. A 级年采购额合计是否为 2,923,000 USD，占 30 家合计 5,042,000 USD 的 58.0%？
5. 下次跟进日期是否分别为 2026-07-14（A）/ 2026-07-30（B）/ 2026-09-28（C）？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，7 列，列名与顺序固定：
客户编号, 客户名称, 区域, 等级, 判定依据, 下次跟进日期, 建议动作
共 30 行，与输入逐行对应，不合并、不遗漏。

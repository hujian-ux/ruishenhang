# MED-13 主提示词 · 多形态资料结构化转换与整合

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/多形态资料结构化转换与整合/SKILL.md`）。
2. 上传两个附件：`多形态资料清单.csv`、`知识条目Schema.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `结构化转换与整合清单.csv` 后，按文末「验收清单」逐项核对。

## 主提示词（复制即用）

```
请基于我上传的两份素材，为「某创新药企业 · 知识管理条线」做多形态资料的结构化转换与整合，输出一张可复核的结构化转换与整合清单。

【输入 1 · 资料清单】多形态资料清单.csv（20 行）
- 含资料编号（D01-D20）、资料名称、形态、来源、关键内容摘要、涉及主题、原始条目数、其中重复条目数
【输入 2 · 知识条目 Schema】知识条目Schema.md
- 条目字段定义（含来源资料编号，条条可溯源）、11 个主题枚举、按形态的转换动作映射
- 去重规则：同主题要点重复的条目合并，入库条目数 = 原始条目数 − 去重条目数
- 冲突处理：同一数据要素在不同来源数值不一致时双保留，后入库一方标记「冲突待裁决」，提交知识管理委员会人工裁决

【输出】结构化转换与整合清单.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「多形态资料结构化转换与整合」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **为什么 D17 壁报扫描件的条目要标冲突？** 期望回答：壁报中的 ORR 数值与 D01 总结报告不一致，双来源条目均保留入库，D17 一方标记「冲突待裁决」，提交知识管理委员会。
2. **去重 18 条删掉的是什么？** 期望回答：同主题要点重复的条目合并后保留信息最全的一条（如文献索引总表中与既有报告重复的 3 条），去重是合并不是删数据，去重条数逐份写明。
3. **D06 竞品A跟踪简报为什么去重为 0？** 期望回答：D06 原始 5 条无重复条目，但其中中位OS数值与 D05 报告不一致，条目全部入库并标记冲突——去重与冲突是两件独立的事。
4. **86 条这个数字怎么来的？** 期望回答：20 份资料原始条目合计 104 条，去重 18 条（涉及 10 份资料），入库 = 104 − 18 = 86 条，逐份可复算。
5. **冲突条目能不能直接给结论？** 期望回答：不能。裁决属于知识管理委员会，裁决前冲突条目不参与下游引用，AI 只负责发现、标记与移交。

## 验收清单

- [ ] 知识条目 86 条 = 原始 104 条 − 去重 18 条（涉及去重资料 10 份）
- [ ] 冲突待裁决 5 处：D06 / D07 / D09 / D17 / D20（分别对 D05 / D01 / D14 / D01 / D13）

- [ ] 全表无静默丢弃：冲突双保留，原始材料只读

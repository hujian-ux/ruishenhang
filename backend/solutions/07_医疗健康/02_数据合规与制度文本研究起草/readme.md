# MED-02 · 数据合规与制度文本研究起草 —— 场景使用说明

- **行业**：医疗健康
- **角色**：合规与制度管理岗（祁悦）
- **场景编号**：MED-02
- **案例主体**：某第三方医学检验机构

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/数据合规与制度文本研究起草/SKILL.md` | Skill 定义 | 只读边界、四类判定规则、修订建议生成口径、引用规范与复核轮要求 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 复核轮指令 + 关键追问 + 验收清单 |
| `合规要求条款库.csv` | 原始输入 | 15 行合规要求：条款编号、要求摘要、适用范围、来源文件、对应制度条款、参数与比较方式 |
| `现行制度文本.md` | 原始输入 | 现行《检验数据安全管理办法》第 1-15 条，9 条带参数行、4 条仅定性表述、2 条无对应条款 |
| `研究边界说明.md` | 原始输入 | 只读原则、判定规则、修订建议生成规则、引用规范、起草与复核分轮 |
| `制度修订建议表.csv` | **交付物** | 15 行：合规条款 × 现行制度对应位置 × 差距判定 × 修订建议 × 引用依据 |
| `合规与制度管理岗-数据合规与制度文本研究起草.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `合规要求条款库.csv`、`现行制度文本.md`、`研究边界说明.md` 三份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 新开会话执行「复核轮指令」，对成果做一次只读复核后再进入人工审议。

## 三、交付物验证记录

生成脚本以 Python 标准库 `csv/re` 实际写出文件，并在脚本内做断言验证（含「现行制度文本零改动」的只读边界断言）。执行结果：

```
OK 交付物 15 行 | 差距分布：一致 3 / 部分一致 4 / 不一致 6 / 制度缺失 2
OK 需修订合计 12 处（不一致 6 + 制度缺失 2 + 部分一致 4）
OK 现行制度文本保持只读（15 条，参数行 9 条）
ALL MED-02 ASSERTIONS PASSED
```

### 断言项

| 断言 | 结果 |
| --- | --- |
| `合规要求条款库.csv` 数据行 = 15（CR01-CR15） | 通过 |
| `制度修订建议表.csv` 数据行 = 15，5 列表头一致 | 通过 |
| 差距分布 = 一致 3 / 部分一致 4 / 不一致 6 / 制度缺失 2 | 通过 |
| 需修订合计 = 12 处（不一致 6 + 制度缺失 2 + 部分一致 4） | 通过 |
| CR01 判定不一致（现行第 4 条报告保存年数=5 < 要求下限 6） | 通过 |
| CR05 判定一致（现行第 3 条分级复核频次=2 ≥ 要求下限 1） | 通过 |
| CR06 / CR08 判定制度缺失（条款库标注无对应条款） | 通过 |
| CR04 / CR11 / CR12 / CR13 判定部分一致（有条款、无参数行） | 通过 |
| CR09 判定不一致（现行第 14 条上报时限=48 > 要求上限 24） | 通过 |
| 现行制度文本在研究前后内容一致（只读边界） | 通过 |

### 可复算口径

- `判定规则`：条款不存在 → 制度缺失；有参数行且不满足（下限类现行值<要求值 / 上限类现行值>要求值 / 是否类现行值≠要求值）→ 不一致；有条款无参数行 → 部分一致；有参数行且满足 → 一致
- `需修订数` = 不一致 + 制度缺失 + 部分一致 = 6 + 2 + 4 = 12

### 关键数字溯源

| 数字 | 出处与算法 |
| --- | --- |
| 15 条合规要求 | `合规要求条款库.csv` 数据行数（CR01-CR15） |
| 6 处不一致 | CR01（5<6 年）/ CR02（5<6 月）/ CR09（48>24 时）/ CR10（5>3 日）/ CR14（8<10 年）/ CR15（7>5 日） |
| 2 处制度缺失 | CR06（数据安全培训）/ CR08（病理切片外送）——现行制度无对应条款 |
| 4 处部分一致 | CR04 / CR11 / CR12 / CR13——现行第 12、13、5、10 条仅定性表述、无参数行 |
| 3 处沿用 | CR03 / CR05 / CR07——参数行比对满足 |
| 现行制度 15 条、9 条参数行 | `现行制度文本.md` 条款计数与「参数：」行计数 |

## 四、真实性等级与边界

- **T2**：只读研究方法与「边界写进需求」的协作模式来自企业应用实践的工作方式描述。
- **T3**：岗位痛点来自合规与制度管理职能的通用工作场景。
- **构造**：条款库与制度文本为构造数据，判定全部机械可复算。
- **人工边界**：修订建议的审议与发文决定、对外协议条款的法务复核、最终合规意见一律人工；AI 不出最终合规意见。

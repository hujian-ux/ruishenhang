# MED-02 主提示词 · 数据合规与制度文本研究起草

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/数据合规与制度文本研究起草/SKILL.md`）。
2. 上传三个附件：`合规要求条款库.csv`、`现行制度文本.md`、`研究边界说明.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `制度修订建议表.csv` 后，按文末「验收清单」逐项核对。
5. 复核轮：新开一个会话，用本提示词的复核指令对成果做只读复核。

---

## 主提示词（复制即用）

```
你是数据合规研究员，请完成一次只读研究：不修改任何文件，不读取任何业务数据文件，只基于我上传的三份素材，为「某第三方医学检验机构 · 检验数据安全管理办法」输出制度修订建议表。

【输入 1 · 合规要求条款库】合规要求条款库.csv（15 行）
- 含条款编号（CR01-CR15）、要求摘要、适用范围、来源文件、对应制度条款、参数名、要求参数值、比较方式（下限/上限/是否）
【输入 2 · 现行制度文本】现行制度文本.md
- 现行办法正文（第 1-15 条），部分条款带参数行（格式：参数：名=值），部分条款仅定性表述
【输入 3 · 研究边界】研究边界说明.md
- 只读原则：不修改文件、不读业务数据、起草与复核分轮
- 判定规则：制度缺失 / 不一致 / 部分一致 / 一致的机械定义
- 修订建议生成规则与引用规范

【输出】制度修订建议表.csv——CSV，5 列，列名与顺序固定：合规条款, 现行制度对应位置, 差距判定, 修订建议, 引用依据

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「数据合规与制度文本研究起草」技能执行（技能附录含本案例完整执行细则）。
```

```
合规条款, 现行制度对应位置, 差距判定, 修订建议, 引用依据
```

输出格式：5 列，列名与顺序固定，与 `制度修订建议表.csv` 表头一致。

## 复核轮指令（起草完成后另开会话使用）

```
你是交付前复核员。请对我提供的制度修订建议表做一次只读复核：不修改任何文件，只检查三件事——
1. 每条差距判定是否与条款库参数和制度文本参数行的比对结果一致；
2. 每条引用依据是否真实指向条款库编号与制度文本条款号；
3. 修订建议口径是否与研究边界说明第三节一致。
输出复核意见清单，只指出不一致处，不重写建议表。
```

## 本案例的关键追问（拿到结果后必须问）

1. **CR01 为什么是不一致？** 期望回答：条款库要求报告保存 ≥6 年（下限），现行第 4 条参数=5 年，5 < 6 → 不一致，建议修订为不少于 6 年。
2. **CR05 现行复核频次是 2 次为什么判一致？** 期望回答：下限类比较，现行值 2 ≥ 要求值 1，满足 → 一致，沿用现行条款。
3. **CR06 和 CR08 为什么是制度缺失？** 期望回答：条款库标注「无对应条款」，现行制度文本中找不到对应条款号 → 制度缺失，需新增条款。
4. **CR12 为什么不是不一致而是部分一致？** 期望回答：现行第 12 条存在对应条款但只有定性表述（「具体口径由科研项目组自行掌握」），无参数行可比较 → 部分一致，建议补充量化与执行要素。
5. **CR09 的 48 小时为什么不行？** 期望回答：上限类比较，现行值 48 > 要求值 24 → 不一致，建议收紧为 24 小时内上报。

## 验收清单

- [ ] 输出 15 行（CR01-CR15 全覆盖），5 列表头与规定一致
- [ ] 差距分布 = 一致 3 / 部分一致 4 / 不一致 6 / 制度缺失 2，需修订合计 12 处
- [ ] 每条引用依据含条款编号、来源文件与现行条款位置
- [ ] 现行制度文本原文零改动（只读边界成立）
- [ ] 不一致 6 条的建议值全部可按参数比对复算

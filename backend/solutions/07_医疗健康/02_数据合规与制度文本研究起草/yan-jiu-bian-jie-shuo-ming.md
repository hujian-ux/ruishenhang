# 研究边界说明（数据合规与制度文本的只读研究与起草）

本说明定义合规研究的角色边界、判定规则与引用规范。本类任务的最高原则：**AI 是研究助手，不是执行者**——不修改任何既有文件，不读取业务数据文件，结论与依据一并沉淀、可独立复核。

## 一、只读原则

1. **不修改任何文件**：现行制度文本、条款库等输入材料在研究全程保持只读；所有差距结论以「修订建议」形式输出到新文件，不直接改动原文。
2. **不读取业务数据**：研究过程不接触标本数据、患者信息等业务文件，只使用条款库与制度文本两类研究材料。
3. **分轮复核**：起草完成后另起一轮独立复核，复核轮同样保持只读，只检查结论与依据的对应关系，不引入新的修改。

## 二、判定规则（机械定义，任何人可复算）

对条款库的每一条合规要求，按其「对应制度条款」到现行制度文本中定位，然后按以下顺序判定：

| 判定 | 条件 |
| --- | --- |
| 制度缺失 | 对应制度条款不存在（条款库标注「无对应条款」，或制度文本中找不到该条款号） |
| 不一致 | 对应条款存在且带参数行，但参数值不满足要求（下限类：现行值 < 要求值；上限类：现行值 > 要求值；是否类：现行值 ≠ 要求值） |
| 部分一致 | 对应条款存在但无参数行——只有定性表述，无量化口径或执行要素 |
| 一致 | 对应条款存在且带参数行，参数值满足要求（下限类：现行值 ≥ 要求值；上限类：现行值 ≤ 要求值；是否类：现行值 = 要求值） |

## 三、修订建议生成规则

| 判定 | 修订建议口径 |
| --- | --- |
| 不一致 | 写明条款号 + 现行值 → 建议修订值（下限类向上调，上限类向下调，是否类改为要求值） |
| 制度缺失 | 写明「新增条款」+ 要求摘要 + 量化口径 |
| 部分一致 | 写明条款号 + 补充量化口径与执行要素（谁来做、多久一次、留什么记录） |
| 一致 | 无需修订，沿用现行条款 |

## 四、引用规范

- 每条修订建议的「引用依据」必须同时包含：合规条款编号、来源文件、现行制度条款位置（如有）与现行参数值（如有）。
- 不允许出现「依据相关要求」「按惯例」这类无出处表述。
- 制度文本中的定性表述引用时注明「现行条款无量化参数」。

## 五、新制度条款起草边界（本场景延伸用法）

当需要就某项差距起草新条款正文时：条款正文只引用条款库中存在的编号与来源文件；正文给出后必须附「引用依据」段，逐句标注依据出处；起草轮与复核轮分开进行，复核轮只查引用与判定的一致性。

## 六、输出边界

- 修订建议不等于生效制度：建议表需经数据安全负责人与制度归口部门审议后方可进入发文流程。
- 涉及对外协议（共建、外送、外包）的条款，法务复核属于人工环节，AI 不出具最终合规意见。

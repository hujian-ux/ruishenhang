# 分产品线分省区销售分析与集采应对

## 一、这个 Skill 解决什么

集采常态化背景下，销售分析的真实困难不是「没有数据」，而是**答案被切成二十份放在二十张口径不一的区域报表里**：

- 各省区各自出报表，格式与口径不统一，管理层无法横向比较
- 集采的影响藏在总额里——销量涨了、均价跌了、销售额到底怎么了没人说得清
- 结论与数据分离，追问依据时要回头翻表
- 集采窗口期的应对动作靠人工拼文档，换一条产品线就要重做一遍

本 Skill 的核心动作，是把月度明细按「产品线 × 省区」双维归一到同一张表，用显式判定式识别集采影响品种，并按固定规则生成应对动作——换产品线、换省区复跑时口径不变。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 季度/半年度经营复盘，管理层要横向可比结论 | 主用场景：双维拆解 + 集采影响识别 |
| 集采中选结果公布前后，需要快速摸清影响面 | 识别量升价跌品种并给出分级应对 |
| 换一条产品线或换一个省区重跑分析 | 同一口径文件 + 新明细数据即可复跑 |
| 汇报前被追问「结论的依据是什么」 | 依据列必须回指规则编号与实测值 |

**不适用**：单一医院的客户级对账（→ 客户对账场景）；供应链补货与库存预警（→ 采购与仓储数字化协同开发）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `销售明细数据.csv` | 必需 | 月份、产品线、省区、销售额（万元）、销量、去年同期销售额（万元）、去年同期销量、集采标记 |
| 2 | `分析口径说明.md` | 必需 | 双维拆解规则、指标口径、集采影响判定式、应对动作规则 A1–A4 |

> 缺 2（口径文件）时，本 Skill **必须拒绝输出应对动作**，只能输出不带判定的汇总表。口径先行是本 Skill 最重要的规则。

## 四、输出（outputs）

唯一交付物：`销售双维分析与集采应对表.csv`，字段固定为 14 列：

```
产品线, 省区, 当期销售额（万元）, 当期销量, 去年同期销售额（万元）, 去年同期销量,
销售额同比, 销量同比, 当期均价（元）, 去年均价（元）, 均价同比, 集采影响, 应对动作, 依据
```

- 行数 = 产品线数 × 省区数（本案例 4 × 5 = 20 行）
- `集采影响` ∈ {量升价跌, -}，判定必须同时满足「集采标记=是 + 量升 + 价跌」
- `应对动作` 按 A1–A4 规则匹配
- `依据` 必须含规则编号（A1–A4）与实测值，**不允许写「综合判断」**

## 五、工作流程（workflow）

### STEP 1 · 读口径，先立规矩再看数

从 `分析口径说明.md` 读入指标口径、集采影响判定式与 A1–A4 动作规则，写成显式判定表。**顺序不可颠倒**——先看数据再定规则，等于给结论找理由。

### STEP 2 · 双维汇总

把 40 行月度明细按「产品线 × 省区」分组汇总为 20 个经营单元，逐组合计算销售额同比、销量同比、当期均价、去年均价、均价同比（百分比保留 1 位小数）。

### STEP 3 · 集采影响识别（量升价跌判定式）

```
集采影响 = 集采标记(任一月)=是 AND 销量同比>0 AND 均价同比<0
```

三个条件缺一不可；非集采组合不进入该口径。这是把「集采到底伤不伤」从感觉变成判定式的关键一步。

### STEP 4 · 应对动作匹配（A1–A4）

| 规则 | 条件 | 应对动作 |
| --- | --- | --- |
| A1 | 集采量升价跌且均价降幅 ≥ 25% | 品类替换 + 渠道下沉 |
| A2 | 集采量升价跌且均价降幅 < 25% | 渠道下沉 + 服务增值 |
| A3 | 非集采且销售额同比 ≥ 0 | 稳价扩容 |
| A4 | 非集采且销售额同比 < 0 | 重点客户深耕与新品导入 |

### STEP 5 · 结论回指数据

每个关键结论必须回指交付表的具体行与字段，或回指明细数据。形成汇报底稿时按「结论 → 依据行 → 动作」三段组织。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出（见主提示词【生成后自检】）。

## 六、关键规则（不可协商）

1. **口径先行。** 没有口径文件不得输出判定与动作。
2. **量升价跌三条件缺一不可。** 只有价跌没有量升的不是集采影响的典型形态，不得打标。
3. **依据必须可追溯。** 规则编号 + 实测值，不允许「综合判断」。
4. **换区复跑口径不变。** 切换产品线、切换省区时只替换明细数据，口径文件不动。
5. **AI 不做经营决策。** 品类替换、渠道调整等动作的最终决定属于管理层；AI 只输出判定依据与建议动作。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（销售运营负责人 / 管理层） |
| --- | --- |
| 双维汇总与指标计算 | 集采应对动作的最终决策 |
| 集采影响判定与证据绑定 | 替代品种的引进决定 |
| A1–A4 动作匹配与底稿成文 | 渠道与价格策略审批 |

## 八、下游衔接

- 集采量升价跌品种的县域下沉清单 → **渠道与客户开发**相关场景
- 服务增值动作的落地 → 售后服务与 SPD 运营（→ MED-05 售后工程师知识体系与服务系统自建）
- 采购端的替代品种引入 → **MED-06 采购与仓储数字化协同开发**


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读口径再看数：把 A1-A4 写成显式判定表，不要看完数据再定规则。
2. 双维汇总：把 40 行明细按产品线 × 省区汇总成 20 个组合，逐组合计算销售额同比、销量同比、当期均价、去年均价、均价同比（百分比保留 1 位小数，正数带 + 号）。
3. 集采影响识别：按「量升价跌」判定式逐组合打标，三个条件缺一不可；非集采组合不进入该口径。
4. 应对动作：按 A1-A4 逐组合匹配，依据列必须写明规则编号与实测值。
5. 结论回指数据：每个关键结论（如「X 个组合量升价跌」「检验试剂线同比 −5.4%」）都要回指到交付表的具体行与字段。

### 硬性约束

【硬性约束】
- 集采影响的判定必须同时满足「集采标记=是 + 量升 + 价跌」三个条件，缺一不可。
- 依据列不允许写「综合判断」，必须含规则编号（A1–A4）与实测值。
- 不写任何效率百分比或效果承诺；不出现真实企业名。
- 百分比统一保留 1 位小数，正数带 + 号。

### 生成后自检

【生成后自检，逐条回答】
1. 输出是否为 20 行（4 产品线 × 5 省区）？
2. 量升价跌组合是否恰好 8 个（介入耗材华中/西南/西北 + 检验试剂全部 5 省区）？
3. 介入耗材×华中均价同比是否为 −31.6%（全场最大降幅）？
4. 检验试剂产品线销售额合计同比是否为 −5.4%？
5. 每行依据是否都含规则编号与实测值？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，14 列，列名与顺序固定：
产品线, 省区, 当期销售额（万元）, 当期销量, 去年同期销售额（万元）, 去年同期销量, 销售额同比, 销量同比, 当期均价（元）, 去年均价（元）, 均价同比, 集采影响, 应对动作, 依据

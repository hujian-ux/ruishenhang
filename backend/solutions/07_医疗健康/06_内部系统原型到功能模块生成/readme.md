# MED-03 · 内部系统原型到功能模块生成 —— 场景使用说明

- **行业**：医疗健康
- **角色**：信息化建设岗（贺一帆）
- **场景编号**：MED-03
- **案例主体**：某第三方医学检验机构

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/内部系统原型到功能模块生成/SKILL.md` | Skill 定义 | 模块类型判定、命名规范、生成方式判定（字段数 ≥7 组件拆分）、交互约定与状态口径 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `内部系统需求清单.csv` | 原始输入 | 12 行需求：编号、需求名、提出岗位、当前做法、期望功能、数据字段、模块类型、归属数据表、原型状态 |
| `原型设计规范.md` | 原始输入 | 模块类型划分、命名规范、生成方式判定规则、交互约定、字段映射规则、状态口径与推进约定 |
| `原型与模块实现方案表.csv` | **交付物** | 12 行：需求 × 原型模块 × 生成方式 × 数据字段映射 × 衔接流程 × 状态 |
| `信息化建设岗-内部系统原型到功能模块生成.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `内部系统需求清单.csv`、`原型设计规范.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 待确认需求（N04/N07/N10/N11/N12）的原型草图发提出岗位确认，确认后重新生成对应行。

### 可复算口径

- `原型模块 = 模块类型 + 「 · 」+ 需求名 + 「页」`
- `生成方式 = 字段数 ≥7 → 组件拆分生成；<7 → 单页生成`
- `状态 = 原型状态已确认 → 模块已生成；待确认 → 待原型确认`
- `字段合计 = 12 项需求字段数求和 = 74`

| 数字 | 出处与算法 |

## 四、真实性等级与边界

- **T2**：「先原型再落地」的建设方式与字段先行、接口后接的做法来自企业应用实践的工作方式描述。
- **T3**：岗位痛点来自信息化建设职能的通用工作场景。
- **构造**：需求清单与模块方案为构造数据，判定全部机械可复算。
- **人工边界**：设计规范的制定、原型页面确认、字段核对与上线验收一律人工；接口就绪后的字段调整决策属人工。

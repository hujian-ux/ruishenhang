# 原型设计规范（某第三方医学检验机构 · 内部系统原型到功能模块生成）

本规范定义内部系统「先原型、后模块」的建设方式：业务侧先出原型页面（界面草图与交互说明），确认后按原型直接生成功能模块；字段在接口就绪前先行定义。所有判定规则机械可执行，保证原型与实现的一致性。

## 一、模块类型划分（按需求的功能形态判定）

| 模块类型 | 判定特征 | 典型页面 |
| --- | --- | --- |
| 表单 | 向系统写入数据 | 登记、录入、审核发布 |
| 列表 | 从系统读取并浏览数据 | 流转跟踪、待办、库存台账 |
| 查询统计 | 按条件聚合数据 | 日统计、月统计、达标率 |

## 二、原型模块命名规范

原型模块名 = 模块类型 + 「 · 」+ 需求名 + 「页」。

例：需求「标本送检登记」（表单）→ 原型模块「表单 · 标本送检登记页」。

## 三、生成方式判定规则

| 条件 | 生成方式 |
| --- | --- |
| 数据字段数 ≥ 7 | 组件拆分生成：主组件 + 子组件（表单拆录入区/操作区，列表拆筛选区/数据区/分页区，查询拆条件区/图表区） |
| 数据字段数 < 7 | 单页生成：一个页面组件直接生成 |

组件拆分的模块，字段在接口就绪前先行定义并挂在组件上，后续按接口调整，不阻塞页面开发。

## 四、交互约定（按模块类型固定）

| 模块类型 | 衔接流程 |
| --- | --- |
| 表单 | 提交后写入归属数据表，供对应列表页查询 |
| 列表 | 读取归属数据表，支持进入详情与筛选 |
| 查询统计 | 按条件聚合归属数据表，支持导出月报 |

## 五、数据字段映射规则

- 每项需求的字段清单以「/」分隔，映射到归属数据表的字段，命名沿用需求字段名。
- 字段先行：接口未就绪时，字段先在数据表定义并挂到组件上，接口就绪后按接口调整，不回改需求名。

## 六、状态口径

| 原型状态 | 实现方案表状态 |
| --- | --- |
| 已确认 | 模块已生成，字段已定义，接口后对接 |
| 待确认 | 待原型确认，原型草图已出 |

## 七、推进约定

1. 原型先行：任何需求先出原型页面（界面草图 + 交互说明），业务提出岗位确认后再生成模块。
2. 逐页推进：按需求清单顺序逐个生成，多页面保持同一结构与风格，避免风格漂移。
3. 非技术岗可用：原型确认与字段核对不需要写代码，提出岗位只需在原型页面上勾选字段与交互。

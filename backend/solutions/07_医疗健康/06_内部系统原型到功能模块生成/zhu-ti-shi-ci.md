# MED-03 主提示词 · 内部系统原型到功能模块生成

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/内部系统原型到功能模块生成/SKILL.md`）。
2. 上传两个附件：`内部系统需求清单.csv`、`原型设计规范.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `原型与模块实现方案表.csv` 后，按文末「验收清单」逐项核对。
5. 待确认需求的原型草图发提出岗位确认后，重新生成对应行。

## 主提示词（复制即用）

```
请基于我上传的两份素材，为「某第三方医学检验机构 · 内部系统建设（9 月批次）」把需求清单转成原型与模块实现方案表：先定型原型模块，再判定生成方式，字段先行、接口后接。

【输入 1 · 内部系统需求清单】内部系统需求清单.csv（12 行）
- 含需求编号（N01-N12）、需求名、提出岗位、当前做法、期望功能、数据字段（/分隔）、模块类型、归属数据表、原型状态
【输入 2 · 原型设计规范】原型设计规范.md
- 模块类型：表单（写入）/ 列表（读取浏览）/ 查询统计（条件聚合）
- 命名规范：原型模块 = 模块类型 + 「 · 」+ 需求名 + 「页」
- 生成方式：数据字段数 ≥7 → 组件拆分生成（主组件+子组件）；<7 → 单页生成
- 交互约定：表单提交后写入归属数据表供列表查询；列表读取归属数据表支持详情与筛选；查询统计按条件聚合支持导出
- 状态口径：原型已确认 → 模块已生成，字段已定义，接口后对接；待确认 → 待原型确认，原型草图已出

【输出】原型与模块实现方案表.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「内部系统原型到功能模块生成」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **N03 检验结果录入为什么是组件拆分生成？** 期望回答：字段数 8 ≥ 7，按规范第三节拆分为主组件+子组件（录入区/复核操作区），字段先行定义、接口后对接。
2. **N05 标本流转列表为什么是单页生成？** 期望回答：字段数 5 < 7，一个页面组件直接生成，不拆分。
3. **N04 报告审核发布为什么状态是待原型确认？** 期望回答：需求清单原型状态=待确认，按状态口径标注「待原型确认，原型草图已出」，不生成模块实现细节。
4. **字段总数 74 怎么算出来的？** 期望回答：12 项需求的字段数求和：6+4+8+6+5+7+7+7+6+6+6+6 = 74。
5. **时效达标率统计（N10）和区域复盘有什么关系？** 期望回答：查询统计类模块按月聚合各实验室达标率，正是 MED-01 区域经营复盘中时效短板跟踪的数据来源，查询结果支持导出月报。

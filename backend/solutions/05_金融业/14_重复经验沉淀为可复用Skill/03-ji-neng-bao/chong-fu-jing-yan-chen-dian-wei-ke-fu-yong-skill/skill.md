# 重复经验沉淀为可复用Skill

## 一、这个 Skill 解决什么

能力沉淀的真实困难不是「没有好做法」，而是**好做法散落在个人手里**：

- 重复动作每次都要重新描述一遍需求
- 会务排序规则、字段口径这类「隐性规则」靠人工记忆
- 周报要从大表里手工筛自己的条目
- 好用的提示词散落在个人会话里，人走了经验就断了

本 Skill 的核心动作，是把「识别重复 → 评估优先级 → 交互式搭技能 → 统一归档」固定成一条流水线，让使用形态从「用工具做任务」升级到「用工具造能力」。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 团队里出现每周都要重复做的动作 | 主用场景：识别 → 评估 → 封装 → 归档 |
| 某个提示词在个人手里越用越顺 | 交互式把输入/输出/规则搭成 SKILL.md |
| 接手的人频繁来问「这个怎么做」 | 技能归档后直接调用，不再重述需求 |
| 技能目录需要治理（命名/路径混乱） | 按目录规范统一重排 |

**不适用**：一次性的项目任务（重复 1-2 次不值得封装）；涉及敏感数据直连外部服务的动作（走数据安全评审）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `重复动作清单.csv` | 必需 | 动作名、业务方、频率-次/周、当前耗时分钟、已有做法描述、典型输入、期望输出 |
| 2 | `技能目录规范.md` | 必需 | 目录结构、命名规范（域代码）、优先级与节时口径、交互式四问、归档流程 |

> 缺 2（目录规范）时，本 Skill **必须拒绝输出优先级与目录路径**——没有规范的沉淀只会制造新的混乱。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`技能封装与归档清单.csv`，字段固定为 9 列：

```
动作名, 业务方, 技能名, 交互输入, 交付输出, 目录路径, 优先级, 预期节时分钟/次, 周度预期节时分钟
```

- `技能名` = `域代码·动作名`（RS/FI/RD/QA/HR/BM/IB）
- `目录路径` = `团队技能目录/<业务方>/<技能名>/`
- `优先级` ∈ {P0（周度节时 ≥90 分钟，本周启动）, P1（45–89，本月完成）, P2（<45，观察合并）}

## 五、工作流程（workflow）

### STEP 1 · 识别高频重复动作

从各业务方收集「每周都要重复做」的动作：主体信用信息提取、会务人员排序、招聘定级、周报整理、市场观察表格提取……落盘为 `重复动作清单.csv`，记录频率与当前耗时。

### STEP 2 · 按口径评估封装优先级

```
预期节时分钟/次 = 当前耗时分钟 × 60%
周度预期节时分钟 = 频率（次/周）× 预期节时分钟/次
P0 ≥ 90 分钟（优先封装，本周启动）；P1 45–89（排期封装）；P2 < 45（观察合并）
```

P0 即「优先封装」清单，直接决定本周启动哪几项。

### STEP 3 · 交互式问答把技能搭出来

对每个待封装动作过固定四问：**输入是什么？输出是什么？规则是什么？谁来复核？**——排序规则、过滤条件、模板骨架、口径约束全部写进 SKILL.md，不留在口头。

### STEP 4 · 统一归档到团队技能目录

按命名规范生成技能名与目录路径，新建技能后归入对应业务域子目录；团队成员直接按技能名调用，不再重述需求。

### STEP 5 · 自检

输出前逐项自检，任一不过则不得输出：

1. 每行的预期节时与优先级是否都能按口径复算？
2. 技能名与目录路径是否符合命名规范？
3. 交互输入 / 交付输出是否与清单的典型输入 / 期望输出一致？
4. P0 项是否覆盖了周频最高的动作？

## 六、关键规则（不可协商）

1. **规范先行。** 优先级与目录路径必须由规范文件推导，不允许在结果表里临时改口径。
2. **节时口径统一。** 预期节时按「当前耗时 × 60%」估算，全表一致，不逐行拍脑袋。
3. **技能定义必须过四问。** 输入/输出/规则缺一项不得归档；首次产出由业务方本人复核。
4. **目录唯一。** 技能只归档到团队技能目录对应业务域下，禁止个人目录另建一套。
5. **不写任何效率百分比或效果承诺**（节时为估算口径，非实测承诺）。

## 七、人工边界

| AI 负责 | 人负责（研发与效能岗 / 业务方） |
| --- | --- |
| 重复动作识别与优先级计算 | 封装排期的最终确认 |
| 交互式问答整理输入/输出/规则 | 技能首次产出的复核 |
| 命名与目录路径生成 | 目录规范本身的修订 |
| 归档清单落盘 | 涉敏动作的数据安全评审 |


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规范再评估：把节时口径、优先级阈值、命名与目录规则写成显式判定表，不要先看清单再定标准。
2. 逐行计算：按口径计算每个动作的预期节时分钟/次与周度预期节时分钟，并判定 P0/P1/P2。
3. 技能名与目录路径：按命名规范逐行生成技能名（域代码·动作名）与目录路径。
4. 交互输入与交付输出：逐行带入清单的典型输入与期望输出，作为交互式四问（输入/输出/规则/复核人）的起点。
5. 汇总优先封装清单：P0 项单独列出，写明每项的周频与周度节时。

### 硬性约束

【硬性约束】
- 预期节时是按口径计算的规则值，不写任何效率百分比或效果承诺。
- 优先级判定必须含周度节时数值依据，不允许「综合判断」。
- 技能名与目录路径必须严格按规范生成，不允许自造格式。
- P0 清单必须与逐行判定结果一致。

### 生成后自检

【生成后自检，逐条回答】
1. 15 行是否全部有技能名与目录路径？
2. P0 是否恰好为周度节时 ≥90 的项？
3. 逐行周度节时是否等于频率 × 单次节时？
4. P0 周度节时合计是否等于各 P0 项之和？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，9 列，列名与顺序固定：
动作名, 业务方, 技能名, 交互输入, 交付输出, 目录路径, 优先级, 预期节时分钟/次, 周度预期节时分钟

# 团队技能目录规范（FIN-14 · 某投资银行）

> 本规范定义「重复经验沉淀为可复用 Skill」的目录结构、命名规范、归档流程与优先级口径。凡是团队内重复发生的动作，先按本规范评估优先级，再通过交互式问答把技能搭出来，统一归档到团队技能目录，团队直接调用不再重述需求。

## 一、目录结构

```
团队技能目录/
├── 研究/
├── 固定收益与做市/
├── 信息技术研发/
├── 测试与质量/
├── 人力资源/
├── 品牌与会议运营/
└── 投资银行/
```

- 每个业务域一个子目录，目录名与业务方名称一致。
- 每个技能一个独立文件夹，文件夹内至少含 `SKILL.md`（输入 / 输出 / 规则）。

## 二、命名规范

- 技能名 = `域代码·动作名`，域代码固定：研究 `RS` / 固定收益与做市 `FI` / 信息技术研发 `RD` / 测试与质量 `QA` / 人力资源 `HR` / 品牌与会议运营 `BM` / 投资银行 `IB`。
- 目录路径 = `团队技能目录/<业务方>/<技能名>/`。
- 动作名沿用团队日常叫法，不做缩写与转译，保证「谁都能按名字找到」。

## 三、优先级与节时口径

| 口径 | 计算方式 |
| --- | --- |
| 预期节时分钟/次 | 当前耗时分钟 × 60%（按已落地技能的单次耗时约为原来的四成估算） |
| 周度预期节时分钟 | 频率（次/周）× 预期节时分钟/次 |
| 优先级 P0 | 周度预期节时 ≥ 90 分钟 → 优先封装，本周启动 |
| 优先级 P1 | 周度预期节时 45–89 分钟 → 排期封装，本月完成 |
| 优先级 P2 | 周度预期节时 < 45 分钟 → 观察积累，合并同类动作后再评估 |

## 四、交互式问答（把技能搭出来）

对每个待封装动作，通过固定四问产出技能定义：

1. **输入是什么？** —— 触发材料、格式与来源（对应清单「典型输入」列）。
2. **输出是什么？** —— 交付形态与验收标准（对应清单「期望输出」列）。
3. **规则是什么？** —— 排序规则、过滤条件、模板骨架、口径约束，全部写进 SKILL.md。
4. **谁来复核？** —— 首次产出由业务方本人复核，确认后归档。

## 五、归档流程

1. 按第三节口径评估优先级，P0 先行。
2. 按第四节四问产出 `SKILL.md`，交互式把输入/输出/规则搭清楚。
3. 新建技能后归入对应业务域子目录，目录路径按第二节规范生成。
4. 团队成员直接按技能名调用，不再重述需求；好用的提示词不再散落在个人手里。

## 六、人工边界

- 封装优先级与排期由团队负责人确认；规范本身的修订同样走「先改规范再重跑」。
- 技能首次产出必须经业务方本人复核后才可归档共享。

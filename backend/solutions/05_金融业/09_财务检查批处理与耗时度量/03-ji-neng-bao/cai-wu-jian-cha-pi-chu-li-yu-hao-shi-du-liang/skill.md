# 财务检查批处理与耗时度量

## 一、这个 Skill 解决什么

财务检查的真实困难不是「看不懂凭证」，而是**作业无法规模化、耗时无法度量**：

- 审批材料以图像与文本混合形式存在，按机构分布，人工逐份翻阅既慢又难量化进度
- 脚本里写死了机构名，换一个机构要重新改一遍代码
- 批处理跑没跑完，靠人工口头汇报，没有可查看的进度文件
- 想优化却不知道哪个环节最耗时——耗时数据从来没有被记录和统计过

本 Skill 的核心动作，是把检查作业变成「**程序跑批 + 进度可查 + 耗时可度量**」：单一机构先跑通，再复制成批，最后量化耗时。新增机构只需加参数，而非改代码。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 费用凭证与审批材料按机构批量到达检查期 | 主用场景：批处理抽取 + 耗时统计 |
| 换一个机构要重新改脚本 | 需要机构参数化改造，输出与进度按机构隔离 |
| 检查进度靠口头汇报、无法追溯 | 需要按机构隔离的进度文件，支持断点续跑 |
| 主管问「哪个环节最慢、要不要加机器」 | 需要按机构按程序量化耗时，定位瓶颈 |
| 抽取规则又要为新单据改硬编码 | 需要配置表驱动抽取规则，规则外置 |

**不适用**：监管报送口径升级的批次兼容方案（→ FIN-10）；企业级编码脚手架与技能目录治理（→ FIN-15）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `审批材料抽取结果.csv` | 必需 | 机构、材料编号、材料类型、抽取程序、抽取字段、抽取值、是否存疑 |
| 2 | `批处理运行日志.csv` | 必需 | 机构、程序、开始时间、结束时间、进度文件状态 |
| 3 | `机构与程序清单.md` | 必需 | 机构代码与输出目录约定、程序与材料类型对应、日志与统计口径 |

> 缺 2（运行日志）时，本 Skill **必须拒绝输出耗时列**，只能交付材料数统计——耗时只能从日志复算，不允许估算。

## 四、输出（outputs）

唯一交付物：`批处理与耗时统计.csv`，字段固定为 8 列：

```
机构, 抽取程序, 开始时间, 结束时间, 耗时分钟, 处理材料数, 存疑材料数, 进度文件状态
```

- 每行 = 一个「机构 × 程序」组合的批处理任务，行数 = 机构数 × 程序数
- `耗时分钟` = 结束时间 − 开始时间，**必须从日志复算**，禁止拍脑袋填数
- `处理材料数` / `存疑材料数` 必须与抽取结果按机构 × 程序分组计数一致
- `存疑材料数 > 0` 的行需人工复核，程序不替人下结论

## 五、工作流程（workflow）

### STEP 1 · 单一机构跑通

先在一个机构上把抽取程序跑通：从费用报销凭证（图像）识别发票代码、发票号码、价税合计等字段，从审批单（文本）提取审批人、审批意见等字段。**先验证正确性，再谈批量**。

### STEP 2 · 补 batch 版本，按机构隔离

为已跑通的程序补 batch 版本：输出文件与进度文件按机构代码隔离（如 `output/SH/`），进度文件记录已处理材料编号，支持断点续跑。

### STEP 3 · 机构参数化

机构作为命令行参数传入（`--org SH`），日志名加机构、输出按机构隔离。其余程序沿用同一改动模式——**新增机构只需加参数而非改代码**。

### STEP 4 · 读日志统计耗时

先给字段列表，再写统计程序：读运行日志，按机构按程序输出开始、结束与耗时。耗时 = 结束 − 开始，不引入任何估算系数。

### STEP 5 · 配置表驱动

按签证单文本描述配置表驱动抽取规则（签证单号、结算金额、供应商名称、费用科目），**减少硬编码**——新单据类型改配置不改程序。

### STEP 6 · 汇总成表与自检

按「机构 × 程序」汇成一表，核对：行数 = 机构数 × 程序数、材料数合计 = 输入行数、耗时合计与分程序合计可复算、存疑行已标注待人工复核。

## 六、关键规则（不可协商）

1. **先跑通一个、再复制成批、最后量化耗时**——顺序不可颠倒。没有单机构验证过的程序直接上批量，错误会乘以机构数。
2. **耗时只能从日志复算**，禁止估算、禁止四舍五入掩盖、禁止用「大概」描述耗时。
3. **机构是参数不是代码**。输出目录、日志文件名、进度文件全部按机构隔离，禁止混写。
4. **进度文件必须存在且可查看**——「跑没跑完」这个问题应该由文件回答，而不是由人回答。
5. **存疑材料交人工复核**。程序只负责标注「是否存疑」，不替检查员下结论。
6. **不承诺效率百分比**。本场景输出的是可复算的耗时事实，不是提效承诺。

## 七、人工边界

| AI 负责 | 人负责（财务检查岗） |
| --- | --- |
| 字段抽取与批处理方案、统计程序 | 存疑材料的最终认定 |
| 日志解析与耗时汇总成表 | 检查结论与整改建议的签发 |
| 配置表驱动的抽取规则整理 | 新单据类型的规则审批 |

## 八、下游衔接

- 存疑材料清单 → 检查岗人工复核（输入：交付物中存疑材料数 > 0 的行）
- 耗时基线 → 后续批处理优化与资源调配的对照基准
- 同类「程序化 → 批处理化 → 参数化」推进方式 → FIN-10 监管报送批次改造


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 按机构 × 程序分组：处理材料数 = 该机构该程序在抽取结果中的行数；存疑材料数 = 其中「是否存疑 = 是」的行数。
2. 从日志复算耗时：每行耗时分钟 = 结束时间 − 开始时间；先给字段列表再成表，不要跳步。
3. 汇总指标一并输出：总耗时、平均耗时（总耗时 ÷ 任务数）、单份材料平均耗时（总耗时 ÷ 材料数）、每个程序的耗时合计与占比、最慢机构。
4. 进度文件状态原样带出，不要改写状态值；存疑材料数 > 0 的行标注「需人工复核」。
5. 发现机构 × 程序在日志与抽取结果中不匹配时，先指出再处理，不要静默补齐。

### 硬性约束

【硬性约束】
- 耗时必须逐行等于结束时间 − 开始时间，任何一行对不上即整表作废。
- 处理材料数合计必须等于 50；存疑材料数合计必须等于抽取结果中存疑行数。
- 不允许出现「约」「大概」「估计」描述耗时；不允许写效率提升百分比。
- 程序不给存疑材料下结论，只标注数量交人工复核。

### 生成后自检

【生成后自检，逐条回答】
1. 是否 18 行 = 6 机构 × 3 程序，无遗漏无重复？
2. 处理材料数合计是否 = 50？存疑合计是否 = 11？
3. 耗时合计是否 = 504 分钟，平均是否 28.0 分钟？
4. 最慢环节是否可指认（按程序合计）？
5. 是否没有任何一行耗时是估算出来的？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，8 列，列名与顺序固定：
机构, 抽取程序, 开始时间, 结束时间, 耗时分钟, 处理材料数, 存疑材料数, 进度文件状态

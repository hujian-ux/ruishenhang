# FIN-15 主提示词 · 企业编码脚手架与技能目录

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/企业编码脚手架与技能目录/SKILL.md`）。
2. 上传两个附件：`团队技能目录现状.csv`、`脚手架规范.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `技能目录治理清单.csv` 后，按文末「验收清单」逐项核对。

---

## 主提示词（复制即用）

```
请基于我上传的两份素材，为「某保险集团 · 企业编码脚手架与技能目录治理」生成一张可复核的技能目录治理清单。先立规范再盘点——以脚手架规范为唯一判定依据。

【输入 1 · 技能现状】团队技能目录现状.csv（15 行）
- 列：技能名、所属团队、目录结构是否合规、术语一致性、当前路径
- 术语一致性列含不一致（骨架）/ 不一致（初始化模板）等非标准表述
- 当前路径含 personal/ 形式的个人目录（跨机器安装不可移植）
【输入 2 · 脚手架规范】脚手架规范.md
- 初始化命令 wb-init 与标准目录结构 skills/<技能名>/
- 术语表：脚手架（禁用「骨架」「初始化模板」）、技能目录（禁用「技能文件夹」）
- 治理判定规则：合规 / 仅目录不合规 / 仅术语不合规 / 目录与术语均不合规
- 优先级规则：双重不合规=高、单项=中、全合规=低

【输出】技能目录治理清单.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「企业编码脚手架与技能目录」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **为什么 personal/ 路径必须迁移？** 期望回答：个人目录跨机器安装不可移植，`wb-init` 初始化命令生成的 `skills/<技能名>/` 标准结构才是可移植路径——本批 6 个需迁移项里 5 个是 personal/ 路径。
2. **「骨架」和「脚手架」不是一回事吗？** 期望回答：术语表明确禁用「骨架」「初始化模板」，统一为「脚手架」——同一概念多种措辞会造成团队理解分歧，术语先统一再盘点。
3. **双重不合规的 2 项是哪些、为什么优先级最高？** 期望回答：批次改造方案（personal/chenw/ + 骨架）、需求文档撰写（personal/wangw/ + 骨架）——目录迁移与术语修正叠加，治理收益最大。
4. **新建技能还会出现目录不合规吗？** 期望回答：不会——`wb-init` 初始化命令让新建技能从第一天就长在标准目录上；治理清单只处理存量。
5. **需求文档技能为什么复用团队文档骨架？** 期望回答：按既有模板新建「写需求文档」技能，文档结构本身进入技能市场，各条线需求文档不再各写各的。

## 验收清单

- [ ] 交付物 15 行，5 个团队 × 3 个技能全覆盖
- [ ] 需迁移 = 6 项；术语不一致 = 5 项；双重待治理 = 2 项
- [ ] 优先级分布 = 高 2 / 中 7 / 低 6；全合规 6 项填「无需迁移」与「无」
- [ ] 术语修正项仅含「骨架」→「脚手架」与「初始化模板」→「脚手架」
- [ ] 所有 personal/ 路径技能均在需迁移清单；需迁移路径符合 skills/<技能名>/
- [ ] 全表判定可按脚手架规范复算，无规范外裁量

# 脚手架规范 · 企业自建编码体系与技能目录标准

> 某保险集团 · 架构与工程效能岗 · 企业级编码脚手架与技能市场治理口径

## 一、初始化命令与标准目录结构

自建初始化命令 `wb-init <技能名>` 统一项目起步结构，新建技能按以下标准目录生成，并放在当前目录内：

```
skills/<技能名>/
├── SKILL.md          # 技能定义（frontmatter 含 name/description/version/role/scene-id）
├── 主提示词.md        # 学员实际发送的提示词原文
├── README.md         # 使用说明与验证记录
└── scripts/          # 可执行脚本与配置
```

**可移植性要求**：路径一律相对 `skills/` 根目录解析；`personal/<个人目录>/` 形式的绝对个人路径在跨机器安装时无法移植，视为不合规。

## 二、术语表（统一措辞，避免团队理解分歧）

| 标准术语 | 禁用表述 | 说明 |
| --- | --- | --- |
| 脚手架 | 骨架 / 初始化模板 | 指统一项目起步结构的初始化命令与生成物 |
| 技能目录 | 技能文件夹 | 指 skills/ 下按标准结构生成的目录 |
| 场景脚本 | 脚本零散文件 | 指带目录归属的可执行脚本 |

## 三、命名规范

- 技能名使用中文、不含空格与特殊符号；
- 新增接口须同时补进接口文档与接口总文档，两处不同步视为文档欠账。

## 四、治理判定规则（可复算）

| 判定 | 条件 |
| --- | --- |
| 合规 | 目录结构合规 且 术语一致 |
| 仅目录不合规 | 目录结构不合规、术语一致 → 需迁移到 `skills/<技能名>/` |
| 仅术语不合规 | 目录结构合规、术语不一致 → 按术语表修正措辞 |
| 目录与术语均不合规 | 两项都不合规 → 先迁目录再改术语 |

## 五、优先级规则

- 高：目录与术语双重不合规
- 中：单项不合规（仅目录 或 仅术语）
- 低：全合规（仅需按初始化命令回归验证）

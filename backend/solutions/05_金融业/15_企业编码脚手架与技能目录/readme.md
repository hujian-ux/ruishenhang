# FIN-15 · 企业编码脚手架与技能目录 —— 场景使用说明

- **行业**：金融业（保险）
- **角色**：架构与工程效能岗
- **场景编号**：FIN-15
- **案例主体**：某保险集团

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/企业编码脚手架与技能目录/SKILL.md` | Skill 定义 | 脚手架规范先行、术语表统一、标准目录结构、接口文档双处同步与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `团队技能目录现状.csv` | 原始输入 | 15 个团队技能：技能名、所属团队、目录合规性、术语一致性、当前路径 |
| `脚手架规范.md` | 原始输入 | 初始化命令与标准目录结构、术语表、命名规范、治理判定与优先级规则 |
| `技能目录治理清单.csv` | **交付物** | 15 行：合规判定、需迁移路径、术语修正项、优先级 |
| `架构与工程效能岗-企业编码脚手架与技能目录.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `团队技能目录现状.csv`、`脚手架规范.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 高优先级治理项（双重不合规 2 项）先执行迁移再改术语；术语表与规范发布为企业技能市场准入标准。

## 三、交付物验证记录

生成脚本 `gen_FIN-15.py`（Python 标准库 csv，无随机数）先写出两个原始输入，再按治理判定规则计算交付物并断言。执行结果：

```
优先级分布：高 2 / 中 7 / 低 6 | 全合规 6
ALL FIN-15 ASSERTIONS PASSED
```

### 断言项

| 断言 | 结果 |
| --- | --- |
| 三个文件存在且 size > 0 | 通过 |
| `团队技能目录现状.csv` 数据行 = 15（5 团队 × 3 技能） | 通过 |
| `技能目录治理清单.csv` 数据行 = 15 | 通过 |
| 需迁移 = 6 项；术语不一致 = 5 项；双重待治理 = 2 项 | 通过 |
| 优先级分布 = 高 2 / 中 7 / 低 6（2 + 7 + 6 = 15） | 通过 |
| 高优先级数 = 双重不合规数 | 通过 |
| 全合规 = 6 项（6 + 6 + 5 − 2 = 15） | 通过 |
| 需迁移路径全部符合 `skills/<技能名>/` 标准结构 | 通过 |
| 术语修正项仅含术语表两条映射 | 通过 |

### 可复算口径

- `合规判定`：目录结构不合规 或 术语不一致 → 对应不合规类别；两者皆可 → 合规
- `需迁移路径`：目录不合规 → `skills/<技能名>/`；合规 → 无需迁移
- `优先级`：双重不合规 = 高；单项不合规 = 中；全合规 = 低
- `需迁移 + 仅术语不一致 = 高 + 中`（治理项合计自洽）

## 四、与页面的数字对齐

| 数字 | 出处 | 在本场景的落点 |

| 优先级 高 2 / 中 7 / 低 6 | 优先级规则计算 | 页面案例卡片 |

## 五、真实性等级与边界

- **T2**：脚手架、技能目录治理、术语统一的方法论来自公开的工程效能实践。
- **T3**：架构与工程效能岗痛点来自素材中的传统模式描述。
- **构造**：技能、团队、路径数据口径可复算。
- **升 T1 还缺**：真实企业技能市场的盘点快照与一次迁移的前后对照。
- **人工边界**：脚手架规范与术语表的评审发布、迁移排期与资源调配、接口文档欠账的业务确认一律人工；本场景全部输出不出现效率百分比承诺。

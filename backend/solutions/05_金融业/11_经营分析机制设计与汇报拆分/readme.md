# FIN-11 · 经营分析机制设计与汇报版拆分 —— 场景使用说明

- **行业**：金融（保险科技与健康保障平台）
- **角色**：经营分析岗（林可）
- **场景编号**：FIN-11
- **案例主体**：某保险科技平台

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/经营分析机制设计与汇报版拆分/SKILL.md` | Skill 定义 | 约束显式化方法、五维加权比较规则、折中原则与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `快报方案要素表.csv` | 原始输入 | 5 个候选方案 × 要素与五维得分（1-5 分）：数据可得时点、依赖方、主要风险 |
| `机制设计约束.md` | 原始输入 | 发薪模式、D+3 快报时点、数据源到岗时点、评分标准、加权权重、折中原则 |
| `方案比较矩阵.csv` | **交付物** | 5 行比较矩阵：五维得分、加权总分、排名、推荐结论与切换条件 |
| `经营分析岗-经营分析机制设计与汇报版拆分.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `快报方案要素表.csv`、`机制设计约束.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 比较矩阵连同分析版 / 汇报版材料以静态数据方式本地化发布；机制采用提交管理层决定。

生成脚本 `gen_FIN-11.py` 以 Python 标准库 `csv` 从 `快报方案要素表.csv` 实际计算写出 `方案比较矩阵.csv`，并在脚本内做断言验证。执行结果：

排名2 方案A（薪酬系统直连快报）：加权总分 3.55（时效5/准确5/成本1/依赖1/风险2）

### 断言项

| 断言 | 结果 |
| --- | --- |
| 输入 5 个方案、交付物 5 行 | 通过 |
| 五维得分全部在 1-5 且与要素表一致 | 通过 |
| 加权总分 = E 4.00 / A 3.55 / C 3.45 / B 3.40 / D 3.20 | 通过 |
| 排名 1-5 与总分降序一致，推荐行为方案 E | 通过 |
| 方案 E 领先第二名（A）0.45 分 | 通过 |
| 推荐结论含切换条件（直连上线且稳定运行 2 个月） | 通过 |

### 可复算口径

- `加权总分 = 时效×0.30 + 准确×0.30 + 成本×0.15 + 依赖×0.10 + 风险×0.15`（保留 2 位小数）
- 复算过程（方案 E）：4×0.30 + 4×0.30 + 4×0.15 + 4×0.10 + 4×0.15 = 1.20+1.20+0.60+0.40+0.60 = 4.00 ✓
- 复算过程（方案 A）：5×0.30 + 5×0.30 + 1×0.15 + 1×0.10 + 2×0.15 = 1.50+1.50+0.15+0.10+0.30 = 3.55 ✓
- 领先幅度：4.00 − 3.55 = 0.45 分 ✓

## 五、真实性等级与边界

- **T3**：机制设计与汇报材料拆分的岗位痛点来自经营分析实践。
- **构造**：方案要素与评分数据为构造数据（案例主体某保险科技平台），口径可复算。
- **人工边界**：硬约束确认、权重与评分标准裁定、机制采用的最终决定一律人工；AI 只输出结构化比较、折中建议与切换条件，不输出「已决定」类表述。

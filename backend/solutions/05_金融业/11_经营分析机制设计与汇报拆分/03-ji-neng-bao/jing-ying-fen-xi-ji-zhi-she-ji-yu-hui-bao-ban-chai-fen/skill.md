# 经营分析机制设计与汇报版拆分

## 一、这个 Skill 解决什么

机制设计类工作的真实困难不是「没有方案」，而是**方案优劣靠文字描述、分析与汇报混在同一份材料里**：

- 五个候选方案各说各的好，缺一张统一维度的比较表
- 管理层要求 D+3 出快报，数据源却要 D+5 才齐——时点约束没人显式摆上桌
- 分析材料与汇报材料是同一份：细节堆给管理层看，论证深度又不够业务复核
- 看板以在线链接方式共享，口径外流、范围失控

本 Skill 的核心动作，是把机制设计固化成「**澄清约束 → 多方案结构化比较 → 折中取舍 → 双版本产出 → 静态发布**」的流水线：每个方案按同一套维度打分、按固定权重加权，推荐结论带切换条件。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 要设计一项周期性机制（快报 / 例会 / 报送）且有多个候选方案 | 主用场景：结构化比较 + 推荐结论 |
| 方案取舍受数据时点、依赖方排期等硬约束 | 约束显式化后再比较，不空谈优劣 |
| 分析材料要向上汇报 | 分析版与汇报版分开产出，先确认框架再调整 |
| 指标口径需与管报底稿联动且控制查看范围 | 静态数据本地化发布 |

**不适用**：日常经营数据的看板汇总与异常标注（→ FIN-03 渠道经营看板与异常线索标注）；区域维度的月度量质拆解（→ FIN-02 区域月报技能与月度经营诊断）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `快报方案要素表.csv` | 必需 | 方案编号、方案名称、机制概述、数据可得时点、依赖方、五维得分（时效性 / 口径准确度 / 实施成本 / 依赖可控性 / 风险可控性）、主要风险描述 |
| 2 | `机制设计约束.md` | 必需 | 发薪模式、D+3 快报时点、数据源到岗时点、评分标准、加权权重、折中原则、汇报版拆分与静态发布要求 |

> 缺 2（约束说明）时，本 Skill **必须拒绝输出推荐结论**——权重与评分标准不由约束文件确定，比较结果就是拍脑袋。

## 四、输出（outputs）

唯一交付物：`方案比较矩阵.csv`，5 行（每方案 1 行），10 列，列名与顺序固定：

```
方案编号, 方案名称, 时效性得分, 口径准确度得分, 实施成本得分, 依赖可控性得分, 风险可控性得分, 加权总分, 排名, 推荐结论与切换条件
```

- 五维得分均为 1-5 整数，直接取自 `快报方案要素表.csv`，**不允许临场改分**
- `加权总分` = 时效×0.30 + 准确×0.30 + 成本×0.15 + 依赖×0.10 + 风险×0.15（保留 2 位小数，任何人可复算）
- `排名` 按加权总分降序，同分按方案编号
- `推荐结论与切换条件` 必须写明采用 / 暂不采用 / 不采用的理由与切换触发条件，**不允许只写「建议采用方案 X」**

## 五、工作流程（workflow）

### STEP 1 · 背景澄清，约束显式化

从 `机制设计约束.md` 读入硬约束：发薪模式（当月发薪、10 日发上月薪）、D+3 快报时点、三个数据源的到岗时点（手工台账 D+1 / 薪酬系统 D+5 / 看板口径 D+5 锁版）。**先摆约束再谈方案**——时点约束不摆上桌，比较就是空谈。

### STEP 2 · 多方案结构化比较

对 5 个候选方案按统一维度（时效 / 准确 / 成本 / 依赖 / 风险）整理要素，得分严格取自要素表，按固定权重计算加权总分并排名。维度统一是前提：各说各的好不叫比较。

### STEP 3 · 折中取舍

按折中原则给出推荐：**以可准时到岗的数据为主干保时效（手工台账 D+3 出快报版），数据准时到则切换看板口径保准确（D+5 出终版）**。快报版缺项用上月占比推补并标注「预估」。同时写明切换条件：直连方案上线且稳定运行后整体切换。

### STEP 4 · 分析版与汇报版分离

- 分析版：完整论证（背景约束、方案要素、评分标准、加权比较、推荐理由、切换条件、敏感性说明）
- 汇报版：从分析版摘出摘要章节，按「结论 → 约束 → 比较 → 建议」框架适当丰富；先确认框架再调整内容，套话空话删除重来
- 两版分开产出，汇报版不承担全部论证负担

### STEP 5 · 静态数据本地化发布

比较矩阵与两版材料以静态数据方式发布：数据存本地、发布为静态页面，避免多人直接查看在线链接，权限范围可控。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出：

1. 五维得分是否与要素表逐项一致，无临场改分？
2. 加权总分是否按固定权重复算可得，排名与总分降序一致？
3. 推荐结论是否写明理由与切换条件？
4. 折中方案是否同时回应了 D+3 时点与口径准确两个约束？
5. 汇报版是否已与分析版分离且无套话空话？

## 六、关键规则（不可协商）

1. **约束先于方案。** 数据时点与发薪模式是不可协商的物理约束，必须显式写入比较前提。
2. **维度统一才叫比较。** 五维得分严格取自要素表，权重取自约束文件，不允许为了推荐某个方案临场调分调权。
3. **推荐必须带切换条件。** 机制不是一次定终身：什么情况下切换到什么方案，写清楚触发条件与检验口径。
4. **分析版与汇报版各归其位。** 深度归分析版，可读性归汇报版；不允许把汇报版当分析版删减版糊弄。
5. **AI 不拍板机制。** 方案评分与比较是决策支持，机制采用的最终决定属于管理层；AI 输出的是可复核的比较矩阵与建议。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（经营分析岗 / 管理层） |
| --- | --- |
| 约束梳理与要素结构化 | 硬约束的确认与裁定 |
| 五维加权计算与排名 | 权重与评分标准的最终确认 |
| 折中建议与切换条件起草 | 机制采用的最终决定 |
| 分析版 / 汇报版双版本产出 | 汇报版框架的确认与调整 |

## 八、下游衔接

- 推荐机制的快报口径 → 与管报三层指标图联动，说明数据来源关系
- 静态发布页 → 数据与看板岗维护（→ FIN-03 渠道经营看板与异常线索标注的规则沉淀方法）
- 快报中的经营异动 → 转区域月度诊断定位量质原因（→ FIN-02 区域月报技能与月度经营诊断）


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先摆约束再谈方案：把发薪模式、D+3 时点与三个数据源到岗时点写成显式约束表，注明哪些是不可协商的物理约束。
2. 结构化比较：5 个方案按统一五维整理，得分严格取自要素表，按固定权重算加权总分（保留 2 位小数）并排名（总分降序，同分按方案编号）。
3. 折中取舍：给出「以某方案为主干 + 数据准时到则切换看板口径」的折中建议，写明快报版缺项的处理方式（上月占比推补 + 标注预估）。
4. 推荐结论：逐方案写明采用 / 暂不采用 / 不采用的理由；推荐方案必须带切换条件（触发条件与检验口径）。
5. 汇报版拆分：说明分析版（完整论证）与汇报版（结论 → 约束 → 比较 → 建议框架）的分工，先确认框架再调整内容，套话空话删除重来。
6. 静态发布：比较矩阵与两版材料以静态数据方式本地化发布，说明权限控制方式。

### 硬性约束

【硬性约束】
- 五维得分必须与要素表逐项一致，不允许临场改分；权重必须与约束文件一致，不允许为了推荐某方案调权。
- 加权总分必须可复算：加权总分 = 时效×0.30 + 准确×0.30 + 成本×0.15 + 依赖×0.10 + 风险×0.15。
- 推荐结论必须写明理由与切换条件，不允许只写「建议采用方案 X」。
- 折中方案必须同时回应 D+3 时点与口径准确两个约束。
- 机制采用的最终决定属于管理层，输出只做决策支持，不写「已决定」类表述。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 五维得分是否与要素表逐项一致？
2. 加权总分是否按固定权重复算可得，排名与总分降序一致？
3. 推荐方案是否为折中方案且带切换条件？
4. 折中方案是否同时回应了 D+3 时点与口径准确？
5. 是否没有任何一行只写结论不写理由？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，5 行（每方案 1 行），10 列，列名与顺序固定：
方案编号, 方案名称, 时效性得分, 口径准确度得分, 实施成本得分, 依赖可控性得分, 风险可控性得分, 加权总分, 排名, 推荐结论与切换条件

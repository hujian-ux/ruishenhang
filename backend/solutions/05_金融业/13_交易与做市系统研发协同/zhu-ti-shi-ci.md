## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/交易与做市系统研发协同/SKILL.md`）。
2. 上传两个附件：`接口文档.md`、`用例参数矩阵.csv`。

## 主提示词（复制即用）

```
请基于我上传的两份素材，为交易与做市系统本轮改造生成用例与会话配置清单，输出一张与接口文档逐条对齐的可复核清单。

【输入 1 · 接口文档】接口文档.md（9 个接口）
- 总览表：接口编号、接口名称、功能说明、输入参数、返回值、会话参数要求、文档状态（完整 / 待补全）
- 明细段落：待补全接口含本轮需补全的说明项（参数 / 返回值 / 会话参数要求 / 错误码）
【输入 2 · 用例参数矩阵】用例参数矩阵.csv（20 行）
- 含序号、接口名称、场景类型（正常 / 边界 / 异常）、会话参数组合、输入要点、预期行为要点

【输出】用例生成与会话配置清单.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「交易与做市系统研发协同」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **这次生成了多少条用例、覆盖几个接口？** 期望回答：20 条用例，9 个接口全覆盖（queryMarketTradableVolume 与 submitTradeOrder 各 3 条，其余 7 个接口各 2 条）。
2. **哪些接口的文档是本轮同步补全的？** 期望回答：4 个——queryMarketTradableVolume（取市场可成交量）、aggregateBondPnl（损益排序汇总）、updateCacheValue（缓存传值更新）、batchImportCases（用例批量导入）；涉及 9 条用例。
3. **queryMarketTradableVolume 为什么缺会话参数要判异常？** 期望回答：接口要求 marketSession 必填，缺失时返回会话未建立错误——不允许跨会话取量，所以矩阵第 3 行是异常场景用例。
4. **updateCacheValue 的边界用例测什么？** 期望回答：载荷超限——结构化载荷直传的传值方式重设计后，超长载荷返回截断告警并拒绝写入，验证无中间类型转换的直传链路。
5. **calcBondPnL 的用例为什么没有会话参数？** 期望回答：接口文档声明损益计算不绑定会话（无会话参数），用例中不得臆造；矩阵中该接口会话参数组合为「无」。

# 渠道经营看板与异常线索标注

## 一、这个 Skill 解决什么

渠道经营的真实困难不是「没有数据」，而是**数据有渠道、时段、人员三个维度，看汇总看不出问题在哪个人**：

- 看板每次重新做，汇总规则不留存，下月从零再来
- 「承接量高但发起率低」的异常人员藏在 60 行明细里，靠人工扫表发现
- 指标取数字段靠口头约定，不同小组各算各的，数对不上
- 线索跟进进展分散在多个项目文档里，拼不出全局待办

本 Skill 的核心动作，是把看板生成固化成「**先定口径 → 分渠道分时段汇总 → 标异常人员 → 沉淀规则**」的流水线：每个汇总数可回溯到明细行，异常人员自动标注并进线索跟进待办。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 每日 / 每周要看分渠道分时段的承接与发起情况 | 主用场景：看板汇总生成 |
| 管理层问「线索承接了为什么案例没发起」 | 用异常判定规则在全员明细中标注「高承接低发起」人员 |
| 不同小组对同一指标各报各数 | 字段口径确认 + 与来源系统截图逐项比对 |
| 线索跟进进展分散在多个文档 | 按渠道 → 人员 → 待办整理跟进表 |

**不适用**：区域维度的月度量质拆解诊断（→ FIN-02 区域月报技能与月度经营诊断）；机制设计与方案比较（→ FIN-11 经营分析机制设计与汇报版拆分）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `渠道人员明细.csv` | 必需 | 渠道类型、时段、人员、承接线索量、发起案例数 |
| 2 | `看板口径说明.md` | 必需 | 汇总口径、异常判定阈值（承接 ≥100 且 发起率 <8%）、字段取数规则、截图比对要求 |

> 缺 2（口径说明）时，本 Skill **必须拒绝输出异常标注**——异常阈值与取数字段不允许临场拍定，否则标注结果不可比也不可信。

## 四、输出（outputs）

唯一交付物：`渠道看板汇总与异常标注.csv`，19 行，8 列，列名与顺序固定：

```
渠道类型, 时段, 对象类型, 对象, 承接线索量, 发起案例数, 发起率%, 异常标注
```

- 行构成：12 行渠道 × 时段汇总（3 渠道 × 4 时段）+ 3 行渠道全天合计 + 1 行总体合计 + 3 行异常人员
- `对象类型` ∈ {时段汇总, 渠道合计, 总体合计, 异常人员}
- `发起率%` = 发起案例数 ÷ 承接线索量 × 100（按行内两数复算，保留 1 位小数）
- `异常标注` 写明判定依据（承接量、发起率与两条阈值的关系），无异常写「—」
- 任何一行汇总数必须能在明细中找到全部构成行，**不允许出现无出处的数字**

## 五、工作流程（workflow）

### STEP 1 · 字段确认，口径先于看板

从 `看板口径说明.md` 读入汇总口径与异常阈值，逐项确认指标取数字段（承接取「已分配且未关闭」，发起取「当时段发起成功」），写成显式判定表。

```
时段口径：09-12 / 12-15 / 15-18 / 18-21
发起率 = 发起案例数 ÷ 承接线索量 × 100
异常判定（人员全天口径）：承接 ≥ 100 且 发起率 < 8%
```

### STEP 2 · 分渠道分时段汇总

对总渠道与分渠道数据按四档时段汇总，输出 12 行渠道 × 时段汇总 + 3 行渠道合计 + 1 行总体合计；每行发起率按合计复算，不做人员发起率的简单平均。

### STEP 3 · 异常人员标注

在全员明细板块中，按人员全天口径逐人判定：承接 ≥100 且 发起率 <8% 即标注「高承接低发起」，异常人员行单列并写明判定依据。只满足一条阈值的不标注（头部高量高效人员、长尾低量人员均不误伤）。

### STEP 4 · 线索跟进表整理

结合项目内容与线索跟进表，按「渠道类型 → 人员 → 待办」整理进展；异常人员的线索跟进待办优先级最高，2 个工作日内回访。

### STEP 5 · 截图比对与口径纠偏

每个汇总数与来源系统截图逐项比对，完全一致才定稿；不一致先查口径再查数据。比对结论记入迭代说明。

### STEP 6 · 规则沉淀与自检

异常阈值、时段口径与取数规则沉淀为看板生成规则，下次只更新数据不重定规则。输出前逐项自检，任一不过则不得输出：

1. 19 行结构是否完整（12 + 3 + 1 + 3）？
2. 每行汇总数是否与明细构成行逐项闭合？
3. 异常人员是否全部满足双阈值且判定依据写明？
4. 高量高效人员是否没有被误标？
5. 发起率是否全部按行内两数复算？

## 六、关键规则（不可协商）

1. **口径先于看板。** 阈值与取数字段以 `看板口径说明.md` 为准，会话中确认并与截图比对，不允许看板做完再补口径。
2. **异常判定用双阈值。** 只看承接量或只看发起率都会误判；人员判定必须用全天口径，不用单时段数据。
3. **汇总必须可回溯。** 每个汇总数都能在明细里找到全部构成行，「大约对得上」不算对得上。
4. **异常标注不等于问责。** 标注输出的是线索跟进优先级，原因分析（培训、线索质量、话术）属于人。
5. **规则必须沉淀。** 本次确认的口径与阈值写入看板生成规则，下次沿用，不允许每次重定。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（渠道经营岗 / 管理层） |
| --- | --- |
| 分渠道分时段汇总与发起率复算 | 取数字段的最终裁定 |
| 异常人员双阈值判定与标注 | 异常原因分析（培训 / 线索质量 / 话术） |
| 线索跟进表整理与优先级排序 | 回访执行与人员辅导 |
| 比对差异的记录 | 与来源系统的口径沟通 |

## 八、下游衔接

- 异常人员线索跟进待办 → 2 个工作日内回访，回访结果回流线索跟进表
- 异常识别规则与阈值 → 沉淀进看板生成规则，供经营分析岗迭代（→ FIN-11 经营分析机制设计与汇报版拆分）

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先定口径再看数：把汇总口径与异常阈值写成显式判定表，不要先看数据再定标准。
2. 分渠道分时段汇总：输出 12 行渠道 × 时段汇总（3 渠道 × 4 时段）+ 3 行渠道全天合计 + 1 行总体合计，每行发起率按行内两数复算。
3. 异常人员标注：按人员全天口径（四时段合计）逐人判定，命中双阈值的人员单列一行，异常标注写明判定依据（承接量、发起率与两条阈值的关系）；只满足一条阈值的不标注（如承接 160 且发起率 17.5% 的高量高效人员）。
4. 线索跟进待办：结合线索跟进表口径，按「渠道类型 → 人员 → 待办」整理，异常人员的回访待办优先级最高（2 个工作日内）。
5. 截图比对：每个汇总数与来源系统截图逐项比对，不一致先查口径再查数据，比对结论记入迭代说明。

### 硬性约束

【硬性约束】
- 任何一行汇总数必须能在明细里找到全部构成行，不允许出现无出处的数字。
- 异常判定必须双阈值同时满足，且用人员全天口径，不允许用单时段数据判定人员。
- 异常标注必须写明判定依据，不允许只写「异常」两个字。
- 口径以看板口径说明.md 为准，不允许临场调整阈值或取数字段。
- 异常标注输出的是跟进优先级，不输出对人员的问责结论。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 19 行结构是否完整（12 时段汇总 + 3 渠道合计 + 1 总体 + 3 异常人员）？
2. 每行汇总数是否与明细构成行逐项闭合？
3. 异常人员是否全部满足双阈值？
4. 高量高效人员是否没有被误标？
5. 发起率是否全部按行内两数复算？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，19 行，8 列，列名与顺序固定：
渠道类型, 时段, 对象类型, 对象, 承接线索量, 发起案例数, 发起率%, 异常标注
行构成 = 12 行时段汇总（对象类型=时段汇总）+ 3 行渠道合计（渠道合计）+ 1 行总体合计（总体合计，渠道类型=总渠道）+ 3 行异常人员（对象类型=异常人员，时段=全天）

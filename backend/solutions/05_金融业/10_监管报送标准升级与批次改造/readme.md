# FIN-10 · 监管报送标准升级与批次改造 —— 场景使用说明

- **行业**：金融业（保险）
- **角色**：报送系统研发岗
- **场景编号**：FIN-10
- **案例主体**：某保险集团

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/监管报送标准升级与批次改造/SKILL.md` | Skill 定义 | 「先讨论方案再落代码」门禁、R1-R5 决策规则、边界情况口径与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |

| `报送标准新旧对照.md` | 原始输入 | 9 条新标准条款（新旧口径、轻重度）、决策规则、边界口径、工作量分档 |
| `批次改造方案表.csv` | **交付物** | 25 行：改造决策（保留/重构/合并）、决策依据（规则+条款）、边界情况、工作量 |
| `报送系统研发岗-监管报送标准升级与批次改造.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `历史批次清单.csv`、`报送标准新旧对照.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 方案表经团队确认后进入改码；待确认事项写入需求文档留痕接续。

### 可复算口径

- `改造决策`：按 R5 → R1 → R2 → R3 → R4 顺序判定，先命中先生效
- `工作量预估人日`：保留 0.5 / 合并 1.5 / 重构按记录数分档（≤1200 → 3；1201-1700 → 5；>1700 → 7）
- `重构占比 = 重构工作量 ÷ 总工作量`

## 五、真实性等级与边界

- **T2**：「先讨论方案再落代码」、批次兼容决策规则方法论来自公开的存量系统改造实践。
- **T3**：报送系统研发岗痛点来自素材中的传统模式描述。
- **构造**：批次、条款、工作量数据口径可复算。
- **升 T1 还缺**：真实监管标准原文与一次实际批次改造的前后对照。
- **人工边界**：新标准条款的最终解释、方案表的评审确认、外部无匹配数据的人工补齐、改码实施与上线决定一律人工；本场景全部输出不出现效率百分比与工期承诺。

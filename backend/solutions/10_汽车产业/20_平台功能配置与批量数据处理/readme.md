# MOB-20 · 平台功能配置与批量数据处理 —— 场景使用说明

- **行业**：汽车与出行
- **角色**：数据工程与算法岗（程一舟）
- **场景编号**：MOB-20
- **案例主体**：某汽车互联网营销企业

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/平台功能配置与批量数据处理/SKILL.md` | Skill 定义 | 两态授权口径、批量拉取规则、失败归集与续跑机制、人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `账号授权明细.csv` | 原始输入 | 30 行账号明细（账号/平台/授权状态/绑定门店/最后同步时间/待拉取/已归档） |
| `批处理任务说明.md` | 原始输入 | 授权配置口径、批量拉取规则、失败归集口径、续跑机制 |
| `授权配置与批处理结果.csv` | **交付物** | 30 行批处理结果：状态处理 + 任务结果 + 失败归集 + 续跑状态 |
| `数据工程与算法岗-平台功能配置与批量数据处理.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `账号授权明细.csv`、`批处理任务说明.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。

## 三、交付物验证记录

生成脚本 `gen_MOB-20.py` 以 Python 标准库 `csv` 按批处理规则从 30 行明细真实计算写出交付物，并在脚本内做断言验证。执行结果：

```
OK  账号授权明细.csv                  30 data rows
OK  授权配置与批处理结果.csv          30 data rows
授权状态：已授权 22 / 待授权 8（授权完成率 73.3%）| 平台 5 个
批量结果：完成 17 个账号无需续跑 | 部分完成 5 个账号
失败样本归集 61 张，待续跑 5 个账号（断点续跑）
ALL MOB-20 ASSERTIONS PASSED
```

### 断言项

| 断言 | 结果 |
| --- | --- |
| `账号授权明细.csv` 数据行 = 30，平台数 = 5 | 通过 |
| 授权分布 = 已授权 22 / 待授权 8（授权完成率 22÷30 = 73.3%） | 通过 |
| 失败样本总数 = 61（澜山选车·迅影 12 + 澜城选车·车声 7 + 澜峰选车·车声 18 + 澜江选车·星潮 15 + 云澜选车·星潮 9） | 通过 |
| 待续跑账号 = 5 个，断点 = 已归档数 + 1 | 通过 |
| 完成无需续跑账号 = 17 个（已归档 = 待拉取） | 通过 |
| 待授权账号 8 个的待拉取 321 张为积压量，不计入失败样本 | 通过 |

### 可复算口径

- `失败张数 = 待拉取图片数 − 已归档图片数`（仅对已授权账号）
- `授权完成率 = 22 ÷ 30 = 73.3%`
- `续跑断点 = 已归档图片数 + 1`
- `失败样本总数 = 12 + 7 + 18 + 15 + 9 = 61`

## 四、与案例链的数字对齐

| 数字 | 出处 | 在本场景的落点 |
| --- | --- | --- |
| 30 个账号 × 5 个平台 | 页面 standfirst 与案例区 | `账号授权明细.csv` 30 行 |
| 8 个待授权 / 授权完成率 73.3% | 页面关键钩子 | 授权状态列计数（22÷30） |
| 61 张失败样本归集、5 个账号待续跑 | 页面四列 SVG | 交付物「失败归集标记」列求和 |
| 17 个账号完成无需续跑 | 素材场景四 | 已归档 = 待拉取的账号计数 |
| 10 家门店与 MOB-17 / MOB-18 同网络 | 案例链 | 绑定门店为同一门店网络 |

## 五、真实性等级与边界

- **T2**：账号授权管理与批处理续跑方法来自行业通行实践。
- **T3**：岗位痛点来自数据工程岗位 JD 与社区。
- **构造**：账号与批处理数据为构造数据，规则口径可复算。
- **人工边界**：平台商务授权推进、限额与频控策略、失败样本重跑触发时机一律人工；AI 只出状态映射、结果计算与续跑标注。

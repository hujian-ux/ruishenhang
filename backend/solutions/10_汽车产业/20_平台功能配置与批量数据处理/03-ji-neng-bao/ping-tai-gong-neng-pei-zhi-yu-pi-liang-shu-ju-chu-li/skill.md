# 平台功能配置与批量数据处理

## 一、这个 Skill 解决什么

平台对接与批处理的真实困难不是「任务复杂」，而是**长耗时任务的连续性**：

- 多个外部平台的账号授权状态散在各部门手里，谁已授权谁待授权说不清
- 批量图片拉取动辄上百张，任务中断后推倒重来，前功尽弃
- 失败样本散落在各处日志里，没有归集就没有重跑
- 授权、批处理、异常归集三件事彼此割裂，串不成一条链路

本 Skill 的核心动作，是把「配置 + 批处理 + 异常归集 + 续跑」串成一条**可连续推进的链路**，任务中断后从断点接力执行，不推倒重来。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 对接新平台，账号授权状态要盘点配置 | 主用场景：30 个账号 × 5 平台的两态管理 |
| 素材库要批量拉取图片归档 | 已授权账号进入队列，逐张拉取 |
| 拉取中断或失败，要归集重跑 | 失败样本进库登记，断点续跑 |
| 任务跨多个时间段推进 | 续跑机制保证产出累积 |

**不适用**：素材内容的审核与裁剪（属于内容运营域）；平台 API 的开发联调本身。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `账号授权明细.csv` | 必需 | 账号、平台、授权状态、绑定门店、最后同步时间、待拉取图片数、已归档图片数 |
| 2 | `批处理任务说明.md` | 必需 | 授权状态口径、批量拉取规则、失败归集口径、续跑机制 |

> **缺「已归档图片数」字段时无法计算断点**，必须先补齐该字段再执行——这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`授权配置与批处理结果.csv`，30 行（每个账号一行），字段固定为 5 列：

```
账号, 状态处理, 批量任务结果, 失败归集标记, 续跑状态
```

- `状态处理` ∈ {维持绑定，纳入批量拉取, 推送授权邀请，暂缓批处理}
- `批量任务结果` 必须含「已归档数 / 待拉取数」对照（如「108/120张，失败12张」），**不允许只写「已处理」**
- `失败归集标记` 必须为明确的是/否，是时注明归集张数
- `续跑状态` 必须写明断点位置（如「从第109张断点继续」）

## 五、工作流程（workflow）

### STEP 1 · 授权状态配置

授权状态列两态呈现：已授权 / 待授权。点击状态弹出明细弹窗（账号、平台、绑定门店、最后同步时间、待处理素材量）。待授权账号展示「推送授权邀请」入口。

### STEP 2 · 批量拉取与归档

已授权账号纳入批量队列，按待拉取图片数逐张拉取并归档；待授权账号不执行，标记「授权完成后自动加入下一轮」。

### STEP 3 · 失败样本归集

失败 = 待拉取图片数 − 已归档图片数，统一归集至失败样本库，逐张登记来源账号与平台，供重跑使用。

### STEP 4 · 断点续跑

任务中断后不推倒重来：已归档数即断点，续跑从第（已归档数 + 1）张继续；待授权账号完成授权后自动入队。

### STEP 5 · 自检

输出前逐项自检，任一不过则不得输出：

1. 30 行输出与账号明细一一对应？
2. 每行批量任务结果都含已归档数 / 待拉取数对照？
3. 失败样本总数 = 各账号失败张数之和？
4. 待续跑账号的断点位置全部写明？

## 六、关键规则（不可协商）

1. **待授权不执行批处理。** 待授权账号的待拉取数是积压量，不计入失败样本；失败只产生于已授权账号的执行过程。
2. **失败必须归集。** 每张失败样本登记来源账号与平台，没有归集就没有重跑。
3. **续跑不重跑。** 已归档数即断点，已完成的张数不重复拉取。
4. **结果必须含对照数。** 「已处理」「部分完成」这类没有数字对照的表述不允许单独出现。
5. **不写效率承诺。** 输出中不写「提速 X%」这类无法核验的表述。

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 授权状态配置：逐账号给出状态处理——待授权账号统一为「推送授权邀请，暂缓批处理」，并说明明细弹窗应展示的字段。
2. 批量拉取：对已授权账号逐个给出批量任务结果，必须含「已归档数/待拉取数」对照（如「108/120张，失败12张」）。
3. 失败归集：失败张数大于 0 的账号标记「是」并注明归集张数；全部完成的账号标记「否」。
4. 断点续跑：部分完成的账号写明续跑断点（从第几张继续）；待授权账号写「授权完成后自动加入下一轮」。
5. 汇总输出：授权完成率、失败样本总数、待续跑账号数、完成无需续跑账号数，全部从明细复算。

### 硬性约束

【硬性约束】
- 待授权账号的待拉取数是积压量，不计入失败样本；失败只产生于已授权账号的执行过程。
- 批量任务结果必须含已归档数/待拉取数对照，不允许只写「已处理」。
- 失败归集标记必须为明确的是/否，是时注明归集张数。
- 续跑不允许写「重新执行全部」，必须写明断点位置。
- 不写任何提速百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输出是否为 30 行且账号无重复？
2. 授权分布是否为已授权 22 / 待授权 8？
3. 失败样本总数是否为 61 张，待续跑账号是否为 5 个？
4. 完成无需续跑的账号是否为 17 个？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，5 列，30 行（每个账号一行），列名与顺序固定：
账号, 状态处理, 批量任务结果, 失败归集标记, 续跑状态

- **案例主体**：某商用车企业

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/车载软件测试工程整体重建/SKILL.md` | Skill 定义 | 只读盘点原则、D1-D4 决策规则、位置映射、迁移批次与人工边界 |

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `测试资产盘点表.csv`、`重建决策规则.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 迁移清单经测试负责人确认后，才在新工作区 `nv-hil-tests/` 开始实施；旧工程保持只读归档。

### 可复算口径

- `决策` 按「复用判定 × 运行状态」查 D1-D4 表得出
- `新工程对应位置 = nv-hil-tests/<类型目录>/<模块代码>/<资产编号><扩展名>`
- `迁移顺序`：保留迁移批 = 1-10、替换升级批 = 11-16、重建批 = 21-25，组内按资产编号
- 决策分布合计 = 盘点资产总数

## 五、真实性等级与边界

- **方法论来源**：测试资产盘点与重构决策（保留/替换/重建/废弃）为软件工程通用实践。
- **构造**：资产清单、框架名称（NW-Test 1.x 为构造自研框架名）与判定结论为构造数据，全部数字可由输入复算。
- **人工边界**：复用判定与业务有效性的最终裁定、重建方案评审确认、实施节奏排期一律人工；AI 只输出决策清单与批次建议，方案确认前不改动任何既有文件。

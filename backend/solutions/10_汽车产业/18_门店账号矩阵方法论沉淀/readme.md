# MOB-18 · 门店账号矩阵方法论沉淀 —— 场景使用说明

- **行业**：汽车与出行
- **角色**：内容策略与方法论岗（温书言）
- **场景编号**：MOB-18
- **案例主体**：某汽车互联网营销企业

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/门店账号矩阵方法论沉淀/SKILL.md` | Skill 定义 | 四阶段判定规则、八步 SOP、取舍调整与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `门店账号现状数据.csv` | 原始输入 | 20 行门店账号现状（门店/粉丝数/月更条数/平均播放/互动率） |
| `成长阶段模型.md` | 原始输入 | 四阶段横向模型、判定规则、八步搭建 SOP、各阶段动作 |
| `门店阶段诊断与SOP行动表.csv` | **交付物** | 20 行诊断行动表：门店 × 所处阶段 × 诊断依据 × SOP 动作 |
| `内容策略与方法论岗-门店账号矩阵方法论沉淀.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `门店账号现状数据.csv`、`成长阶段模型.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。

## 三、交付物验证记录

生成脚本 `gen_MOB-18.py` 以 Python 标准库 `csv` 按模型判定规则从 20 行现状数据真实计算写出交付物，并在脚本内做断言验证。执行结果：

```

OK  门店阶段诊断与SOP行动表.csv      20 data rows
阶段分布：冷启动期 5 / 起步期 8 / 成长期 5 / 成熟期 2
起步期门店 8 家 = 40.0% | 矩阵粉丝合计 308,800 | 月更合计 200 条
ALL MOB-18 ASSERTIONS PASSED
```

### 断言项

| 断言 | 结果 |
| --- | --- |
| `门店账号现状数据.csv` 数据行 = 20 | 通过 |
| 阶段分布 = 冷启动期 5 / 起步期 8 / 成长期 5 / 成熟期 2 | 通过 |
| 起步期占比 = 8 ÷ 20 = 40.0% | 通过 |
| 矩阵粉丝合计 = 308,800；月更合计 = 200 条 | 通过 |
| 抽查判定：澜山店/澜城店=成熟期，澜林店/澜台店=冷启动期，青澜店/澜谷店=起步期，澄澜店/澜湾店=成长期 | 通过 |
| 交付物 = 20 行且门店无重复 | 通过 |

### 可复算口径

- `阶段判定`：自上而下命中即停——成熟期（粉丝 ≥50,000 且互动率 ≥4.0%）→ 成长期（粉丝 ≥10,000 且月更 ≥12）→ 起步期（粉丝 ≥2,000 且月更 ≥8）→ 冷启动期（其余）
- `起步期占比 = 8 ÷ 20 = 40.0%`
- `矩阵粉丝合计 = 20 家门店粉丝数求和 = 308,800`
- `月更合计 = 20 家门店月更条数求和 = 200`

## 五、真实性等级与边界

- **T2**：账号矩阵成长模型与搭建 SOP 方法来自行业通行实践。
- **T3**：岗位痛点来自内容运营岗位 JD 与社区。
- **构造**：门店现状数据为构造数据，判定口径可复算。
- **人工边界**：阶段门槛值的最终设定、与门店的沟通结论、品牌侧宣讲培训一律人工；AI 只出框架、诊断与 SOP 映射。

# 文档命名与版本规范（成套产出 · 版本与日期 · 流程归档）

适用企业：某新能源汽车企业
适用范围：产品与整车功能岗为新能力建设配套测评体系时的成套文档产出、命名、版本与流程归档。

## 一、成套文档类型

每个测评能力项配套四类文档，成套产出、缺一不可：

| 文档类型 | 内容 | 用途 |
| --- | --- | --- |
| 方案说明 | 测评目标、范围、用例设计思路 | 评审与立项依据 |
| 部署说明 | 测评环境、设备、软件版本与部署步骤 | 测评执行前置条件 |
| 验收方案 | 验收标准、判定阈值、通过条件 | 交付验收口径 |
| 测试评分表 | 评分维度、权重、评分记录表 | 结果量化与留档 |

## 二、命名规范

```
<能力项编号>-<能力项名称>-<文档类型>_V<版本>_<日期>.md
```

- 如：`IC-01-语音多轮对话-方案说明_V1.0_20261015.md`
- 日期格式 `YYYYMMDD`，为该能力项的计划交付日期，纳入文件名。
- 命名统一由规范生成，不允许自造缩写或中英混排变体。

## 三、版本规则

| 版本 | 适用情形 |
| --- | --- |
| V1.0 | 新建文档：验收标准现状为「缺失」或「口头约定」的能力项 |
| V2.0 | 升版文档：验收标准现状为「部分文档」的能力项，既有文档经补全后重大升版 |

- 小修（错别字、格式）升 V1.x / V2.x 小版本；范围或标准变更必须升大版本。

## 四、优先级与交付日期

| 优先级 | 判定 | 计划交付日期 |
| --- | --- | --- |
| P0 | 验收标准现状 = 缺失 | 2026-09-30 |
| P1 | 验收标准现状 = 口头约定 | 2026-10-15 |
| P2 | 验收标准现状 = 部分文档 | 2026-10-31 |

## 六、补齐动作口径

| 验收标准现状 | 补齐动作 |
| --- | --- |
| 缺失 | 从零起草验收标准，先补方案说明并同步定稿验收方案 |
| 口头约定 | 将口头口径固化为书面验收标准，评审后入版本库 |
| 部分文档 | 对既有文档查漏补全，统一命名与版本后重新归档 |

## 七、流程文件与岗位职责归档

- 测评体系文档定稿后同步梳理流程文件：按「测评发起 → 方案评审 → 部署执行 → 验收评分 → 归档复盘」五步固化流程，命名规则与本规范一致（前缀 FL-）。
- 岗位职责按 RACI 记录：谁负责起草、谁评审、谁批准、谁归档，写入流程文件附表。
- 版本与日期纳入命名规范后，文档管理混乱度下降：任何文档都能从文件名读出所属能力项、版本与交付时间。

## 八、验收口径

- 15 个能力项 × 4 类文档 = 60 份文档计划，文件名全部不重复；
- 先确认结构（方案说明的目录骨架）再成套产出，对不满意的结构先分析再动手；
- 优先级分布、版本分布、交付日期必须可从清单按规则复算；
- 页面引用的「文档计划数 / 优先级分布 / 版本分布」必须可复算得出。

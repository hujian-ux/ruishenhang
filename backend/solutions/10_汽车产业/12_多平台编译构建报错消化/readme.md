# MOB-14 · 多平台编译构建报错消化 —— 场景使用说明

- **行业**：汽车与出行
- **角色**：系统与平台适配工程师（魏承）
- **场景编号**：MOB-14
- **案例主体**：某智能座舱软件企业

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/多平台编译构建报错消化/SKILL.md` | Skill 定义 | 错误分类、未定义符号三类来源、三级处置规则与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `编译报错日志样本.csv` | 原始输入 | 15 条多平台编译报错：记录编号、芯片平台、错误类型、报错原文摘要、涉及文件 |
| `排障决策规则.md` | 原始输入 | 错误分类定义、未定义符号三类来源、三级处置规则（只诊不改边界） |
| `报错归因与处理清单.csv` | **交付物** | 15 行归因清单：报错 × 归因 × 处理方向 × 处置等级 × 是否需人工确认 |
| `系统与平台适配工程师-多平台编译构建报错消化.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `编译报错日志样本.csv`、`排障决策规则.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 按清单逐条处置：L1 类自行决定是否修改；L2 类确认环境后执行修正命令；L3 类在 IDE 中采纳最小修改建议。

OK  需人工确认 11 条 | 平台分布 ZX-A9 6 / ZX-M7 5 / ZX-S5 4

### 可复算口径

- `错误类型分布`：按日志样本「错误类型」列计数
- `处置等级`：链接错误 → L1；路径错误 → L2；语法错误 → L3（对应排障决策规则三级处置）
- `需人工确认数`：处置等级为 L1 与 L2 的条数之和
- `平台分布`：按日志样本「芯片平台」列计数

## 五、真实性等级与边界

- **T2**：把报错原文直接交给 AI、只诊不改等协作方法来自企业应用实践总结。
- **T3**：岗位痛点来自多芯片平台并行开发的典型工作场景。
- **构造**：报错日志、芯片平台与文件名为构造数据，归因口径可复算。
- **人工边界**：是否修改代码与链接配置、构建环境变更执行、跨模块依赖判断一律人工；AI 只输出归因清单与处理方向。

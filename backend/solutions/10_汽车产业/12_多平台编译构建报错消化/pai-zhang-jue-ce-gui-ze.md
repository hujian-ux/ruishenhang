# 排障决策规则 · 多平台编译构建报错消化

> 适用范围：ZX-A9 / ZX-M7 / ZX-S5 三类座舱芯片平台的编译与构建报错处理。
> 核心原则：**先分类，再归因，后处置**——禁止跳过分类直接给修改方案。

## 一、错误分类定义

| 错误类型 | 识别特征 | 常见报错关键词 |
| --- | --- | --- |
| 链接错误 | 链接阶段符号解析失败 | undefined reference to |
| 路径错误 | 文件 / 目录定位失败 | 执行目录、产物目录、No such file、cannot find -l、No rule to make target |
| 语法错误 | 编译阶段源码解析失败 | expected、macro expands、invalid suffix |

## 二、链接错误（未定义符号）的三类来源

未定义符号类错误必须按以下顺序逐一排查，禁止只给一种可能：

1. **实现文件未参与编译**：源文件未加入构建清单，或头文件声明与实现签名不一致（常见于接口改签名后只更新了一侧）。
2. **条件编译裁剪**：符号实现被平台条件编译宏裁剪，对应平台未开启启用宏（stub / 裁剪文件名是典型线索）。
3. **外部库未链接**：符号来自预编译库，库未加入链接列表或库名与实际产物不匹配（wrapper / lib 前缀文件名是典型线索）。

## 三、三级处置规则（只诊不改边界）

| 处置等级 | 适用错误 | AI 动作边界 |
| --- | --- | --- |
| L1 只诊不改 | 链接错误 | 只输出归因链与验证命令（nm / objdump 确认符号所在库），是否修改由工程师决定；不自动改链接脚本、不自动开宏 |
| L2 命令待确认 | 路径错误 | 给出配置核对清单与修正命令（如回到仓库根目录重新发起构建、补 include / 库搜索路径），命令执行前必须人工确认——构建环境是团队共享资产 |
| L3 建议可直接采纳 | 语法错误 | 定位到文件与行号，给出最小修改建议；采纳与执行仍由工程师在 IDE 中完成 |

## 四、通用约束

1. 报错原文完整粘贴，不做截断；涉及文件与行号必须保留。
2. 一次只处理一条报错，处理完再进入下一条，避免交叉污染。
3. 涉及跨模块依赖决策（如开启某平台宏会影响其他模块）的一律交人工。
4. AI 不自动修改任何代码、不直接改构建环境变量与目录配置。
5. 归因必须写明「来源类别 + 验证方法」，不允许只写「重新编译试试」。

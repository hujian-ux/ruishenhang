# MOB-01 主提示词 · 数据治理痛点梳理与机制设计

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/数据治理痛点梳理与机制设计/SKILL.md`）。
2. 上传两个附件：`数据问题原始清单.csv`、`治理机制框架.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `痛点归纳与机制设计表.csv` 后，按文末「验收清单」逐项核对。

## 主提示词（复制即用）

```
请基于我上传的两份素材，为「某汽车集团 · 数据治理专项」做痛点归纳与长期机制设计，输出一张可复算的痛点归纳与机制设计表，并附演示材料大纲。

【输入 1 · 数据问题原始清单】数据问题原始清单.csv（25 行）
- 含问题编号、问题描述、所在系统、所在部门、数据域、发现频率
【输入 2 · 治理机制框架】治理机制框架.md
- 痛点归类维度：口径不一致 / 数据质量缺陷 / 源头录入不规范 / 跨系统协同断点 / 安全与权限缺失（各含触发关键词）
- 机制分层：标准层（指标字典与口径备案）/ 执行层（质量规则库与源头管控）/ 运营层（接口对账与分级授权）
- 优先级规则：高频且属口径/质量类 → 高；高频其他类或中频 → 中；低频 → 低

【输出】痛点归纳与机制设计表.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「数据治理痛点梳理与机制设计」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **为什么 DQ-02（一次交检合格率两个数字对不上）归为口径不一致而不是跨系统协同断点？** 期望回答：问题描述同时含「对不上」与「统计范围定义不同」两个触发词，按框架顺序「口径」先于「协同」匹配，取首个命中。
2. **高优先级 9 项是怎么算出来的？** 期望回答：高频且属口径/质量类——口径类高频 5 项 + 质量类高频 4 项 = 9。
3. **为什么安全与权限类没有高优先级？** 期望回答：该类 3 项中发现频率最高为中频，按规则只能得到中或低，规则不因风险性质调整档位；如需提级应先修订框架规则。
4. **DQ-18 夜间同步失败归哪类？** 期望回答：跨系统协同断点——「接口」「同步失败」触发，映射运营层接口监控与对账机制。
5. **汇报大纲为什么高优先级排在机制设计之前？** 期望回答：先让委员会看到最痛的 9 项再讨论机制投入，结构服务于决策顺序。

## 验收清单

- [ ] 覆盖系统数 = 8（整车MES / 质量QMS / 集团ERP / 供应商SRM / 经销商DMS / 客户CRM / 研发PLM / 集团数据中台）
- [ ] 优先级分布 = 高 9 / 中 12 / 低 4
- [ ] 每行治理视角与业务视角表述同行对照、指向同一问题
- [ ] 机制要点全部来自框架三层，无自创机制名，无效率百分比表述

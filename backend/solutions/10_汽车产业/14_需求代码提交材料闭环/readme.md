# MOB-16 · 需求代码提交材料闭环 —— 场景使用说明

- **行业**：汽车与出行
- **角色**：研发经理与技术调研岗（苏黎）
- **场景编号**：MOB-16
- **案例主体**：某智能座舱软件企业

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/需求代码提交材料闭环/SKILL.md` | Skill 定义 | 四件套齐套口径、模板与章节结构、人工边界 |

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `需求变更记录.csv`、`提交与文档规范.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 按清单补材料：先补提交说明与变更文档，再做汇报单页；技术选型类需求同步整理调研网页。

### 可复算口径

- `完成度` = 既有配套材料项数 ÷ 4（四件套：提交说明 / 变更文档 / 汇报单页 / 材料清单）
- `需补齐材料` = 四件套 − 既有配套材料
- `材料缺口合计` = 各需求需补齐项数之和（本批次 2+3+4+1+3+2+0+3+2+3 = 23）
- `提交说明草稿` = [需求号][首个涉及模块] 变更内容摘要（依据提交与文档规范模板）
- `影响模块数` = 需求变更记录涉及模块列按分号计数

## 五、真实性等级与边界

- **T2**：提交说明模板、变更文档结构、汇报单页规格与调研网页化来自企业应用实践总结。
- **T3**：岗位痛点来自快速迭代节奏下材料被压缩的典型场景。
- **构造**：需求号、提交号与材料状态口径可复算。
- **人工边界**：需求立项与验收决策、提交说明与文档内容审核、技术选型最终决定一律人工；AI 只输出材料清单与草稿。

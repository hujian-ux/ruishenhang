# 度量体系设计规则（一阶 / 二阶 · 命名规范）

适用企业：某新能源汽车企业
适用范围：经营分析与数据岗为十大业务场景设计分层度量体系。

## 一、一阶与二阶的定义

### 一阶度量（过程层）

- 定义：直接刻画业务过程本身运行状态的度量，来源于业务过程记录（排产、报工、到货、工单、发布日志）。
- 特征：
  - 采集频率高（日/周级）；
  - 责任主体是执行团队；
  - 回答「这个过程跑得怎么样」。
- 如：排产达成率、到货准时率、一次下线合格率、版本崩溃率。

### 二阶度量（影响层）

- 定义：刻画一阶过程对经营结果（收入、成本、体验、资产效率）的放大影响的度量。
- 特征：
  - 采集频率低（月/季级）；
  - 责任主体是经营分析团队；
  - 回答「这个过程跑得好坏，最终对经营意味着什么」。
- 如：单车制造费用摊薄幅度、订单锁定周期对交付承诺的影响、补能客单成本。

### 关联递进关系（硬性要求）

每一项二阶度量必须声明它承接哪一项一阶度量，递进方式限于三种：

| 递进类型 | 含义 | 典型情形 |
| --- | --- | --- |
| 结果放大 | 一阶过程指标的变化，按系数放大为经营结果变化 | 一次下线合格率每降 1 个百分点 → 返工工时与单车制造费用上升 |
| 结构解释 | 一阶指标的波动，解释二阶结果的结构性成因 | 到货准时率下降 → 解释安全库存上升、资金周转变慢 |
| 冗余平衡 | 一阶指标的改善以二阶指标的让步为代价，需对照看 | 库存周转加快 → 备件满足率下降，需在两阶之间找平衡点 |

## 二、命名规范（业内通用体系校准）

1. 命名结构统一为：`对象 + 动作/状态 + 限定语`，如「一次下线合格率」而非「合格率（下线的）」。
2. 有业内通用叫法的，一律按通用叫法校准，避免自造词：
   - 准时类 → 参照 OTD（Order To Delivery）口径命名，如「到货准时率」「开票即交付率」；
   - 一次通过类 → 参照 FTQ（First Time Quality）口径命名，如「一次下线合格率」「一次修复率」；
   - 设备与节拍类 → 参照 OEE（Overall Equipment Effectiveness）口径命名；
   - 库存类 → 参照 ITR（Inventory Turnover Ratio）口径命名；
   - 体验类 → 参照 NPS（Net Promoter Score）口径命名；
   - 进度类 → 参照 PMBOK 里程碑管理口径命名。
3. 一律用「率 / 周期 / 成本 / 达成」四个后缀族，不混用「比 / 水平 / 度」等口语后缀。
4. 二阶度量命名时须能看出承接对象，如「备件 24 小时满足率对单次维修工时的影响」须能在名称中回溯到一阶项。

## 三、版式适配规则

- 体系定稿后按经营看板既有页面适配：单页画幅 1440 × 900，左右边距 32，行距 1.5；
- 一阶度量列居左、二阶度量列居右，中间为关联递进关系列；
- 每个业务场景占一个分组块，分组块之间留 24px 间隔，不跨页拆分同一场景。

## 四、验收口径

- 每个业务场景的一阶维度不少于 3 个（本批按 4 个设计）；
- 每个一阶维度至少有 1 项一阶衡量指标与 1 项二阶度量；
- 二阶度量与一阶维度的关联递进关系必须逐行声明，不得留空、不得写「相关」「有关联」这类无信息量的表述；
- 命名校准参照必须写明所参照的业内通用体系（OTD / FTQ / OEE / ITR / NPS / PMBOK 或「行业通用命名结构」）。

# MOB-13 · 座舱显示逻辑调整与影响面自查 —— 场景使用说明

- **行业**：汽车与出行
- **角色**：座舱应用开发工程师（陈屿）
- **场景编号**：MOB-13
- **案例主体**：某智能座舱软件企业

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/座舱显示逻辑调整与影响面自查/SKILL.md` | Skill 定义 | 影响面检索规则、调整口径、监听核查标准与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `显示逻辑配置表.csv` | 原始输入 | 20 行显示项明细：数据能力、车型形态、能源形态、当前展示逻辑、所属模块、更新监听 |
| `模块引用关系表.csv` | 原始输入 | 25 行模块引用关系：数据能力、引用模块、调用方式 |
| `影响面分析与调整方案表.csv` | **交付物** | 20 行影响面清单：显示项 × 影响模块数 × 需同步调整模块 × 调整方案 × 监听核查 |
| `座舱应用开发工程师-座舱显示逻辑调整与影响面自查.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用|

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `显示逻辑配置表.csv`、`模块引用关系表.csv` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 按交付物逐项实施：先补监听缺失项，再新增 ZX-C 旗舰形态展示分支；涉及跨模块的同步调整先与模块负责人确认。

### 可复算口径

- `是否需调整`：车型形态列不含「全形态」= 是（ZX-C 旗舰形态当前未覆盖）
- `影响模块数`：模块引用关系表中该数据能力的引用行数
- `需同步调整模块`：引用模块集合 − 所属模块
- `监听缺失数`：显示逻辑配置表「更新监听」列取值为「缺失」的行数

## 四、与页面的数字对齐

| 数字 | 出处 | 在本场景的落点 |
| --- | --- | --- |
| 20 个显示项 | `显示逻辑配置表.csv` 20 行 | 交付物 20 行一一对应 |
| 9 个显示项需调整 | 车型形态不含「全形态」的行数 | 交付物「是否需调整=是」共 9 行 |
| 5 处更新监听缺失 | 「更新监听=缺失」的行数 | 交付物监听核查列 5 处标注 |
| 25 条模块引用 | `模块引用关系表.csv` 25 行 | 影响模块数合计的来源 |
| getBatterySoc 被 4 个模块引用 | 引用表聚合 | 电池电量百分比行影响模块数 = 4 |
| 语音助手是隐藏调用方 | 引用表 getBatterySoc 行 | 需同步调整模块清单含语音助手模块 |

## 五、真实性等级与边界

- **T2**：影响面先查后改、小步迭代、只诊不改等协作方法来自企业应用实践总结。
- **T3**：岗位痛点来自智能座舱研发团队的典型工作场景。
- **构造**：显示项、数据能力、模块引用数据为构造数据，口径可复算。
- **人工边界**：分支代码修改与合入、跨模块同步调整确认、回归测试范围决定一律人工；AI 只输出影响面清单与调整方案。

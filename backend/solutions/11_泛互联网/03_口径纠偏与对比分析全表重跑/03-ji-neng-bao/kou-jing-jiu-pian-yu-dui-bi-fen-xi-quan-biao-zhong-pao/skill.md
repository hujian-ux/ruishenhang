# 口径纠偏与对比分析全表重跑

## 一、这个 Skill 解决什么

口径变更的真实困难不是「新口径算不出来」，而是**旧表全部作废**：

- 采购成本的测算规则要迭代，毛利率的分母要改基准
- 口径一变，此前所有基于旧口径的表都要重算，逐表手工改公式、改筛选
- 多份底表版本混乱，容易用错来源；跨表匹配靠人工查找
- 规则迭代后，历史数据难以回算，新旧口径的差异没人说得清

本 Skill 的核心动作：把**规则变更**与**数据重算**拆开——规则表讲清「旧口径→新口径」，数据表只管「门店 × 指标 × 旧值 / 新值」，对照表把两者关联后量化差异，口径的迭代成本从「重做一批表」降到「改一句规则 + 全表重跑」。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 口径规则更新（如销售额剔除平台补贴） | 主用场景：规则一变，全表重跑 |
| 底表来源指定变更（换工作表 / 换底表） | 锁定来源后整表重算，旧值保留对照 |
| 老板问「口径改了以后，数字差多少」 | 差异额、差异率、影响等级逐行量化 |
| 对比口径需要与 AI 先确认（如推广门店 vs 大盘） | 口径确认后按新前提重跑 |
| 规则迭代后要沿历史数据滚动重算 | 对照表保留旧值列，差异可回溯 |

**不适用**：看板的日常搭建与维护（→ INT-01 经营看板持续维护与线上分享）；固定频率的批量日报与无人值守推送（→ INT-02 跨仓跨期跨平台批量报表与自动化）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `口径规则版本记录.csv` | 必需 | 规则编号、规则名称、涉及指标、变更类别、旧口径、新口径、生效日期、变更原因 |
| 2 | `报表数据样本.csv` | 必需 | 门店编号、门店名称、指标名称、单位、旧口径值、新口径值、涉及规则编号 |
| 3 | `重跑机制.md` | 必需 | 触发条件、差异量化规则、影响等级判定（≥8% 高 / 3%–8% 中 / <3% 低 / 0% 无变化）、复核与发布流程 |

> 缺 1（规则版本记录）时，本 Skill **必须拒绝输出对照表**——没有规则基准的「新旧对照」无法复核，等于给差异编理由。

## 四、输出（outputs）

唯一交付物：`口径纠偏重跑对照表.csv`，字段固定为 14 列：

```
门店编号, 门店名称, 指标名称, 单位, 涉及规则编号, 规则名称, 生效日期,
旧口径值, 新口径值, 差异额, 差异率, 差异方向, 影响等级, 重跑动作
```

- `差异方向` ∈ {上调, 下调, 无变化}
- `影响等级` ∈ {高, 中, 低, 无变化}，按 |差异率| 判定
- `重跑动作` 只能取重跑机制中的四个固定值，**不允许自造动作词**
- 每行差异额、差异率必须能从旧值 / 新值直接复算

## 五、工作流程（workflow）

### STEP 1 · 规则澄清与底表锁定

读入 `口径规则版本记录.csv`，把每条规则的旧口径、新口径、生效日期写成显式判定表；确认数据样本的底表来源。**先对齐口径再动数据**——口径没讲清就重跑，等于把错算放大一遍。

### STEP 2 · 全表重算

对 `报表数据样本.csv` 逐行按新口径取新值，旧口径值保留为对照列；数值不变的归属类调整（如新店爬坡期单独列示）按「无变化」处理。

### STEP 3 · 差异量化

```
差异额 = 新口径值 − 旧口径值（保留位数随指标单位）
差异率 =（新口径值 − 旧口径值）÷ 旧口径值（1 位小数，带符号）
```

### STEP 4 · 影响等级判定

按 |差异率|：≥8% 高 / 3%–8% 中 / >0% 且 <3% 低 / =0% 无变化，并挂接对应重跑动作。

### STEP 5 · 规则关联复核

逐行核对涉及规则编号与规则表一致，规则名称、生效日期由规则表带出；高影响行推送战区复核。

### STEP 6 · 自检

输出前逐项自检（见附录），任一不过则不得输出。

## 六、关键规则（不可协商）

1. **规则一变，全表重跑。** 禁止局部修补、禁止只改受影响行；旧值一律保留为对照列。
2. **规则与数据分离。** 规则表只讲口径，数据表只讲数值，对照表负责关联——不允许在数据表里内嵌规则解释。
3. **差异必须可复算。** 每行差异额、差异率从旧值 / 新值直接算出，不允许手工修正。
4. **重跑动作固定四值。** 高 / 中 / 低 / 无变化各挂固定动作，不允许自造动作词。
5. **对照表不判口径对错。** 口径本身的合理性由提出方与战区复核，AI 只量化差异。
6. **不承诺效率百分比。** 输出中不写「节省 X 小时」这类无法核验的表述。

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 规则澄清与底表锁定：先读 15 条口径规则版本记录，把旧口径、新口径、生效日期写成显式判定表；确认报表数据样本的底表来源后再动数据。
2. 全表重算：对 20 行「门店 × 指标」样本逐行按新口径取新值，旧口径值保留为对照列；数值不变的归属类调整按「无变化」处理。
3. 差异量化：差异额 = 新值 − 旧值（保留位数随单位：万元 1 位小数 / 百分比 1 位小数 / 个取整 / 元取整）；差异率 =（新值 − 旧值）÷ 旧值，保留 1 位小数并带符号，旧值为 0 时差异率记「不可计算」并单独标注。
4. 影响等级：按 |差异率| ≥8% 高 / 3%–8% 中 / >0% 且 <3% 低 / =0% 无变化 判定，等级与动作一一对应。
5. 规则关联：每行涉及规则编号必须能在规则版本记录中找到，规则名称与生效日期由规则表带出，不允许凭记忆补写。

### 硬性约束

【硬性约束】
- 全表 20 行，行序按门店编号升序、同门店按指标原序排列。
- 禁止局部修补与覆盖旧值：每行必须同时保留旧口径值与新口径值。
- 重跑动作只取四个固定值：全表重跑 · 推送战区复核 / 全表重跑 · 看板刷新 / 全表重跑 · 留档备查 / 归属调整 · 保留单列标注。
- 不允许出现任何口径对错的判定（如「新口径更合理」）；不允许出现经营结论。
- 每行差异额、差异率必须能从旧值 / 新值直接复算；不允许手工修正值。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输出是否为 20 行、14 列，列名与顺序固定？
2. 每行差异率是否等于（新值 − 旧值）÷ 旧值，符号与方向是否一致？
3. 影响等级分布是否与阈值表逐条吻合（≥8% 高 / 3%–8% 中 / <3% 低 / 0% 无变化）？
4. 涉及规则编号是否全部能在规则版本记录中找到对应行？
5. 是否没有任何一行出现口径对错判定、经营结论或效率承诺？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，14 列，列名与顺序固定：
门店编号, 门店名称, 指标名称, 单位, 涉及规则编号, 规则名称, 生效日期, 旧口径值, 新口径值, 差异额, 差异率, 差异方向, 影响等级, 重跑动作

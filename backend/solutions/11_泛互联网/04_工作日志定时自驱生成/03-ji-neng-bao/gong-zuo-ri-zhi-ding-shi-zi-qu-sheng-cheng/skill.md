# 工作日志定时自驱生成

## 一、这个 Skill 解决什么

工作日志的真实困难不是「不会写」，而是**记录散、口径乱、提交靠自觉**：

- 事项散在当天的沟通、任务、会议里，下班前凭记忆回写，容易漏
- 板块划分各写各的，有人按项目、有人按时间，周报合并时口径对不上
- 遗漏条目要翻聊天记录补，成本远高于当时记一笔
- 忘交日志要靠别人提醒，「记得做」的心智负担一直压在人身上

本 Skill 的核心动作：把碎片流水**自动归集、合并、推导**成结构化日志草稿，并按固定时间定时生成——人只做确认，不做整理。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 每天固定时间要交一份工作记录 | 主用场景：17:30 定时自驱生成日报草稿，无需人工发起 |
| 周报发现板块缺条目 | 用项目归集视角补录对应板块，不重新生成整份周报 |
| 多岗位记录口径不统一 | 按统一模板规范归集，板块结构固定，长期口径一致 |
| 忘交日志需要他人提醒 | 定时触发、无人值守，从流程上消除「忘交」 |

**不适用**：需要原创分析结论的深度复盘（AI 只归集事实，判断由人写）；跨周期的经营分析报表。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `工作记录流水.csv` | 必需 | 记录编号、日期、岗位、姓名、事项、所属项目、完成状态、耗时分钟 |
| 2 | `日志模板规范.md` | 必需 | 板块结构（已完成/进行中/明日计划）、双视角汇总口径、R1-R6 硬性规则、触发时间 |

> 缺 2（模板规范）时，本 Skill **必须拒绝直接生成**——没有口径的汇总等于把碎片换一种方式打碎。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`工作日志生成表.csv`，字段固定为 12 列：

```
视角, 日期, 归集对象, 岗位, 事项条数, 耗时合计分钟,
已完成事项, 进行中事项, 明日计划, 日志口径, 生成方式, 提交状态
```

- `视角` ∈ {按人按日, 项目归集}
- `已完成事项 / 进行中事项` 按流水顺序以「；」合并，无则记「无」
- `明日计划` 只能由当日进行中事项滚动推导，不允许虚构新增
- `提交状态` 固定为「草稿待人工确认」——AI 不代提交

## 五、工作流程（workflow）

### STEP 1 · 读规范，先立口径再看流水

从 `日志模板规范.md` 读入板块结构与双视角口径，写成显式判定表。**顺序不可颠倒**——边看记录边定口径，等于给日志找理由。

### STEP 2 · 按人按日合并

同一人同一天的多条记录合并为一条日志行：事项条数与耗时合计分钟逐条累加，已完成 / 进行中分别归入对应板块。

### STEP 3 · 项目归集（周报板块补录）

同一项目的记录跨人跨日归集为一条：日期记最早日至最迟日，岗位记去重列表。用于周报对应板块补录，**不重新生成整份周报**。

### STEP 4 · 明日计划推导

进行中事项原样滚动为次日「继续推进」项；无进行中事项时记「无进行中事项，按排期接续」。规则 R4：计划里不允许出现流水里不存在的事项。

### STEP 5 · 自检与人工边界声明

输出前逐项自检（见附录），任一不过则不得输出；全表保持「草稿待人工确认」。

## 六、关键规则（不可协商）

1. **AI 不代提交。** 所有输出为草稿，人工确认后才提交；误报的代价由人把关。
2. **明日计划不虚构。** 只能来自当日进行中事项，新增事项必须先登记流水。
3. **状态不擅改。** 已完成 / 进行中只看流水原文，不凭印象改判。
4. **数字必须可复算。** 条数与耗时逐条对应，任何人复算结果一致。
5. **口径纠偏。** 发现「周报 / 日报」混称时，一律按日报口径重算当日记录，再补录周报板块。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责 |
| --- | --- |
| 流水归集与板块划分 | 哪些事项值得记的判断 |
| 条数与耗时合计 | 明日计划合理性的确认 |
| 明日计划滚动推导 | 最终提交与补录的决定 |

## 八、下游衔接

- 项目归集行 → 周报对应板块补录，缺失条目定点补进
- 人日日报归档 → 月度汇总与工时统计


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规范再看流水：把板块结构与双视角口径写成显式判定表，不要边看记录边定口径。
2. 按人按日合并：同一人同一天的多条记录合并为一条日志行，事项条数与耗时合计分钟逐条累加；日期升序、人员按流水首次出现顺序排列。
3. 项目归集：同一项目的记录跨人跨日归集为一条，日期记该项目记录的最早日至最迟日，岗位记涉及岗位去重列表，用于周报板块补录。
4. 明日计划推导：只能由当日进行中事项滚动生成「继续推进」项；无进行中事项时记「无进行中事项，按排期接续」。
5. 输出排序：先输出全部按人按日行，再输出项目归集行（按项目在流水中的首次出现顺序）。

### 硬性约束

【硬性约束】
- 完成状态只认「已完成 / 进行中」两类，不允许凭印象改判。
- 耗时合计与事项条数必须与流水逐条对应，任何人复算都得同一结果。
- 明日计划不允许虚构新增事项，只能来自当日进行中事项。
- 全表提交状态固定「草稿待人工确认」，AI 不代为提交。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 交付物是否 26 行 = 按人按日 20 行 + 项目归集 6 行？
2. 耗时合计总数是否等于流水 25 条耗时之和（本例 1,930 分钟），人日合计与项目合计是否相等？
3. 每个人日行的已完成 / 进行中事项是否与当天流水逐条对应，无遗漏无虚增？
4. 进行中 7 条是否全部出现在对应日志的明日计划中？
5. 是否没有任何一行由 AI 直接标记「已提交」？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，12 列，列名与顺序固定：
视角, 日期, 归集对象, 岗位, 事项条数, 耗时合计分钟, 已完成事项, 进行中事项, 明日计划, 日志口径, 生成方式, 提交状态

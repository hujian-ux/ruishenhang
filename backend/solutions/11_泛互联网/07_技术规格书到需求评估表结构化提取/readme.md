# INT-07 · 技术规格书到需求评估表结构化提取 —— 场景使用说明

- **行业**：泛互联网
- **角色**：售前技术岗（周铭）
- **场景编号**：INT-07
- **案例主体**：某协同办公软件企业（与本场景库 INT-08 / INT-09 同一案例链）

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/技术规格书到需求评估表结构化提取/SKILL.md` | Skill 定义 | 符合度四档口径、风险规则、工作量基准、应答策略与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `技术规格书要点.csv` | 原始输入 | 22 行规格书条目（章节/要求/必选或可选/规格值），7 个章节 |
| `评估表框架.md` | 原始输入 | 符合度四档标准、风险规则、工作量估算基准、应答策略口径 |
| `需求评估表.csv` | **交付物** | 22 行需求评估：符合度 × 实现方式 × 工作量人日 × 风险 × 应答策略 |
| `gen_INT-07.py` | 生成脚本 | 从两份输入按框架规则计算生成交付物，含断言 |
| `售前技术岗-技术规格书到需求评估表结构化提取.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用 |

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `技术规格书要点.csv`、`评估表框架.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 「需定制开发」行移交研发与交付侧做定制可行性确认；评估表作为投标应答逐条核对清单。

## 三、交付物验证记录

生成脚本以 Python 标准库 `csv` 实际写出文件，并在脚本内做断言验证。执行结果：

```
OK  需求评估表.csv  22 data rows
必选 18 / 可选 4
符合度分布：{'完全符合': 11, '基本符合': 5, '需定制开发': 4, '部分符合': 2}
风险分布：{'低': 16, '中': 3, '高': 3}（高风险项：REQ-11/REQ-14/REQ-15）
总工作量 127 人日；高风险项 55 人日，占比 43.3%
ALL INT-07 ASSERTIONS PASSED
```

### 断言项

| 断言 | 结果 |
| --- | --- |
| 输入 22 行、必选 18 / 可选 4 | 通过 |
| 交付物 22 行、10 列固定列名 | 通过 |
| 符合度分布 = 完全符合 11 / 基本符合 5 / 部分符合 2 / 需定制开发 4 | 通过 |
| 风险分布 = 高 3 / 中 3 / 低 16 | 通过 |
| 高风险项 = REQ-11 / REQ-14 / REQ-15 | 通过 |
| 总工作量 = 127 人日；高风险 3 项 = 55 人日（43.3%） | 通过 |
| 复算抽检 REQ-11 = 8×2.5 = 20 / REQ-18 = 3×0.5 = 1.5→2 / REQ-21 = 4×1.5×0.8 = 4.8→5 | 通过 |

### 可复算口径

- `工作量人日 = 章节基础人日 × 符合度系数`（完全符合 .5 / 基本符合 1.0 / 部分符合 1.5 / 需定制开发 2.5）
- 可选需求工作量再 ×0.8，四舍五入取整，最低 1 人日
- `风险等级`：需定制开发且必选 → 高；需定制开发且可选、部分符合 → 中；其余 → 低

## 五、真实性等级与边界

- **T2**：需求评估方法论与符合度判定口径来自售前应标实践。
- **T3**：规格书条目按政企协同办公项目常见技术要求构造，口径可复算。
- **升 T1 还缺**：客户真实规格书与中标/失标复盘记录。
- **人工边界**：产品能力对照事实确认、定制可行性判断、商务报价与投标决策一律人工；评估表不构成报价依据。

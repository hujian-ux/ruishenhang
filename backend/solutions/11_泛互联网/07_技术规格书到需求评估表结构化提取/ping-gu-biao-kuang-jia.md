# 需求评估表框架（政务协同平台投标应标）

本框架由售前技术岗在拆解客户技术规格书前先行确认，定义从「规格书条目」到「需求评估表」的评估口径。先立标准，再逐条评估。

## 一、符合度判定标准（四档）

| 档位 | 判定标准 |
| --- | --- |
| 完全符合 | 产品标准能力开箱即用，无需配置与开发 |
| 基本符合 | 产品能力具备，需在实施阶段配置启用 |
| 部分符合 | 产品能力部分覆盖，需以低代码平台搭建补齐 |
| 需定制开发 | 产品能力不覆盖，需项目定制开发或依赖第三方系统对接 |

## 二、风险等级规则

- **高**：需定制开发 且 必选——直接影响应标应答与交付承诺，须在投标前明确可行性与工作量
- **中**：需定制开发 且 可选；或 部分符合——存在交付不确定性，需预留应对预案
- **低**：基本符合、完全符合

## 三、工作量估算基准

估算工作量 = 章节基础工作量 × 符合度系数；可选需求在结果上按 0.8 折算；四舍五入取整人日，最低 1 人日。

| 章节 | 基础工作量（人日） |
| --- | --- |
| 系统架构 | 6 |
| 公文管理 | 4 |
| 流程审批 | 4 |
| 集成接口 | 8 |
| 安全合规 | 6 |
| 性能要求 | 3 |
| 移动应用 | 4 |

| 符合度 | 系数 |
| --- | --- |
| 完全符合 | 0.5 |
| 基本符合 | 1.0 |
| 部分符合 | 1.5 |
| 需定制开发 | 2.5 |

## 四、应答策略口径

| 符合度 × 必选/可选 | 应答策略 |
| --- | --- |
| 完全符合 / 基本符合（必选或可选） | 正向应答，写明满足方式与配置项 |
| 部分符合（必选或可选） | 正向应答 + 实现路径说明（低代码补齐方式） |
| 需定制开发 且 必选 | 负偏离提示，必须写明补偿措施与工作量 |
| 需定制开发 且 可选 | 可选应答，写明实现建议与工作量 |

## 五、评估依据写法

每行评估依据必须同时包含两部分：

1. 需求定位：`技术规格书要点.csv` 的需求编号与规格值或参数；
2. 命中规则：本框架的符合度档位、风险规则与工作量基准（章节基础人日 × 符合度系数，可选拆八折）。

## 六、硬性要求

1. 必选项逐条应答，不允许合并或省略。
2. 负偏离必须给出补偿措施，禁止空应答。
3. 工作量估算仅覆盖需求条目本身，不含项目管理与联调缓冲。
4. 评估表不构成报价依据，商务报价由商务评审另行确定。

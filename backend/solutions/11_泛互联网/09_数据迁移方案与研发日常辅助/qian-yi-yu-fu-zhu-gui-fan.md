# 迁移与辅助规范（存量系统切换数据迁移）

本规范由研发效能岗在生成迁移方案前先行确认，定义从「数据迁移清单」到「迁移方案与辅助记录表」的判定口径。AI 生成方案初稿与映射初稿，工程师补充项目特有技术细节。

## 一、映射状态判定（三档）

按「字段对齐率 = 可直连字段数 ÷ 源表字段数」判定：

| 档位 | 判定标准 |
| --- | --- |
| 直连映射 | 对齐率 ≥ 90% |
| 转换映射 | 60% ≤ 对齐率 < 90% |
| 重建映射 | 对齐率 < 60% |

## 二、清洗动作分类规则

按清洗规则要求的关键词归类，优先级从高到低：

1. 含「权限 / 挂接」→ 权限重挂
2. 含「去重 / 展开 / 扁平 / 关联」→ 去重与结构归并
3. 含「编码 / 映射 / 编号 / 序列 / 统一」→ 编码归一
4. 含「格式 / 脱敏 / 路径 / 转换」→ 格式标准化
5. 含「补全 / 默认值」→ 补默认值

## 三、迁移策略判定

- 源表为在途业务（源表名或目标平台表名含「在途 / 待办」）→ 双轨并行：新老系统并行至在途实例办结
- 风险提示含「体量大 / 量大」→ 分批增量：按时间切片分批迁移与校验
- 其余 → 停机窗口迁移：割接窗口内一次完成

## 四、研发辅助口径

每张表记录一条 AI 辅助动作，判定优先级从高到低：

1. 风险提示含「需确认 / 需人工确认」→ 文档补全：把待确认项写进迁移说明，供迁移决策会确认
2. 映射状态为重建映射 → 评审清单：生成映射变更评审要点与检查项，工程师确认映射模型后方可执行
3. 映射状态为转换映射 → 映射初稿：生成源表到目标平台的字段映射初稿，工程师复核修订
4. 映射状态为直连映射 → 校验脚本：生成迁移前后行数与字段抽检脚本

## 五、硬性约束

1. 在途流程实例必须连续，双轨期内不得中断任务
2. 审计日志迁移不可篡改，保留原时间戳
3. 重建映射表必须经工程师确认映射模型后方可执行
4. 每批迁移必须留存行数核对记录，差异为零方可放行

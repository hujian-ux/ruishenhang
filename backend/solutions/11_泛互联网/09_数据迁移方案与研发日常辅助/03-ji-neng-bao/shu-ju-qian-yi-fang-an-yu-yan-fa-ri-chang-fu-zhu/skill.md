# 数据迁移方案与研发日常辅助

## 一、这个 Skill 解决什么

存量数据迁移的真实困难，不是「不会写方案」，而是**框架每次从空白文档开始搭**：

- 每个政企客户的源系统都不同，表结构与字段口径无法直接复用
- 18 张表逐张判「直连还是重建」，靠工程师脑中经验，评审没有共同口径
- 在途流程实例、大体量历史表这些特殊表，策略漏判一次就是割接事故
- 开发规范、校验脚本、评审清单这些配套材料分散在多份文档里

本 Skill 的核心动作，是把「迁移清单 + 判定规范」变成一张每表一行、每行可复核的方案表：映射状态有对齐率依据，清洗动作有规则归类，迁移策略有判定路径，AI 辅助动作逐表留痕——框架与图例先成型，工程师只补项目特有的技术细节。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 政企客户从旧系统切换到新平台，需要存量数据迁移方案 | 主用场景：映射状态 + 清洗动作 + 迁移策略 + 辅助记录一体化产出 |
| 迁移清单在手，需要逐表判定直连/转换/重建 | 按「字段对齐率」三档判定，评审有共同口径 |
| 割接方案评审前需要识别特殊表 | 在途业务双轨并行、大体量分批增量，逐表留痕 |
| 研发日常需要 AI 辅助动作留档 | 映射初稿 / 校验脚本 / 评审清单 / 文档补全，逐表对应 |

**不适用**：数据治理主数据标准制定（先于迁移立项）；上线后的数据质量巡检（→ 运维场景）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `数据迁移清单.csv` | 必需 | 表序号、源系统表名、目标平台表名、字段数、清洗规则要求、风险提示 |
| 2 | `迁移与辅助规范.md` | 必需 | 映射状态三档判定（对齐率）、清洗动作关键词分类、迁移策略判定、研发辅助口径 |

> 缺 2（迁移与辅助规范）时，本 Skill **必须拒绝输出**——没有判定规则的迁移方案只是表格搬运，这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`迁移方案与辅助记录表.csv`，字段固定为 11 列：

```
表序号, 源系统表名, 目标平台表名, 字段总数, 可直连字段数, 字段对齐率,
映射状态, 清洗动作, 迁移策略, 研发辅助记录, 风险提示
```

- `映射状态` ∈ {直连映射, 转换映射, 重建映射}
- `字段对齐率` = 可直连字段数 ÷ 字段总数，按三档阈值判定映射状态
- `迁移策略` ∈ {停机窗口迁移, 双轨并行, 分批增量}
- `研发辅助记录` ∈ {映射初稿, 校验脚本, 评审清单, 文档补全}

## 五、工作流程（workflow）

### STEP 1 · 明确约束

读入迁移与辅助规范：三档映射阈值（90% / 60%）、清洗动作关键词优先级、迁移策略判定路径、研发辅助口径——先立规则再过表。

### STEP 2 · 逐表映射判定

对 18 张表逐张计算字段对齐率，判定直连（≥90%）/ 转换（60%-89%）/ 重建（<60%）三档；重建表必须走评审清单，工程师确认映射模型后方可执行。

### STEP 3 · 清洗动作归类

按清洗规则要求的关键词（权限/挂接 → 权限重挂；去重/展开/扁平/关联 → 去重与结构归并；编码/映射/编号/序列/统一 → 编码归一；格式/脱敏/路径/转换 → 格式标准化；补全/默认值 → 补默认值）逐表归类。

### STEP 4 · 迁移策略判定

在途业务表（源表名或目标平台表名含「在途/待办」）→ 双轨并行；风险提示含「体量大/量大」→ 分批增量；其余 → 停机窗口迁移。

### STEP 5 · 研发辅助记录

按判定优先级逐表记录 AI 辅助动作：待确认项 → 文档补全；重建映射 → 评审清单；转换映射 → 映射初稿；直连映射 → 校验脚本。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出。

## 六、关键规则（不可协商）

1. **在途流程实例必须连续。** 在途实例表与待办任务表强制双轨并行，双轨期内不得中断任务。
2. **审计日志不可篡改。** 日志迁移保留原时间戳，分批增量策略下逐批核对。
3. **重建映射必须人工确认。** 映射模型工程师确认前，重建表不得进入执行排期。
4. **每批迁移留存行数核对记录。** 差异为零方可放行，核对记录随方案归档。
5. **AI 只出初稿与留痕。** 映射初稿、校验脚本、评审清单、文档补全均需工程师复核修订，方案可行性由人裁定。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（研发效能岗 / 工程师） |
| --- | --- |
| 对齐率计算与三档映射判定初判 | 重建表映射模型确认 |
| 清洗动作归类与策略判定 | 项目特有技术细节补充 |
| 映射初稿 / 校验脚本 / 评审清单生成 | 每批迁移放行裁决 |
| 待确认项文档化 | 割接窗口与回滚决策 |

## 八、下游衔接

- 交付物「重建映射」行 → 转映射模型评审，工程师确认后进入执行排期
- 交付物「双轨并行」行 → 转割接方案，明确并行窗口与撤轨条件

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读 `迁移与辅助规范.md` 再看清单：确认三档映射阈值（直连 ≥90% / 转换 60%-89% / 重建 <60%）、清洗动作关键词优先级、迁移策略与研发辅助判定路径，不要边写边定规则。
2. 读入 `数据迁移清单.csv` 18 行，确认字段齐全：表序号 / 源系统表名 / 目标平台表名 / 字段数 / 清洗规则要求 / 风险提示。
3. 逐表计算字段对齐率并判定映射状态：直连 7 / 转换 9 / 重建 2（重建表：公文主表 T-05、流程定义表 T-07）。
4. 清洗动作按关键词优先级归类：权限重挂（含权限/挂接）> 去重与结构归并（含去重/展开/扁平/关联）> 编码归一（含编码/映射/编号/序列/统一）> 格式标准化（含格式/脱敏/路径/转换）> 补默认值（含补全/默认值）。
5. 迁移策略判定：在途业务表（源表名或目标平台表名含在途/待办）→ 双轨并行（T-08 流程实例表、T-09 待办任务表）；风险提示含体量大/量大 → 分批增量（T-10 已办历史表、T-18 日志审计表）；其余 14 张 → 停机窗口迁移。
6. 研发辅助按优先级记录：待确认 → 文档补全（T-01、T-02）；重建映射 → 评审清单（T-05、T-07）；转换映射 → 映射初稿（8 张）；直连映射 → 校验脚本（6 张）。

### 硬性约束

【硬性约束】
- 在途流程实例必须连续：在途实例表与待办任务表强制双轨并行，双轨期内不得中断任务。
- 审计日志迁移不可篡改，保留原时间戳。
- 重建映射表必须经工程师确认映射模型后方可执行；输出中重建行必须带评审清单。
- 每批迁移必须留存行数核对记录，差异为零方可放行。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输出是否为 18 行、11 列，列名与顺序固定？
2. 映射状态分布是否为：直连 7 / 转换 9 / 重建 2？重建表是否为 T-05 / T-07？
3. 清洗动作分布是否为：编码归一 6 / 格式标准化 5 / 去重与结构归并 4 / 权限重挂 2 / 补默认值 1？
4. 迁移策略分布是否为：停机窗口 14 / 双轨并行 2（T-08、T-09）/ 分批增量 2（T-10、T-18）？
5. 字段总数是否 = 349、可直连合计是否 = 266（总体对齐率 76.2%）？
自检全过再输出 CSV。

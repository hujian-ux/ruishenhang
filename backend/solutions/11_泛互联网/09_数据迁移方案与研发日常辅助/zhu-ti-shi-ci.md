# INT-09 主提示词 · 数据迁移方案与研发日常辅助

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/数据迁移方案与研发日常辅助/SKILL.md`）。
2. 上传两个附件：`数据迁移清单.csv`、`迁移与辅助规范.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `迁移方案与辅助记录表.csv` 后，按文末「验收清单」逐项核对。

## 主提示词（复制即用）

```
请基于我上传的两份素材，为「某协同办公软件企业 · 政务协同平台存量切换」生成数据迁移方案与研发日常辅助记录，输出一张可评审复核的迁移方案与辅助记录表。

【输入 1 · 数据迁移清单】数据迁移清单.csv（18 行）
- 含表序号、源系统表名、目标平台表名、字段数、清洗规则要求、风险提示
- 18 张表覆盖组织权限、公文、流程、会议、协作空间、消息与审计，字段数合计 349

【输入 2 · 迁移与辅助规范】迁移与辅助规范.md
- 映射状态三档判定（直连 ≥90% / 转换 60%-89% / 重建 <60%）、清洗动作关键词分类
- 迁移策略判定（在途业务双轨并行 / 大表分批增量 / 其余停机窗口）与研发辅助口径

【输出】迁移方案与辅助记录表.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「数据迁移方案与研发日常辅助」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **哪两张表必须重建？为什么？** 期望回答：公文主表（T-05，对齐率 52.2%）与流程定义表（T-07，对齐率 45.5%）——对齐率低于 60% 判重建，必须经工程师确认映射模型后方可执行，评审清单已逐项生成。
2. **在途流程为什么强制双轨并行？** 期望回答：流程实例表（T-08）与待办任务表（T-09）是在途业务，在途实例必须连续，双轨期内不得中断任务——单靠停机窗口切换会中断在途审批。
3. **T-01 和 T-02 的辅助动作为什么是文档补全而不是映射初稿？** 期望回答：风险提示含「需确认 / 需人工确认」（多级部门合并、离职人员是否迁移），按优先级先走文档补全——把待确认项写进迁移说明，供迁移决策会确认后再定辅助类型。
4. **76.2% 的总体对齐率怎么复算？** 期望回答：18 张表可直连字段合计 266 ÷ 字段总数 349 = 76.2%——映射状态三档（直连 7 / 转换 9 / 重建 2）均由逐表对齐率判定。
5. **大表怎么处理？** 期望回答：已办历史表（T-10）与日志审计表（T-18）风险提示含「量大 / 体量大」→ 分批增量，按时间切片分批迁移与校验；审计日志保留原时间戳不可篡改。

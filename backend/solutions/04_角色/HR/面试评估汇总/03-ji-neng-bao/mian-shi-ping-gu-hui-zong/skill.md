# Skill · 面试评估汇总

## 一句话定位

**输入多位面试官对候选人的碎片化反馈（口头/微信/备注），输出维度化对比表 + 三色决策 + 矛盾点标注 + 下一轮建议。**

不是"记录面评"，是把面试官的**主观印象变成可对比、可决策、口径统一**的评估结论——把"手动整理面评 2 小时"压到"5 分钟出汇总"。

---

## 触发条件

当用户表达以下意图时召唤本 Skill：
- "这几个人面试结果帮我汇总一下" / "面评汇总"
- "谁可以发 Offer？" / "这几个候选人怎么样？"
- "帮我把面试官的反馈整理成对比表"
- 关键词：**面试评估、面评、面试汇总、录用建议、候选人对比、三色决策**

---

## 输入契约

| 字段 | 必填 | 说明 |
|---|---|---|
| interviews | ✅ | 多轮面试反馈记录，推荐直接上传《面试评估汇总·原始数据.xlsx》（Sheet1 反馈明细，逐条原文）或《面试面评记录.docx》（按候选人组织） |
| dimensions | 可选 | 评估维度及权重（默认 5 维度：专业深度 35% / 行业经验 25% / 量产质量 20% / 沟通协作 10% / 稳定性 10%） |
| thresholds | 可选 | 三色决策阈值（默认 🟢≥80 / 🟡60-79 / 🔴<60） |
| context | 可选 | 岗位画像（用于权重调整，如销售岗更看重沟通） |

---

## 执行步骤（内部流程）

1. **解析反馈**：将面试官的每条碎片反馈（口头/微信/备注）提取为"候选人 + 维度 + 评价内容 + 倾向（正面/负面）"结构
2. **维度映射与评分**：将评价映射到 5 个评估维度，每个维度 **0-100 分**（百分制，与页面案例输出口径一致）；某维度无评价 → 标记"需补充"
3. **加权求和**：维度分 × 权重，得到每位候选人总分（保留整数）
4. **三色决策**（总分阈值 + 风险复核双重判定）：
   - 🟢 **总分 ≥ 80**：强烈推荐，直接推进 Offer
   - 🟡 **总分 60-79**：保留，需加试或补充材料后评议
   - 🔴 **总分 < 60**：不推荐，终止流程
   - **降级复核**：总分 ≥ 80 但存在显著风险或未决矛盾（到岗 > 6 周 / 技术方向冲突 / 职级定位分歧等）→ 降为 🟡 待定，先解决问题再定（示例：王海 83 分因到岗 2 个月标 🟡）
   - **边界通过**：总分 ≥ 80 且风险可控，但某项关键指标未完全验证（如安规细节）→ 标 🟢 边界通过，附补测条件（示例：李敏 82 分进二面补测安规）
5. **矛盾点标注**（3 类，均需 HR 跟进确认，不隐藏）：
   - 同维度不同面试官评分差距 > 15 分（百分制）→ 标注分数矛盾
   - 评价方向冲突：同一候选人某维度被不同面试官一正面一负面评价（如"信号完整性强" vs "功率电子弱"）→ 标注技术方向侧重矛盾
   - 结论性分歧：面试官对职级/定位/风险判断不一致（如"达不到高级" vs "愿意培养"）→ 标注定位分歧
6. **下一轮建议 + 录用排序**：🟢 候选人列最终确认项并按总分降序；🟡 候选人列加试方向

**特殊规则**：
- 某维度完全没有评价 → 标"需补充"，不得默认给分
- 一票否决项（造假 / 严重诚信问题）→ 直接 🔴，跳过评分

## 输出格式说明（Excel 交付）

**对话内默认输出**：Markdown 表格/结构化结果，直接在对话中展示。

**交付 Excel**：当用户需要 .xlsx 文件（对应 demo 中的参考输出）时，用 Python openpyxl 生成：
- 文件名：`面试评估汇总·交付物.xlsx`
- Sheet「维度评分」：候选人/专业深度(35%)/行业经验(25%)/量产质量(20%)/沟通协作(10%)/稳定性(10%)/加权总分/三色决策/矛盾点（4 位候选人逐行，结果与页面案例一致：赵立军 90 通过 / 王海 83 待定 / 李敏 82 边界通过 / 孙悦 67 待定）
- Sheet「三色决策」：候选人/加权总分/决策/说明（🟢≥80 推进 / 🟡60-79 加试 / 🔴<60 终止）
- Sheet「矛盾点标注」：候选人/矛盾点/各面试官评价对比/Skill 建议
- Sheet「下一轮建议」：候选人/决策/下一步行动/责任人
- 生成方式：调用 `openpyxl` 创建工作簿 → 写入表头与数据行 → 保存到输出目录 → 在回复中告知文件路径（参考 `` 中的同名样例）

**输入格式**：直接上传《面试评估汇总·原始数据.xlsx》（openpyxl/read_file 读取 Sheet1 反馈明细逐条解析）或《面试面评记录.docx》（python-docx 解析按候选人分节的面评）；也支持直接粘贴反馈文字。


---

## 依赖工具（底层 MCP / 能力）

- `read_file` / 附件解析（Excel 面评明细 → openpyxl 读取 Sheet；Word 面评记录 → python-docx 解析段落）
- `parse_feedback`（碎片反馈 → 候选人+维度+评价结构）
- `weighted_score`（维度加权评分）
- 前置：可接 `简历筛选排序` Skill（筛选 → 面试评估的链路）

## 适用场景清单

| 岗位 | 场景 | 复用点 |
|---|---|---|
| **招聘 TA** | 多轮面试评估汇总 | 主用（本包场景） |
| **招聘 TA** | 定薪前候选人对标 | 维度分 + 决策辅助 Offer 定薪 |
| **HRBP** | 晋升 / 转正评估 | 同一套维度评分 + 三色决策 |
| **管理者** | 团队内部选拔 | 多源评价汇总成对比表 |

**至少 3-4 个场景可复用同一 Skill**——面试评估是招聘闭环里承上启下的关键环节。

---

## 一句话结论

**面试评估汇总 = 招聘决策的"汇总大脑"**。面试官的信息是碎片化的（口头、微信、备注各说各话），本 Skill 把它变成统一的维度分 + 三色结论 + 矛盾标注，让"谁发 Offer、谁加试、谁淘汰"一眼可见，且每次评估口径一致、可追溯。

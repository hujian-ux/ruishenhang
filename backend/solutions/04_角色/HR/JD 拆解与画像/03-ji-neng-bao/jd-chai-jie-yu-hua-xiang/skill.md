# Skill · JD 拆解与岗位画像

## 一句话定位

**输入业务部门的一段模糊用人需求（"要个做板子的 / 带项目的 / 跑渠道的"），输出结构化岗位画像（硬性条件 / 软性加分 / 红线）+ 完整 JD + 渠道建议**

不是"帮业务写 JD"，是把业务的**一句需求翻译成一套招聘标准**——业务只负责说，AI 负责把"感觉"变成"可执行的筛选条件"。

---

## 触发条件

当用户表达以下意图时召唤本 Skill：
- "帮我写份 JD" / "这个岗位要求怎么定"
- "业务说要招个人，帮我理一下画像"
- "这段需求帮我拆成岗位要求"
- 关键词：**JD、岗位画像、职位描述、用人需求、招聘要求、HC**

---

## 输入契约

| 字段 | 必填 | 说明 |
|---|---|---|
| raw_requirement | ✅ | 业务部门原始需求描述（一段/多段文本，越模糊越体现本 Skill 价值） |
| context | 推荐 | 行业/公司类型/团队规模（用于补全画像常识） |
| budget_hint | 可选 | 薪资预算范围（用于定职级与红线） |

---

## 执行步骤（内部流程）

1. **解析需求**：提取关键信息（岗位方向 / 经验等级 / 技术栈 / 管理是否需要 / 紧急程度 / 到岗时间 / 预算）
2. **补全常识**：根据行业背景补全"没说但默认需要"的通用条件（如工控默认需要画板工具、互联网前端默认需要框架经验）
3. **硬性三关定义**：学历 / 经验年限 / 必要技能 → 可与后续「简历筛选排序」Skill 直接衔接
4. **软性加分项**：行业经验 / 工具链 / 证书 / 跨部门能力
5. **红线设定**：薪资天花板 / 跳槽频率 / 到岗期限 / 是否接受破格（供后续筛选 Skill 用）
6. **渠道建议**：根据岗位稀缺度 + 紧急程度 + 预算，推荐社招 / 猎头 / 内推 / 校招组合
7. **风险标注**：需求模糊点需二次确认（如"能带人"是带几个人？项目管理还是人员管理？）
8. **输出**：结构化画像 + 可发布 JD + 渠道建议 + 待确认清单

## 输出格式说明（Excel 交付）

**对话内默认输出**：Markdown 表格/结构化结果，直接在对话中展示。

**交付 Excel**：当用户需要 .xlsx 文件（对应 demo 中的参考输出）时，用 Python openpyxl 生成：
- 文件名：`JD 拆解与画像·交付物.xlsx`
- Sheet「JD拆解结果」：需求ID / 原始需求 / 关键词 / 岗位名称 / 硬性条件 / 加分项 / 红线 / 建议渠道 / 风险提示（每段需求一行）
- 生成方式：调用 `openpyxl` 创建工作簿 → 写入表头与数据行 → 保存到输出目录 → 在回复中告知文件路径（可参考 `` 下的同名样例文件）

**输入格式**：模糊需求文本（MD / 粘贴文字），无需转换。

## 依赖工具（底层 MCP / 能力）

- `parse_requirement`（需求字段抽取）
- `fill_domain_knowledge`（行业常识补全）
- `suggest_red_lines`（红线设定建议）
- 后置：产出直接喂给「简历筛选排序」Skill 的 jd 字段

## 适用场景清单

| 岗位 | 场景 | 复用点 |
|---|---|---|
| **招聘 TA** | JD 需求拆解 | 主用（本包场景一） |
| **招聘 TA** | 新岗位画像定义 | 每个新 HC 先跑一遍 |
| **HRBP** | 业务提招聘需求 | HRBP 收到需求后先用本 Skill 拆解再转 TA |
| **销售** | 报价评审中的用人成本 | 快速拿到岗位画像和预算建议 |

**至少 4 个场景可复用同一 Skill**。

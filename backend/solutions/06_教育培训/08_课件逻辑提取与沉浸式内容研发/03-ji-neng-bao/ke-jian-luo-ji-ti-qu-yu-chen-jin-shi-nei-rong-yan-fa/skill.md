# 课件逻辑提取与沉浸式内容研发

## 一、这个 Skill 解决什么

课件研发的真实困难不是「不会做课件」，而是**优秀课件的逻辑锁在制作者脑子里，新课件每次从零设计**：

- 精品课件的环节编排、练习分层、总结手法只有作者本人说得清
- 新知识点的课件从空白页开始做，结构一致性全凭个人经验
- 低龄段改写耗时：同一套逻辑改成小学生能懂的剧情，要反复磨
- 研发出的内容与知识点体系脱节，练习配比与考情结论（→ EDU-01）对不上

本 Skill 的核心动作，是把课件逻辑**显式化为可迁移的骨架**：四环节拆解 → 可复用元素沉淀 → 四类沉浸式改造套模板 → 对齐知识点体系排出优先级。新课件研发 = 逻辑复用 + 内容改写。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 拿到一批优秀课件，要把制作逻辑沉淀下来 | 主用场景：逐页精读 → 四环节骨架 |
| 新知识点要快速产出结构一致的新课件 | 按同一逻辑套用，不从零设计 |
| 低龄段 / 剧情化 / 游戏化内容改写 | 四类沉浸式改造模板 + 学段适配规则 |
| 排产：决定先做哪批课件 | P1/P2/P3 优先级规则 |

**不适用**：考情研究与占比统计（→ EDU-01 试卷知识点分析）；期次经营复盘（→ EDU-02）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `优秀课件样本清单.csv` | 必需 | 课件编号、课件名称、学科年级、教学环节结构、核心亮点、可复用元素、拟改造方向、情境素材 |
| 2 | `课件逻辑框架.md` | 必需 | 四环节拆解规则、四类沉浸式改造规范与模板、研发优先级规则、课件与知识点对齐表 |

> 缺 2（框架文件）时，本 Skill **必须拒绝输出对齐知识点与优先级**——知识点条目与优先级规则只允许来自显式对齐表，不允许自行编造。

## 四、输出（outputs）

唯一交付物：`课件逻辑与内容研发计划表.csv`，字段固定为 9 列、12 行（每份课件一行）：

```
课件编号, 课件名称, 学科年级, 提取的教学骨架, 可复用元素, 沉浸式改造点, 改造类型, 对齐知识点, 研发优先级
```

- `提取的教学骨架` 格式为「导入·手法 → 讲解·手法 → 练习·手法 → 总结·手法」，四环节必须齐备
- `改造类型` ∈ {互动剧情, 情境化练习, 游戏化交互, 讲解层动画}，改造点必须引用清单中的情境素材与可复用元素
- `对齐知识点` 只允许来自框架文件的对齐表
- `研发优先级` ∈ {P1（首批研发）, P2（次批研发）, P3（观察池）}

## 五、工作流程（workflow）

### STEP 1 · 先读框架再拆课件

把四环节拆解规则、改造类型定义、优先级规则写成显式判定表。**顺序不可颠倒**——先看课件再定规则，等于给结构找理由。

### STEP 2 · 逐份提取教学骨架

「教学环节结构」按「-」拆分，每段按末二字映射（导入→导入；讲解/演示→讲解；练习→练习；总结→总结），归一为「环节·手法」骨架；四环节缺一即停下说明，不允许自行补环节。

### STEP 3 · 沉浸式改造点生成

按类型套模板：互动剧情 = 情境素材为剧情主线的角色扮演任务；情境化练习 = 练习层整体迁移到情境素材；游戏化交互 = 围绕情境素材搭建可操作组件；讲解层动画 = 讲解层嵌入情境动画与即时提问。每条改造点必须绑定可复用元素。

### STEP 4 · 对齐知识点体系

逐份从框架文件的对齐表取数（如 CW-08 → 数与代数·函数及其图象），保证练习配比与考情结论衔接（函数及其图象占 20.0% 分值 → 相关课件优先排产）。

### STEP 5 · 优先级判定与排产

小学学段或互动剧情 → P1（直接复用既有框架，最快形成供给）；初中学段的情境化练习与游戏化交互 → P2（需补情境素材或做组件验证）；讲解层动画 → P3（随批次迭代）。

### STEP 6 · 自检与边界声明

输出前逐项自检，任一不过则不得输出：

1. 12 行一行不落，每行骨架四环节齐备（12 × 4 = 48 个环节）？
2. 改造类型分布 = 互动剧情 4 / 情境化练习 3 / 游戏化交互 4 / 讲解层动画 1？
3. 研发优先级分布 = P1 6 / P2 5 / P3 1，小学学段全部 P1？
4. 每条改造点是否都引用了清单中的情境素材？
5. 对齐知识点是否全部来自框架文件的对齐表？

## 六、关键规则（不可协商）

1. **四环节缺一即停。** 骨架不齐备的课件不允许自行补环节，必须回退说明。
2. **改造必须绑定可复用元素。** 凭空新增的情境、素材、组件一律不允许出现在改造点里。
3. **对齐知识点只认对齐表。** 知识点条目不允许编造，与考情体系（EDU-01）的衔接靠对齐表保证。
4. **学段适配是硬规则。** 小学学段改造必须生活化：情境取材于家庭与校园生活，任务指令句长不超过 15 字。
5. **优先级只认规则。** P1/P2/P3 由学段与改造类型决定，不允许按个人偏好调序。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（简溪 / 内容研发负责人） |
| --- | --- |
| 四环节骨架提取与归一 | 优秀课件的遴选与定级 |
| 改造点模板化生成 | 剧情脚本与互动组件的最终定稿 |
| 知识点对齐与优先级排产 | 排产顺序的业务确认 |

## 八、下游衔接

- 知识点占比结论（函数 20.0% 居首）← **EDU-01 中高考考情与试卷知识点分析**
- P1 批次研发计划 → 下一期次课件排产（与 EDU-02 期次经营节奏对齐）
- 沉淀的骨架库与可复用元素 → 新知识点课件的起手模板

### 执行要求

【执行要求】
1. 先读框架再拆课件：把四环节拆解规则、改造类型定义、优先级规则写成显式判定表。
2. 逐份提取教学骨架：把「教学环节结构」按规则归一为「导入·手法 → 讲解·手法 → 练习·手法 → 总结·手法」，四环节缺一即停下说明，不允许自行补环节。
3. 沉浸式改造点按类型模板生成：互动剧情 = 以情境素材为剧情主线的角色扮演任务；情境化练习 = 练习层整体迁移到情境素材；游戏化交互 = 围绕情境素材搭建可操作互动组件；讲解层动画 = 讲解层嵌入情境素材动画并配套即时提问。
4. 对齐知识点：逐份从框架文件的对齐表取数，不允许自行编造知识点条目。
5. 优先级判定：小学学段或互动剧情 → P1；初中学段的情境化练习与游戏化交互 → P2；讲解层动画 → P3。
6. 小学学段的改造必须执行生活化改写：情境取材于家庭与校园生活，任务指令句长不超过 15 字。

### 硬性约束

【硬性约束】
- 12 份课件一行不落，48 个教学环节全部归入标准骨架。
- 每条沉浸式改造点必须绑定清单中的情境素材与可复用元素，不允许凭空新增。
- 对齐知识点只允许来自框架文件的对齐表。
- 不写任何效率百分比或效果承诺。

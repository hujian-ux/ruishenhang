# 产品能力矩阵与规格对照底稿

## 一、这个 Skill 解决什么

多产品线选型的真实困难不是「没有资料」，而是**规格散落在多处、口径不统一**：

- 规格书按产品写，不告诉你它在某个场景到底强不强
- 官网产品页讲卖点，字段与友商对不齐
- 售前每次做方案，都在多个页面之间重新比对一遍
- 高层要简版、交付要详版，每次都手工重排

结果是：对照底稿「更新一次等于重做一次」，选型判断依赖个人经验。本 Skill 的核心动作，是把产品与规格数据按**场景 × 产品**构建成矩阵，能力等级、规格对照与选型建议全部按统一规则计算，任何人都能复算。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 售前做方案，需要按场景选产品组合 | 主用场景：矩阵定位 + 选型建议 |
| 产品大版本发布，需要重估能力等级 | 按更新机制重估该产品全部场景行 |
| EDU-04 趋势洞察出现 S 级趋势 | 把趋势纳入需求基线后重估受影响场景 |
| 高层汇报需要能力对照简版 | 一份底稿按口径裁剪，不重做 |

**不适用**：竞品方案的对外调研（→ EDU-04 技术趋势洞察与竞品方案调研）；现网故障与质量分析（→ EDU-06）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `产品能力与规格数据.csv` | 必需 | 记录编号、产品线、产品型号、适用场景、场景需求基线、关键规格、规格达标项数、代际领先项数、能力等级、软件版本、规格信源 |
| 2 | `矩阵构建规则.md` | 必需 | L1-L5 能力分级定义、场景需求基线（5 场景 × 3 项）、选型建议规则、规格对照口径、矩阵更新机制 |

> 缺规格信源或软件版本列时，本 Skill **必须拒绝输出矩阵**，只能退回补录——无法追溯版本的规格数据没有维护价值。

## 四、输出（outputs）

唯一交付物：`产品能力矩阵与对照底稿.csv`，字段固定为 10 列：

```
产品线, 产品型号, 适用场景, 能力等级, 矩阵定位, 规格对照, 关键规格, 规格达标项数, 软件版本, 选型建议
```

- `能力等级` ∈ {L1, L2, L3, L4, L5}
- `矩阵定位` = L4 及以上 → 优势组合；L3 → 适配可选；L2 及以下 → 不建议
- `规格对照` = 「X/3 项达标，其中 Y 项代际领先」格式，与达标/领先两列一致
- `选型建议` 按等级映射固定口径，禁止逐行自由发挥

## 五、工作流程（workflow）

### STEP 1 · 读规则，先立口径再看数据

从 `矩阵构建规则.md` 读入 L1-L5 分级定义、5 场景需求基线与选型建议规则。**顺序不可颠倒**——先看产品再定标准，等于给自家产品找理由。

### STEP 2 · 数据完备性检查

逐行核对 30 行产品数据：场景基线三项是否齐备、规格达标/领先项数与能力等级是否自洽、软件版本与规格信源是否可追溯。

### STEP 3 · 场景 × 产品矩阵构建

按「一行 = 一个产品在一个场景」构建 30 行矩阵，能力等级取自输入，不做二次改动；同一产品在不同场景等级不同，禁止「产品高级 = 全场景高分」平推。

### STEP 4 · 规格对照与定位判定

每行生成规格对照结论（X/3 项达标 + 代际领先项），并按等级映射矩阵定位（优势组合 / 适配可选 / 不建议）。

### STEP 5 · 选型建议与分布核账

按等级映射输出选型建议口径；汇总分布（优势 13 / 可选 11 / 不建议 6）与规格总账（90 项中达标 82、领先 17），供汇报引用。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出：

1. 矩阵行数是否 = 产品数 × 场景数（6 × 5 = 30）？
2. 能力等级分布与定位分布是否能从输入复算？
3. 是否没有出现「报价」「承诺」类表述？
4. L2 及以下行是否都给出了替代方向（改高配 / 换专用方案）？

## 六、关键规则（不可协商）

1. **AI 不做最终选型决策。** 矩阵定位是口径化建议，具体项目选型由解决方案岗与客户共同确认；输出不构成报价与承诺依据。
2. **等级与定位必须可复算。** L1-L5 映射关系写死在规则里，「优势 / 可选 / 不建议」由等级推导，不允许逐行自由裁量。
3. **场景基线不可为产品定制。** 基线一旦为某个产品放松，整个矩阵失去横向比较意义；改基线必须走版本化更新并全量重跑。
4. **代际领先要给依据。** 领先项必须能指向具体规格字段（如 Wi-Fi 7 相对 Wi-Fi 6），且与 EDU-04 的趋势定级互相印证。
5. **更新机制必须执行。** 版本变更、S 级趋势、竞品发布三类触发必须重估，禁止「底稿常年不动」。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（解决方案岗 / 客户） |
| --- | --- |
| 矩阵构建、等级映射与定位判定 | 具体项目的最终选型确认 |
| 规格对照结论与分布总账 | 需求基线的版本化调整决策 |
| 简版/详版裁剪与更新触发提示 | 报价与对外承诺 |

## 八、下游衔接

- 上游 **EDU-04 技术趋势洞察与竞品方案调研**：S 级趋势纳入需求基线后重估矩阵
- 矩阵中「不建议」组合 → 方案设计时改用组合方案或专用方案，缺口反馈产品部
- 质量维度（现网故障分布）→ **EDU-06 测试方案故障分析与质量月报** 交叉验证产品稳定性


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规则再看数据：把 L1-L5 分级、场景基线与选型建议规则写成显式判定表，不要先看产品再定标准。
2. 数据完备性检查：30 行逐行核对场景基线三项、达标/领先项数与能力等级是否自洽，软件版本与规格信源是否可追溯。
3. 矩阵构建：按「一行 = 一个产品在一个场景」输出 30 行矩阵；能力等级取自输入不改动，同一产品在不同场景等级不同，禁止「产品高级 = 全场景高分」平推。
4. 规格对照与定位：每行生成「X/3 项达标，其中 Y 项代际领先」的对照结论，并按等级映射矩阵定位（优势组合 / 适配可选 / 不建议）。
5. 选型建议与分布核账：按等级映射输出选型建议；汇总能力等级分布、定位分布与规格总账（90 项基线中达标与领先数），供汇报引用。
6. 更新提示：结合规则中的更新机制，标出哪些行会在「版本变更 / S 级趋势 / 竞品发布」触发时需要重估。

### 硬性约束

【硬性约束】
- 不出现「报价」「承诺」「中标」类表述——最终选型由解决方案岗与客户共同确认，AI 只出矩阵定位与选型建议口径。
- 能力等级、矩阵定位、规格对照三者必须一致，不允许出现「等级 L2 却写可选」这类矛盾行。
- 场景需求基线不可为任何产品定制或放松，改基线必须走版本化更新。
- 每行的规格对照必须能指回输入的达标/领先两列，可复算。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 矩阵行数是否 = 6 产品 × 5 场景 = 30？
2. 能力等级分布是否为 L5 4 / L4 9 / L3 11 / L2 4 / L1 2？
3. 定位分布是否为优势组合 13 / 适配可选 11 / 不建议 6？
4. 规格总账是否为 90 项基线中达标 82 项、代际领先 17 项？
5. 是否没有任何一行出现报价承诺类表述？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，10 列，列名与顺序固定，30 行：
产品线, 产品型号, 适用场景, 能力等级, 矩阵定位, 规格对照, 关键规格, 规格达标项数, 软件版本, 选型建议

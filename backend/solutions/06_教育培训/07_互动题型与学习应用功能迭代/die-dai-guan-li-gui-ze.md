# 迭代管理规则 · 互动题型与学习应用功能迭代（某教育培训集团 · 产品功能岗）

> 本规则是「互动题型与学习应用功能迭代」场景的判定依据：优先级怎么评分、版本怎么分配、验收怎么写，全部以本文件为准。

## 一、优先级评分公式

```
优先级评分 = 影响分 × 0.5 + 类型分 × 0.3 + 模块分 × 0.2（保留 2 位小数）
```

| 维度 | 权重 | 分档规则 |
| --- | --- | --- |
| 影响分 | 0.5 | 按影响用户数分档：≥5000→5；≥3000→4；≥1500→3；≥800→2；≥300→1；<300→0 |
| 类型分 | 0.3 | 缺陷 5；功能需求 4；用户反馈 3 |
| 模块分 | 0.2 | 拖拽排序 5；连线匹配 5；情景选择 4；发音跟读 4；学习报告 3 |

设计逻辑：影响面占一半权重（覆盖多少学习者决定紧迫度）；缺陷优先于功能需求、功能需求优先于体验反馈（体验受损必须先修）；核心互动题型模块（拖拽/连线）分值高于支撑模块（学习报告）。

## 二、版本节奏规则

学习应用保持双周一个迭代版本。版本分配按评分分档：

| 优先级评分 | 目标版本 | 说明 |
| --- | --- | --- |
| ≥ 3.5 | v2.4（下一版本） | 两周内发布 |
| 2.5 – 3.5（不含） | v2.5 | 下一迭代排期 |
| < 2.5 且类型 = 缺陷 | v2.6 | 缺陷不暂缓，低优先级修复 |
| < 2.5 且类型 ≠ 缺陷 | 暂缓 | 不排期，季度末随新数据重评 |

**缺陷特例**：体验受损的问题不允许「暂缓」，评分再低也进 v2.6 排期——这是学习应用对低龄用户的产品底线。

## 三、改动范围与回归规则

1. **范围限定**：每项需求的改动只作用于指定题型组件（模块列），避免影响其他交互模块。
2. **同类回归**：涉及动画时序、音频触发、判定逻辑的改动，必须在同类题型上回归确认表现一致。
3. **验收要点**：每项进入版本的需求必须写明可回归的验收要点，无验收要点的项不得排期。

## 四、输出口径

- 交付物行数 = 需求清单行数（20 行），逐项给出评分、目标版本与验收要点。
- 「X 项进入下一版本」= 目标版本为 v2.4 的项数。
- 评分与分档必须可复算：影响分/类型分/模块分三列保留在交付物中，任何人可按公式验算。
- 暂缓项不等于拒绝，季度末按最新影响用户数重评。

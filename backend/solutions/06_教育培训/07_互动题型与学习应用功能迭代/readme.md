- **案例主体**：某教育培训集团（本场景库 EDU-07 / EDU-08 / EDU-09 同一案例链）

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `功能需求与反馈清单.csv`、`迭代管理规则.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. v2.4 的 7 项进迭代排期并同步研发；暂缓 4 项登记重评条件，季度末按最新影响用户数重算。

### 可复算口径

- `影响分`：≥5000→5；≥3000→4；≥1500→3；≥800→2；≥300→1；<300→0
- `类型分`：缺陷 5；功能需求 4；用户反馈 3
- `模块分`：拖拽排序 5；连线匹配 5；情景选择 4；发音跟读 4；学习报告 3
- `优先级评分` = 影响分×0.5 + 类型分×0.3 + 模块分×0.2（保留 2 位小数），三列分值保留在交付物中
- `目标版本`：≥3.5 → v2.4；2.5–3.5（不含）→ v2.5；<2.5 且缺陷 → v2.6；<2.5 且非缺陷 → 暂缓
- 「7 项进入下一版本」= 目标版本列为 v2.4 的行数

## 五、真实性等级与边界

- **方法论来源**：需求结构化 + 范围限定 + 同类回归的迭代链路来自企业应用案例素材。
- **构造**：20 项需求、影响用户数与评分分档为构造数据，口径全部可复算。
- **人工边界**：新题型模块立项论证、版本容量超限取舍、技术方案评估、紧急发布决定一律人工；AI 只做评分计算、版本分配与验收要点绑定。

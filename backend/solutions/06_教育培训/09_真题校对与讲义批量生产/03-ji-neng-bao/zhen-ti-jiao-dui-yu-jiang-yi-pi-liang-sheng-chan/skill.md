# 真题校对与讲义批量生产

## 一、这个 Skill 解决什么

教学内容的正式发布卡在两件事上：

- **校对靠人眼**：真题录入后，题干是否与原卷一致、选项有没有错位、答案和解析是否互相矛盾，过去全靠人工逐字比对，覆盖范围有限，错误常常带进讲义；
- **讲义靠手工**：按单元产讲义要在多个文档间复制粘贴，格式风格容易漂移，校对完的修订也不会自动同步到讲义。

本 Skill 的核心动作：**机器前置校对（只标记、按权威参照纠正）+ 模板化归章编排 + 人工终审**，校对结论直接驱动讲义生产，两条线合成一张进度表。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 新一批真题录入完成，入库前需全量校对 | 主用场景：四要素一致性核对 |
| 按新学期单元批量生产讲义 / 练习册 | 校对通过的题按模板归章编排 |
| 上线后收到勘误反馈，需回溯错题 | 按错误类型定位、修订并留痕 |
| 讲义修订版需与最新校对状态同步 | 以进度表为准重新编排 |

**不适用**：全新知识点的原创讲义撰写（无真题底稿时本 Skill 不产生内容）；试卷排版印刷（→ 出版流程）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `真题校对任务清单.csv` | 必需 | 题目编号、科目、题型、题目简称、知识点模块、录入状态、校对要点、发现错误类型 |
| 2 | `讲义生产规范.md` | 必需 | 四要素一致性规则、错误分类与处理规则、讲义结构与归章规则、进度表口径 |

> 缺 2（讲义生产规范）时，本 Skill 只能输出校对结论，**不得自行编排讲义章节**——归章规则必须来自规范文件，不允许临场发明。

## 四、输出（outputs）

唯一交付物：`校对与讲义生产进度表.csv`，字段固定为 9 列：

```
题目编号, 科目, 题型, 题目简称, 校对结论, 错误类型, 错误处理, 归入讲义章节, 讲义动作
```

- `校对结论` ∈ {通过, 修正后通过, 待教师裁定}
- `错误处理` 必须写明处理依据（按原卷扫描件 / 按官方答案 / 移交教师），不允许写「已处理」了事
- `归入讲义章节` 命名为 `<科目>·<知识点模块>`
- `讲义动作` ∈ {例题精讲, 课堂练习, 课后练习, 裁定后编排}

## 五、工作流程（workflow）

### STEP 1 · 读规范，先立规则再校对

从 `讲义生产规范.md` 读入四要素一致性规则与错误分类规则，写成显式判定表。顺序不可颠倒——先看题再定标准，等于给结论找理由。

### STEP 2 · 全量四要素校对

对任务清单中每道题逐项核对：题干对原卷扫描件、选项对原卷、答案对官方答案、解析结论对答案。发现差异**先标记类型，不自行改写**。

### STEP 3 · 错误分类处理

| 错误类型 | 处理 |
| --- | --- |
| 题干识别错误 / 选项错位 / 答案录入笔误 | 有唯一权威参照 → 按参照纠正，结论记「修正后通过」 |
| 解析与答案矛盾 | 无唯一权威参照 → 移交学科教师裁定，结论记「待教师裁定」，讲义动作记「裁定后编排」 |

> 机器只做有权威参照的纠正。解析与答案冲突时无法判定哪一侧出错，AI 不得替教师改答案。

### STEP 4 · 归章与讲义编排

按 `<科目>·<知识点模块>` 归章；章内按题目编号顺序编排：第一道校对通过的题作「例题精讲」（配考点讲解），第二道作「课堂练习」，其余作「课后练习」；待裁定题暂缓编排。

### STEP 5 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出：

1. 进度表行数 = 任务清单行数（全量覆盖）？
2. 「修正后通过」行数 = 题干识别错误 + 选项错位 + 答案录入笔误的题数？
3. 每个讲义章节是否恰好 1 道「例题精讲」？
4. 「待教师裁定」的题是否全部标注「裁定后编排」且未进入讲义正文？
5. 每行错误处理是否写明处理依据？

## 六、关键规则（不可协商）

1. **AI 不改答案。** 解析与答案矛盾时只能标记移交，改答案、改解析的最终决定属于学科教师。
2. **纠正必须有权威参照。** 原卷扫描件与官方答案是仅有的两个参照源；没有参照的差异只标记不修改。
3. **校对与生产同链路。** 交付物必须同时给出校对结论与讲义编排结果，不允许只交一半。
4. **全量覆盖。** 任务清单里每一道题都必须出现在进度表中，不允许抽样。
5. **淘汰/暂缓要留痕。** 待裁定题写明裁定后去向，不允许静默丢弃。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（学科教师 / 教研主管） |
| --- | --- |
| 四要素逐项比对与差异标记 | 解析与答案矛盾的最终裁定 |
| 按权威参照的自动纠正与留痕 | 例题精讲的讲解口径审订 |
| 归章与讲义动作编排 | 讲义定稿签发 |
| 校对与生产进度表汇总 | 勘误对外发布的决定 |


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规范再校对：把错误分类与归章规则写成显式判定表，不要先看题再定标准。
2. 全量校对 25 题，每题给出校对结论：
   · 无错误 → 通过
   · 题干识别错误 / 选项错位 / 答案录入笔误 → 修正后通过，错误处理写明权威参照（按原卷扫描件纠正 / 按原卷重排选项 / 按官方答案修订）
   · 解析与答案矛盾 → 待教师裁定，移交学科教师核对原卷答案后定稿，机器不得自行改写
3. 归章：按「科目·知识点模块」命名章节（如「数学·函数与导数」）。
4. 讲义动作编排：章内按题目编号顺序，第一道校对通过的题作「例题精讲」（配考点讲解），第二道作「课堂练习」，其余作「课后练习」；「待教师裁定」的题标注「裁定后编排」，不得进入讲义正文。
5. 校对结论与讲义编排必须同表输出，不允许只交校对不编排。

### 硬性约束

【硬性约束】
- AI 不改答案：解析与答案矛盾只能标记移交，改答案/改解析的最终决定属于学科教师。
- 纠正必须有权威参照（原卷扫描件 / 官方答案），错误处理不允许只写「已处理」。
- 全量覆盖：进度表行数必须等于任务清单行数（25 行），不允许抽样。
- 待裁定题不得编入讲义正文，必须标注「裁定后编排」。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 进度表是否 25 行，与任务清单逐题对应？
2. 「修正后通过」是否 = 题干识别错误 4 + 选项错位 3 + 答案录入笔误 2 = 9 处？
3. 「待教师裁定」是否 = 解析与答案矛盾 2 处，且均标注「裁定后编排」？
4. 8 个讲义章节是否每章恰好 1 道「例题精讲」？
5. 每行错误处理是否写明处理依据（原卷扫描件 / 官方答案 / 移交教师）？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，9 列，列名与顺序固定：
题目编号, 科目, 题型, 题目简称, 校对结论, 错误类型, 错误处理, 归入讲义章节, 讲义动作

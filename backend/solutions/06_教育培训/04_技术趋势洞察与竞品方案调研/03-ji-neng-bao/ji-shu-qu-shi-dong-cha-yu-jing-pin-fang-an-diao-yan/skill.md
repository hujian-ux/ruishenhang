# 技术趋势洞察与竞品方案调研

## 一、这个 Skill 解决什么

竞品调研的真实困难不是「找不到信息」，而是**答案被切成碎片放在四个信源里**：

- 厂商官网讲卖点，不讲真实成交价
- 公开招标有成交价，但没有技术口径
- 行业媒体有案例故事，但细节失真
- 白皮书有架构，但不知是否规模出货

结果是：调研每次从零开始、摘录与出处分离、不同人写出的结构无法横向合并。本 Skill 的核心动作，是把碎片化调研记录按**六类要素**归一到同一张表，并强制每个结论附信源与记录编号。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 季度/半年技术趋势简报要交 | 主用场景：调研记录 → 对照表 → 趋势建议 |
| 新竞品发布教育行业方案，需快速评估压力 | 按要素补录记录，重跑对照 |
| 产品路线评审前需要竞品证据 | 输出直接作为路线讨论的论据底稿 |
| 老板问「为什么我们要跟这条趋势」 | 用记录编号与信源逐条回溯 |

**不适用**：自身产品规格维护（→ EDU-05 产品能力矩阵与规格对照底稿）；现网故障与质量分析（→ EDU-06）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `竞品方案要素调研表.csv` | 必需 | 记录编号、竞品厂商、方案场景、方案定位、组网架构、核心特性、定价带（万元/校）、标杆案例、信源、信源类型、采集日期 |
| 2 | `趋势分析框架.md` | 必需 | 六类要素口径、趋势分级规则（S/A/B）、趋势命中判定规则、影响等级判定规则 |

> 缺信源列或记录编号时，本 Skill **必须拒绝输出对照结论**，只能退回补录。无出处的调研记录比没有记录更危险。

## 四、输出（outputs）

唯一交付物：`竞品对照与趋势洞察表.csv`，字段固定为 12 列：

```
记录类型, 对象, 记录支撑数, 方案定位, 组网架构, 核心特性, 定价带, 标杆案例,
证据来源, 趋势关联, 影响等级, 影响与建议
```

- `记录类型` ∈ {竞品对照, 趋势洞察}
- 竞品行 `证据来源` = 信源类型分布（如「官网2+公开招标1+行业媒体1」）
- 趋势行 `证据来源` = 命中的记录编号列表，逐条可回溯
- `影响等级` 按框架规则计算：竞品行按趋势覆盖数（3→高 / 2→中 / 0-1→低），趋势行按定级（S→高 / A→中 / B→低）

## 五、工作流程（workflow）

### STEP 1 · 读框架，先立口径再看记录

从 `趋势分析框架.md` 读入六类要素口径、三条趋势定义与命中关键词、影响判定规则。**顺序不可颠倒**——先定分级标准再看竞品，等于先立规矩再开卷。

### STEP 2 · 记录归一与完备性检查

逐条核对 20 条调研记录：六类要素是否齐备、信源是否可点击回溯、定价带口径是否统一（万元/校）。缺项标注「未公开」并计入信息缺口。

### STEP 3 · 竞品×要素对照

按竞品分组，汇总每家的方案定位、组网架构、核心特性、定价带区间（min-max）、标杆案例与信源分布，形成每家一行的对照记录。

### STEP 4 · 趋势命中与定级

按关键词在「组网架构 + 核心特性」中命中三条趋势（Wi-Fi 代际演进 / 物联感知融合 / AI 智能运维），统计每条趋势的命中记录数、涉及竞品与价位带，按 S/A/B 规则定级。

### STEP 5 · 影响建议与竞争压力判定

竞品行按趋势覆盖数判竞争压力（高/中/低），趋势行按定级判路线影响，各附「对云梯产品路线的影响建议」。建议须指向可执行动作（对标、预留接口、版本规划纳入），并与 EDU-05 能力矩阵联动。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出：

1. 每个对照结论是否能指回具体记录编号？
2. 「X 家竞品覆盖 Y 个要素」类结论是否能从输入复算？
3. 趋势定级是否引用了框架的判定标准？
4. 是否没有出现「立项决定」「投资结论」类表述？

## 六、关键规则（不可协商）

1. **AI 不做路线决策。** 趋势定级与影响建议是讨论底稿，产品路线调整由产品委员会人工裁决。
2. **结论必须带信源。** 不允许出现「据了解」「业内公认」类无出处表述；每行证据来源必须指向真实信源类型或记录编号。
3. **已公开信息与推断结论必须区分。** 竞品出货量、市占率等推断只能标注「推断」，不得与官网/招标事实混写。
4. **定价带口径统一。** 万元/校基准配置，跨竞品可横向比较；不同口径须换算后标注。
5. **调研记录可复用。** 对照表与论据沉淀后，下一期只追加新记录，不重做旧记录。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（产品市场岗 / 产品委员会） |
| --- | --- |
| 多源调研记录归一到同一张表 | 趋势定级与路线影响的最终确认 |
| 趋势命中统计与竞争压力判定 | 对竞品的深度访谈与渠道验证 |
| 影响建议初稿与信源追溯 | 产品路线的实际调整决策 |

## 八、下游衔接

- 趋势影响建议 → **EDU-05 产品能力矩阵与规格对照底稿**（把 Wi-Fi 7 等趋势纳入能力矩阵基线项）
- 竞品定价带 → 定价策略讨论的论据底稿
- 全部对照记录 → 下一期调研的论据库（追加式维护）


## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读框架再读记录：把要素口径、趋势定义与影响规则写成显式判定表，不要先看竞品再定标准。
2. 记录完备性检查：20 条记录逐条核对六类要素与信源，缺项标注「未公开」并汇总信息缺口。
3. 竞品×要素对照：按竞品分组汇总，每家一行的对照记录（定价带取该家记录的 min-max；证据来源 = 信源类型分布，如「官网2+公开招标1+行业媒体1」）。
4. 趋势命中统计：按关键词命中三条趋势，统计命中记录数、涉及竞品与命中记录的定价带区间；趋势行按框架定级并给出对云梯产品路线的影响建议。
5. 竞争压力判定：竞品行按趋势覆盖数判影响等级（高/中/低），影响建议须指向可执行动作（对标 / 预留接口 / 版本规划纳入），并与 EDU-05 能力矩阵联动。
6. 区分事实与推断：来自官网/招标/媒体/白皮书的信息写明信源类型；任何推断结论必须标注「推断」。

### 硬性约束

【硬性约束】
- 不出现「立项决定」「投资结论」类表述——路线决策属于产品委员会，AI 只出对照证据与建议初稿。
- 每个对照结论必须能指回具体记录编号或信源类型，不允许「据了解」「业内公认」。
- 已公开信息与推断结论分开表述，推断必须显式标注。
- 定价带口径统一为万元/校（基准配置），不做跨币种换算时须标注口径。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 20 条记录是否覆盖 5 家竞品 × 4 类方案场景 × 6 类要素？
2. 「X 家竞品已布局 Wi-Fi 7」是否能从记录复算？（应为 3 条记录 / 3 家）
3. 每个趋势行的证据来源是否为命中记录编号列表？
4. 竞品行影响等级分布是否与规则一致？（应为高 2 / 中 1 / 低 2）
5. 是否没有任何一行出现路线决策类表述？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，12 列，列名与顺序固定，8 行（5 家竞品对照 + 3 条趋势洞察）：
记录类型, 对象, 记录支撑数, 方案定位, 组网架构, 核心特性, 定价带, 标杆案例, 证据来源, 趋势关联, 影响等级, 影响与建议

# 测试与质量框架（测试方案故障分析与质量月报）

某教育信息化企业 · 质量与测试岗 · 用于把现网故障记录归类汇总为质量月报，并按固定口径生成测试方案约束。

## 一、三级归类口径

每条现网故障按「现象 → 根因 → 责任域」三级归类，一级不能跳级：

| 层级 | 说明 | 取值 |
| --- | --- | --- |
| 现象类别 | 用户侧看到的表现 | 无线掉线 / 网络中断 / 认证失败 / 终端异常 / 平台功能异常 |
| 根因分类 | 定位后的真实原因 | 软件缺陷 / 配置错误 / 硬件质量 / 环境干扰 / 版本兼容 / 第三方对接 |
| 责任域 | 承接改进的产品域 | 无线产品域 / 交换产品域 / 云桌面域 / 平台软件域 / 安全产品域 |

## 二、根因分类定义

| 根因 | 定义 |
| --- | --- |
| 软件缺陷 | 版本内缺陷，需缺陷修复与回归验证 |
| 配置错误 | 现场实施或参数配置不当，非产品问题 |
| 硬件质量 | 板卡、模块、终端等硬件批次或器件问题 |
| 环境干扰 | 现场电磁、施工等外部环境因素 |
| 版本兼容 | 终端/平台/固件跨版本不匹配 |
| 第三方对接 | 外部系统或第三方接口问题 |

## 三、月报指标定义

| 指标 | 计算口径 |
| --- | --- |
| 故障总数 | 当月记录行数 |
| 平均解决时长 | Σ解决时长 ÷ 故障总数（保留 1 位小数） |
| 根因占比 | 该根因起数 ÷ 故障总数 × 100%（保留 1 位小数） |
| 责任域占比 | 该责任域起数 ÷ 故障总数 × 100% |
| 超长故障 | 解决时长 ≥48 小时的故障 |
| 快速解决 | 解决时长 ≤24 小时的故障 |

## 四、改进指向映射

| 根因 | 改进指向 |
| --- | --- |
| 软件缺陷 | 缺陷修复纳入版本回归，列入测试方案通过标准 |
| 配置错误 | 配置模板化与交付前基线检查 |
| 硬件质量 | 来料抽检加严与批次追溯 |
| 环境干扰 | 现场工勘与干扰排查前移到交付前 |
| 版本兼容 | 版本兼容性测试矩阵扩充 |
| 第三方对接 | 接口联调测试前置 |

## 五、测试方案结构约束（长期记忆口径）

周期性测试方案与质量月报遵循固定结构，同类报告风格保持一致：

1. **用例**：按场景化组织（高教无线 / 交换 / 云桌面 / 平台 / 安全），用例编号可追溯到故障编号；
2. **环境**：写明版本基线（软件版本 + 固件版本），与现网版本对齐；
3. **通过标准**：零严重缺陷 + 回归全过；上期月报的软件缺陷改进项必须出现在本期回归范围；
4. **依据章节放最后**：引用的规范与依据统一置于文档末尾，不插入正文；
5. **按责任域对比**：分布分析固定按责任域横向对比，结论作为固定章节保留，不得压缩省略。

## 六、人工边界

归类与汇总由 AI 按上述口径计算，**改进项的排期与责任划分由质量例会人工裁决**；月报不构成对个人或团队的考核依据。

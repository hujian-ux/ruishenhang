# 经营驾驶舱与多视图可视化（技术开发 · 零售业）

## 适用时机
- 品牌方/老板/运营/甲方各自要看不同维度的数据，一份大而全看板谁都不满意
- 每周手工从 BI 截图拼 PPT 发群，耗时且口径混乱
- 只有 KPI 大数字没有经营洞察，客单价掉了 10% 都没人发现
- 需要给品牌方甲方一个"不怕随时查"的独立自助看板链接以建立信任

## 输入（inputs）
1. 经营数据长表 CSV（3 列：date + metric_name + metric_value，所有 BI/后台一句 SQL 可出）
2. 指标口径定义（如"活跃"=7 天登录还是 30 天下单，一次定义全公司一致）
3. 角色视图配置（运营 5 页 / 老板深色大屏 4 大数字 / 客户方绿色成果视图）

## 输出（outputs）
1. 7 页经营驾驶舱（20+ 图表：柱/饼/环/雷达/桑基/词云/玫瑰/面积）
2. 自动异常告警规则（客单价跌/客诉超线/词云聚集 自动推送企微）
3. 客户方独立自助访问链接（不含 Agency 成本 ROI）

## workflow（4 步）
1. **导入长表 CSV**：仅 3 列 date+metric_name+metric_value，所有后台一句 SQL 即可导出。
2. **定义指标口径**："活跃/转化/复购"等词一次定义，全公司一致，杜绝一数多义。
3. **生成驾驶舱**：5 主视图 + 2 角色视图，20+ 图表自动配色，移动端自适应。
4. **告警 + 分享**：异常自动推送企微；客户方拿到独立自助访问链接。

## 关键规则 / 提示
- 同一份底层数据、同一套指标口径，输出多角色"刚刚好"的视图，绝不把成本数据暴露给品牌方甲方。
- 图表类型按洞察目的选择：来源流转用桑基、反馈聚集用词云、能力对比用雷达、周期分布用玫瑰。
- 告警必须有明确阈值与通道，让运营从"事后救火"变"事前预警"。

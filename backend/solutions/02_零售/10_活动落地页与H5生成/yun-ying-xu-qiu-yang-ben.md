# 运营需求样本 · 活动落地页与 H5（r4-1）

> 真实脱敏的运营自然语言需求，供练习"需求解构 → 落地页"使用。场景：劲能健身房 · 北京朝阳店新店开业。

## 样本一（主案例）

> "做个新店开业活动页，能预约体验课、拉好友组队送次卡、地图能导航到店。"

解析出的结构化模块：

| 模块 | 功能 | 交互逻辑 |
| --- | --- | --- |
| Hero 主视觉 | 开业主题 + LOGO + 主 CTA | 顶部 100vh · CTA 锚点滚到预约 |
| 预约体验课 | 手机号 + 时段选择 + 门店定位 | 手机号实时正则验证 + 位置权限申请 |
| 拉好友组队 | 邀请卡片 + 组队进度 + 头像堆叠 | URL 携带 `?inviter=` 感知邀请上下文 |
| 地图导航 | 地址展示 + 一键导航 | 三方 URI Scheme 兼容（微信/高德/百度） |
| 门店信息 | 营业时间 + 设施展示 + 电话 | 点击电话直接拨号 |
| 数据回流 | Beacon 埋点 + 客户 CDP 对接 | 13 关键事件 · 保证 beforeunload 不丢包 |
| 分享传播 | 系统分享 + 剪贴板降级 | Web Share API · 微信内引导右上角 |

## 样本二（练习变体）

> "月底会员日，做个签到领券页，老带新各得 7 天会员，要能显示附近门店和剩余名额。"

提示：可复用相同 7 模块骨架，仅替换 Hero 文案、组队奖励文案、门店数据字段。

## 样本三（练习变体）

> "双十一大促预热，做个游戏化抽奖页，转盘抽奖 + 分享得额外次数 + 落地商城小程序。"

提示：重点练习"分享得额外次数"的 Web Share API + 剪贴板降级，以及抽奖结果的数据回流。

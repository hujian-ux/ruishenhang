# 内部效率自动化工作流搭建（技术开发 · 零售业）

## 适用时机
- 团队中存在"每天/每周手工拼数据、导表、截图发群"的重复劳动
- 工单/素材靠人工分类、命名、归档，长尾被埋没、约 15% 素材找不回
- 需要把散落的企微/有赞/CRM/OA 系统通过凭证托管串联成自动 pipeline

## 输入（inputs）
1. 待自动化操作的原始描述（含日耗时、出错风险、当前人工步骤）
2. 数据源连接信息（企微客服 API / 有赞开放 API / 只读 MySQL / OA 网盘 等）
3. 调度与 SLA 要求（cron 表达式、时区、抖动、owner）

## 输出（outputs）
1. 工作流 YAML 配置（触发/步骤/凭证/容错/告警 一体化）
2. 日报/工单聚类/素材归档三类典型配置示例
3. 三层容错策略 + P0/P1/P2 告警分级定义
4. 可复用工作流模板清单（10 个）

## workflow（6 步）
1. **工作流选型**：列出高频重复操作，评估日耗时/出错风险/可自动化度，确定优先搭建的 1-3 条工作流。
2. **触发与调度定义**：编写 cron + jitter + timezone + owner + sla，避免整点峰值。
3. **凭证托管**：全部使用系统专属应用密钥（员工个人账号 ≠ 工作流账号），KMS 加密、90-365d 分级轮换、最小权限（仅 GET/SELECT）、双人审批、审计日志。
4. **步骤编排**：多源拉取 → JOIN/计算 → AI 摘要/聚类/识别 → 渲染 → 推送/归档，每步声明 connector 与 output 变量。
5. **容错与告警**：L1 步内指数退避重试；L2 步间降级（兜底数据源/快照）；L3 工作流回滚 + P1 告警。配置 P0/P1/P2 通道。
6. **可观测与归档**：runtime 日志入 ClickHouse（180 天），audit 日志入 WORM（3 年），Grafana + OpenTelemetry 监控成功率/p95/单次成本。

## 关键规则 / 提示
- 凭证绝不明文出现在工作流配置文件，统一走 Secret Vault（KMS）。
- 最小权限原则：工作流账号禁止 DELETE/UPDATE。
- 所有外部依赖失败都有降级路径，不能因单点失败整体崩。
- 告警分级必须可落地（电话/企微/静默），避免告警疲劳。

## 内嵌提示词（主提示词要点）
见同目录 `assets/主提示词.md`，或把"待自动化操作 + 数据源 + 调度要求"粘贴给 WorkBuddy，要求输出一体化工作流 YAML。

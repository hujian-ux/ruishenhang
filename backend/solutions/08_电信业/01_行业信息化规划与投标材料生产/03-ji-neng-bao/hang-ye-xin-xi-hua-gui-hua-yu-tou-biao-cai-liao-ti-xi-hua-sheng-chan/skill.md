# 行业信息化规划与投标材料体系化生产

## 一、这个 Skill 解决什么

政企规划与投标材料的真实困难不是「不会写」，而是**每份材料都从零开始、定位反复跑偏**：

- 提纲要靠多轮会议来回碰撞，一轮会一个版本
- 政策与先进地区对标做法要临时翻文件找案例
- 字体字号、章节顺序每份人工调一遍，规范无法延续
- 方案结构关系靠文字描述，评审方看不清主线

结果是：**写作时间都花在文字堆砌上，定位判断反而没时间做**。本 Skill 的核心动作，是把「需求归一 → 方向判定 → 受众定位 → 三件套成文 → 结构可视化」固化成一条流水线，并强制每行需求可映射到材料清单与共性能力引用。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 政企客户规划与投标季，手上有十几到几十项客户需求 | 主用场景：需求归一 + 三件套批量生产 |
| 材料初稿被评审判定「内容偏了」 | 重新给定受众定位与政策对标，整体重写而非逐句修改 |
| 多份方案要体现统建与共性能力复用思路 | 按规则统一标注共性能力引用 |
| 投标截止前需要一份可复核的材料清单 | 输出直接作为材料生产与进度跟踪台账 |

**不适用**：投标报价与商务策略（人工决策）；已中标项目的交付运营材料（→ 运营日报周报月报批量生成）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `行业客户需求与调研要点.csv` | 必需 | 客户编号、客户行业、客户类型、信息化痛点、核心需求、现状系统、现状系统年限、需求优先级、调研阶段、提纲迭代轮次 |
| 2 | `投标材料框架.md` | 必需 | 三件套编号规则、章节方向关键词映射、共性能力引用规则、受众定位规则、服务承诺分级口径、生产流程规则 |

> 缺 2（材料框架）时，本 Skill **必须拒绝直接成文**，只能输出调研归一表——章节模板与编号规则未定，成文必然返工。

## 四、输出（outputs）

唯一交付物：`规划与投标材料表.csv`，字段固定为 13 列：

```
客户编号, 客户行业, 核心需求, 需求优先级, 章节方向, 方案定位（受众）, 技术方案要点,
实施方案要点, 服务承诺要点, 材料清单, 共性能力引用, 提纲迭代轮次, 生产状态
```

- `章节方向` ∈ {平台建设类, 数据分析类, 物联感知类, 统一门户类, 流程再造类}
- `材料清单` 必须按 `ZB-客户序号-JS/SS/CN` 编号规则成套给出，技术方案版本跟随提纲迭代轮次
- `共性能力引用` 不允许写「待定」，可映射即引用，不可映射必须写明「定制开发为主」
- `生产状态` ∈ {已成文（导图已输出）, 提纲评审中, 调研补充中}

## 五、工作流程（workflow）

### STEP 1 · 需求归一，先看盘子再动笔

把所有客户的痛点、需求、现状系统整理进同一张表，确认需求优先级与调研阶段口径。**顺序不可颠倒**——未归一的需求直接写方案，等于边写边补调研。

### STEP 2 · 章节方向判定

按 `投标材料框架.md` 的关键词映射，自上而下命中即止：门户 → 共享/指挥 → 物联网/联网/巡检/采集/能源 → 调度/治理/追溯/预约/协同/实训/招商 → 数据/报表/案例/分析 → 其余归平台建设类。

### STEP 3 · 受众定位与提纲先行

按需求优先级确定方案定位（高→决策层汇报、中→评审组应答、低→业务沟通），**先出提纲多版迭代，未过评审不成文**。迭代轮次 ≥2 视为一次定位纠偏——纠偏是整体重写，不是逐句修补。

### STEP 4 · 三件套成文与编号

技术方案按章节方向套模板，实施方案与服务承诺按优先级分档，材料编号按 `ZB-序号-JS/SS/CN` 规则成套生成。

### STEP 5 · 共性能力标注与结构可视化

凡可映射共性能力的需求必须复用统一表述；成文同步输出可编辑导图，方案结构关系一图呈现。

### STEP 6 · 自检

输出前逐项自检，任一不过则不得输出（见附录「生成后自检」）。

## 六、关键规则（不可协商）

1. **AI 不做投标决策。** 报价策略、商务承诺兑现、方案终审属于人。AI 只输出材料生产表与缺口标注。
2. **先提纲后成文。** 提纲未过评审的材料不得标注「已成文」。
3. **定位纠偏而非细节修改。** 内容偏了就重新给定受众与政策对标后整体重写，禁止在偏掉的稿子上逐句修。
4. **共性能力必须显式标注。** 不允许出现「待定」；流程再造类要写明「定制开发为主」，不硬凑复用。
5. **规范一次交代长期生效。** 字体字号、章节顺序、报送口径固化后自动沿用，不逐份重述。
6. **不承诺效率百分比。** 输出中不写「提效 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（行业方案岗 / 商务） |
| --- | --- |
| 需求归一与章节方向判定 | 客户关系与需求优先级终判 |
| 三件套要点与材料清单生成 | 投标报价与商务策略 |
| 共性能力引用标注 | 服务承诺兑现责任 |
| 提纲多版迭代与定位纠偏重写 | 方案终审与递交 |

## 八、下游衔接

- 已成文材料 → 投标递交与评标应答
- 全部项目进入交付期 → **TCM-02 运营日报周报月报批量生成**（项目运营数据按三周期批量出报表）

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

1. 先读需求再看框架：把 20 项客户需求按客户编号顺序归一，确认需求优先级、调研阶段、提纲迭代轮次三列口径后再进入判定。
2. 章节方向判定严格按关键词映射自上而下命中即止，输出五类之一：平台建设类 / 数据分析类 / 物联感知类 / 统一门户类 / 流程再造类。
3. 三件套按编号规则成套生成：`ZB-客户序号-JS 技术方案 V1.{提纲迭代轮次}；ZB-客户序号-SS 实施方案 V1.1；ZB-客户序号-CN 服务承诺 V1.0`，每行需求恰好 3 份材料。
4. 受众定位与服务承诺按需求优先级三档执行（高/中/低），实施方案要点同步分档。
5. 共性能力引用按章节方向映射；流程再造类一律写「无共性能力引用，定制开发为主」。
6. 生产状态按调研阶段映射：完成调研→已成文（导图已输出）；深度访谈→提纲评审中；初访→调研补充中。

### 硬性约束

- 不允许出现「示例」「样例」「待补充」「占位」等字样。
- 材料清单必须可按编号逐份清点，合计 = 行数 × 3。
- 共性能力引用不允许写「待定」。
- 技术方案版本号必须等于该行提纲迭代轮次，不得虚构迭代历史。
- 不写任何效率百分比或效果承诺。

### 生成后自检

1. 交付物行数是否 = 输入需求行数（20）？
2. 材料清单合计是否 = 60 份（20 × 3）？
3. 章节方向分布是否为：平台建设 2 / 数据分析 6 / 物联感知 4 / 统一门户 1 / 流程再造 7？
4. 共性能力覆盖是否 = 13/20 客户，其余 7 个为定制开发？
5. 平均提纲迭代是否 = 1.6 轮，定位纠偏（≥2 轮）是否 = 10 次？
6. 生产状态分布是否为：已成文 7 / 提纲评审中 8 / 调研补充中 5？
自检全过再输出 CSV。

### 输出格式

CSV，13 列，列名与顺序固定：
客户编号, 客户行业, 核心需求, 需求优先级, 章节方向, 方案定位（受众）, 技术方案要点, 实施方案要点, 服务承诺要点, 材料清单, 共性能力引用, 提纲迭代轮次, 生产状态

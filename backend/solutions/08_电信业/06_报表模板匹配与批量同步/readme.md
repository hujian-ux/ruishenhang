# TCM-06 · 报表模板匹配与批量同步 —— 场景使用说明

- **行业**：运营商生态
- **角色**：报表管理岗（林晓）
- **场景编号**：TCM-06
- **案例主体**：某终端分销与供应链企业（运营商旗下终端分销企业）

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/报表模板匹配与批量同步/SKILL.md` | Skill 定义 | 三级映射优先级、V1.2→V2.0 对照表、数值校验与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `多渠道报表数据.csv` | 原始输入 | 25 行四渠道字段-数值对（V1.2 与 V2.0 并存，含空格变体与异常数值） |
| `模板映射规则.md` | 原始输入 | 标准字段集、版本差异对照表、映射优先级、数值校验规则 |
| `模板匹配同步表.csv` | **交付物** | 25 行同步结果：标准模板字段、转换后数值、映射方式、同步状态、异常标记 |
| `gen_TCM-06.py` | 生成脚本 | 从原始输入计算生成交付物，含断言验证与 Skill zip 打包 |
| `报表管理岗-报表模板匹配与批量同步.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用 |

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `多渠道报表数据.csv`、`模板映射规则.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 3 条待人工处理行转报表管理岗：补录异常数值、决定未映射字段归类；归类结论回填 `模板映射规则.md` 对照表。

## 三、交付物验证记录

### 断言项

| 断言 | 结果 |
| --- | --- |
| 输入 25 行，输出 25 行且序号一一对应 | 通过 |
| 映射方式分布 = 直接 7 / 对照 11 / 模糊 5 / 未映射 2 | 通过 |
| 同步状态 = 已同步入库 22 / 待人工处理 3 | 通过 |
| 异常标记 = 数值格式异常 1 + 字段未映射 2 | 通过 |
| 渠道分布 = 线上商城 7 / 授权门店 7 / 营业厅 5 / 行业直供 6 | 通过 |
| T8201 三渠道合计 = 1,021 台 / 3,675,600 元，均价 3,600 元/台 | 通过 |

### 可复算口径

- `映射优先级 = 直接映射 ＞ 版本对照映射（V1.2 对照表）＞ 模糊匹配（去空格）＞ 未映射`
- `数值型字段（销售台数/销售金额元/库存台数/退机台数）须为非负数字；编码型字段（机型编码/渠道编码）非空即通过`
- `T8201 三渠道合计台数 = 356 + 142 + 523 = 1,021`
- `T8201 三渠道合计金额 = 1,281,600 + 511,200 + 1,882,800 = 3,675,600 元`

## 四、与案例的数字对齐

| 数字 | 出处 | 在本场景的落点 |
| --- | --- | --- |
| 25 行、4 渠道、双版本模板 | 输入明细 | `多渠道报表数据.csv` V1.2 与 V2.0 并存 |
| 空格变体 5 行 | 输入明细 | 营业厅报表「机型 编码」等，去空格模糊匹配 |
| 同步成功 22 条 / 待人工 3 条 | 交付物 | 同步状态列计数 |
| 未映射 2（结算价、运费）+ 数值异常 1（待门店确认） | 交付物 | 异常标记列 |
| T8201 均价 3,600 元/台 | 交付物复算 | 三渠道台数与金额交叉验证 |

## 五、真实性等级与边界

- **T2**：模板匹配填充、串码状态同步、批量同步方法论来自客户应用案例素材。
- **T3**：岗位痛点来自素材中的传统/WorkBuddy 模式对比。
- **构造**：25 行明细与同步结果全部可由脚本复算。
- **人工边界**：对照表新增维护、未映射字段归类、异常数值补录一律人工；AI 不猜字段、不按 0 处理。

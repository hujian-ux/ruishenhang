# 报表模板匹配与批量同步

## 一、这个 Skill 解决什么

多渠道报表同步的真实困难不是「数据多」，而是**每个渠道一套模板、每个版本一套字段名**：

- 线上商城用 V2.0 标准字段，授权门店还在用 V1.2 的「机型号」「当日销量」
- 营业厅报表的字段带空格变体（「销售 台数」），人工对照总漏行
- 行业直供的报表明明多了「结算价」「运费」两个字段，硬往标准模板里塞就会错列
- 字段逐一人工对照、多表切换复制粘贴，批量任务枯燥且易错

结果是：同步入库靠人肉逐格搬运，错一列整张报表作废。本 Skill 的核心动作，是把「模板匹配 + 列映射 + 数值校验 + 同步状态」固化成一条流水线，每一行都可追溯。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 多渠道日报 / 周报需要按标准模板批量同步入库 | 主用场景：字段-数值对逐行映射 |
| 源报表模板版本不一（V1.2 与 V2.0 并存） | 按版本对照表映射，多版本兼容 |
| 源字段带空格等变体，人工对照总漏行 | 去空格模糊匹配兜底 |
| 同步前需要把未映射字段与异常数值挑出来 | 输出异常标记清单，转人工处理 |

**不适用**：源数据本身的口径修订（属于报表管理岗人工）；异常数值的补录与回填（人工）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `多渠道报表数据.csv` | 必需 | 序号、渠道、源字段、源数值、模板版本 |
| 2 | `模板映射规则.md` | 必需 | 标准字段集、V1.2→V2.0 版本对照表、映射优先级、数值校验规则 |

> 缺 2（映射规则）时，本 Skill **必须拒绝执行同步**——字段对照关系必须显式给定，不允许 AI 凭直觉猜字段。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`模板匹配同步表.csv`，字段固定为 10 列：

```
序号, 渠道, 源字段, 源数值, 模板版本, 标准模板字段, 转换后数值, 映射方式, 同步状态, 异常标记
```

- `映射方式` ∈ {直接映射, 版本对照映射, 模糊匹配, 未映射}
- `同步状态` ∈ {已同步入库, 待人工处理}
- `异常标记` ∈ {无, 字段未映射, 数值格式异常}
- `标准模板字段`：未映射行置空；`转换后数值`：未映射或数值异常行置空
- 输出行序与输入行序一一对应，逐行可回溯

## 五、工作流程（workflow）

### STEP 1 · 读规则，先立对照表再看数据

从 `模板映射规则.md` 读入标准字段集、V1.2→V2.0 对照表与映射优先级，写成显式判定表。**顺序不可颠倒**——先看数据再定对照，等于边同步边造规则。

```
标准字段集：机型编码 / 销售台数 / 销售金额元 / 库存台数 / 退机台数 / 渠道编码 / 数据日期
V1.2 对照：机型号→机型编码、当日销量→销售台数、销售额→销售金额元、月末库存→库存台数、退货数量→退机台数
优先级：直接映射 ＞ 版本对照映射 ＞ 模糊匹配（去空格）＞ 未映射
```

### STEP 2 · 逐行匹配列映射

对每行按优先级尝试匹配：

| 优先级 | 条件 | 映射方式 |
| --- | --- | --- |
| ① | 源字段与标准字段同名 | 直接映射 |
| ② | 源字段命中 V1.2 对照表 | 版本对照映射 |
| ③ | 源字段去空格后与标准字段一致 | 模糊匹配 |
| ④ | 以上均不命中 | 未映射（异常） |

### STEP 3 · 数值校验

- 源数值可解析为非负数字 → `转换后数值` = 解析值
- 源数值含文字（如「待门店确认」）→ `转换后数值` 置空，标记「数值格式异常」
- **禁止**把异常数值按 0 处理后入库

### STEP 4 · 同步状态判定

映射成功且数值校验通过 → `已同步入库`；字段未映射或数值格式异常 → `待人工处理`。

### STEP 5 · 异常清单与移交

- 汇总「字段未映射」「数值格式异常」两类异常行，转报表管理岗人工处理
- 未映射字段的归类意见（入模板 / 单独台账）由人工决定

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出（见附录「生成后自检」）。

## 六、关键规则（不可协商）

1. **对照表必须来自规则文件。** V1.2→V2.0 字段对照不允许 AI 自行扩充或猜测；新差异先入表、再同步。
2. **未映射不猜字段。** 「结算价」「运费」不在标准字段集与对照表中，宁可标记「字段未映射」待人工，也不断然归入某个近似字段。
3. **异常数值不按 0 处理。** 「待门店确认」不是 0，置空 + 异常标记 + 待人工，是唯一合法处理。
4. **映射逐行可回溯。** 输出行序与输入一致，每行写明映射方式，事后可审计每一格的来源。
5. **AI 不改源数据。** 源字段与源数值原样保留在输出中，改写只发生在「转换后数值」列。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（报表管理岗） |
| --- | --- |
| 三级匹配与列映射 | V1.2 对照表新增维护 |
| 数值校验与同步状态 | 未映射字段的归类决定 |
| 异常清单输出 | 异常数值补录与回填 |

## 八、下游衔接

- 同步入库后的标准数据 → 库存与销售分析（→ TCM-05 终端库存分层分析）
- 未映射字段的归类结论 → 反哺 `模板映射规则.md` 对照表（人工维护）
- 异常行处理记录 → 报表口径治理台账

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规则再看数据：把标准字段集、V1.2→V2.0 对照表、映射优先级写成显式判定表，不要边看数据边定对照。
2. 逐行匹配：按「直接映射＞版本对照映射＞模糊匹配（去空格）＞未映射」的优先级对 25 行源数据逐行匹配；
   · 直接映射 = 源字段与标准字段同名
   · 版本对照映射 = 按对照表（机型号→机型编码、当日销量→销售台数、销售额→销售金额元、月末库存→库存台数、退货数量→退机台数）
   · 模糊匹配 = 源字段去空格后与标准字段一致（如「销售 台数」→销售台数）
3. 数值校验：数值型标准字段（销售台数/销售金额元/库存台数/退机台数）的源数值须可解析为非负数字；编码型标准字段（机型编码/渠道编码）非空即通过。含文字（如「待门店确认」）→ 置空并标记「数值格式异常」。
4. 同步状态：映射成功且数值通过 → 已同步入库；字段未映射或数值格式异常 → 待人工处理。
5. 输出行序与输入一一对应（序号 1-25），每行写明映射方式与异常标记。

### 硬性约束

【硬性约束】
- 未映射字段禁止猜测目标字段，宁可标记「字段未映射」待人工处理。
- 异常数值禁止按 0 处理，置空 + 异常标记是唯一合法处理。
- 对照表必须来自 `模板映射规则.md`，不允许 AI 自行扩充；新增差异先入表再同步。
- 源字段与源数值原样保留，改写只发生在「转换后数值」列。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输入 25 行是否逐行对应输出 25 行，序号一致无遗漏？
2. 映射方式分布是否为直接映射 7 / 版本对照映射 11 / 模糊匹配 5 / 未映射 2？
3. 同步状态是否为已同步入库 22 / 待人工处理 3？
4. 异常标记是否为数值格式异常 1（行业直供·销售额=待门店确认）+ 字段未映射 2（结算价、运费）？
5. 是否没有任何异常数值被按 0 处理入库？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，10 列，列名与顺序固定：
序号, 渠道, 源字段, 源数值, 模板版本, 标准模板字段, 转换后数值, 映射方式, 同步状态, 异常标记

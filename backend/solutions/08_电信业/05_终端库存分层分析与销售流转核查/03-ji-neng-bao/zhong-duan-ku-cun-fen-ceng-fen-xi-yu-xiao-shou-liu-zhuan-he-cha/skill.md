# 终端库存分层分析与销售流转核查

## 一、这个 Skill 解决什么

终端库存分析的真实困难不是「没有数据」，而是**答案被切成三份放在三张仓别报表里**：

- 同一机型在总部仓、省仓各有一行，汇总靠手工拼表
- 机型编码存在前导零变体（`01005` 与 `1005` 是同一机型），人工匹配总漏行
- 进销存差异藏在对账数字里，肉眼逐行核对既慢又容易漏
- 哪些机型滞销没有统一口径，每次盘点都要重新对齐规则

结果是：滞销机型在库里一躺几个月，等问题暴露时促销窗口已经错过。本 Skill 的核心动作，是把三张仓别报表归到同一张机型级核查表上，并强制每行分层结论可复算。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 月度盘点，需要总部仓与省仓分层库存展示 | 主用场景：三仓明细 → 机型级汇总表 |
| 排查滞销机型，需要统一库龄与周转口径 | 输出三档分层 + 滞销预警依据 |
| 库存报表与销售报表对不上，需要流转核查 | 行级进销存核对，差异行单列 |
| 编码带前导零变体，跨表匹配总漏行 | 归一规则显式兼容，确认后长期沿用 |

**不适用**：单仓单机型的即时库存查询（直接查系统即可）；滞销机型的最终处置决定（调拨/促销/退换属于人工）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `终端库存与销售明细.csv` | 必需 | 机型编码、机型名称、仓库、期初库存台、本期入库台、近30天销量台、上报期末库存台、库龄天数 |
| 2 | `分层与核查规则.md` | 必需 | 编码归一口径、三档分层阈值、进销存核对公式、滞销预警条件 |

> 缺 2（规则文件）时，本 Skill **必须拒绝输出分层结论**——分层阈值（60 天 / 2.0 月）必须显式给定，不允许默认值。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`库存分层与流转核查表.csv`，字段固定为 12 列：

```
机型编码, 机型名称, 合计库存台, 总部仓库存台, 省仓库存台, 加权平均库龄天,
近30天销量台, 周转月数, 库存分层, 滞销预警, 预警依据, 进销存核查
```

- `库存分层` ∈ {畅销层, 关注层, 滞销层}
- `滞销预警` ∈ {是, 否}；为「是」时 `预警依据` 必须写明库龄与周转实测值
- `周转月数` 保留 2 位小数；`加权平均库龄天` 四舍五入取整
- `进销存核查` 逐机型写「全部一致」或具体差异（仓库 + 差异数量 + 台）
- 机型合计库存按各行**上报期末库存**汇总，差异行不调整、单列标记

## 五、工作流程（workflow）

### STEP 1 · 读规则，先立口径再看数

从 `分层与核查规则.md` 读入归一口径、三档阈值与核对公式，写成显式判定表。**顺序不可颠倒**——先看数据再定阈值，等于给结论找理由。

```
编码归一：去前导零后匹配，01005 ≡ 1005
分层阈值：畅销 = 周转≤2.0月 且 库龄≤45天；滞销 = 库龄>60天 且 周转>2.0月
核对公式：期初 + 入库 − 近30天销量 = 上报期末
省仓库存 = 华东省仓 + 华南省仓
```

### STEP 2 · 编码归一与三仓汇总

对每行机型编码去前导零归一，同一编码视为同一机型；按仓库分列汇总（总部仓 / 省仓=华东+华南），得到机型级的合计库存与近 30 天合计销量。

### STEP 3 · 行级进销存核对

逐行计算理论期末库存 = 期初 + 入库 − 近 30 天销量，与上报期末库存比对：

| 比对结果 | 处理 |
| --- | --- |
| 差异 = 0 | 标记「一致」，进入汇总 |
| 差异 ≠ 0 | 标记「流转差异」，写明仓库与差异数量，转人工核查 |

### STEP 4 · 机型分层（三档）

计算周转月数（合计库存 ÷ 近 30 天销量）与加权平均库龄（按上报期末库存加权），按规则分三档；命中滞销层的机型触发滞销预警并写明实测值。

### STEP 5 · 滞销预警与差异输出

- 滞销层机型输出预警依据 + 滞销库存合计
- 流转差异行单列，供人工认定差异原因（串货 / 录入错误 / 在途未入账）

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出（见附录「生成后自检」）。

## 六、关键规则（不可协商）

1. **分层阈值必须来自规则文件。** 库龄 60 天、周转 2.0 月是本案例给定口径，不允许 AI 自行默认或调整。
2. **编码归一是硬规则。** 前导零变体不归一，汇总必然漏行；归一口径一经确认，后续同类查询沿用。
3. **差异不调整账面。** 进销存差异行只标记、写明仓库与数量，不擅自调整合计库存；原因认定属于人工。
4. **滞销预警必须带依据。** 「感觉卖不动」不是理由；每个预警机型写明库龄与周转实测值，任何人可复算。
5. **AI 不出处置结论。** 调拨、促销、集采退换协商属于人工决定，AI 只输出分层与证据。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（库存分析岗 / 仓储运营） |
| --- | --- |
| 编码归一与三仓汇总 | 差异原因认定（串货/录入/在途） |
| 机型分层与滞销预警 | 滞销处置决定（调拨/促销/退换） |
| 进销存差异标记与数量 | 与省仓对账、追责与更正 |

## 八、下游衔接

- 滞销预警机型 → 渠道促销与省仓调拨方案（人工裁决）
- 流转差异行 → 与省仓对账单核对，认定原因后更正报表
- 机型级汇总表 → 月度经营分析（→ TCM-08 经营分析可视化）

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规则再看数：把编码归一、三档分层阈值、进销存核对公式写成显式判定表，不要先看数据再定阈值。
2. 编码归一：机型编码去前导零后匹配，归一后同一编码视为同一机型；三仓汇总时省仓库存 = 华东省仓 + 华南省仓。
3. 行级进销存核对：理论期末 = 期初库存 + 本期入库 − 近30天销量；与上报期末库存逐行比对，差异 ≠ 0 的行标记「流转差异」并写明仓库与差异数量（如「华东省仓差异-40台」）。
4. 机型分层：周转月数 = 合计库存 ÷ 近30天合计销量（保留 2 位小数）；加权平均库龄 = Σ(上报期末库存 × 库龄天数) ÷ 合计库存（取整）；
   · 畅销层 = 周转≤2.0月 且 加权平均库龄≤45天
   · 滞销层 = 加权平均库龄>60天 且 周转>2.0月 → 滞销预警=是
   · 关注层 = 其余机型
5. 滞销预警依据必须写明库龄与周转实测值（如「平均库龄84天>60天且周转6.94月>2.0月」）；未触发预警的机型写「未触发预警」。

### 硬性约束

【硬性约束】
- 分层阈值必须来自 `分层与核查规则.md`，不允许 AI 自行默认或调整；缺规则文件时拒绝输出分层结论。
- 进销存差异行只标记不调整：合计库存按上报期末库存汇总，差异原因认定属于人工。
- 编码前导零变体必须归一，禁止按原始编码串直接分组导致漏行。
- AI 不输出滞销处置结论（调拨/促销/退换属于人工），只输出分层与证据。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输入 30 行明细是否归一为 10 个机型，无漏行？
2. 分层分布是否为畅销 4 / 关注 2 / 滞销预警 4？
3. 滞销库存合计是否为 12,600 台（占合计 56,500 台的 22.3%）？
4. 进销存差异是否恰好 1 行（华东省仓 老款4G手机D，-40 台）且未调整账面？
5. 每个滞销预警机型的依据是否含库龄与周转实测值？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，12 列，列名与顺序固定：
机型编码, 机型名称, 合计库存台, 总部仓库存台, 省仓库存台, 加权平均库龄天, 近30天销量台, 周转月数, 库存分层, 滞销预警, 预警依据, 进销存核查

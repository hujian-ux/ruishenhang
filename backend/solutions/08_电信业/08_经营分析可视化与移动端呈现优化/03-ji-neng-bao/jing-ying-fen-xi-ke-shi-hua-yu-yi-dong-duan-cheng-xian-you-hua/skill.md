# 经营分析可视化与移动端呈现优化

## 一、这个 Skill 解决什么

经营分析可视化的真实困难不是「算不出来」，而是**算出来之后「看不懂、看不清」**：

- 业务线月度数据散在多张表里，合计、达成率、同比各有各的口径
- 该用环形图的地方堆了折线图，该看达成率的地方只给了绝对值
- 结果常在手机上看：横向滚动、字号过小、图例一堆，老板只回一句「重做」
- 图表选型没有统一标准，每次汇报都换一套画法

结果是：分析从「能算出来」到「随时随地看得懂」之间，还隔着一次又一次返工。本 Skill 的核心动作，是把「综合口径 → 图表选型 → 移动端适配」固化成一条决策链，每条业务线的呈现方式都有规则依据。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 月度 / 季度经营分析需要出可视化看板 | 主用场景：业务线汇总 + 图表选型 + 适配要点 |
| 结果要在手机上看，表格呈现效果差 | 移动端适配要点逐线输出 |
| 图表选型没有统一标准，汇报反复返工 | 按选型决策表自动判定 |
| 业务线多、指标多，不知道先看哪个 | 关键指标卡置顶 + 优先级判定 |

**不适用**：经营结论解读与汇报口径（属于经营分析人员）；数据源本身的取舍与修订（人工）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `经营分析月度数据.csv` | 必需 | 月份、业务线、收入万元、目标收入万元、同比增速% |
| 2 | `可视化与移动端规范.md` | 必需 | 图表选型决策表、业务线选型优先级、移动端适配要点、呈现口径 |

> 缺 2（规范文件）时，本 Skill **必须拒绝输出选型结论**——选型阈值（30% / 15% / 95%）必须显式给定，不允许默认值。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`经营可视化数据表.csv`，字段固定为 10 列：

```
业务线, 三个月合计收入万元, 合计目标收入万元, 综合达成率%, 同期收入万元,
综合同比增速%, 收入占比%, 图表选型, 图表要点, 移动端适配要点
```

- 数据行 = 各业务线（按输入顺序）+ 末行合计
- `综合达成率%` / `综合同比增速%` / `收入占比%` 保留 1 位小数
- `图表选型` 由规范文件的优先级规则自动判定，命中即止
- `合计` 行图表选型固定为「关键指标卡 + 月度折线图」

## 五、工作流程（workflow）

### STEP 1 · 读规范，先立选型标准再看数据

从 `可视化与移动端规范.md` 读入选型决策表与阈值，写成显式判定表。**顺序不可颠倒**——先看数据再定选型，等于给结论找画法。

```
占比 ≥30% → 环形图 + 月度折线；同比 ≥15% → 双系列折线；达成 <95% → 横向条形图；其余 → 条形图
综合达成率 = 合计收入 ÷ 合计目标；同期收入 = 当月收入 ÷ (1+同比)
```

### STEP 2 · 综合口径汇总

按业务线汇总三个月合计收入与合计目标，计算综合达成率；由同比增速还原同期收入，计算综合同比增速与收入占比。

### STEP 3 · 图表选型判定

按优先级（占比 ≥30% ＞ 同比 ≥15% ＞ 达成 <95% ＞ 其余）逐线判定图表选型，命中即止；合计行固定「关键指标卡 + 月度折线图」。

### STEP 4 · 图表要点生成

按选型写明呈现要点：构成主角 / 趋势对比 / 达成差距 / 规模对比，绑定该业务线的实测数字。

### STEP 5 · 移动端适配要点生成

按选型输出适配要点：单列布局、字号下限、图表高度上限、图例数量上限、触控热区。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出（见附录「生成后自检」）。

## 六、关键规则（不可协商）

1. **选型阈值必须来自规范文件。** 30% / 15% / 95% 是本案例给定口径，不允许 AI 自行默认或调整。
2. **选型按优先级命中即止。** 一条业务线只输出一种主图表，不允许「全都画」。
3. **口径统一可复算。** 综合达成率、综合同比、占比的公式写死，任何人拿原始数据都能重算。
4. **视觉只用主色与灰阶。** 不用红 / 绿 / 橙区分好坏，达成差距用 100% 基准线呈现。
5. **移动端要点必须具体。** 「优化显示」不算要点——字号、高度、图例、热区要给出数值下限。
6. **AI 不代写经营结论。** 业务线好坏的解读、汇报口径、数据源取舍属于经营分析人员。

## 七、人工边界

| AI 负责 | 人负责（经营可视化岗 / 经营分析） |
| --- | --- |
| 综合口径汇总与复算 | 经营结论解读与汇报口径 |
| 图表选型判定与要点生成 | 数据源取舍与修订 |
| 移动端适配要点输出 | 看板最终布局与上线决定 |

## 八、下游衔接

- 可视化数据表 → 看板搭建（关键指标卡置顶 + 各业务线主图表）
- 行业直供达成差距 → 分省 / 分客户下钻分析（人工立项）
- 泛智能终端高增长结论 → 下一周期资源倾斜讨论（人工裁决）

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规范再看数据：把选型决策表、优先级阈值（占比≥30% / 同比≥15% / 达成<95%）、呈现口径写成显式判定表。
2. 综合口径汇总：按业务线汇总 7-9 月合计收入与合计目标；同期收入 = 当月收入 ÷ (1+同比增速)；综合达成率 = 合计收入 ÷ 合计目标；综合同比 = 合计收入 ÷ 同期收入合计 − 1；收入占比 = 业务线合计 ÷ 全部合计。全部保留 1 位小数。
3. 图表选型按优先级命中即止：占比≥30% → 环形图（构成）+月度折线图（趋势）；同比≥15% → 双系列折线图（本期 vs 同期）；达成<95% → 横向条形图（100% 基准线）；其余 → 条形图（业务线对比）。合计行固定「关键指标卡 + 月度折线图」。
4. 图表要点绑定实测数字（如「收入占比 49.2%」「综合达成率 92.0%」），不允许空泛描述。
5. 移动端适配要点给出数值下限：字号≥14px、指标大数字≥28px、图表高度≤320px、图例≤3、触控热区≥44px、单列布局去横向滚动。

### 硬性约束

【硬性约束】
- 选型阈值必须来自 `可视化与移动端规范.md`，不允许 AI 自行默认或调整；缺规范文件时拒绝输出选型结论。
- 一条业务线只输出一种主图表，选型按优先级命中即止，不允许叠加多种。
- 视觉只用主色 #0052D9 与灰阶，不用红/绿/橙区分好坏；达成差距用 100% 基准线呈现。
- 图表要点与适配要点必须具体到数值或明确动作，禁止空泛表述。
- AI 不代写经营结论（好坏解读 / 汇报口径 / 资源取舍），只输出口径、选型与要点。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输入 15 行月度数据是否汇总为 5 条业务线 + 1 行合计？
2. 合计收入是否为 127,700 万元、目标 129,800 万元、综合达成率 98.4%、综合同比 8.9%？
3. 终端销售是否占比 49.2% 判环形图+月度折线？泛智能终端是否同比 17.0% 判双系列折线？
4. 行业直供是否达成 92.0% 判横向条形图（100% 基准线）？
5. 每条业务线的图表要点是否绑定实测数字、移动端要点是否给出数值下限？
自检全过再输出 CSV。

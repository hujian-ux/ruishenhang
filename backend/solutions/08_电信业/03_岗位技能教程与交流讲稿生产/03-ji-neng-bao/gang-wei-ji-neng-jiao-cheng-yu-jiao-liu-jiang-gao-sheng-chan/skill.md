# 岗位技能教程与交流讲稿生产

## 一、这个 Skill 解决什么

培训材料的真实困难不是「没内容」，而是**内容有了没人看得懂、时长对不上**：

- 技能散落在个人经验和散落文档里，新手接手无从下手
- 教程写成「文档」，复杂逻辑没有概念图、拓扑图，非专业读者看不懂
- 代码没有注释、目录不能跳转，「能用」但不好用
- 讲稿按内容写，不看现场时长，超时了临场砍段落

结果是：**教程从「文档」到「能用、好懂」差最后一公里，讲稿与现场时长永远对不上**。本 Skill 的核心动作，是把「受众判定 → 大纲套用 → 图示配置 → 时长裁剪 → 缺口标注」固化成一条生产流水线。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 岗位技能（网络/系统/交付/平台）要整理成培训教程 | 主用场景：大纲 + 图示 + 注释一步到位 |
| 对外技术交流或客户培训要配讲稿 | 三段式讲稿按受众定制 |
| 讲稿超出场合时长需要裁剪 | 按固定顺序裁剪，保主线结论 |
| 培训计划要排产，需要缺口清单 | 素材缺口与优先级直接排班 |

**不适用**：交付期运营报表生产（→ TCM-02 运营日报周报月报批量生成）；平台文档体系建设（→ TCM-04 数据平台文档与算力支撑）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `岗位技能与分享需求.csv` | 必需 | 技能编号、技能主题、技能类别、所属岗位、受众、分享场合、场合时长分钟、现有材料状态、现有材料字数、期望交付 |
| 2 | `教程与讲稿框架.md` | 必需 | 教程大纲章节串模板、图示配置规则、三段式讲稿规范、时长裁剪规则、素材缺口与优先级判定、责任人分工 |

> 缺「现有材料字数」时，本 Skill **必须拒绝做裁剪判定**——字数与上限缺一就无法裁剪。

## 四、输出（outputs）

唯一交付物：`教程与讲稿生产表.csv`，字段固定为 14 列：

```
技能编号, 技能主题, 技能类别, 交付形态, 受众类别, 教程大纲, 图示需求, 交互需求,
讲稿要点, 讲稿字数上限, 裁剪方案, 素材缺口, 生产优先级, 责任人
```

- `交付形态` ∈ {教程, 讲稿, 教程+讲稿}，不允许出现其他值
- `讲稿字数上限` = 场合时长（分钟） × 200 字；纯教程类写「不适用」
- `裁剪方案` 必须写明删减字数与顺序，或明确「无需裁剪 / 新制 / 不适用」
- `素材缺口` ∈ {全量缺口, 归集重构, 局部完善}，与生产优先级一一对应

## 五、工作流程（workflow）

### STEP 1 · 受众归类

受众字段含「客户」且含「管理层」→ 非专业读者；含「客户」→ 客户技术侧；含「新入职」→ 新入职；其余 → 内部横向序列。**受众决定图示与讲稿姿态**，先归类再动笔。

### STEP 2 · 教程大纲套用

按技能类别套章节串模板：先讲功能模块关系，再进操作细节；代码与命令逐段注释，目录项可跳转。

### STEP 3 · 图示配置

按受众类别配图：非专业读者概念图 2 张 + 拓扑图 1 张；客户技术侧拓扑图 + 操作截图；新入职操作截图 + 流程图；内部横向流程图。

### STEP 4 · 讲稿三段式与时长裁剪

讲稿按「结构-案例-演示」三段式组织；字数上限 = 时长 × 200 字/分钟；超限按固定顺序裁剪：先删技术细节 → 再删案例背景 → 保留主线结论。

### STEP 5 · 缺口标注与排产

按现有材料状态判定素材缺口（全量缺口/归集重构/局部完善）与生产优先级（高/中/低），责任人按技能类别指派。

### STEP 6 · 自检

输出前逐项自检，任一不过则不得输出（见附录「生成后自检」）。

## 六、关键规则（不可协商）

1. **AI 不替代技能专家。** 技术内容的正确性由责任专家把关；AI 只做结构化、图示配置与裁剪。
2. **教程必须「保姆级」。** 复杂逻辑必配概念图或拓扑图；代码必配注释；目录必须可跳转。
3. **讲稿必须匹配时长。** 超限必须裁剪且顺序固定，不允许「讲快一点」这种口径。
4. **缺口必须显式标注。** 不允许「待定」；无材料就是全量缺口，不假装有底稿。
5. **可读性增强不砍内容正确性。** 裁剪只删细节与背景，主线结论与技术红线必须保留。
6. **不承诺效率百分比。** 输出中不写「提效 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（知识运营岗 / 技能专家） |
| --- | --- |
| 大纲套用与图示配置 | 技术内容正确性审核 |
| 讲稿裁剪与时长匹配 | 现场演讲与答疑 |
| 素材缺口与优先级标注 | 素材补充与案例授权（客户环境案例脱敏确认） |

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

1. 受众归类先于一切：含「客户」且含「管理层」→ 非专业读者；含「客户」→ 客户技术侧；含「新入职」→ 新入职；其余 → 内部横向序列。
2. 教程大纲按技能类别套章节串（网络/系统/交付/平台四套模板）；纯讲稿项大纲列写「不适用（纯讲稿）」。
3. 图示需求按受众类别配置；交互需求：含教程项写「代码与命令逐段注释，目录项可跳转」，纯讲稿项写「演示节点与章节锚点对齐」。
4. 讲稿字数上限 = 场合时长 × 200；现有字数超上限必须写明删减字数与固定顺序；字数为 0 写「新制讲稿，按字数上限控制篇幅」；纯教程写「不适用」。
5. 素材缺口与生产优先级按现有材料状态三档映射；责任人按技能类别指派（网络类顾北辰 / 系统类白景行 / 交付类陆知行 / 平台类秦风眠）。

### 硬性约束

- 交付形态只允许 {教程, 讲稿, 教程+讲稿} 三值。
- 讲稿字数上限必须等于场合时长 × 200，不得取整或调整。
- 裁剪顺序固定：先删技术细节 → 再删案例背景 → 保留主线结论。
- 不允许出现「示例」「样例」「待补充」「占位」等字样。
- 不写任何效率百分比或效果承诺。

### 生成后自检

1. 交付物是否 = 15 行，与技能清单一一对应？
2. 交付物合计是否 = 教程 11 份 + 讲稿 9 份（教程+讲稿 5 项双交付）？
3. 受众分布是否 = 客户技术侧 7 / 新入职 4 / 内部横向 3 / 非专业读者 1？
4. 讲稿裁剪是否 = 2 份共 3300 字（JN-03 删 2000 / JN-07 删 1300）？
5. 图示合计是否 = 概念图 2 / 拓扑图 8 / 流程图 7 / 操作截图 11 套？
6. 素材缺口与优先级是否均为 5/5/5？
自检全过再输出 CSV。

### 输出格式

CSV，14 列，列名与顺序固定：
技能编号, 技能主题, 技能类别, 交付形态, 受众类别, 教程大纲, 图示需求, 交互需求, 讲稿要点, 讲稿字数上限, 裁剪方案, 素材缺口, 生产优先级, 责任人

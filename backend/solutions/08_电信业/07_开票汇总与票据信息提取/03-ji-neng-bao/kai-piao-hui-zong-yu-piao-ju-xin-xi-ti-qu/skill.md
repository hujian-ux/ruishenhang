# 开票汇总与票据信息提取

## 一、这个 Skill 解决什么

票据处理的真实困难不是「没有数据」，而是**关键信息埋在冗余文本里、异常藏在格式细节里**：

- 数电票号混在「红冲说明 + 附言」的单元格里，肉眼找数又慢又错
- 税号少一位、票号位数不足，不校验就带病入账
- 红冲票据没登记关联原票号，冲正链条断在半路
- 当日应开、直开、需转换票种、实际开出几类口径混在一起，汇总靠手工
- 资产采购票据混在销售票据里，资产明细归集全凭人工挑

结果是：日终汇总靠「肉眼找数」，异常项无台账留痕，月底对账才发现冲正链条对不上。本 Skill 的核心动作，是把「提取 → 校验 → 汇总 → 归集」固化成一条流水线，每个异常都有类型和去向。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 日终开票汇总，需要应开 / 直开 / 需转换票种 / 实开四类口径 | 主用场景：逐票分类汇总 |
| 票号混在红冲说明等冗余文本里，需要提取 | 20 位 / 8 位数规则提取，多票号时排除关联原票号 |
| 税号 / 票号格式校验，异常要留痕 | 三类异常标记 + 转人工去向 |
| 资产采购票据需要归集资产明细 | 购方为本企业的票据单独归集 |

**不适用**：异常票据的补录与更正（人工）；需转换票种的转开决定（人工）；红字发票的代开（税控权限属于人）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `开票与票据数据.csv` | 必需 | 票据序号、票据号码原文、票据类型、购方名称、购方税号、票面金额元、开票状态、关联原票据号、业务内容 |
| 2 | `票据校验规则.md` | 必需 | 票号位数规则、票号提取规则、税号校验、红冲规则、开票类别口径、资产归集口径 |

> 缺 2（校验规则）时，本 Skill **必须拒绝输出校验结论**——票号位数（20 位 / 8 位）与税号位数（18 位）必须显式给定，不允许默认值。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`开票汇总与票据校验表.csv`，字段固定为 14 列：

```
票据序号, 提取后票据号, 票据类型, 购方抬头, 购方税号, 票面金额元, 开票状态,
票号校验, 税号校验, 校验结果, 异常类型, 资产归集, 开票类别, 处理建议
```

- `票号校验` ∈ {通过, 位数不足, 不适用（未开票）}
- `税号校验` ∈ {通过, 位数异常}
- `校验结果` ∈ {通过, 异常}；`异常类型` ∈ {无, 税号位数异常, 票号位数不足, 红冲关联缺失}
- `资产归集` ∈ {归集资产明细, 不归集}
- `开票类别` ∈ {当日已开, 按规则直开, 需转换票种, 红字冲销}
- `处理建议` 逐票写明去向（正常流转 / 转人工补录 / 转开数电专票后入库 / 红冲留痕备查）

## 五、工作流程（workflow）

### STEP 1 · 读规则，先立校验口径再看票

从 `票据校验规则.md` 读入票号位数、提取规则、税号位数、红冲规则与汇总口径，写成显式判定表。**顺序不可颠倒**——先看票据再定规则，等于边校验边改标准。

```
票号：数电 20 位 / 纸质 8 位；未开票记不适用
提取：冗余文本中取位数匹配的连续数字；多票号时排除关联原票据号
税号：18 位统一社会信用代码
红冲：金额为负 + 必须带关联原票据号
```

### STEP 2 · 票号提取

从「票据号码原文」提取位数匹配的连续数字：

| 情形 | 处理 |
| --- | --- |
| 原文干净（纯票号） | 直接提取 |
| 含红冲说明、多个 20 位号码 | 排除关联原票据号，取剩余（红字现票） |
| 最长数字串位数不足 | 记「位数不足」，转人工核实 |
| 未开票 | 提取后票据号置空，记「不适用（未开票）」 |

### STEP 3 · 逐票校验

- 税号 18 位校验，位数异常 → 「税号位数异常」
- 红字票据：金额为负 + 关联原票据号非空，缺失 → 「红冲关联缺失」
- 任一校验不过 → `校验结果 = 异常`，写明异常类型与处理建议

### STEP 4 · 开票类别汇总

按「当日已开 / 按规则直开 / 需转换票种 / 红字冲销」逐票归类；日终口径：已开合计、应开合计、红字合计、净开票金额（已开 + 红字）。

### STEP 5 · 资产归集

购方为本企业（某终端分销与供应链企业）的资产采购票据 → 归集资产明细；渠道客户销售票据 → 不归集，计入销售开票台账。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出（见附录「生成后自检」）。

## 六、关键规则（不可协商）

1. **校验规则必须来自规则文件。** 票号 20 位 / 8 位、税号 18 位是本案例给定口径，不允许 AI 自行默认或调整。
2. **红冲链条必须闭合。** 红字票据金额为负且必须带关联原票据号，缺失即异常——冲正链条断了，月底对账就是对不上的那笔。
3. **异常不擅自修复。** 税号补位、票号核实、关联补登记全部转人工；AI 只标记类型与去向，不代改。
4. **提取必须可复算。** 提取后票据号来自原文的连续数字，任何人在原文里都能重新圈出来。
5. **需转换票种的转开属于人工。** AI 只按业务内容标记「需转换票种」，不代开。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（财务开票岗） |
| --- | --- |
| 票号提取与位数校验 | 异常票据补录与更正 |
| 税号校验与异常标记 | 需转换票种的转开决定 |
| 开票口径汇总与资产归集标记 | 红字发票开具（税控权限） |

## 八、下游衔接

- 异常票据清单 → 财务开票岗补录台账（留痕可追溯）
- 需转换票种票据 → 转开数电专票后重新入池
- 资产明细归集 → 固定资产台账（→ 财务月结）
- 开票汇总口径 → 经营分析（→ TCM-08 经营分析可视化）

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读规则再看票：把票号位数（数电 20 位 / 纸质 8 位）、税号位数（18 位）、红冲规则、开票类别口径写成显式判定表。
2. 票号提取：从「票据号码原文」提取位数匹配的连续数字；含红冲说明且出现多个 20 位号码时，排除「关联原票据号」列已登记号码，取剩余（红字现票）；未开票的应开行提取后票据号置空、票号校验记「不适用（未开票）」。
3. 逐票校验：税号位数 ≠18 → 「税号位数异常」；最长数字串不足票号位数 → 「票号位数不足」；红字票据金额非负或关联原票据号缺失 → 「红冲关联缺失」。任一命中即校验结果=异常。
4. 开票类别：已开出 → 当日已开；应开未开且业务内容无转开说明 → 按规则直开；应开未开且业务内容含「需转开数电专票」→ 需转换票种；数电发票（红字）→ 红字冲销。
5. 资产归集：购方名称为「某终端分销与供应链企业」且业务内容为资产采购 → 归集资产明细；其余 → 不归集。
6. 处理建议逐票写明：正常流转 / 转人工补录税号 / 转人工核实票号 / 转人工补关联原票号 / 转开数电专票后入库 / 红冲留痕备查。

### 硬性约束

【硬性约束】
- 异常票据只标记类型与处理建议，不擅自补录、改写或代开。
- 红字票据金额必须为负且必须登记关联原票据号，缺失即异常。
- 票号提取必须来自原文连续数字，可人工复圈，不允许凭空构造。
- 资产归集以购方名称 = 本企业泛称为准，不允许按金额大小猜测。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输入 22 票是否逐票对应输出 22 行，序号一致？
2. 校验异常是否恰 3 票：税号位数异常 1（17 位）/ 票号位数不足 1（19 位）/ 红冲关联缺失 1？
3. 开票类别是否为当日已开 14 / 按规则直开 4 / 需转换票种 2 / 红字冲销 2？
4. 已开合计 4,942,000 元、红字合计 −140,000 元、净开票 4,802,000 元、应开未开合计 1,367,000 元是否可复算？
5. 资产归集是否恰 3 票、合计 486,000 元，且全部购方为本企业泛称？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，14 列，列名与顺序固定：
票据序号, 提取后票据号, 票据类型, 购方抬头, 购方税号, 票面金额元, 开票状态, 票号校验, 税号校验, 校验结果, 异常类型, 资产归集, 开票类别, 处理建议

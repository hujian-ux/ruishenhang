# 新产品数据模型建表与映射规范化

## 一、这个 Skill 解决什么

新产品数据建模的真实困难是**规则明确、重复度高、人工极易遗漏**：

- 建表语句逐张手写，字段命名各写各的，两个版本的表结构对不上
- 对象映射靠人工台账维护，新增对象一多必然漏
- 输入写错（对象不存在、类型乱写）要到建表执行才报错
- 模型定义与代码实现脱节，改了表结构忘了改代码

本 Skill 的核心动作，是把规范写死、把映射分三类、把缺口显式登记——让输出天然一致，遗漏无处藏身。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 新版本交付，要为一批新对象（服务器型号）建数据表 | 主用场景：批量生成规范化 DDL 要点 |
| 新对象要和老系统字段逐一对齐 | 映射三分类 + 缺口登记 |
| 老系统枚举/类型口径和新平台不一致 | 编码对照表 + 固定转换规则 |
| 拿到一份字段清单，不确定能不能直接建表 | 前置校验：非真实对象直接拦截 |

**不适用**：已定版模型的物理性能调优（索引策略权衡属 DBA 职责）；跨平台数据迁移的批量数据搬运。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `新产品字段清单.csv` | 必需 | 字段编号（F01~）、字段名、数据类型、枚举值域、老系统对应字段、备注 |
| 2 | `建表与映射规范.md` | 必需 | 前置校验、建表基线、映射三分类、枚举与类型归一规则、缺口处理 |

> 缺 2（规范文件）时，本 Skill 必须拒绝输出——没有规范就没有归一与缺口的判定依据。

## 四、输出（outputs）

唯一交付物：`数据模型与映射表.csv`，字段固定为 7 列：

```
字段编号, 字段名, 数据类型, 老系统对应字段, 建表DDL要点, 映射结果, 缺口处理
```

- `映射结果` ∈ {直接对齐, 归一转换（枚举统一）, 归一转换（类型转换）, 老系统缺失（待补建）}
- `建表DDL要点` 必须含具体约束（NOT NULL / CHECK / 唯一索引 / COMMENT 对照关系），不允许只写「按规范」
- `缺口处理` 直接对齐行写「无缺口；核对通过」，其余行必须写明归一规则或补建回填要求

## 五、工作流程（workflow）

### STEP 1 · 前置校验

确认输入对象是平台中真实存在的对象；字段清单含字段名、类型、枚举值域、老系统对应字段四要素。校验不过 → 提示并停止。

### STEP 2 · 按基线生成建表要点

命名小写下划线、单位固化进字段名（`_gb`/`_w`/`_c`/`_db`）、数值不带单位文本、枚举显式声明值域、必带 COMMENT、数值范围加 CHECK。

### STEP 3 · 逐字段映射三分类

老系统字段同名同义且类型一致 → 直接对齐；名称/类型/枚举口径不一 → 归一转换；老系统无对应字段 → 老系统缺失（待补建）。

### STEP 4 · 枚举与类型归一

枚举统一走编码对照表（对照关系写入 COMMENT）；类型转换按固定规则：文本数字→数值（剥离单位）、容量文本→固定单位数值、文本路数→数值、标记位→枚举、区间文本→结构化格式。

### STEP 5 · 缺口登记与交付

老系统缺失字段由新平台先建并登记缺口清单，标记待补建回填；输出逐字段核对后的映射表，与建表产物一并交付。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出（见附录「生成后自检」）。

## 六、关键规则（不可协商）

1. **前置校验先于一切。** 非平台真实对象直接提示并停止，不产出任何建表内容。
2. **缺口禁止静默丢弃。** 老系统缺失字段必须显式标记「待补建回填」，不得删字段、不得用空值顶替了事。
3. **枚举统一必须留对照。** 老编码到新值域的逐值对照关系必须写入 COMMENT，供事后追溯。
4. **单位固化进字段名。** `_gb`/`_w`/`_c`/`_db` 后缀与数值类型绑定，禁止带单位文本入库。
5. **人工边界不可越。** 字段业务含义与枚举值域的最终裁定属于数据架构师；补建排期与建表执行放行属于人。
6. **不写效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（数据架构师） |
| --- | --- |
| 前置校验与拦截提示 | 输入对象真实性的最终确认 |
| 建表 DDL 要点批量生成 | 字段业务含义与枚举值域裁定 |
| 映射三分类与归一规则执行 | 老系统补建排期与上线窗口 |
| 缺口清单登记与回填要求 | 建表语句执行前的复核与放行 |

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

1. 先做前置校验：输入对象必须是平台真实对象，字段清单四要素（字段名/类型/枚举值域/老系统对应字段）齐全，不合规直接提示并停止。
2. 逐字段生成建表 DDL 要点：命名小写下划线、单位固化进字段名、枚举显式声明值域、必带 COMMENT、数值范围加 CHECK、主键与唯一约束显式命名。
3. 映射三分类逐字段给出结论：直接对齐 / 归一转换（枚举统一 / 类型转换）/ 老系统缺失（待补建）。
4. 归一转换写明规则：枚举附编码对照，类型转换写明剥离单位/换算口径；缺失字段写明「新平台先建并登记缺口，待老系统补建后回填」。
5. 保持输入字段编号（F01~F25）与原始顺序，逐行对应，不得增删行。

### 硬性约束

- 不允许出现任何真实客户名/品牌名/产品名，案例主体统一以泛称「某算力设备制造企业」叙述。
- 每行「建表DDL要点」必须含具体约束或 COMMENT 内容，不允许只写「按规范执行」。
- 老系统缺失字段不得从输出中删除或以空值顶替，必须显式标记待补建。
- 不允许出现任何未完成的标记或留空待办的表述。
- 不写任何效率百分比或效果承诺。

### 生成后自检

1. 输出是否 25 行，字段编号 F01~F25 与输入一致、顺序不变？
2. 映射分布是否为：直接对齐 12 / 归一转换 8（枚举统一 4 + 类型转换 4）/ 老系统缺失 5？
3. 缺失字段是否恰为 F14/F19/F20/F22/F23，且均标记待补建回填？
4. 枚举字段是否全部显式声明值域，归一行的 COMMENT 对照是否写明？
5. 全表是否无真实企业名、无未完成标记、无效率百分比？
自检全过再输出 CSV。

### 输出格式

CSV，7 列，列名与顺序固定：
字段编号, 字段名, 数据类型, 老系统对应字段, 建表DDL要点, 映射结果, 缺口处理

# ENG-11 主提示词 · 新产品数据模型建表与映射规范化

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/新产品数据模型建表与映射规范化/SKILL.md`）。
2. 上传两个附件：`新产品字段清单.csv`、`建表与映射规范.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `数据模型与映射表.csv` 后，按文末「验收清单」逐项核对。

## 主提示词（复制即用）

```
请基于我上传的两份素材，为「某算力设备制造企业 · 新产品数据模型」做建表与老系统字段映射规范化，输出一张可复核的数据模型与映射表。

【输入 1 · 新产品字段清单】新产品字段清单.csv（25 行）
- 含字段名、数据类型、枚举值域与老系统对应字段；部分字段老系统无对应或口径不一
- 字段编号 F01~F25，输出保持原编号与顺序

【输入 2 · 建表与映射规范】建表与映射规范.md
- 输入对象先做前置校验：非平台真实对象直接提示并停止；建表按命名与类型基线统一生成
- 映射分三类：直接对齐 / 归一转换（枚举走编码对照、类型按固定规则）/ 老系统缺失（标记待补建回填，禁止静默丢弃）

【输出】数据模型与映射表.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「新产品数据模型建表与映射规范化」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **25 个字段的映射分布？** 期望回答：直接对齐 12 / 归一转换 8（枚举统一 4：产品形态、硬盘规格、电源冗余、散热方式 + 类型转换 4：CPU 路数、内存容量、电源功率、额定电压）/ 老系统缺失 5。
2. **哪 5 个字段老系统没有？** 期望回答：F14 PCIe 插槽数 / F19 带外管理口 / F20 工作温度下限 / F22 噪音等级 / F23 认证列表——均标记待补建回填，不得静默丢弃。
3. **「550W」这种带单位的值怎么处理？** 期望回答：类型转换规则——剥离单位文本后以 INT 入库，单位 W 固化进字段名 psu_power_w。
4. **产品形态的枚举怎么归一？** 期望回答：编码对照 2U→2U机架 / 4U→4U机架 / MD→多节点 / HD→高密度，对照关系写入 COMMENT。
5. **如果输入的型号在平台里不存在会怎样？** 期望回答：前置校验不通过，直接提示并停止，不产出任何建表内容。

## 验收清单

- [ ] 输出 25 行，字段编号 F01~F25 与输入一致、顺序不变
- [ ] 映射分布 = 直接对齐 12 / 归一转换 8（枚举 4 + 类型 4）/ 老系统缺失 5
- [ ] 缺失字段 = F14 / F19 / F20 / F22 / F23，均标记待补建回填
- [ ] 每行建表 DDL 要点含具体约束或 COMMENT 对照，无「按规范执行」这类空话
- [ ] 枚举字段全部显式声明值域；单位固化命名（_gb/_w/_c/_db）落地
- [ ] 全表无真实企业名、无未完成标记、无效率百分比

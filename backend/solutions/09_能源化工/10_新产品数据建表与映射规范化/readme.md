# ENG-11 · 新产品数据模型建表与映射规范化 —— 场景使用说明

- **行业**：制造与能源
- **角色**：产品数据岗
- **场景编号**：ENG-11
- **案例主体**：某算力设备制造企业（服务器与算力基础设施制造商）

## 一、文件清单

| 文件 | 类型 | 作用 |
| --- | --- | --- |
| `03_技能包/新产品数据模型建表与映射规范化/SKILL.md` | Skill 定义 | 前置校验、建表基线、映射三分类、枚举与类型归一规则与人工边界 |
| `主提示词.md` | 提示词 | 学员实际发送的主提示词 + 关键追问 + 验收清单 |
| `新产品字段清单.csv` | 原始输入 | 25 行字段明细：字段名 / 数据类型 / 枚举值域 / 老系统对应字段，含 5 处映射缺失 |
| `建表与映射规范.md` | 原始输入 | 前置校验、命名与类型基线、映射三分类、归一规则与缺口处理 |
| `数据模型与映射表.csv` | **交付物** | 25 行：建表 DDL 要点 × 映射结果 × 缺口处理 |
| `产品数据岗-新产品数据模型建表与映射规范化.zip` | Skill 包 | 仅含 SKILL.md 的技能定义，可直接导入 WorkBuddy 启用 |

## 二、使用步骤

1. 在 WorkBuddy 左侧「专家·技能·连接器」→「添加技能 → 上传技能」，导入本 Skill 包并在「已安装」中启用。
2. 上传 `新产品字段清单.csv`、`建表与映射规范.md` 两份素材。
3. 复制 `主提示词.md` 中的主提示词发送。
4. 按 `主提示词.md` 文末「验收清单」核对输出。
5. 字段业务含义与枚举值域交数据架构师终裁；缺口字段（F14/F19/F20/F22/F23）的补建排期由人决定，AI 只登记与回填要求。

### 可复算口径

- 映射结果 = f(字段)：老系统对应字段为「无对应字段」→ 老系统缺失（待补建）；属枚举口径组 → 归一转换（枚举统一）；属类型口径组 → 归一转换（类型转换）；其余 → 直接对齐
- 缺口处理 = 直接对齐 → 无缺口核对通过；归一 → 编码对照/固定转换规则；缺失 → 新平台先建并登记，待补建后回填

## 四、与案例链的数字对齐

| 数字 | 出处 | 在本场景的落点 |
| --- | --- | --- |
| 25 个字段 | 页面案例卡 | 输入 25 行 + 交付物 25 行 |
| 直接对齐 12 / 归一 8 / 缺失 5 | 页面 standfirst 与案例卡 | gen 脚本断言 |
| 归一 8 = 枚举统一 4 + 类型转换 4 | 素材「字段对齐/枚举统一」场景 | gen 脚本断言 |
| 缺失 5 = F14/F19/F20/F22/F23 | 素材「映射无遗漏」 | 输入「无对应字段」行 + 交付物缺口处理列 |
| 枚举对照 2U→2U机架 等 | 素材「枚举统一」 | F03 建表 DDL 要点 COMMENT |
| 单位固化 _gb/_w/_c/_db | 建表基线 | 字段命名与 DDL 要点 |

## 五、真实性等级与边界

- **T2**：建表规范化与映射维护方法论来自客户应用案例素材（建表语句生成、对象映射维护、输入前置校验）。
- **T3**：岗位痛点来自素材中的业务特征描述。
- **构造**：字段清单与映射结论按素材场景构造，口径可由 gen 脚本复算。
- **升 T1 还缺**：客户真实建表工单与一次映射遗漏复盘记录。
- **人工边界**：字段业务含义与枚举值域终裁、老系统补建排期、建表执行放行一律人工；AI 只生成 DDL 要点、执行归一规则、登记缺口。

# 新产品数据模型建表与映射规范

适用范围：某算力设备制造企业产品数据岗，新产品（服务器型号）对象建表与老型号字段映射规范化。

## 1. 前置校验（不合规直接拦截）

- 输入对象必须是平台中**真实存在的对象**；校验不通过 → 给出提示并停止，不进入建表。
- 字段清单必须含字段名、数据类型、枚举值域、老系统对应字段四要素，缺失即拦截。

## 2. 建表基线

- **命名**：小写下划线；单位固化进字段名（`_gb` / `_w` / `_c` / `_db`）。
- **类型**：数值一律数值型，禁止带单位文本入库；枚举字段必须显式声明值域。
- 每字段必带 `COMMENT`；主键与唯一约束显式命名。
- 数值范围加 `CHECK`；默认值须与业务口径一致。

## 3. 映射三分类

| 分类 | 判定 | 处理 |
| --- | --- | --- |
| 直接对齐 | 老系统字段同名同义且类型一致 | 核对通过，登记映射关系 |
| 归一转换 | 名称 / 类型 / 枚举口径不一 | 枚举走编码对照表，类型按固定规则转换后入库 |
| 老系统缺失 | 老系统无对应字段 | 新平台先建并登记，标记**待补建回填**，禁止静默丢弃 |

## 4. 枚举与类型归一规则

- **枚举统一**：老编码 → 新值域逐值对照，对照关系写入 `COMMENT`（如 prod_form 的 2U→2U机架 / 4U→4U机架 / MD→多节点 / HD→高密度）。
- **类型转换**：文本数字→数值（剥离单位，如「550W」→ 550）；容量文本→固定单位数值（如「2TB」→ 2048 GB）；文本路数→数值（单路=1 / 双路=2 / 四路=4）；标记位→枚举；区间文本→结构化格式。

## 5. 缺口处理

- 老系统缺失字段由新平台先建并登记缺口清单，待老系统补建后回填映射。
- 缺口字段不得从模型中删除，也不得用空值顶替了事——必须显式标记。

## 6. 人工边界

- 字段业务含义与枚举值域的**最终裁定**属于数据架构师。
- 老系统补建字段的排期与上线窗口由人决定；AI 只登记缺口与回填要求。
- 建表语句在平台执行前的复核与放行属于人。

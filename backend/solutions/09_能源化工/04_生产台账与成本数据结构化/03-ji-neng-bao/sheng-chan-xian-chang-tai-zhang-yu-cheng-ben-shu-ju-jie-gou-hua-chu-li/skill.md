# 生产现场台账与成本数据结构化处理

## 一、这个 Skill 解决什么

生产现场台账的真实困难不是「没有数据」，而是**数据散在各处的格式里**：

- 交接班记录一半是纸质本，一半是各车间自己画的散表，字段名和单位各写各的
- 产量、电耗、辅料、人工分散在不同人手里，月末才拼到一起
- 单位成本要拿计算器逐行按口径折算，口径换了就得整月重算
- 电耗超标、辅料异常这类信号，往往要等成本月报出来才发现，滞后半个月

结果是：**台账记了，但算不了、比不了、追不了**。本 Skill 的核心动作，是先把散表按统一 schema 归一，再按固定成本口径计算单位成本，并按车间阈值逐行留异常痕迹。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 每日/每周交接班台账要入共享台账 | 主用场景：纸质或拍照记录 → 统一 schema 结构化 |
| 需要按车间、按日看单位成本 | 电耗、辅料、人工按固定口径折算成 元/吨 |
| 现场电耗或辅料异常要当班发现 | 按车间阈值逐行判定，命中即标注类型与实测值 |
| 成本科要复核现场数据 | 结构化结果可复算：每行都能回到原始记录 |

**不适用**：跨车间工艺参数优化（属工艺工程分析）；集团多口径财务合并（→ ENG-06 集团财务与数据多口径分析）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `车间台账原始记录.csv` | 必需 | 序号、车间、日期、产量吨、电耗kWh、辅料成本元、人工成本元 |
| 2 | `结构化与成本口径.md` | 必需 | 统一 schema 定义、电价 0.68 元/kWh、成本计算公式、各车间异常阈值 |

> 缺 2（口径文件）时，本 Skill **必须拒绝输出单位成本列**——没有书面口径的成本数不可入台账。这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`台账结构化与单位成本表.csv`，字段固定为 11 列：

```
车间, 日期, 产量吨, 电耗kWh, 电力成本元, 辅料成本元, 人工成本元, 合计成本元,
单位电耗kWh每吨, 单位成本元每吨, 异常标注
```

- `电力成本元` = 电耗kWh × 0.68，保留 2 位小数
- `合计成本元` = 电力成本元 + 辅料成本元 + 人工成本元，保留 2 位小数
- `单位电耗kWh每吨`、`单位成本元每吨` 保留 1 位小数
- `异常标注` ∈ {正常, 单位电耗超限, 单位成本超基准, 两项以「；」连接并附异常原因}

## 五、工作流程（workflow）

### STEP 1 · 读口径，先立 schema 再看数据

从 `结构化与成本口径.md` 读入统一 schema、电价、公式与各车间阈值，写成显式判定表。**顺序不可颠倒**——先看数据再定口径，等于给结果找理由。

```
电价 0.68 元/kWh
单位电耗阈值：熔铸 470 / 挤压 140 / 盘拉 120 / 退火 240（kWh/吨）
单位成本基准：熔铸 740 / 挤压 500 / 盘拉 580 / 退火 400（元/吨）
```

### STEP 2 · 转录清洗：散表 → 统一 schema

逐条核对车间名是否为 4 个枚举值之一、日期是否在统计区间、产量与成本是否为正数；发现变体写法、越界日期、空值时**不得擅自补写**，标记退回现场核实。

### STEP 3 · 成本计算

按口径公式逐行计算电力成本、合计成本、单位电耗、单位成本，保留位数按口径文件执行，不做四舍五入之外的修饰。

### STEP 4 · 异常判定与留痕

对照该车间阈值逐行判定：单位电耗高于阈值标「单位电耗超限」，单位成本高于基准标「单位成本超基准」，两项同时命中用「；」连接。异常原因由现场确认后补记，AI 不得编造。

### STEP 5 · 自检与人工确认声明

输出前逐项自检（见附录），任一不过则不得输出。结构化结果须经现场管理岗逐行确认后才写入共享台账，确认前一律为草稿。

## 六、关键规则（不可协商）

1. **沿用既有表结构，不新增字段。** 转录只做归一，不改 schema；新增字段会破坏与历史台账的可比性。
2. **口径先于数据。** 电价、公式、阈值一律以书面口径文件为准；口径变更须由成本科书面确认并同步口径文件，不得在台账层面临时调整。
3. **每行可回溯。** 输出表任意一行的任意数字，都能用原始记录行的产量/电耗/辅料/人工按口径复算得出；复算不一致即为错误。
4. **异常必须留痕。** 标注要写明规则类型与实测值；不带实测值的「感觉偏高」不是合格标注。
5. **AI 不编造异常原因。** 异常原因由现场管理岗确认后补记，AI 只做规则判定。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（现场管理岗 / 成本科） |
| --- | --- |
| 散表转录清洗与统一 schema 归一 | 纸质原件与转录结果的逐行确认 |
| 电力成本、单位成本按口径计算 | 电价与成本口径变更的书面确认 |
| 异常规则判定与类型标注 | 异常原因的现场核实与补记 |
| 结构化草稿整理 | 确认后写入共享台账的动作 |

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读口径再看数据：把统一 schema、电价 0.68 元/kWh、成本公式与各车间阈值写成显式判定表。
2. 转录清洗：车间名仅允许熔铸/挤压/盘拉/退火 4 个枚举值；日期限 2026-09-07 至 09-12；产量为 0 或成本为负的记录不得写入，标记退回现场核实。
3. 成本计算：电力成本元 = 电耗kWh × 0.68（2 位小数）；合计成本元 = 电力成本元 + 辅料成本元 + 人工成本元（2 位小数）；单位电耗kWh每吨 = 电耗kWh ÷ 产量吨（1 位小数）；单位成本元每吨 = 合计成本元 ÷ 产量吨（1 位小数）。
4. 异常判定：按车间阈值（单位电耗：熔铸 470 / 挤压 140 / 盘拉 120 / 退火 240；单位成本基准：熔铸 740 / 挤压 500 / 盘拉 580 / 退火 400）逐行判定，命中即标注类型，两项同时命中以「；」连接并附现场确认的异常原因；未命中标注「正常」。

### 硬性约束

【硬性约束】
- 不新增 schema 字段，不污染车间枚举值，沿用既有表结构。
- 保留位数严格按口径文件执行，不做其他修饰；任何数字不四舍五入以外的加工。
- 异常标注必须含规则类型与实测值对比（如 485.7>470）；AI 不得编造异常原因。
- 全表 24 行，每个原始记录行有且仅有一行输出，不得增删行。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输出是否为 24 行，与原始记录行一一对应？
2. 任意行合计成本元是否 = 电力成本元 + 辅料成本元 + 人工成本元（误差 ≤0.01 元）？
3. 任意行单位成本元每吨是否 = 合计成本元 ÷ 产量吨（1 位小数）？
4. 异常行是否写明类型与实测值，正常行是否全部低于阈值？
5. 是否没有任何一行出现编造的异常原因或与场景无关的标注说明？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，11 列，列名与顺序固定：
车间, 日期, 产量吨, 电耗kWh, 电力成本元, 辅料成本元, 人工成本元, 合计成本元, 单位电耗kWh每吨, 单位成本元每吨, 异常标注

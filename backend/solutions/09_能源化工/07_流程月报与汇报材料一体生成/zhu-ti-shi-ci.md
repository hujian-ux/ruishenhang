# ENG-08 主提示词 · 流程月报与汇报材料一体化生成

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/流程月报与汇报材料一体化生成/SKILL.md`）。
2. 上传两个附件：`流程执行月度数据.csv`、`月报模板.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `流程月报与汇报材料表.csv` 后，按文末「验收清单」逐项核对。

---

## 主提示词（复制即用）

```
请基于我上传的两份素材，为「某消费电子制造企业 · 研发流程月度汇报」做流程执行数据汇总与达标判定，输出一张可复核的流程月报与汇报材料表。

【输入 1 · 流程执行月度数据】流程执行月度数据.csv（18 行）
- 含流程编号、流程名称、所属流程域、本月发起量、本月完成量、平均处理时长小时、主要卡点
- 完成率 = 本月完成量 ÷ 本月发起量；时长与目标时长的比较按流程域查表

【输入 2 · 月报模板】月报模板.md
- 达标判定三级口径：达标 / 关注 / 改进；目标时长按流程域给定
- 卡点按关键词归因；汇报要点问题逐条列出，不做归类堆叠，表述通俗化

【输出】流程月报与汇报材料表.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「流程月报与汇报材料一体化生成」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **整体口径是多少？** 期望回答：18 条流程，总发起 1669 / 总完成 1592，整体完成率 95.4%，达标 12 / 关注 4 / 改进 2。
2. **F02 完成率 95.6% 为什么不是达标？** 期望回答：平均时长 52 小时超过研发域目标 48 小时（≤57.6 小时的 1.2 倍容差内），完成率 ≥80%，判为「关注」——完成率高不等于时长达标。
3. **F10 工程变更ECN 为什么直接判改进？** 期望回答：完成率 71.4%（25/35）低于 80%，卡点「变更影响面评估周期长」，无论时长如何都进「改进」档。
4. **卡点最集中在哪里？** 期望回答：跨部门协同 7 条（F01/F05/F08/F09/F13/F15/F16）居首，占 38.9%。
5. **改进项下月怎么盯？** 期望回答：F09 质量问题复盘（跨部门结论难约定）、F10 工程变更ECN，列入月度专项治理，逐条写明责任人与节点。

## 验收清单

- [ ] 表 18 行，与流程执行月度数据一一对应
- [ ] 完成率逐行 = 完成量 ÷ 发起量（1 位小数）
- [ ] 综合判定分布 = 达标 12 / 关注 4（F02/F05/F08/F15）/ 改进 2（F09/F10）
- [ ] 卡点归因分布 = 跨部门协同 7 / 资源与工具 4 / 审批流转 3 / 标准与口径 3 / 无明显卡点 1
- [ ] 汇报要点逐条列出，格式统一，无归类堆叠
- [ ] 全表无效率百分比承诺，原始数据未被修改

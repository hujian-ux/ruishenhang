# 流程月报与汇报材料一体化生成

## 一、这个 Skill 解决什么

周期性汇报的真实困难不是「数据难拿」，而是**格式固定、内容常变、对象多样**把人耗住：

- 数据分散在多张表，汇总靠人工搬运，每次月报都像重新做一遍
- 完成率算完还要逐条对比目标时长，达标与否的口径因人而异
- 卡点描述五花八门，管理层问「卡点到底集中在哪」答不上来
- 换一个汇报对象就要重写一版表述；演示稿、可打印文档、网页版各改一遍

本 Skill 的核心动作：**读本月数据 → 统一判定口径 → 逐条生成汇报要点 → 月报正文与演示稿大纲一体化产出**。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 月度流程汇报成稿 | 主用场景：正文 + 演示稿大纲一次生成 |
| 管理层追问「卡点集中在哪」 | 卡点归因口径统一，占比一眼可读 |
| 换受众需要调整详略与措辞 | 数据口径不变，只调表述 |
| 材料更新后需重新生成并分发 | 数据同源，转换格式不重做 |

**不适用**：目标时长与判定阈值的修订（→ 流程管理团队决策）；单条流程的深度审计（→ 专项分析）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `流程执行月度数据.csv` | 必需 | 流程编号、流程名称、所属流程域、本月发起量、本月完成量、平均处理时长小时、主要卡点 |
| 2 | `月报模板.md` | 必需 | 五段式月报结构、达标判定三级口径、目标时长表、卡点归因口径、汇报要点生成规则 |

> 缺 2（月报模板）时，本 Skill **必须拒绝输出判定结论**——没有目标时长表就没有达标口径，产出的只是数字堆砌。

## 四、输出（outputs）

唯一交付物：`流程月报与汇报材料表.csv`，字段固定为 13 列：

```
流程编号, 流程名称, 所属流程域, 本月发起量, 本月完成量, 完成率, 平均处理时长小时,
目标时长小时, 综合判定, 主要卡点, 卡点归因, 汇报要点, 下月行动
```

- `完成率` = 本月完成量 ÷ 本月发起量，保留 1 位小数百分数呈现
- `综合判定` ∈ {达标, 关注, 改进}，判定条件命中即停、逐行可复算
- `汇报要点` 固定格式：`流程名称：完成率 X%（完成/发起），判定为「XX」；卡点：XX`

## 五、工作流程（workflow）

### STEP 1 · 读模板，先立口径再看数据

从 `月报模板.md` 读入三级判定口径与目标时长表，写成显式判定表。**先定标准再看数据**。

### STEP 2 · 逐条汇总与判定

对 18 条流程逐条计算完成率、查表对比目标时长，命中即停地判出达标 / 关注 / 改进。

### STEP 3 · 卡点归因

按关键词口径归因（无明显卡点 / 审批流转 / 资源与工具 / 标准与口径 / 跨部门协同），输出归因分布。

### STEP 4 · 汇报要点与下月行动生成

每条流程按固定格式生成汇报要点；下月行动按判定分档：达标→维持监控，关注→卡点专项跟进，改进→列入月度专项治理并明确责任人与节点。

### STEP 5 · 正文与演示稿大纲一体化

按五段式结构组装月报正文，演示稿大纲固定三条：整体口径、最大卡点归因、改进项清单。换受众只调详略，数据口径不动。

### STEP 6 · 自检与人工边界声明

输出前逐项自检，任一不过则不得输出（见附录「生成后自检」）。

## 六、关键规则（不可协商）

1. **判定口径唯一。** 达标 / 关注 / 改进按目标时长表与三级口径逐行判出，不允许「整体看还行」式结论。
2. **问题逐条列出。** 汇报要点不归类堆叠，一条流程一行证据，通俗化表达。
3. **多受众同源。** 换受众只调整详略与措辞，任何版本的数据口径必须一致。
4. **归因可追溯。** 每条卡点归因都能指回原始描述，不允许凭印象归类。
5. **不承诺效率百分比。** 输出中不写「提效 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（流程管理岗） |
| --- | --- |
| 多源数据汇总与完成率计算 | 目标时长与判定阈值的修订 |
| 三级口径判定与归因 | 改进项责任人与节点的确定 |
| 汇报要点与演示稿大纲生成 | 材料的最终签发 |
| 格式转换与定向分发执行 | 汇报结论的解读与答辩 |

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

1. 先读模板再看数据：把三级判定口径、目标时长表、卡点归因口径写成显式判定表。
2. 逐条判定：完成率 = 本月完成量 ÷ 本月发起量（保留 1 位小数）；达标 = 完成率 ≥90% 且时长 ≤ 目标；关注 = 完成率 ≥80% 且时长 ≤ 目标 × 1.2；改进 = 其余，命中即停。
3. 卡点归因：无明显卡点 → 审批流转（档期/签批/影响面评估）→ 资源与工具（工具/环境/排队/超时）→ 标准与口径（标准/定级/模板）→ 跨部门协同（默认）。
4. 汇报要点固定格式：`流程名称：完成率 X%（完成/发起），判定为「XX」；卡点：XX`。
5. 下月行动按判定分档：达标→维持监控，纳入例行看板；关注→卡点专项跟进；改进→列入月度专项治理（明确责任人与节点）。

### 硬性约束

- 判定只允许三种取值，且必须与完成率、时长的复算结果一致。
- 汇报要点逐条列出，不做归类堆叠；面向管理层不使用内部缩写。
- 目标时长只按流程域查表取值，不允许按单条流程另行设目标。
- 不写任何效率百分比或效果承诺。
- 不修改原始数据；数据修正属于流程管理团队。

### 生成后自检

【生成后自检，逐条回答】
1. 18 行输出是否与流程清单一一对应？
2. 每行完成率是否 = 完成量 ÷ 发起量（1 位小数）？
3. 综合判定分布是否可复算？（本案例应为：达标 12 / 关注 4 / 改进 2）
4. 卡点归因分布是否与关键词口径一致？（跨部门协同 7 / 资源与工具 4 / 审批流转 3 / 标准与口径 3 / 无明显卡点 1）
5. 汇报要点是否逐条列出且格式统一？
自检全过再输出 CSV。

### 输出格式

CSV，13 列，列名与顺序固定：
流程编号, 流程名称, 所属流程域, 本月发起量, 本月完成量, 完成率, 平均处理时长小时, 目标时长小时, 综合判定, 主要卡点, 卡点归因, 汇报要点, 下月行动

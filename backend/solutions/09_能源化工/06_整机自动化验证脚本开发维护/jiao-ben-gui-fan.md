# 整机自动化验证脚本规范

适用范围：整机功能与稳定性验证脚本的批量生成、结构约束与版本维护。所有「可自动化」测试项统一按本规范生成脚本，人工保留项只登记执行安排。

## 1. 脚本命名规范

```
AUTO_<类型码>_<测试项编号>_<测试项名称>.py
```

- 类型码：信号类=SIG、接口类=IFC、显示类=DSP、音频类=AUD、网络类=NET、系统类=SYS
- 测试项名称写入脚本名时去掉全角括号（如「信源自动识别（HDMI1）」→「信源自动识别HDMI1」）
- 同一测试项升级版本时只改脚本内部版本号，不改脚本名

## 2. 脚本结构规范（五段式）

每支脚本固定包含五段：`初始化（设备连接） → 前置动作 → 执行步骤 → 结果断言 → 日志回收`。

**主函数注释中的步骤编号必须与实际代码步骤严格一致**：注释编号从 1 起连续递增，代码步骤顺序不得与注释错位；每支脚本交付前必须完成一次全量注释对齐校验。

## 3. 前置动作规则（按测试类型插入）

| 测试类型 | 前置动作 | 前置步数 |
| --- | --- | --- |
| 接口类 | 端口复位、外设握手 | 2 |
| 网络类 | 网络环境复位、连通性探测 | 2 |
| 系统类 | 缓存清理并重启 | 1 |
| 信号类 | 信源预设 | 1 |
| 显示类 | 画质模式预设 | 1 |
| 音频类 | 音量预设 | 1 |

执行步骤数 = 验证要点条数（按「；」切分） + 前置步数。

## 4. 预期输出口径

预期输出必须写成可复核的判定描述，统一格式：`全部判定点通过，执行日志回收至 LOG_<脚本名去扩展名>.log`。人工保留项预期输出写「人工主观判定，按评审记录表归档」。

## 5. 维护状态口径（由上轮回归结果判定）

| 上轮回归结果 | 维护状态 |
| --- | --- |
| 通过 | 稳定运行 |
| 异常 | 待回归（上轮异常） |
| 未执行 | 本轮新增（首轮接入） |
| 不适用（人工保留项） | 人工保留 |

## 6. 版本维护与回归纪律

- 待回归脚本在修复后必须先单跑通过，再进整机回归序列；
- 本轮新增脚本首轮执行即纳入日志回收，异常直接转入下一轮问题清单；
- 人工保留项不生成脚本，按评审记录表人工执行并归档结论。

## 7. 人工边界

脚本生成、结构校验、日志回收由 AI 承担；判定标准（阈值、容差、目标值）的制定与修订、主观画质与音质评定、回归通过与否的最终裁决，属于测试工程师。

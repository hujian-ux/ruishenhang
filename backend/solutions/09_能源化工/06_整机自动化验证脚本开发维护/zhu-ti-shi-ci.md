# ENG-07 主提示词 · 整机自动化验证脚本编写与维护

## 使用说明

1. 先在 WorkBuddy 中启用本场景 Skill 包（`03_技能包/整机自动化验证脚本编写与维护/SKILL.md`）。
2. 上传两个附件：`整机测试项清单.csv`、`脚本规范.md`。
3. 复制下方「主提示词」原文发送。
4. 拿到 `自动化脚本覆盖表.csv` 后，按文末「验收清单」逐项核对。

## 主提示词（复制即用）

```
请基于我上传的两份素材，为「某消费电子制造企业 · 整机自动化验证」批量生成验证脚本并整理覆盖台账，输出一张可复核的自动化脚本覆盖表。

【输入 1 · 整机测试项清单】整机测试项清单.csv（20 行）
- 含测试项编号、所属模块、测试项名称、测试类型、手动耗时分钟、自动化标记、上轮回归结果、验证要点
- 自动化标记为「人工保留」的项不生成脚本，只登记人工执行安排

【输入 2 · 脚本规范】脚本规范.md
- 脚本命名 AUTO_类型码_测试项编号_名称.py；主函数注释步骤编号必须与实际代码步骤严格一致
- 前置动作按测试类型插入（接口类/网络类 2 步，其余 1 步）；维护状态按上轮回归结果判定

【输出】自动化脚本覆盖表.csv——列名与格式按技能输出定义执行。

执行步骤、判定规则、硬性约束与生成后自检，一律按已启用的「整机自动化验证脚本编写与维护」技能执行（技能附录含本案例完整执行细则）。
```

## 本案例的关键追问（拿到结果后必须问）

1. **为什么 T14、T16 没有脚本？** 期望回答：画质主观评价与扬声器音质听感是人工保留项，需人眼与人耳主观判定，只登记执行安排，不生成脚本。
2. **T08 的执行步骤数怎么算出来的？** 期望回答：验证要点 3 条（4K 视频解码 / 音频解码 / 进度条拖动）+ 接口类前置动作 2 步（端口复位、外设握手）= 5 步。
3. **哪几支脚本这轮要重点盯？** 期望回答：T04（4K60 输入稳定性）、T10（Wi-Fi 断电重连）、T19（整机待机与唤醒）上轮回归异常，维护状态为待回归（上轮异常），须修复后先单跑通过再进回归序列。
4. **T07、T20 为什么是本轮新增？** 期望回答：上轮回归结果为未执行，属首轮接入，本轮首次纳入日志回收。
5. **回归一轮省下多少人工时间？** 期望回答：20 个测试项手动合计 300 分钟，自动化承接 18 项共 240 分钟，人工仅保留 2 项主观判定 60 分钟（按清单手动耗时列复算）。

## 验收清单

- [ ] 台账 20 行 = 18 支脚本 + 2 项人工登记（T14 / T16）
- [ ] 脚本名严格按 AUTO_类型码_编号_名称.py 拼接（如 AUTO_SIG_T01_信源自动识别HDMI1.py）
- [ ] 执行步骤数逐行 = 验证要点条数 + 前置步数，合计 65 步
- [ ] 维护状态分布 = 稳定运行 13 / 待回归 3（T04/T10/T19）/ 本轮新增 2（T07/T20）/ 人工保留 2
- [ ] 日志回收 18 份，命名 LOG_脚本名去扩展名.log
- [ ] 全表无效率百分比承诺，判定标准未被修改

# 终端系统问题定位方法框架

适用范围：智能终端系统问题（崩溃、卡顿、联网失败、显示异常、音频异常、待机唤醒异常）的日志归因、修复方案整理与验证闭环。原始日志由问题单系统与设备日志平台提供，本框架承接「日志 → 根因 → 修复 → 验证 → 回归」链路。

## 1. 六类根因定义与判定关键词

按以下优先级顺序扫描日志摘要，命中即停（先专项后兜底）：

| 优先级 | 根因分类 | 判定关键词 |
| --- | --- | --- |
| 1 | 内存资源类 | lowmemorykiller / OOM |
| 2 | 线程阻塞类 | blocked / ANR / watchdog |
| 3 | 驱动兼容类 | EDID / HDCP / 握手 / 链路重训练 / 时序抖动 |
| 4 | 网络协议类 | DHCP / DNS / ARP |
| 5 | 配置错误类 | 配置加载失败 / 默认配置 / 参数缺失 |
| 6 | 电源管理类 | suspend / resume / 唤醒源 |

> 兜底原则：六类均未命中时，标注「待人工归因」，不得强行归类。

## 2. 定位路径模板（按根因分类一一对应）

| 根因分类 | 定位路径 |
| --- | --- |
| 内存资源类 | 内存水位曲线 → 回收名单 → 前台保活清单核对 |
| 线程阻塞类 | ANR trace → 主线程调用栈 → 锁持有关系 |
| 驱动兼容类 | 链路状态日志 → EDID/握手抓包 → 时序容差复测 |
| 网络协议类 | 连通性分段探测 → 协议抓包 → 重试路径回放 |
| 配置错误类 | 配置加载日志 → 默认值比对 → 缺失项回填验证 |
| 电源管理类 | 电源状态机日志 → 唤醒源注册表 → 竞争时序复现 |

## 3. 修复方案模板（按根因分类一一对应）

| 根因分类 | 修复方案 |
| --- | --- |
| 内存资源类 | 调整后台回收白名单并前台保活，优化大内存场景释放策略 |
| 线程阻塞类 | 主线程耗时任务移入工作线程，收敛锁粒度并加超时释放 |
| 驱动兼容类 | 更新握手重试与容差参数，增加链路重训练失败后的复位流程 |
| 网络协议类 | 增加 DHCP 失败后的静态兜底与二次探测，修正 DNS 缓存超时策略 |
| 配置错误类 | 补齐默认配置写入路径，增加配置加载失败的校验与回滚 |
| 电源管理类 | 固化唤醒源注册时序，为关键场景增加唤醒锁持有 |

## 4. 影响面评估口径（按严重级别）

| 严重级别 | 影响面评估 |
| --- | --- |
| P0 | 全量机型阻断级，须随版本修复并全量推送 |
| P1 | 高频场景可复现，随常规版本修复 |
| P2 | 特定条件偶发，随维护版本择机修复 |

## 5. 验证结论口径（按严重级别 × 复测轮次）

| 严重级别 | 闭环所需复测轮次 |
| --- | --- |
| P0 | 2 轮（双轮复测） |
| P1 | 1 轮 |
| P2 | 1 轮（抽样复测） |

- 复测轮次 = 0 → 「待复测」；
- 0 < 复测轮次 < 所需轮次 → 「复测中（P0 需双轮）」；
- 复测轮次 ≥ 所需轮次 → 「复测通过」。

## 6. 回归标记口径

- 复测通过 且 严重级别为 P0/P1 → 「已入回归」；
- 复测通过 且 P2 → 「待入回归」；
- 未闭环 → 「待闭环后入回归」。

## 7. 人工边界

日志归因、定位路径生成、修复方案整理与验证结论判定由 AI 承担；根因的最终裁决、修复方案评审、发布与否与全量推送决定，属于终端软件团队。

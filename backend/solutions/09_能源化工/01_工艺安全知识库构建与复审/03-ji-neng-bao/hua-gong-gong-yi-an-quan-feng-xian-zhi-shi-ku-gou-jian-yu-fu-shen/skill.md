# 化工工艺安全风险知识库构建与复审

## 一、这个 Skill 解决什么

工艺安全风险点知识库的真实困难不是「没条目」，而是**条目经不起审**：

- 风险点靠专家个人经验逐条补，覆盖范围随人而异
- 评审要协调外部专家，排期长，最后常常「自己审自己」
- 「风险描述写得吓人、管控措施一栏是空的」这类错配混进定稿
- 复审意见没有固定基准，A 说该补报警、B 说该补培训，口径随轮次漂移

本 Skill 的核心动作，是把「编制—对抗—修订—收口」的评审闭环内置进知识生产：编制按框架结构化，复审以独立身份只提反对意见，分级用两张词表（高危词 × 工程控制词）固定判定基准，最后换身份收口终审。

## 二、什么时候用（适用时机）

| 触发情形 | 说明 |
| --- | --- |
| 新建或扩编工艺安全风险点知识库 | 主用场景：批量结构化 + 对抗式复审 |
| 现有知识库条目多年未复审 | 用分级规则全量重跑，暴露措施空白与工程控制缺位 |
| 装置改造 / 新工艺投用前 | 新增风险点按同一框架编号入册，与历史条目同基准复审 |
| 上级检查或事故复盘要求提供复审记录 | 复审追问、补漏结论、定稿轮次随表留档，可追溯 |

**不适用**：HAZOP/LOPA 等定量场景分析（本 Skill 只做条目级定性分级）；措施设计本身（补什么型号的联锁属于工程设计，属于人）。

## 三、输入（inputs）

| # | 输入文件 | 必需 | 关键字段 |
| --- | --- | --- | --- |
| 1 | `工艺安全风险点清单.csv` | 必需 | 序号、装置单元、环节类别（反应/储运/操作）、风险描述、现有管控措施（「暂无」= 措施空白） |
| 2 | `知识库条目框架.md` | 必需 | 条目编号规则与正文结构、风险分级规则 R1–R3、高危词表与工程控制词表、对抗式复审与收口确认机制 |

> 缺 2（框架）时，本 Skill **必须拒绝输出风险等级**——没有词表与分级规则，等级判定无基准可依，这是本 Skill 最重要的一条硬规则。

## 四、输出（outputs）

唯一交付物：`安全风险知识库表.csv`，字段固定为 9 列：

```
条目编号, 装置单元, 环节类别, 风险描述, 结构化条目, 对抗式复审追问, 补漏结论, 风险等级, 复审结论
```

- `条目编号` = 环节代码（反应 FY / 储运 CY / 操作 CZ）+ 两位流水号
- `风险等级` ∈ {重大, 高, 中}，按框架 R1→R2→R3 顺序判定，命中即止
- `对抗式复审追问` 必须指向该条目的具体薄弱点，不允许出现「建议进一步完善」这类确认式空话
- `补漏结论` ∈ {复审不通过（措施空白）, 有条件通过（补工程控制）, 通过}
- `复审结论` 写明定稿路径：重大/高 = 第一轮退回、第二轮复审通过后定稿；中 = 首轮通过、收口确认无新意见

## 五、工作流程（workflow）

### STEP 1 · 读框架，先立基准再编条目

从 `知识库条目框架.md` 读入编号规则、R1–R3 分级规则与两张词表，写成显式判定表。**顺序不可颠倒**——先看条目再定基准，等于给结论找理由。

### STEP 2 · 条目编制与结构化

按 `【环节类别·装置单元】风险描述。管控现状：现有管控措施。` 结构逐条生成知识库正文；措施为「暂无」的条目，管控现状必须明示「经对抗式复审确认为措施空白，补齐前不得定稿」。

### STEP 3 · 对抗式复审（独立审核人身份）

换「独立审核人」身份，对每条只提反对意见：

| 情形 | 追问方向 |
| --- | --- |
| 措施空白（重大） | 第一道工程防线是什么？由哪个岗位在什么时限内补齐？ |
| 高危词命中但措施缺工程控制（高） | 异常工况如何在人员介入前被自动发现？ |
| 覆盖充分（中） | 设定值是否校核？试验/执行记录是否留存、可审计？ |

### STEP 4 · 补漏修订

被拦截条目按补漏结论修订：R1 条目补充工程控制与管理措施；R2 条目补充报警/联锁/检测中适用项。修订后进入第二轮复审。

### STEP 5 · 收口终审（独立收口审核人身份）

再换「独立收口审核人」身份对修订稿终审，未提出新意见方可判定通过。全表风险等级分布与拦截记录随表留档。

## 六、关键规则（不可协商）

1. **对抗不确认。** 复审身份的产出只能是反对意见与追问，不允许出现「条目编写规范、总体良好」这类确认式评价。
2. **分级有基准。** 风险等级只能按框架 R1–R3 与两张词表判定，不允许「综合评估为较高风险」这类无基准表述。
3. **措施空白零容忍。** 现有措施为「暂无」的条目一律判重大、退回补漏，不得以「风险描述已写清」为由放行。
4. **高风险描述必须配工程控制。** 命中高危词而措施只有管理动作（双人复核、挂牌、交底）的，一律判高——管理措施不能替代报警/联锁/检测。
5. **身份隔离。** 编制、对抗复审、收口终审三个身份不得混用，防止自我确认偏差。
6. **不承诺效率百分比。** 输出中不写「提升 X%」这类无法核验的表述。

## 七、人工边界

| AI 负责 | 人负责（工艺安全岗 / 装置技术负责人） |

## 附 · 执行细则（本案例主提示词约束并入）

以下细则来自本场景案例的主提示词，与上文「关键规则」同等效力，执行时一并遵守。

### 执行要求

【执行要求】
1. 先读框架再编条目：把编号规则、R1-R3 分级规则与两张词表写成显式判定表，不要先看清单再定基准。
2. 结构化编制：按「【环节类别·装置单元】风险描述。管控现状：现有管控措施。」生成 20 条知识库条目；措施为「暂无」的条目，管控现状明示措施空白、补齐前不得定稿。
3. 对抗式复审：换「独立审核人」身份逐条只提反对意见——
   · 措施空白（R1，重大）：追问第一道工程防线是什么、由谁在什么时限内补齐
   · 高危词命中且措施缺工程控制（R2，高）：追问异常工况如何在人员介入前被自动发现
   · 覆盖充分（R3，中）：追问设定值校核、试验记录有效期或执行记录留存方式
4. 补漏修订：重大条目补充工程控制与管理措施，高条目补充报警/联锁/检测中适用项，进入第二轮复审。
5. 收口终审：换「独立收口审核人」身份终审，未提出新意见方可判定通过；全表等级分布与拦截记录随表留档。

### 硬性约束

【硬性约束】
- 对抗式复审追问必须指向具体条目的具体薄弱点，不允许出现「建议进一步完善」等确认式空话。
- 风险等级必须按 R1→R2→R3 顺序判定且命中即止，不允许「综合评估」类无基准表述。
- 现有管控措施为「暂无」的条目一律判重大并退回补漏，不得放行进入定稿。
- 编制、对抗复审、收口终审三个身份严格隔离，不得在同一轮内自我确认。
- 不写任何效率百分比或效果承诺。

### 生成后自检

【生成后自检，逐条回答】
1. 输出行数是否等于输入清单行数（本案例 20 行），且每行输入都有对应条目编号？
2. 风险等级分布是否与分级规则一致？（本案例应为：重大 3 / 高 8 / 中 9）
3. 措施空白条目（应为 FY-05、FY-07、CY-04）是否全部判重大并写明退回补漏？
4. 每条「高」级条目的追问是否都点明高危词与工程控制缺位的错配？
5. 是否没有任何一条复审意见是确认式评价？
自检全过再输出 CSV。

### 输出格式

【输出格式】CSV，9 列，列名与顺序固定：
条目编号, 装置单元, 环节类别, 风险描述, 结构化条目, 对抗式复审追问, 补漏结论, 风险等级, 复审结论

# 嵌入式控制软件开发与现场问题定位规范

适用范围：某算力设备制造企业嵌入式研发岗，覆盖 BMC/控制软件模块开发与现场问题（风扇调控、上电时序等）的日志定位。

## 1. 开发流程规范（需求类条目）

- **计划—实现—验证—授权**：所有开发需求先确定实现计划与边界，拆成多个子任务逐个执行；每个子任务完成后回传实现与验证结果，经人明确确认（往往需要二次、三次确认）才授权进入下一任务或提交。
- 需求条目在**单元测试与代码走查均通过**、并经确认门放行后，状态记为「已完成」。
- 硬件抽象层迁移类需求（如 GPIO 引脚配置表迁移）须额外做**新旧平台接口回归验证**。

## 2. 日志埋点规范

- 关键控制路径（风扇调速、上电时序、电源切换、告警判定）必须埋点，统一三类事件：**入口事件 / 出口事件 / 异常分支**。
- 埋点带毫秒级时间戳与模块标识；发布版本默认日志级别按发布配置收敛，调试日志不得全量输出。

## 3. 现场问题定位路径（问题类条目，三选一）

| 路径 | 适用情形 | 执行口径 |
| --- | --- | --- |
| A · 整段日志归因 | 已有现场运行日志与状态回显 | 整段日志交 AI 建因果链；硬件侧判断（哪一路辅源、哪个反馈引脚）由人给出，AI 负责在代码与日志之间建立对应 |
| B · 补日志验证 | 日志不足以下结论 | 在关键路径插入日志输出，由 AI 生成插桩代码并说明预期输出，用实际打印验证控制假设，验证后回收插桩 |
| C · 配置回退 | 引脚/外设配置存疑 | 存疑配置**先行整批回退**并标注「待确认」，由现场工程师确认连接关系后再重新提交 |

## 4. 问题状态口径

- **已闭环**：根因确认 + 验证复现 + 修复经确认门放行。
- **已定位待修复**：根因已确认，修复排期中。
- **已回退待确认**：改动已整批回退，等待现场确认。

## 5. 优先级与严重级

- 需求优先级：高 / 中 / 低；问题严重级：致命 / 严重 / 一般。
- 致命问题优先占用排期；回退类改动不得与其他变更混在同一批次提交。

## 6. 人工边界

- 硬件事实判断（引脚连接关系、辅路归属、传感器好坏）由现场工程师给出。
- 变更的最终决定权与放行属于人；AI 负责因果链建立、验证代码生成与回退清单整理，**不得替人放行**。

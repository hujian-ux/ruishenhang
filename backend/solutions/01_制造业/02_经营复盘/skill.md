# Skill · 经营复盘

## 适用时机
- 管理层每月回看"经营是否健康"，需要把五个部门交来的五套数字拼成一个结论。
- 当某主指标"看起来很好"但你想确认它是否靠代价堆出来时。
- 当复盘结论总是落不到动作（"要加强成本管控"式空话）时。

## 输入（inputs）
- 五份部门报表：销售（订单）、PMC（交付/OTD）、物控（库存/呆滞）、品质（质量）、财务（成本/毛利）。
- 至少含：主指标本期值、上期值、目标值，以及支撑指标（加班工时、加急插单次数、呆滞金额、缺料预警项数、不合格报告份数等）。

## 工作流程（workflow）
1. **五条线判定**：对每条线做"对上期 + 对目标"双向比，给出 改善 / 存疑·持平 / 恶化 三档判定。
2. **矛盾检测**：主指标达标时强制检查支撑指标；只要有一个支撑指标反向，则改判"存疑/持平"而非"改善"，并标注矛盾点。
3. **归因下钻**：对恶化项走四层下钻——指标层 → 产品线层 → 成本项层 → 订单层（落到具体单号与客户），每层带金额/占比。
4. **出简报**：一句话结论开头 + 五条线判定（含矛盾标注）+ 三个带主责部门/动作/时限/衡量口径的"必须关注问题"。

## 输出（outputs）
- 一页式经营简报 Markdown：五条线健康度表、矛盾点清单、四层归因链、三个签字级问题。
- 每个数字必须可当场验算（影响金额 = 件数 ×（实际单价 − 目标单价））。

## 关键规则
- 禁止只报主指标达标就判"改善"——支撑指标反向必须改判。
- 归因必须落到具体订单号和客户，不停留在"毛利率下滑"层面。
- 每个问题必须唯一主责部门 + 可验收的动作 + 明确时限 + 衡量口径（如"加急插单 ≤ 12 次/月"）。
- 所有状态用文字判定（改善/存疑/恶化），不使用红绿橙状态色。

## 提示词入口
见同目录 `主提示词.md`，或发送给 WorkBuddy：

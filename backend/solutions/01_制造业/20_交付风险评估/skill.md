# 交付风险评估（出货前五档处置决策）· Skill

## 适用时机
- 出货前检出批次异常，OQC 判了"不合格"，但正确结论往往不是简单的一句"不放"。
- 拍板的人不是品质（是老板 / 业务负责人），品质的真实角色是把判断依据凑齐、把后果说清楚。
- 判据分散在多个部门：让步口径在销售保管的《客户质量协议》里，返工来不来得及在生产班组长和外协厂嘴里。
- 需要输出一份能让老板签字的决策单，而不是让品质一个人背。

## 输入（原始数据源）
1. `检验记录_OQC不合格单.csv` —— 批次 / 客户 / 产品 / 数量 / 缺陷 / OQC 判定 / 交货日。
2. `客户质量协议条款.csv` —— 各客户的让步口径与条款编号、版本号。
3. `返工产能.csv` —— 返工方式、单件工时、可投人数、返工后是否复检。
4. `先例台账.csv` —— 历史同类缺陷的处置结论与依据。

## 三条硬拦截红线（一票否决，命中即禁止让步）
1. 安全 / 特殊特性超差。
2. 合同写明零缺陷（如客户协议第 6.3 条）。
3. 影响无法评估。

## 五档处置结论（关键是中间三档）
- **放行**：按正确档位判定合格，或协议明文可让且有先例；附让步清单与送货单备注。
- **返工后复检**：返工可行且赶得上交期；需写明返工风险与复检项目。
- **暂缓放行**：中小企业最常落此档；带暂缓原因、责任人、预计关闭时间，不是"不发"而是"先不发"。
- **让步接收**：须客户书面回函方生效，未获回函前不得发货。
- **拒收隔离**：命中硬拦截红线；标识隔离并追溯全批去向。

## 工作流程（5 步）
1. **读齐五份材料**：检验记录 / 订单交期 / 客户协议 / 返工产能 / 先例台账。
2. **过红线拦截**：安全特性 / 合同零缺陷 / 影响无法评估，命中即禁让步，不给模型裁量空间。
3. **按档位复核判定**：缺陷分 CR / MA / MI，对应 AQL 1.0 / 2.5 重算接收数（外观次要缺陷按 AQL2.5，功能主要缺陷按 AQL1.0）。
4. **五档结论 + 代价**：放行 / 返工 / 暂缓 / 让步 / 拒收，两边代价都摆出来。
5. **待确认 + 沉淀**：列明要向谁问什么（销售确认哪条款、技术确认哪个图纸版本、客户书面回函哪一项），并把本次处置写进先例台账。

## 关键规则 / 提示词
- **先拦红线，再谈取舍**：命中即禁止让步，模型无裁量空间。
- **把商务门槛摆到桌面**：技术全过，协议锁死照样出局；反之有明文可让且有先例就该痛快放行。判据带条款编号与版本号。
- **不确定的明说，不硬写**：拿不到的数据单独列一节，附建议话术，比什么都敢判更可信。
- **"暂缓放行"必须单独立档**：现场真实处境常是"现在还不能发，但有条路能救"，写清关闭条件与责任人。

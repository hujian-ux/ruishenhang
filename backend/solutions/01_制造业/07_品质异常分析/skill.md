# 品质异常分析（8D 根因追溯）· Skill

## 适用时机
- 收到客户投诉 / 退货，客户只给一个**出货批号**，要求限时（常见 3 个工作日）提交 8D。
- 需要把生产报工、车间检验记录、来料台账、历史异常台账几份证据交叉比对。
- 必须回答「问题为什么发生」**和**「我们的检验为什么没检出来」两条路径。
- 需要判断这是否是同一原因**第三次发作**（体系审核高频不符合项）。

## 输入（原始数据源）
1. `投诉与检验记录.csv` —— 客户投诉单 + 我方出货前检验记录（首件 / 巡检 / 终检）。
2. `报工参数记录.csv` —— 各工序实际参数 vs 工艺卡要求，用于逐项算偏差。
3. `历史异常台账.csv` —— 历史同类问题，含设备 / 班组 / 工序 / 批次背景 / 来料批次五维。

## 工作流程（6 步，顺序不可乱）
1. **资料汇聚**：几份表一起读，字段自动对齐（批号 / 工序 / 设备 / 班组 / 来料批）。
2. **履历还原**：顺批号追全工序——每道工序的设备、班组、操作员、用的哪批料、谁检验放行。
3. **参数比对**：报工实际值 vs 工艺要求，逐项算偏差；完成参数与不良的关联归因。
4. **重复性回查（必须在归因之前）**：按设备 / 班组 / 工序 / 批次背景 / 来料批次五维交叉比对历史，判定是否复发。一旦判定复发，追问方向从「这一批为什么出问题」转为「这个条件为什么反复出现、前两次整改为什么没防住」。
5. **双路径归因**：既答「为什么发生」，也答「为什么没拦住」。输出带证据的可疑变异点与候选根因，拿不准的明确说拿不准。
6. **出报告全套**：措施按性质分类（永久 / 系统 / 横向展开 / 纠正 / 待改文件 / 排除项），附责任人、时限、验收标准、需验证的批次数、客户签核栏与版本号。

## 输出
- 一份完整 8D 报告（每条结论标证据出自哪份表哪一行 + 客户签核栏 + 版本号）。
- 一份整改动作清单（措施按性质分类，每条带责任人 / 时限 / 验收标准 / 验证批次数）。
- 一份支撑分析（履历时间轴、参数偏差表、五维交叉比对结果、被排除的方向与排除依据）。

## 关键规则 / 提示词
- **Agent 不替你「定」根因**：只把能拿到的维度全部交叉比一遍，输出带证据的可疑变异点和候选根因，最终判断权在人手里。
- **重复性回查必须先于归因**，否则会又写出一份「加强培训」。
- **排除也要写依据**：像「来料方向」这类候选，要给出排除证据（如三次用三个不同来料批、力学性能接近），直接省掉整轮供应商追溯。
- 双路径都要答：只写「问题怎么产生」会被客户退回；「为什么没检出来」是退件头号原因。

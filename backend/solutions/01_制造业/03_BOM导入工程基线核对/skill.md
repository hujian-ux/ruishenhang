# BOM 导入 · 工程基线核对 Skill

## 适用时机
- 研发发来新版 BOM，要求与 ERP/PLM 现行基线对齐
- 输入形态混杂：Excel + PDF + 邮件正文表格 + 扫描件截图
- 目的：导入前"先把雷找出来，并算清每颗雷值多少钱"，再走变更审批

## 输入
- 文件 A：现行基线（从 ERP 导出的当前受控 BOM，CSV/XLSX）
- 文件 B：新版 BOM（研发发来的 Excel / PDF / 邮件正文表格 / 截图，多份不一致也可）
- 可选：在途采购订单、未完工工单、库存台账（用于展开影响面金额）

## 工作流（6 步）
1. **读两份 BOM** — 多格式解析，自动识别哪份是基线、哪份是新版
2. **脏数据体检** — 比对前先扫：疑似重复料（描述像编码不同）、单位混用、用量为空、层级孤儿件、替代料未标、版本号缺失
3. **对齐与匹配** — 料号对齐；字符相近料号（如 M-PCB-001 / M-PCB-002）标置信度，拿不准的列出
4. **差异分类** — 按 新增 / 删除 / 替换 / 用量变化 / 信息修订 分组，每条附旧值、新值、判断依据
5. **影响面展开** — 每条变更牵动的未完工工单、已下采购订单/在途、旧料剩余库存金额
6. **澄清与留痕** — 把 AI 明确表示"拿不准"的项单列，每条判断附依据，供人复核

## 输出
- 差异清单（按类型分组，每条含 旧值 / 新值 / 判断依据）
- 脏数据体检报告（三份来源之间的不一致、单位可疑项、替代料被清空、疑似重复料）
- 影响面与待确认（在途采购金额 + 旧料库存金额 + 待人工确认项）
- 关键设计：不追求"全自动写进 ERP"；定位是"把该查的全查一遍，拿不准的老实说出来，判断留给人"

## 关键规则 / 提示词
- 差异必须用行业语言分组，禁止只给"两边不一样标黄"
- 任一替代料被清空，必须交叉核对邮件/附件备注，判断是否"有意待评估"而非漏填
- 影响面金额 = 在途采购金额 + 旧料库存残值，让管理层也能读懂
- 输出前自检：料号字符相近项是否都标了置信度？替代料清空项是否查了备注？

# 场景使用说明 · 异常分级与升级归口（离散制造 · 管理层）

## 一、场景定位
一套引擎吃三种入口（客户投诉 / 现场停线 / 跨部门久拖），走同一套三级分级 → 建议归口哪个部门并说明为何不是别的部门 → 输出可贴群协调稿、对外话术、带 SLA 的台账。价值是"降级"和"归口"，不是"报警"。

案例：泰昌机械 2026-08-09 上午，三个群 6 条异常都说很急，真正该找老板的只有 3 条。

## 二、文件清单与作用
| 文件 | 角色 | 在场景中的作用 |
| --- | --- | --- |
| `03_技能包/异常分级与升级归口/SKILL.md` | Skill 定义 | 去重 + 反向检索 + 四维判据分级 + 归口建议 + 协调稿台账的规则 |
| `主提示词.md` | 提示词 | 学员实际发送给 WorkBuddy 的主提示词（已含案例数字） |
| `异常原始上报.csv` | 原始输入 | 6 条原始上报 / 3 入口，供去重与分级 |
| `异常分级升级矩阵.csv` | 预期交付物 | 异常类型×等级×归口岗位×SLA，5 件事定级结果 |
| `README.md` | 场景说明 | 介绍本场景使用方式与验证对照 |

## 三、交付物验证记录（Python 生成）
- `异常原始上报.csv`：生成成功，size 623 字节，6 行（3 客户投诉 / 2 现场停线 / 1 跨部门）。
- `异常分级升级矩阵.csv`：生成成功，size 1317 字节，7 行（5 件事 + 1 分级规则参考行）。定级结果与素材对齐：
  - 合并：R1+R6 → 门锁装不上（第 3 次）
  - P1（3 件）：门锁装不上 / 折弯机漏油 / 喷涂返工率（均非首次）→ L3 总经理，2h/24h
  - P2（0 件）：本次无，分级不为填满每一格
  - P3（2 件）：外箱磕碰（C 级已验收）/ 焊接新人产量（班长已处置）→ L1 班组，3 日响应
- 数字对齐：6 条→5 件事、3 P1 / 0 P2 / 2 P3、跨 4 部门、拖 23 天、第 3 次。

## 四、怎么用
1. 在 WorkBuddy 左侧「专家·技能·连接器」导入并启用 `03_技能包/异常分级与升级归口/SKILL.md` 所在 Skill 包。
2. 收集三类入口原始记录（可参考 `异常原始上报.csv` 字段口径）与历史台账。
3. 复制 `主提示词.md` 内容发送，附记录数据。
4. 核对矩阵：2 条合并、2 条降级、3 条 P1 均非首次、归口都带排除理由、SLA 正确。
5. 下载 `异常分级升级矩阵.csv` 作为升级台账与协调依据。

# Skill · 异常分级与升级归口

## 适用时机
- 群里多条异常都说"很急"，但真正该占用管理层的只有少数几条。
- 需要判断一件事"该升级还是留现场""该归口哪个部门"。
- 同一台设备/同一客户反复出同样问题，却每次都当新问题处理。

## 输入（inputs）
- 三类入口的原始记录：客户投诉（销售转发的微信/邮件/电话）、现场停线（班长群内一句话）、跨部门久拖（周会记录里反复出现的同一条）。
- 历史异常台账（用于反向检索重复性，无"是否重复"系统字段，需按设备号/部位/客户交叉检索）。

## 工作流程（workflow）
1. **读原文并去重**：三类入口原始记录一次读完，先合并同一问题的多次上报。
2. **反向检索历史**：按设备/部位/客户交叉检索，判断是第几次发生（第三次性质不同）。
3. **四维判据分级**：影响面（停线/交期/金额）· 紧迫度（客户上线日/SLA）· 复杂度（涉及几个部门）· 是否重复发生 → 定 P1/P2/P3。
4. **建议归口 + 排除**：给出"建议归口 X，因为不是 Y 也不是 Z"，理由摆出，老板一眼能改（指派是组织权力，本技能只建议）。
5. **协调稿 + 台账**：输出可贴群协调稿（≤300 字）+ 对外话术 + 带 SLA 与责任人的台账。

## 三级分级（中小企业只维持得住三级）
- **P1 紧急**：已致/将致客户停线、A 级客户要求升级、影响 3 张以上在制工单、同一问题第 3 次以上 → 升 L3 总经理，2h 响应、24h 出临时方案。
- **P2 重要**：影响单张工单交期、B/C 级客户投诉未停线、同一问题第 2 次、跨 2 个部门 → 升 L2 部门经理，当日响应、3 个工作日出方案。
- **P3 一般**：客户提醒改进已验收、现场可自行消化、首次发生且影响面单一 → L1 班组自行处理 + 记录归档，3 日响应。

## 输出（outputs）
- 异常分级升级矩阵（CSV/表）：异常类型 × 等级 × 归口岗位 × SLA。
- 可贴群协调稿（≤300 字）、对外话术、带 SLA 与责任人的台账。

## 关键规则
- 价值在"降级"与"归口"，不在"报警"。全都标最高级 = 全都不级。最高级比例压到 15% 左右。
- 重复性靠反向检索历史，不靠系统字段。
- 归口只"建议"并说明排除理由，不越权指派部门。
- 状态用 P1/P2/P3 文字分级，不使用红绿橙状态色。

## 提示词入口
见同目录 `主提示词.md`，或发送给 WorkBuddy：

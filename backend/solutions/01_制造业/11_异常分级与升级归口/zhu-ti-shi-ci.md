# 主提示词 · 异常分级与升级归口（管理层 · 离散制造）

复制以下内容发送给 WorkBuddy（配合已启用的「异常分级与升级归口」Skill 包）。把三类入口的原始记录与历史台账粘贴到【输入】位置即可。

---

请基于以下三类入口异常记录与历史台账，为「泰昌机械 2026-08-09 上午」做异常分级与升级归口，严格按五步输出。

【输入 · 三类入口原始记录】（节选自 异常原始上报.csv）
- 客户投诉×3：门锁装不上（客户产线受影响，第3次）/ 外箱磕碰（C级客户已验收）/ 折弯机漏油（第3次）
- 现场停线×2：焊接新人产量上不去（排班问题，班长已处置）/ 喷涂返工率高（周会拖23天，跨4部门）
- 跨部门×1：门锁装不上重复上报（与"客户投诉-门锁装不上"同问题）

【历史台账检索口径】
- 按设备号 / 部位 / 客户交叉检索，判定是第几次发生（第三次性质与第一次不同）

【分级规则】
- P1 紧急：致/将致客户停线、A级客户升级、影响≥3张工单、同一问题第3次以上 → L3 总经理，2h响应/24h临时方案
- P2 重要：影响单张工单交期、B/C级投诉未停线、第2次、跨2部门 → L2 部门经理，当日响应/3工作日
- P3 一般：已验收提醒改进、现场可消化、首次单点 → L1 班组，3日响应

【输出要求】
1. 合并同一问题重复上报（6 条→5 件事），标出哪 2 条该合并
2. 反向检索历史，标出每条"第几次发生"
3. 四维判据分级（影响面/紧迫度/复杂度/重复性）→ P1/P2/P3，标出 2 条该降级到 P3
4. 每条给建议归口岗位，并写明"为什么不是 Y 和 Z"
5. 输出：异常分级升级矩阵（类型×等级×归口×SLA）+ 可贴群协调稿（≤300字）+ 对外话术 + 带 SLA 责任人台账

生成后自检：真正需老板的只有 3 件且都不是第一次发生？被降级的都已留现场？归口都给了排除理由？确认无误再输出。

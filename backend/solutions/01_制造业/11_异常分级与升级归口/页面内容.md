现状与痛点

中小企业没有"升级机制"，只有老板的微信。所有异常最后都汇到同一个人，而他没有筛子。

所有事都"很急"

一线上报倾向把问题说重：说轻了怕没人管，说重了至少有人看。结果每条都是"客户很生气""马上要停线"，老板一天在二十几个群几百条消息里自己判断，依据往往只是谁的语气更急。

高频

重复发生查不清

判一件事该不该升级，最关键的是"是否重复发生"。第一次是意外，第三次就是管理问题。但系统里没有这个字段，只能靠人翻记录回忆，同一台设备半年漏三次油每次都当新问题。

高风险

跨部门集体沉默

喷涂返工率高，生产说来料有油污、采购说报告合格、品质说要定标准、工艺说设备湿度不稳。每一方都成立，所以每一方都不用负责——本质是谁有权限定标准，于是周会提了三次没结论。

协同断点

升级不带信息包

老板被叫住通常只得到一句"客户投诉了怎么办"：没影响范围、没已做动作、没证据、没可选方案。等于把判断责任转移给了信息最少的那个人，问一圈的时间事还在恶化。

耗时

好的升级机制 = 把不该占用管理层的摘出去，剩下的才拿得到真资源。全都标红，等于全都不红。

{brand} 的解决与价值

三类入口原始记录一次读完 → 反向检索历史判重复性 → 三级分级（含降级）→ 建议归口并说明排除理由 → 输出可贴群协调稿、对外话术与带 SLA 的台账。

传统做法

六条异常散在三个群，每条都说很急，老板凭语气判轻重：有的当场拍、有的"知道了"、跨部门那条继续悬着，处理完不留台账。"上次也有过"没人查得清。

WorkBuddy 做法

三类入口一次读完 → 先合并重复上报 → 反向检索历史判重复性 → 三级分级（含降级）→ 每条给建议归口并说明为何不是别的部门 → 输出协调稿 + 对外话术 + 带 SLA 责任人台账。

三个核心价值
01价值在降级不在报警

六条上报里两条该合并、两条该降级。把不该占用管理层的摘出去，剩下的才拿得到真资源。最高级压到 15% 左右，满意度反而上升。
02重复性靠检索不靠字段

系统没有"是否重复"这一列。按设备号、部位、客户交叉检索——第三次发生的事，性质和第一次完全不同，直接变"必须老板拍板改机制"。
03归口只建议并排除

指派部门是组织权力，不越权。给的是"建议归口 X，因为不是 Y 也不是 Z"，理由摆出来，老板一眼能改。

方案定位

不是多一个报警渠道，而是给管理层一把"筛子"：合并重复、降级留现场、把真正该升级的按正确归口和 SLA 推到对的人手里，并留下可复核台账。

解决方案的工作流程

从三类入口的原始记录到可贴群的协调稿，共 5 步，每条结论带判据出处。

01读原文并去重

三类入口原始记录一次读完，先合并同一问题的多次上报（6 条→5 件事）。

02反向检索历史

按设备/部位/客户交叉查，判是第几次发生（第三次性质不同）。

03四维判据分级

影响面·紧迫度·复杂度·重复性 → P1/P2/P3，该降级的降级。

04建议归口 + 排除

建议归 X，并写明为什么不是 Y 和 Z，老板一眼能改。

05协调稿 + 台账

可贴群协调稿（≤300 字）+ 对外话术 + 带 SLA 与责任人的台账。

案例基本介绍

脱敏案例，展示从三个群的 6 条异常到一份升级矩阵的全过程。全都说很急，但跑完只有 3 件真要老板——而这 3 件的共同点都不是第一次发生。

脱敏案例：泰昌机械 2026-08-09 上午

行政把上周五到今天的异常从三个群里摘出来：3 条客户投诉、2 条现场停线、1 条周会拖了 23 天的跨部门问题，每条描述都很急。但跑完一遍：2 条是同一件事的重复上报该合并，2 条按正确判据其实是 P3 该留现场，真正需要老板今天处置的只有 3 件——而这 3 件（门锁装不上第 3 次、折弯机漏油第 3 次、喷涂返工率拖 23 天跨 4 部门）的共同点，是它们都不是第一次发生。

提示词
TRAINING PROMPT · 复制即用
请基于以下三类入口异常记录与历史台账，为「泰昌机械 2026-08-09 上午」做异常分级与升级归口，严格按五步输出。

【输入 · 三类入口原始记录】（节选自 异常原始上报.csv）
- 客户投诉×3：门锁装不上（第3次）/ 外箱磕碰（C级已验收）/ 折弯机漏油（第3次）
- 现场停线×2：焊接新人产量（排班，班长已处置）/ 喷涂返工率（拖23天，跨4部门）
- 跨部门×1：门锁装不上重复上报（与"门锁装不上"同问题）

【分级规则】
- P1 紧急：致/将致停线、A级升级、影响≥3工单、第3次以上 → L3 总经理，2h/24h
- P2 重要：单张工单交期、B/C级未停线、第2次、跨2部门 → L2 经理，当日/3工作日
- P3 一般：已验收提醒、现场可消化、首次单点 → L1 班组，3日

【输出要求】
1. 合并重复上报（6→5），标出 2 条合并
2. 反向检索历史，标"第几次发生"
3. 四维判据分级，标出 2 条降级到 P3
4. 每条给建议归口，并写明"为什么不是 Y 和 Z"
5. 输出：异常分级升级矩阵（类型×等级×归口×SLA）+ 协调稿（≤300字）+ 对外话术 + 台账

生成后自检：真需老板的只有 3 件且非首次？被降级已留现场？归口都带排除理由？确认无误再输出。

怎么用
01在 WorkBuddy 左侧「专家·技能·连接器」入口点击「添加技能 → 上传技能」，导入本场景 Skill 包（zip 解压后的 异常分级与升级归口/ 文件夹或上方 Skill 包），并在「已安装」列表中启用该技能

03准备历史异常台账，供反向检索"第几次发生"
04复制上方提示词，粘贴记录数据到【输入】位置并发送
05核对矩阵：2 条合并、2 条降级 P3、3 条 P1 均非首次、归口都带排除理由
06按归口与 SLA（P1→L3 2h/24h）派单，贴出协调稿并归档台账

# 客户单据转系统订单 · Skill

## 适用时机
- 客户发来 Excel 叫料计划 / 邮件正文 / 图纸图片，口径五花八门，无法直接建单；
- 料号有精确码、历史别名、老编码、规格无编码、新品未建档 5 种形态；
- 客户按"套"报、企业按"件"算，存在单位陷阱（1 套 = N 件）；
- 到货日期写法混乱（8/12、2026/08/15、8月20日、Aug-25、Q3）；
- 一行写了两个规格、存在重复行、同一料号前后单价不一致；
- 急件交期不足，客服拍脑袋接单后挂系统才发现交期冲突。

## 不依赖的前提
客户单据长什么样就从哪读：Excel 读 Excel，邮件读邮件，图片附件也能读。**不要求客户先规范口径、不要求企业先上 ERP**——WorkBuddy 一边读一边把口径归一。

## Workflow（六步转化，每步都有明确产出）
1. **料号翻译**：精确匹配 → 历史别名 → 规格反查，三层机制；4/4 命中即高置信度，命中不到转下一步或归口挂起。
2. **单位换算**：识别"套 vs 件"等异构单位，按主数据换算关系（如 1 套 = 4 件）把数量与单价统一到系统基准单位，单价自动 ÷N、总量 ×N。
3. **日期归一**：5 种写法 → `yyyy-mm-dd`；写不清（如 Q3）标黄待澄清。
4. **单价核对**：对照价格表 + 批量档，识别同一料号前后单价不一致，标注需澄清。
5. **拆行合并**：一行两规格 → 拆行；重复行 → 合并并标确认。
6. **三色归口**：✅ 可直接建单 / 🟡 需澄清 / ⚪ 需挂起，每类附具体动作 + 责任岗位 + 完成时限。

## Inputs
- 客户叫料计划（Excel/邮件/图片）
- 料号对照表（精确/历史别名/老编码 → 系统料号）
- 价格表（标准单价 + 批量档）
- 主数据（系统料号 → 基准单位/客户常用单位/换算关系）
- 客户邮件备注（急件、图片附件说明等）

## Outputs
- `客户单据转系统订单结果.xlsx`：
  - Sheet1 转换明细（18 行：料号翻译结果 / 单位换算 / 日期归一 / 单价 / 金额 / 三色归口 / 差异处置 / 责任岗位）
  - Sheet2 三色归口汇总（✅10 / 🟡5 / ⚪3）
  - Sheet3 关键差异说明（第 6 行单位陷阱：传统误算 13,950 元 vs 正确 55,800 元，差额 41,850 元）

## 关键规则 / 提示词要点
- 料号翻译三层机制：精确 → 别名 → 规格反查；命中不到则归口挂起（新品流研发建档）。
- 单位陷阱：识别"套 vs 件"，按主数据换算（如 1 套 = 4 件），单价自动 ÷4、总量 ×4；第 6 行支架 300 套 → 1200 件 × 46.50 = 55,800 元，若按套误算仅 13,950 元，差 4 倍 41,850 元。
- 日期归一 5 种写法 → `yyyy-mm-dd`；写不清标黄。
- 三色归口动作：✅ 直接建单；🟡 自动生成客户确认清单交销售一次性问回；⚪ 自动流转研发建档后回写。
- 让客服从"翻资料的搬运工"变成"下决策的核对员"。

## 禁止
- 不要把"套/件"等不同单位混算，单价与数量必须统一到同一基准单位；
- 不要对急件拍脑袋接单——交期冲突必须标黄交 PMC 确认；
- 不要对新品未建档项强行建单，必须归口挂起流转研发；
- 仅做单据口径转换与风险提示，不构成商务决策。

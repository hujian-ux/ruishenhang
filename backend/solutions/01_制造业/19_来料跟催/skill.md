# 来料跟催 · 用缺口天数排优先级，而不是逾期天数

## 一、适用时机

命中以下任一表述即启用本技能：

- 「这 18 张在途单先催哪几张」「来料跟催怎么排优先级」
- 「供应商又逾期了，要不要催」「逾期的是不是真急」
- 「预测一下这张单哪天到」「断料风险怎么算」
- 「跟催话术怎么写，供应商才配合」
- 「供应商履约画像怎么建」

**不适用**：单纯查在途单状态、单纯查库存余额（走「齐套与缺料预警」或「库存水位监控」技能）；询价与比价（走「询价比价」技能）。

## 二、核心原则（违反即跟催无序、催错对象）

### 原则 1 · 排序基准是"缺口天数"，不是"逾期天数"

```
缺口天数 = 预测到货日 − 断料日
```

- 缺口天数 ≥ 0 → 🔴 紧急催：预测到货晚于断料，会停线
- −3 ≤ 缺口天数 ≤ −1 → 🟡 关注：缓冲不足 3 天，供应商波动一次即转红
- 缺口天数 ≤ −4 且未逾期 → 🟢 正常：不用催
- 缺口天数 ≤ −4 且已逾期（但下游还很远）→ ⚪ 逾期但不急：只登记不催

**逾期天数只反映供应商爽没爽约，缺口天数才反映会不会停你的线。** 两张单逾期 5~6 天但下游 9 月才上线，缺口 −35~−47 天，本周根本不用催；另一张还没到承诺期、供应商准时率只有 61.5%，缺口 +2 天，反而必须今天催。

### 原则 2 · 预测到货日要用"供应商自己的历史"推算

```
预测到货日 = (已逾期取基准日 / 未逾期取承诺日) + 该供应商延误单平均延误(向上取整缓冲)
```

禁止直接拿承诺日到货日当预测到货日。准时率 92% 的供应商和准时率 61.5% 的供应商，
同一张"未逾期"的单，推算出来的到货日天差地别。缓冲天数 = `math.ceil(平均延误天数)`。

### 原则 3 · 断料日用"下游上线日 + 库存可撑天数（向下取整）"

```
库存可撑天数 = 当前库存 / 日均用量
断料日 = 下游工单上线日 + int(库存可撑天数)   # 向下取整，保守
```

库存可撑 1.0 天，断料日就是上线当天 + 1 天，绝不四舍五入去当 2 天。少一天缓冲就多一次停线风险。

### 原则 4 · 跟催话术四要素，缺一个供应商就不重视

1. **履约数据** —— 该供应商近 6 个月准时率、延误单平均晚几天、波动度（标准差）。
2. **预测结果** —— 按原则 2 推算的预计到货日，并说明是否已逾期。
3. **后果** —— 我方哪张工单、哪天上线、库存只够几天、哪天断料、为什么不能用替代料顶。
4. **具体请求** —— 几月几日几点前先发多少量，回哪个单号；24h 不落实升级到谁。

话术必须带数字。没有履约数据支撑的"请尽快发货"，供应商当耳旁风。

### 原则 5 · 四色分级与动作一一对应，红色当日升级

| 档 | 缺口天数 | 动作 | 责任人与时点 |
|---|---|---|---|
| 🔴 紧急催 | ≥ 0 | P1 今日 10:00 前电话 + 书面确认分批发运，24h 不落实升级采购经理 | 采购 + 采购经理 / 当日 |
| 🟡 关注 | −3 ~ −1 | P2 今日书面确认发运 + 物流单号，每日跟踪 | 采购 / 当日 17:00 |
| 🟢 正常 | ≤ −4 未逾期 | P4 系统自动监控，承诺日前 2 天再核 | 系统自动 |
| ⚪ 逾期但不急 | ≤ −4 已逾期 | P3 只登记逾期原因，纳入月度履约考核，本周不催 | 采购（仅登记） |

### 原则 6 · 供应商分级要落到"重点辅导"

准时率 < 70% 的供应商（本案例 S-007 66.7%、S-021 61.5%、S-052 63.6%）列为重点辅导，
由采购经理约谈改善计划并纳入月度考核，不是每次出事才临时催。

## 三、输入（四份数据）

| 序号 | 文件 | 关键字段 |
|---|---|---|
| 01 | 在途采购单.csv | 采购单号、供应商编码、物料编码、订购数量、下单日、承诺到货日、下游工单号 |
| 02 | 供应商逐单履约记录.csv | 记录号、供应商编码、承诺到货日、实际到货日、延误天数、是否准时（反算履约画像） |
| 03 | 下游工单上线计划.csv | 工单号、产品编码、客户、计划台数、计划上线日、关键物料编码 |
| 04 | 物料库存与日均用量.csv | 物料编码、当前库存、日均用量、库存可撑天数 |

缺任一份都要**显式提示缺哪份、会导致哪条预测算不出**，不得静默跳过。缺 02 则履约画像无法建立、预测到货日退化为承诺日，须在输出中标注"预测未考虑历史延误"。

## 四、工作流程（5 步）

### STEP 1 · 导入四份数据并对齐口径
读全 4 份，对在途单的供应商编码 / 物料编码 / 下游工单号能否交叉对上；对不上的行单独列出。

### STEP 2 · 反算供应商履约画像
由 `02_供应商逐单履约记录.csv` 逐单反算：近 6 月单数、准时单数、准时率、延误单平均延误、波动度（标准差）、预测缓冲天数（= `ceil(平均延误)`）。本案例 6 家供应商：
S-007 66.7% / S-012 92.0% / S-021 61.5% / S-033 75.0% / S-041 90.9% / S-052 63.6%。

### STEP 3 · 算预测到货日与断料日
对每张在途单：预测到货日按原则 2；断料日按原则 3；缺口天数 = 预测到货日 − 断料日。

### STEP 4 · 四色风险分级
按原则 1 的口径逐单判定 🔴/🟡/🟢/⚪，并产出"传统按逾期排序 vs WorkBuddy 按缺口排序"对照，证明两种排序结论相反。

### STEP 5 · 生成跟催话术与待办清单
对 🔴 与 🟡 每张写四要素话术（原则 4）；⚪ 只登记纳入考核；产出带责任人与完成时点的待办清单，并列出重点辅导供应商。

## 五、输出（来料跟催表）

主表逐行 = `在途采购单`，列序固定：

```
采购单号 / 供应商编码 / 供应商名称 / 供应商准时率(%) / 供应商平均延误(天) / 供应商波动度 /
物料编码 / 物料名称 / 订购数量 / 单位 / 下单日 / 承诺到货日 / 实际到货日 /
是否已逾期 / 逾期天数 / 预测到货日 /
下游工单号 / 下游客户 / 下游上线日 / 当前库存 / 日均用量 / 库存可撑天数 / 断料日 /
缺口天数 / 风险分级 / 跟催优先级 / 跟催动作 / 跟催话术 / 责任人 / 完成时点
```

主表之后附 6 张汇总：
1. 供应商履约画像（由 02 逐单反算）
2. 四色风险分级结果（含传统排序对照）
3. 传统按逾期排序 vs WorkBuddy 按缺口排序（前 5 名对照）
4. 跟催话术（四要素）
5. 待办清单（带责任人与完成时点）
6. 反差最鲜明的两组（已逾期却判不急 / 未逾期却判紧急）

## 六、输出前自检清单

- [ ] 排序基准是否用了缺口天数，而不是逾期天数？
- [ ] 预测到货日是否按"该供应商自己的历史延误"推算（已逾期取基准日 + 缓冲）？
- [ ] 断料日是否用 `int(库存可撑天数)` 向下取整，没有四舍五入？
- [ ] 四色分级是否与动作一一对应（🔴 当日升级 / 🟡 当日书面 / 🟢 自动 / ⚪ 只登记）？
- [ ] 跟催话术是否四要素齐全且带数字（履约数据 + 预测结果 + 后果 + 具体请求）？
- [ ] 是否产出了"传统排序 vs 缺口排序"对照，并说明结论为何相反？
- [ ] ⚪ 档是否只登记不催、是否纳入供应商月度考核？
- [ ] 准时率 < 70% 的供应商是否列为重点辅导并安排约谈？

## 七、禁止事项

- 禁止拿承诺日到货日当预测到货日（必须叠加供应商历史延误）。
- 禁止用逾期天数排跟催优先级（必须用缺口天数）。
- 禁止把库存可撑 1.0 天四舍五入成 2 天去算断料日。
- 禁止给 ⚪ 档发跟催（浪费采购精力，且供应商会习惯性忽视真正紧急的单）。
- 禁止跟催话术里没有履约数据与具体请求（空话不被供应商重视）。
- 禁止在未标注"预测未考虑历史延误"的情况下，跳过 02 供应商履约记录。

现状与痛点

试产 / 量产前的开工条件确认，是研发 PE 的例行动作 —— 但也是最容易"带病开工"的环节。

问一圈几小时

PE 要跨 5 个部门问：BOM 齐了吗、料齐了吗、SOP 有了吗、产能腾出来了吗、工装到位了吗？发企微群、打电话、开碰头会，2-3 小时起步。

耗时

答案凑齐又变了

上午问齐套是齐的，下午车间领了别的工单又不齐；早上问喷涂有位，中午插了张急单就满载。状态变化速度比人跑腿快。

高频

带病开工最常见

一开工才发现产能没位、料还在待检、SOP 是旧版 —— 现场一堆坑，返工、停线、返修，损失直接翻倍。

高风险

结论不是'能开 / 不能开'二元的，而是给出黄灯 + 具体补齐动作 —— 告诉 PE 达成哪些动作即可开工。

{brand} 的解决与价值

把开工条件核查做成"一句话问就够" —— AI 并行读 5 份状态报表，跑五项检查，一次给结论 + 卡点补齐建议 + 责任岗位。

传统做法

PE 发企微群问 5 个部门 → 等回复 → 打电话追 → 5 份报表汇总 → 手写结论。谁没回就少一项，报上去的结论自己也不确定全不全，2-3 小时起步。

WorkBuddy 做法

一句话问 → 1 分钟拿到五项红黄绿 + 综合结论（可开工 / 需补 / 不可开工）+ 每项卡点的补齐建议 + 责任岗位。带病开工的隐患提前拦住。

两个核心价值
01并行读 5 份报表

同时读 BOM 基线、齐套报表、SOP 台账、产能负荷表、工装状态表 5 份文件，按产品 ID 交叉过滤，PE 不再逐个部门问。
02不只打颜色给方案

主控板缺 60 → "用替代料 M-PCB-002 补齐"；喷涂满载 → "300 台分 3 批过喷涂"。每项卡点配具体补齐动作 + 责任岗位。

方案定位

不是替 PE 做决策，而是把跨部门的分散状态一次聚齐、按统一口径判红黄绿，并把"怎么补、谁来补"一并给到 —— 让 PE 从"发现问题→自己想办法→亲自协调"的独角戏里解放出来。

提示词
TRAINING PROMPT · 复制即用
请基于以下 5 份跨部门状态报表，为「P-IPC-01 智能控制柜 · 试产 300 台」做开工前条件核查，严格按 4 段输出。

【输入 · 5 份报表】（节选自各 CSV）
- BOM 基线：版本 V2.3，已发布受控
- 齐套报表：主控板 M-PCB-001 需求 300 / 库存 240 / 缺口 60
- SOP 台账：WI-ASM-001 版本 V1.3，已生效
- 产能负荷表：喷涂线满载，P-IPC-01 需 300 台喷涂位
- 工装状态表：工装治具到位

【输出要求】
1. 五项结论：BOM 版本 / 物料齐套 / 工艺 SOP / 产能位 / 工装治具，用 通过 / 需补 / 不足 表达
2. 综合结论：可开工 / 需补后开工 / 不可开工（本例预期"需补后开工"）
3. 卡点补齐建议：物料缺口 60 → 用替代料 M-PCB-002 补齐 60；喷涂满载 → 300 台分 3 批过喷涂
4. 责任岗位：每项卡点写明归口（PMC / 仓库 / 工艺 / 生产 / 设备）

生成后自检：结论是否给具体补齐动作而非只打颜色？每项是否都带责任岗位？

怎么用
01在 WorkBuddy 左侧「专家·技能·连接器」入口点击「添加技能 → 上传技能」，导入本场景 Skill 包（zip 解压后的 开工条件核查/ 文件夹或上方 Skill 包），并在「已安装」列表中启用该技能

03确认报表含五维状态字段（版本 / 需求库存 / 生效 / 负荷 / 到位）
04复制上方提示词，粘贴 5 份报表内容到指定位置并发送
05查看五项结论与综合结论，核对卡点补齐建议是否合理
06按责任岗位协调补齐（替代料 M-PCB-002 补齐 60 / 喷涂分 3 批），达成后给出开工许可

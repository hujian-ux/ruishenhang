结论先行（一句话）

前端已 fail-closed 支持收口，无需改前端代码；收口本质是后端 .env 配置 + Casdoor 侧配置。 致命顺序：OIDC_ENABLED 当前默认 0（未启用），必须先启用并验证真实 SSO 能登录，再开 AUTH_ENFORCE_OIDC=1，否则 dev token 被拒、OIDC 分支又没启用 → 全员锁死。

P0 · 当前状态（代码事实）

项现状出处含义
OIDC_ENABLED默认 "0"（未启用）config.py:217只认 dev token；OIDC 验签分支完全不激活
AUTH_ENFORCE_OIDCdev 默认 Falseconfig.py:256-257(raw=="1") if raw is not None else (APP_ENV=="prod")；dev 下 dev_admin 后门敞开

⚠️ 致命顺序（务必遵守）： security.py:10 明确「OIDC_ENABLED=1 且配置 issuer 时，OIDC 分支才启用；否则只认 dev token」。
若你先设 AUTH_ENFORCE_OIDC=1（或 APP_ENV=prod）而 OIDC_ENABLED 仍为 0：security.py:192/195 拒掉 dev token，但 :185/10 的 OIDC 验签因未启用也不会受理真实 id_token → 没有任何可用身份通道，全员无法登录。
正确顺序：启用 OIDC → 验证 SSO 真能登录 → 再开 enforce。

以下变量均定义在 backend/app/core/config.py:213-235。改动只动 .env，不动代码。

P1 · 分步执行（严格按序）

第 1 步 · 启用并配置 OIDC（不动 enforce）
在 .env 加/改：
OIDC_ENABLED=1
OIDC_ISSUER=http://<casdoor-host>:8000
OIDC_AUDIENCE=<your-casdoor-client-id>
OIDC_CLIENT_ID=<your-casdoor-client-id>
OIDC_REDIRECT_URI=https://<your-frontend>/callback
# 其余 claim 先用默认值
重启后端。
第 2 步 · 验证 OIDC 配置健康
curl -s http://127.0.0.1:8000/auth/oidc/health | python -m json.tool
期望 enabled:true, ok:true（能拉到 JWKS）。若 reason 提示缺 issuer，回到第 1 步补。
第 3 步 · 验证真实 SSO 登录链路（此时 enforce 仍 0，演示入口还在，便于回退）
浏览器走「企业身份登录」→ 跳 Casdoor → 用企业微信/钉钉账号登录 → 回跳前端拿到 id_token → POST /auth/sso/callback {"id_token":"..."} 返回 200 且含真实用户。确认 /auth/settings 的 oidc_enabled=true。
第 4 步 · 开启收口
在 .env 追加：
AUTH_ENFORCE_OIDC=1
# 生产部署同时：
APP_ENV=prod
重启后端。
第 5 步 · 验证后门已封 + 演示入口隐藏
# dev_admin 应 403
curl -s -X POST http://127.0.0.1:8000/auth/sso/callback \
  -H "Content-Type: application/json" \
  -d '{"code":"dev_admin"}'
# 期望：403 "身份收口已开启或处于生产环境..."

# 公开设置应回传 enforce_oidc=true
curl -s http://127.0.0.1:8000/auth/settings | python -m json.tool
# 前端 Login.tsx 读到后自动隐藏演示入口
第 6 步 · 全量回归（可选但建议）
收口态下跑测试需注意：部分用例依赖 dev token。可用 EAP_SKIP_ENV_LOCAL=1 隔离或确认测试用真实 OIDC mock。生产仅验证核心登录链路即可。

P1 · Casdoor 侧配置（平台外，需管理员操作）

  • 部署 Casdoor：自托管（Apache-2.0），后端/OIDC 通常 8000 端口，OIDC_ISSUER 即其访问地址。
  • 注册 Application：拿到 Client ID（填 OIDC_AUDIENCE / OIDC_CLIENT_ID）。
  • Redirect URLs：登记前端回跳地址，须与 OIDC_REDIRECT_URI 逐字符一致。
  • 接入企业身份源：配置企业微信 / 钉钉 IdP（Casdoor 原生支持）。
  • 角色/组织映射：按 isGlobalAdmin→platform_admin、isAdmin→dept_admin 推导，或用 role claim 直接下发 employee|dept_admin|platform_admin。
  • 多租户（可选）：每家企业在 Casdoor 建 organization，映射到本平台 tenant_store 的 casdoor_org。
前端 ConnectSetup.tsx:46 与 Identity.tsx 已暴露 OIDC 状态与「配置身份源」入口；Casdoor 管理员账号可走 auth.py 的实验性一键写入（失败不影响手动在 Casdoor 后台填）。

P2 · 回滚方案

# 任一异常（如 SSO 不通、全员登不进），立即在 .env 回退：
OIDC_ENABLED=0
AUTH_ENFORCE_OIDC=0
APP_ENV=dev        # 若改过
# 重启后端 → dev token / 演示入口恢复可用

因前端 fail-closed，回退后 /auth/settings 回传 enforce_oidc=false，Login.tsx 自动放开演示入口，无需改前端。

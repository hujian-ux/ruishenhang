硅基流动（SiliconFlow）免费池可用模型 ID 核对清单

产出日期 2026-11-14 · 关联 backend/scripts/real_e2e_smoke.py 真模型联调 · 针对 .env 的 LLM_DEFAULT_MODEL=Qwen/Qwen2.5-7B-Instruct 实测返回 HTTP 400「Model does not exist」

结论先行（一句话）

密钥没问题，是模型 ID 大小写敏感导致 400。 直连通道 _direct_key() 优先读 LLM_API_KEY（你的 .env 已正确配置），SILICONFLOW_API_KEY 只是兜底。唯一可靠做法：用你的 key 调 GET /v1/models 拿精确（大小写敏感）的模型 ID，再回填 LLM_DEFAULT_MODEL。

P0 · 根因分析（三个假设，按优先级）

序号假设概率验证方式
1模型 ID 大小写敏感。Qwen/Qwen2.5-7B-Instruct 与实际免费池 ID 仅大小写不同（例如控制台实为 qwen/qwen2.5-7b-instruct 或带别的前缀/后缀）。SiliconFlow 模型 ID 区分大小写，错一个字符即 400。高见下方「P1 权威核验」命令，逐候选跑 chat/completions，返回 200 即命中。
2该模型已从免费池移出 / 改名。免费池名单会随运营调整，Qwen2.5-7B-Instruct 可能已转为付费或并入新代号。中登录硅基流动控制台「模型广场」核对「免费」标签；或用 /v1/models 看当前可用列表。
3免费池区域/额度未激活。账号未领取免费额度、或该模型仅在特定区域免费。低控制台账户页确认免费额度为 normal；GET /v1/user/info 返回 status:normal。
已排除：密钥失效。 llm_available() 在 direct 通道只校验 LLM_API_KEY 是否非空；且 400 是「模型不存在」而非 401「未授权」，说明鉴权已通过、请求已到达硅基流动，只是模型名对不上。

P1 · 权威核验命令（在你的出网环境执行）

前置：已配置 LLM_API_KEY。沙箱出网被拦截，以下命令须在本机/服务器出网环境跑。

① 拉取你账号下全部模型（拿精确 ID，大小写敏感）

# Windows PowerShell / bash 通用：先取 key
export SF_KEY="$(grep '^LLM_API_KEY=' D:/enterprise-ai-platform/.env | cut -d= -f2)"
curl -s https://api.siliconflow.cn/v1/models \
  -H "Authorization: Bearer $SF_KEY" | python -m json.tool | grep '"id"'

② 单模型冒烟（返回 200=可用；400=ID 对不上）

curl -s https://api.siliconflow.cn/v1/chat/completions \
  -H "Authorization: Bearer $SF_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen/Qwen2.5-7B-Instruct","messages":[{"role":"user","content":"你好"}],"max_tokens":16}'

把上面 model 依次换成候选表中的 ID，谁返回 200 就用谁。这是判断「免费且对你的 key 可用」的最直接证据。

③ 确认 key 状态正常

curl -s https://api.siliconflow.cn/v1/user/info -H "Authorization: Bearer $SF_KEY" | python -m json.tool

P1 · 修正 .env 步骤

  1. 用上面命令②确认某个候选 ID 返回 200（建议首选 Qwen/Qwen3-8B，免费池常驻且稳定）。
  2. 打开 D:/enterprise-ai-platform/.env，把第 12 行： 
    LLM_DEFAULT_MODEL=Qwen/Qwen2.5-7B-Instruct
    改为（示例，以你实测 200 的 ID 为准）： 
    LLM_DEFAULT_MODEL=Qwen/Qwen3-8B
  3. 不要动 LLM_API_KEY、LLM_PROVIDER=direct、LLM_VENDOR=siliconflow、LLM_BASE_URL —— 它们是对的。
  4. 重跑 backend/scripts/real_e2e_smoke.py，Tier1 裸模型调用应返回 real=True 而非 400。
key_env 陷阱： PROVIDER_PRESETS["siliconflow"]["key_env"] 写的是 SILICONFLOW_API_KEY，但 _direct_key() 优先返回 settings.LLM_API_KEY。你的 key 配在 LLM_API_KEY 下，所以无需新增 SILICONFLOW_API_KEY。若有人按 PRESETS 去设 SILICONFLOW_API_KEY 却留空 LLM_API_KEY，反而会落到兜底读不到 key。

P2 · 与 real_e2e_smoke.py 的衔接

  • 该脚本已写「已知坑」：LLM_DEFAULT_MODEL 在免费池可能 400，须核对。
  • 修对模型 ID 后，在出网环境：cd backend && ./.venv/Scripts/python.exe scripts/real_e2e_smoke.py（勿带 EAP_SKIP_ENV_LOCAL=1）。
  • 预期：Tier1 输出 real=True；Tier2 run_agent 全链路含 P1-12 压缩观测 context.window_turns/dropped_turns/summary.provider 有值。

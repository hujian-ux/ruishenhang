## 一、M12 真实身份认证（企业 SSO / OIDC）

### 做了什么
把身份来源从「单一 dev token」升级为**可插拔**：
- `app/core/security.py` 的 `decode_token` 增加 OIDC/JWT 校验分支（RS256 + JWKS 自动拉取，走标准 discovery）。
- 对接**任意**企业 IdP（钉钉 / 飞书 / 微信企业号 / Keycloark）只需填 issuer，**不写死各厂商 SDK**。
- 下游 `X-Caller-Context` 契约**完全不变**，所有路由零改动——身份来源与权限逻辑解耦。
- 安全规则：未配置 IdP 时只认 dev token（CI / 本地 / 演示照常）；`APP_ENV=prod` 时**拒绝 dev token**，强制走真实身份。

### 配置项（`backend/.env` 或环境变量）
| 变量 | 说明 |
|---|---|
| `OIDC_ENABLED=1` | 开启真实身份 |
| `OIDC_ISSUER` | IdP 地址，如 `https://keycloak.xxx/realms/ruishenxing` |
| `OIDC_AUDIENCE` | 本平台在 IdP 注册的 client_id |
| `OIDC_USER_CLAIM` / `DEPT_CLAIM` / `ROLE_CLAIM` | 字段名映射（按你的 IdP 调整，默认 `preferred_username` / `dept` / `role`） |

### 验收（`tests/test_m12_oidc.py` · 6 passed）
映射正确、过期拒绝、audience 不符拒绝、签名篡改拒绝；dev token 在 OIDC 开启时仍可用；生产环境拒绝 dev token。

### 还差你的一步
前端登录走标准授权码流拿到的 JWT 直接当 `Authorization: Bearer <jwt>` 发来即可（资源持有者模式），`/auth/sso/callback` 骨架已存在、可改为真实换码。**需要你给 IdP 的 issuer + client_id**，我据此补前端登录页与回调换码。

## 二、M13 审计日志

### 做了什么
新建 `app/services/audit.py` + `AuditTraceMiddleware`：
- **四类动作**落审计：检索（retrieve）/ 生成（generate，即 agent invoke）/ 下载原文（download）/ 审批决策（approval）。
- 字段：`trace_id`、caller（租户/部门/用户/角色）、action、target、result、meta（**自动脱敏，不存原文正文/令牌**）、时间戳。
- 存储：PG 落库（`audit_logs` 表，jsonb 载荷），**PG 不可达自动降为 SQLite 文件**，与计量同源降级。
- 查询端点 `GET /audit/logs`：**RBAC 收敛**——平台管理员看全量、部门管理员看本部门、员工只看自己。
- 与 `usage_records`（计量对账）是两套独立数据，互不污染。

### 验收（`tests/test_m13_audit.py` · 6 passed）
SQLite 兜底正确；员工/部门/平台三级隔离；敏感字段脱敏；动作过滤。

### 价值
客户现场合规第一问「谁查了什么、下载了哪份原文」现在可答、可追溯、可导出。

## 三、M14 第二部门真实语料试点（流程固化）

### 做了什么
固化「**导入双部门 → 评估 → 跨域隔离校验**」SOP 为 `scripts/pilot_second_dept.py`，一次命令跑通：
- 同一进程把两个部门（d_sales / d_marketing）语料导入**统一检索空间**——证明多租户隔离不是「分库存」，而是同一索引里按 caller 可见性**候选阶段预筛**（M10 机制）。
- 用第二部门自己的 golden（标题反查 + viewer=本部门）评估召回。
- 构造**跨域泄露探针**：用 d_sales 身份去查 d_marketing 文档标题，期望全部 drop。

### 实测结果（伪向量下限，真实模型会更高）
| 指标 | 值 |
|---|---|
| 导入 | d_sales 200 + d_marketing 200 = 400 篇，by_dept 计数正确 |
| 第二部门 Recall@5 / @10 / @100 | 0.65 / 0.95 / **1.0** |
| MRR@10 | 0.37（伪向量下限） |
| 过滤正确率 | **1.0** |
| 跨域泄露探针 Recall@5 | **0.0（零泄露）** |
| 门禁 | PASS |

> `@5 / MRR 偏低是伪向量（无真实语义）的预期下限。真实 bge-m3 下 M11 已验证 Recall@5=0.9802，上线真实模型后这俩指标会显著提升，不影响「隔离正确 + 召回可达」的结论。

### 真实数据替换
把脚本里两段 `generate_dept` 换成一次 `ingest.import_corpus(真实目录, caller, dept_id="d_xxx")` 即可；golden 仍只写 `query + expected_title`，系统自动反查 doc_id。

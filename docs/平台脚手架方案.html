1. 总体架构与数据流

四层：客户端 → API 网关（注入身份 + 第 18 章单一过滤点）→ 服务层 → 存储层。所有读/写/外发均经网关过滤，不绕过。
关键约束落点：① 单一过滤点只在网关一处实现，下游服务信任 caller 上下文，不再各自判权；② 知识库三元存储（PG 元数据 + Qdrant 向量 + MinIO 文件），三者由 knowledge-svc 统一编排；③ eval-svc 独立，评测结果反哺第 20 章演化与 CI 门禁。

4. 关键骨架 stub（先透传，后接业务逻辑）

只搭接口与契约边界，标注对应蓝图章节；业务实现留到 P0 迭代。

① 网关：X-Caller-Context + 单一过滤点

# services/api-gateway/app.py (FastAPI stub)
from fastapi import Request, FastAPI
app = FastAPI()

async def inject_caller(req: Request):
    # 第18章：由 token 解出 userId/deptId/role
    ctx = decode_token(req.headers.get("Authorization"))
    req.state.caller = ctx          # 下游信任此上下文

async def single_filter(point, caller, data):
    # 单一过滤点：按 scope/owner/dept 裁切可见性
    return [d for d in data
            if visible(d.meta, caller)]   # 不绕过

# 路由均经此中间件；知识/工具/外发统一过滤

② 知识库：权限元数据 schema

-- infra/init/01_acl.sql (节选)
CREATE TABLE kb_documents (
  id          UUID PRIMARY KEY,
  tenant_id   TEXT,
  scope       TEXT,        -- personal/owner/department/global
  owner       TEXT,        -- 负责人（多人知识库）
  dept        TEXT,        -- 部门
  visible_to  JSONB,       -- 第18章过滤点派生

);
-- 写入由服务端强制回填，前端/演化不可伪造

先底座，再按 P0 优先级填业务；每阶段有明确产出与验收。

7. 待确认的技术决策点

蓝图已定选型范围，以下需在搭脚手架前拍板，避免返工。
决策项候选 / 说明影响

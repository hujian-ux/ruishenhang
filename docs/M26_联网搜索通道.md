# M26 · 联网搜索通道（联网查资料 / 竞品调研）

**一句话结论**：平台第一次有了通往公网的正规通道，且与企业内部 RAG 在编号、接口、响应字段三层完全隔离；免费网页源即可开箱用，中文实测搜狗优于 Bing，但严肃调研仍需配官方 API key。

> 实测时间：2026-11-06，本机 Windows / 后端 8080 / 前端 5173，无 PG、无 Qdrant（内存模式）。
> 数据口径：本轮所有数字均来自本机真实 HTTP 调用；检索耗时为**一次搜索请求耗时，不含模型生成与产出物渲染**。模型仍为 stub（硅基流动 402 余额不足），因此**答案语义质量未验**，脚本明确报 SKIP。

---

## 一、为什么现在补

M24 对标 WorkBuddy 内置技能时，明确把「联网核验」列为**不抄**：平台 `httpx` 只用于 OIDC 与模型网关，没有搜索通道。结果是「查政策」「看竞品」这类每个岗位都会遇到的活只能走纯生成，模型凭常识编，比不答更危险。

本次补的不只是「能发一个 HTTP 请求」，而是把**外部事实**当成一种独立来源接进运行时：内部制度有 `[1][2]`，公网网页有 `[W1][W2]`，两套编号永不混用。

---

## 二、三条不可退让的边界

| # | 边界 | 落点 |
|---|---|---|
| 1 | **公网 ≠ 公司内部制度** | 命中固定 `origin=public_web`；证据块用 `[W编号]`；内部片段用 `[编号]`；双通道技能提示词明写「不得用内部制度证明外部事实，也不得用公开网页推翻公司内部规定」 |
| 2 | **失败不许编** | 通道禁用 / provider 抛错 / 零命中都返回 `ok=false` 与明确空信号；证据块要求模型写「未检索到公开信息」，不许拿常识、行业惯例、示例补；`search()` 永不抛异常，接口不会 500 |
| 3 | **公网结果不入库** | 只在当轮上下文存活，不写知识库、不参与向量检索、不跨租户共享；`citations` 只放内部文档，`web_sources` 只放公网链接 |

第 3 条尤其要紧：一旦把外部网页灌进知识库，它就会变成「授权片段」绕过 RBAC 过滤点，M12 的跨部门/跨租户红线等于白做。

---

## 三、Provider：可插拔，无 key 也能用

`WEB_SEARCH_PROVIDER=auto` 时按「有 key 用官方，全没配走免费」自动选；任一通道失败自动降级并标 `degraded=true`，降级结果在聊天页提示「需人工复核来源」。

| Provider | 凭据 | 适用 | 实测 |
|---|---|---|---|
| `bocha` 博查 | `BOCHA_API_KEY` | 中文网页、国内合规 | 未配 key，未实测 |
| `serper` | `SERPER_API_KEY` | Google 结果、海外资料 | 未配 key，未实测 |
| `tavily` | `TAVILY_API_KEY` | LLM 友好、自带摘要 | 未配 key，未实测 |
| `bing_api` | `BING_SEARCH_KEY` | Bing Web Search v7 | 未配 key，未实测 |
| `searxng` | `SEARXNG_BASE_URL` | 自建、数据不出内网 | 未部署，未实测 |
| `sogou_html` | 无 | **免费首选**，中文长 query | ✅ 实测 200，前 3 条全命中主题 |
| `bing_html` | 无 | 免费备份，中文偏泛 | ✅ 实测 200，可解析 10 条 |

**实测相关性对比**（同一句「广东 独立储能 容量补偿 政策 2026」）：

- 搜狗前三条：`2026年最新国内各省独立储能政策与收益情况分析报告` / `广东电力现货市场结算实施细则(2024年修订):独立储能充电电量…` / `广东: 独立储能试行电费补偿,标准100元/千瓦.年`。
- Bing 前三条：`广东省_百度百科` / `广东省人民政府门户网站` / `广东政务服务网` —— 主题被拆散成地名泛结果。

所以免费兜底顺序定为 **sogou_html → bing_html**。搜狗结果块里带 `data-url` 原始链接，优先取它，避免把 `/link?url=` 中转页写进来源表。

**免费源的局限**（不粉饰）：竞品调研那句「半成品菜 供应链 品牌 报价」返回的是阿里巴巴商品聚合页，能看价但不是调研级来源；网页抓取依赖对方页面结构，随时可能失效。**生产必须配官方 key**，免费源只作本地演示与断网降级。

## 四、安全设计（SSRF 面）

| 层 | 做法 |
|---|---|
| 入参 | query 截断 200 字、去控制字符；`top_k ≤ 10`、`fetch_top ≤ 3`；**接口不接受自定义 URL** |
| 结果 URL | 只认 http/https；拒绝 `localhost` / `.local` / `.internal` / `.localdomain` / `metadata*`；私网、回环、保留、组播字面 IP 一律丢；只放行 80/443；域名黑名单可配 |
| 去重 | 去 `utm_*` / `spm` / `fbclid` 等跟踪参数后按规范化 URL 去重 |
| 正文抓取 | 只有**本进程刚搜到的 URL** 进短期白名单（TTL 300s）才能抓；二次做 DNS 解析，任一结果为私网即整条拒绝；content-type 白名单、512KB 上限、8s 超时；只取纯文本，不执行脚本、不落库 |
| 审计 | `/search/web` 每次落 `web_search` 审计事件（provider / mode / hits / degraded / 耗时），带 trace_id |

## 五、新增的三条公共技能（第 7 组「联网查证」）

| 技能 | 适配器 | 产出 | 干法要点 |
|---|---|---|---|
| 联网查资料（带链接） | `llm_web_search` | Word | 唯一答案 / 多种说法 / 完全查不到分三种处理；每条事实挂 `[W编号]` + 完整链接；来源优先级官方 > 行业 > 公司 > 媒体 > 自媒体 |
| 竞品调研 | `llm_web_search`（抓前 2 篇正文） | Excel | 直接竞品/替代方案/上下游各 1-2 家；对照表每格要么有证据要么写「未查到」；价格必须写清口径与时间 |
| 内外资料交叉核对 | `llm_web_search_rag`（双通道） | Word | 内部依据与公开信息分两张表、两套编号；冲突只并列标「待确认」，不私自调和、不替审批人拍板 |

三条都补齐了「什么时候用 / 要给什么 / 会拿到什么」契约。平台硬规则从 M25 的 7 条扩到 8 条，新增第 7 条管外部检索，28 条公共技能全量注入、单一来源、启动刷新自愈（`hard_rules_version=2026-11-06.m26`）。硬规则仍不许含 `## `（渲染器按它切页）。

**口径变化**：公共库 25 → 28 条、6 → 7 组（`5/3/5/5/4/3/3`）；`total` 仍 **115**（公共库不进业务包口径）；财务岗 `17 + 28 + 1 = 46`。数量上限从 25 提到 28 只此一次，理由是「外部事实获取」是新能力类别，独立成组，不往原 6 组里塞同质条目；再加必须先合并同类项。

## 六、接口与配置

| 接口 | 说明 |
|---|---|
| `POST /search/web` | body `{query, top_k, fetch_top}`，返回 `hits/provider/mode/ok/degraded/error/elapsed_ms`；每条 hit 带 `origin=public_web`、url、snippet、发布时间 |
| `GET /search/status` | provider、mode、各 key **是否配置**（不回显密钥）、是否允许抓正文 |
| `POST /agent/invoke` | 响应新增 `web_sources`、`web_search`，与 `citations` 分开；来源挂在会话轮次上，刷新历史对话仍在 |

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `WEB_SEARCH_ENABLED` | `1` | 总开关，置 0 时技能收到明确「通道关闭」信号 |
| `WEB_SEARCH_PROVIDER` | `auto` | 可强制指定任一 provider |
| `WEB_SEARCH_TIMEOUT_S` | `10` | 单次检索超时 |
| `WEB_SEARCH_MAX_RESULTS` | `6` | 上限 10 |
| `WEB_SEARCH_ALLOW_FETCH` | `1` | 是否抓正文 |
| `WEB_SEARCH_FETCH_CHARS` | `3000` | 单篇正文上限 |
| `WEB_SEARCH_BLOCK_DOMAINS` | 空 | 逗号分隔域名黑名单 |
| `BOCHA/ SERPER/ TAVILY/ BING_SEARCH_KEY`、`SEARXNG_BASE_URL` | 空 | 官方通道凭据 |

openapi 同步加 `/search/web`、`/search/status` 与 `WebSearchRequest` / `WebSearchHit` / `WebSearchResponse`（39 → 41 paths）。

## 八、已知短板与下一步

| 级别 | 事项 |
|---|---|
| **P0** | 配一个官方搜索 key（建议博查或 Serper），复跑 `verify_web_search.py`；免费网页源只保证「能通」，不保证调研级质量 |
| **P0** | 真模型跑分：硅基流动 key 仍是 402 余额不足，28 条提示词（尤其「逐条标 [W编号]」「冲突并列」）的实际遵守率尚未验 |
| P1 | 检索词自动拆解：竞品调研现在一次查询，理想是「品类 + 价格 + 渠道」三轮再合并，能显著改善聚合页问题 |
| P1 | 来源可信度落地：目前只在提示词里让模型标「官方/行业/媒体/自媒体」，没有代码级打分与排序 |
| P2 | 联网结果的时效缓存与费用台账（按 provider 计费）；域名白名单模式（只允许 gov.cn / 交易所等）供合规场景 |
| P2 | 岗位自选仍是组织分配漏洞（M22 遗留）：员工可自选「管理者」看到别人包，与本次通道无关但优先级不低 |

**维护提醒**：`PROVIDERS` 是模块加载时绑定的函数字典，替换实现要改字典项而不是只改模块级同名函数；网页解析逻辑已抽成 `_parse_sogou_html()` / `_search_bing_html()` 两处，页面改版时优先改这里并补一条离线解析回归。

## 二、真模型怎么接

### 通道 A：直连厂商（推荐起步，不额外起容器）

```bash
LLM_PROVIDER=direct
LLM_VENDOR=zhipu                     # zhipu | dashscope | openai | deepseek | moonshot
LLM_API_KEY=sk-xxxx                  # 或直接设 ZHIPU_API_KEY
LLM_DEFAULT_MODEL=glm-4.6
LLM_STRICT=1                         # 验收/生产必须开
```

端点自动组成 `{base_url}/chat/completions`，五家全是 OpenAI 兼容，一套代码通吃。

### 通道 B：LiteLLM 代理（多厂商统一账单，生产推荐）

```bash
LLM_PROVIDER=litellm
LITELLM_BASE_URL=http://127.0.0.1:4000
LITELLM_MASTER_KEY=sk-proxy
```

`backend/app/services/model_gateway/litellm_config.yaml` 已登记 glm-4.6 / qwen / bge。

### 关键参数（都有默认值，不改也能跑）

| 变量 | 默认 | 为什么是这个值 |
|---|---|---|
| `LLM_MAX_TOKENS` | 8192 | 技能包一次要吐 2–4 张表，给小了会被截断成半张表 |
| `LLM_TEMPERATURE` | 0.2 | 财务归因要可复现：同输入两次跑结论应一致 |
| `LLM_DISABLE_THINKING` | 1 | GLM-4.5/4.6 混合思考对结构化表格抽取是纯浪费（思考 token 也计费） |
| `LLM_STRICT` | 0 | 开发/CI 允许回退 stub；**验收与生产必须置 1** |
| `MODEL_PRICES_JSON` | 空 | 合同价≠牌价，`{"glm-4.6":[0.004,0.014]}`（元/1k tokens） |

### 诊断入口

```bash
curl -H "Authorization: Bearer <dev token>" \
  "http://127.0.0.1:8000/api/v1/models/probe?model_id=glm-4.6"
```

和 `/models/gateway` 的区别：那个只看「通道配好了没」，这个**真发一次极短调用**，
401 / 429 / 模型名不存在会原样回显——省去翻日志。

## 三、多格式产出怎么用

```json
POST /api/v1/agent/invoke
{
  "agent_id": "ag_fei_yong",
  "input": "做本期对上期的环比 + 量价分离",
  "file_ids": ["file_xxx"],
  "output_formats": ["xlsx", "docx", "pptx", "html", "pdf"]
}
```

| 值 | 产出 | 谁看 |
|---|---|---|
| `xlsx` | 多 sheet：执行结论 + 答案里的每张表 + 输入数据摘要 | 财务核数 |
| `docx` | 封面 + 元信息表 + 分章正文 + 表格（工业蓝表头） | 归档、走签批 |
| `pptx` | 封面 → 每章要点页 → 每张表分页 → 执行信息尾页 | 给老板汇报 |
| `html` | 单文件、内嵌样式、`@media print` 可直接打印成 PDF | 发群、发客户 |
| `pdf` | A4 直绘，长表自动分页（不依赖 Office / LibreOffice） | 盖章归档 |

- **不传 = xlsx**，M16 的老调用方行为完全不变。
- **`auto`** 按技能包 `outputs_contract` 关键词猜（汇报/PPT→pptx，文档→docx，归档→pdf）。
- 单个格式渲染失败**不拖垮整单**：其余格式照常返回，失败项写进 `data.artifact_errors`。
- 下载仍走后端代理 `/agent/files/{file_id}`，不暴露 MinIO。
- 前端对话页已加**格式多选按钮**（Excel/Word/PPT/PDF/HTML），默认只勾 Excel；
  真模型没跑通时气泡里会直接标红「本次未走真模型」，不让 stub 结果看着像模型结论。

### 版式约定

- 工业蓝 `#1F4E79`，与前端主题、xlsx 表头同色；正文等线/微软雅黑。
- 章节**自带表格**：`## 二、量价分离` 下面紧跟它自己的表，而不是把所有表堆到文末。
  （早期版本把表堆文末，导致「只有表没正文」的章节标题整段消失——`test_m17` 有回归护栏。）
- 行内 markdown（`**粗体**`、`` `代码` ``、`[文字](链接)`）在模型层统一剥掉，
  否则 Word/PPT/PDF 里会原样显示一堆星号。
- PPT 单页最多 8 行表格、6 条要点，超出自动续页，不缩字号。

## 四、验收怎么跑

```bash
cd backend
set ZHIPU_API_KEY=sk-xxxx            # 换一个有效 key
.venv/Scripts/python.exe scripts/accept_real_llm.py

# 没有 key 时先验证链路（不调模型，用技能包示例答案走完上传→渲染→打分→出报告）
.venv/Scripts/python.exe scripts/accept_real_llm.py --dry-run
```

脚本做四件事：① 走真实接口导入两个技能包并**过批次审批**（与正式上线同一条路径）；
② 上传技能包自带的真实 xlsx；③ 调模型；④ 按对照答案逐条打分并落盘产出物。

对照答案来自技能包**自带的示例产出物**（`fei-yong-yi-chang-bo-dong-fen-xi.xlsx`、
`bao-xiao-he-gui-yu-shen-qing-dan.xlsx`），不是我们编的标准：

| 用例 | 检查项 | 判分口径 |
|---|---|---|
| 费用异常波动分析 | 保洁费为主异常项 / 本期 12000 / 上期 10000 / 涨幅 20% / 量差 0 / 价差 2000 / 归因为价涨 / 有结构化表 | 8 条，数字须精确命中（2000 和 1800 对财务是两回事） |
| 报销单合规预审 | 李四被拦 / 招待超 3000 / 李四退单 / 张三通过 / 王五待复核 / 退单理由挂条款 / 有逐张清单表 | 7 条 |

达标线 **80%**。报告与 15 个产出物落在 `docs/验收/M17_真模型/<用例>/`。

### 当前 dry-run 结果

```
平均得分 100% · 达标
费用异常波动分析  8/8   5 个产出物
报销单合规预审    7/7   5 个产出物
```

这证明的是**链路与版式**：上传解析、审批、渲染、分页、下载全通。
真模型的效果分要等有效 key 才能出。

## 五、已知边界（别当成没做）

1. **PDF 不做公式复算**：数字来自模型输出，和 xlsx 一样不做二次校验。
2. **PPT 是「要点 + 表」的汇报骨架**，不是品牌模板套版；要客户 VI 得先给模板。
3. **表格识别认 markdown 表与 ```json 数组**，模型输出纯散文时只有正文没有表。
4. **单次调用出 5 种格式**会多花一点本地 CPU（约 200–400ms），但不额外消耗 token。
5. **图片/图表不进产出物**：技能包产出契约里没有图，等有真实需求再加 echarts 截图链路。

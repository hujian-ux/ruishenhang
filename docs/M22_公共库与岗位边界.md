# M22 · 公共库与岗位边界

## 1. 需求原话

> 选完岗位后，对应岗位，应该只能看到自己的技能和公共库的技能。要设立一个公共库，里面放的都是办公基础技能例如：文案生成/PPT制作/表格制作等等

## 2. 判断：这是两件事，一件是边界，一件是资产

**第一件：岗位从"排序偏好"变成"可见边界"。**
M19 做完后，选财务只是把 4 个核心包排到前面，往下滚还是 115 个全在——包括制造业、跨境电商、销售。用户点进「换一个」能看见别人的包。这不叫岗位工作台，叫"带推荐位的技能大全"。

**第二件：公共库不能塞进 115 里。**
文案、PPT、表格是**每个岗位每周都干**的活，跟行业无关。如果每个岗位各抄一份，就是 11 份维护成本加口径漂移；如果直接放进 115，客户对不上数（115 变 125），且会被当成"第 12 个岗位"。

## 3. 公共库放什么：只放"每个岗位每周都干"的

判断标准很硬：**这件事是否跟岗位无关、且每周都会发生**。不满足就不放，否则公共库会变成第二个"不知道点哪个"。

| 分组 | 技能 | 产出 | 干什么 |
|---|---|---|---|
| 写作 | 文案生成 | Word | 通知、公告、朋友圈、公众号开头 |
| 写作 | 制度与流程起草 | Word | 口头规矩 → 可执行的适用范围/职责/流程/罚则 |
| 演示 | PPT 制作 | PPT | 主题 → 逐页结论 + 要点 + 讲稿 + 图表建议 |
| 演示 | 汇报框架 | Word | 周报月报项目汇报：结论/进展/风险/要什么支持 |
| 表格 | 表格制作 | Excel | 口述或乱数据 → 规范表（列名带单位、一行一对象） |
| 表格 | 数据速览 | Excel | 一堆数字先给结论：总量/结构/变化/异常/口径 |
| 沟通 | 会议纪要 | Word | 散会就能发：决议 + 待办（谁/做什么/何时交） |
| 沟通 | 邮件与消息 | Word | 催办、道歉、拒绝、协调，给措辞也说明为什么这么写 |
| 沟通 | 润色与翻译 | Word | 去 AI 味、拆长句、中英互译保留术语 |
| 阅读 | 文件信息提取 | Excel | 合同/发票/截图 → 字段表，逐项标出处与置信度 |

十条都写了真实提示词（不是占位），并规定用 Markdown 二级标题分节——因为下游渲染器按 `##` 切页、按表格切 Sheet，写成散文就出不了 PPT/Excel。

## 4. 三个取舍

**① 公共库不挂岗位标签。** 一条包挂多个岗位，各岗计数会互相叠加，"财务 17 + 人事 20 + …" 就大于 115。公共库直接不进岗位目录：`role_tags` 为空、`category=public`。

**② 主职业唯一，所以只有本岗的包出现在本岗。** 「对账与开票核对」既属制造业也属财务，但主职业是财务，就只在财务出现。代价：挂多岗的包在副岗看不见（如「经营复盘」主职业是管理者，财务岗看不到）。取舍理由：宁可少数包在副岗不出现，也不要各岗数字加起来对不上总数——后者客户一眼就发现。

**③ 岗位是视图过滤，不是权限。** 真正的隔离仍然是 RBAC（`_visible`）。岗位只决定"先摆哪些"。所以接口叫 `?role=` 而不是 `?scope=`——写清楚它不承担安全职责，避免以后有人拿它当权限用。

## 5. 接口变化

| 接口 | 变化 |
|---|---|
| `GET /agents/catalog` | 新增 `public` / `public_groups` / `public_total`；新增 `?role=` 收窄；`total` 仍只算业务包 |
| `GET /agents/roles` | 两份响应都附 `public`（本岗工作台 = 本岗 + 公共库） |
| `GET /agents` | **新增** GET 契约（此前只有 POST），支持 `?role=` / `?category=public` / `?status=` |

口径红线（有测试守着）：`total` 与 `role_total` 不含公共库，115 个业务包保持 115。

## 6. 前端

- **技能库**：`[我的岗位] [公共库] [按行业]`。第三个只对 `platform_admin` 出现——员工不该顺手点开全公司 115 个包。未选岗位时不默认落到某个岗（那等于替用户做决定），显示岗位网格 + "不急着选，先用公共库"。
- **岗位页**：`岗位胶囊（点开换岗）→ 开箱即用 4 个 → 其他 13 个 → 公共库 6 个（精选）`。卡片标签从行业名（制造业/跨境电商）改成职能（财务/销售）——我在财务岗，不需要知道这个包原属制造业。
- **首页**：推荐 4 卡下面加一行公共库胶囊（文案生成 / PPT 制作 / 表格制作 / 会议纪要），点一下直接选中。选技能时自动带出建议产出格式（表格 → Excel，PPT → PPTX），用户手动改过格式就不再覆盖。
- **技能选择器**：只列本岗 + 公共库，公共库条目带「公共」标；换岗后如果原来选的技能不在新岗范围，自动退回通用助手。
- **侧栏**：员工看「技能库 27」（本岗 17 + 公共库 10），管理员仍看 115。

## 8. 已知短板

1. **公共库不走 RAG**。润色、文案这类不需要知识库，但"制度与流程起草"理想上应该先查公司现有制度。现在它只凭通用规矩写。要接，得给公共库单独挂知识域。
2. **岗位是自选，不是组织分配**。真上客户应由部门/职级映射默认岗位，否则员工可以随手切成"管理者"看到别人的包。这条和 M19 的 P1 是同一件事，越早做越省事。
3. **公共库暂时不能停用/改提示词**。启动时按代码刷新，管理员改了会被覆盖（`status` 保留）。若客户要定制，需要加"租户覆盖层"。
4. **采购 4 / 客服 5 / 品质 5 仍然单薄**（M19 遗留），加上公共库 10 个才勉强够用。

## 9. 下一步

- **P0**：部门 → 默认岗位映射（补上"岗位由组织给，不由员工自己挑"）
- **P1**：公共库接知识域（制度起草先查现有制度）；常用技能按使用频次排序
- **P2**：租户级公共库覆盖层（客户可改提示词、可停用某条）

## 二、三条不可退让的口径

1. **默认只观测，不改写结果**。`GUARDRAILS_STRICT=0`、`HANDOFF_AUTO=0`，缓存与路由只给建议（`applied:false`）。要真正拦截 / 转人工 / 降本，由运维显式开开关。
2. **骨架就是骨架**。LLM 判分标 `mode=heuristic`、语义缓存标 `char_3gram_jaccard`、工作流 LLM 节点标 `dry_run`、MLOps 四项标 `done=False`、自助删除未覆盖项标 `manual_review`。
3. **权限不另起炉灶**。工具鉴权复用第 18 章 `visible_fields`，审计导出复用既有 RBAC，部门创建自动继承 scope/owner/dept，公网结果仍不入库（M26 红线不变）。

## 五、文档型交付（对应第 16/17/22/23/32/33/38 章）

### 5.1 移动端 MVP 清单（4–6 周，未开发）
- 页面：登录（复用 OIDC）、会话列表、对话（复用消息流）、技能库（岗位 + 公共库）、产出物预览、审批待办、我的数据导出/删除。
- 接口：全部复用现有 `/api/v1/*`，不新增移动端专用接口；仅补 `device_id` 与推送令牌字段。
- 权限点：沿用三角色 + 第 18 章单一过滤点；移动端只读为主，写/外发敏感文件强制走审批节点。
- 验收：430px 无横向溢出（M18 已验）；弱网下请求超时 8s 有明确提示；刷新 `/callback` 需 SPA fallback；生物识别仅作本地解锁，不作服务端身份凭据。

### 5.2 外部专业工具对接契约（PS / CAD，未开发）
工具注册中心统一形态：`{tool_id, name, kind: api|cli|desktop, required_scope[], params_schema, result_schema, sandbox, approval_required}`。
调用链：智能体 → `guard_tool_call(tool_id, args, caller)`（本轮已实现）→ 沙箱/网关 → 结果继承调用者 `scope/owner/dept`。
落地前置条件：客户指定软件版本与授权目录、沙箱方案、人工审核节点；本轮只把「鉴权闸门」做完。

### 5.3 本地文件网关契约（未开发桌面客户端）
授权目录 → 文件 ACL 映射 `{scope, owner, dept, tenant}` → 拖入即切片入库（保留原路径）→ 回答引用可一键打开原文件。
本轮 M16 已覆盖「网页上传 xlsx → 解析 → 产出物下载」；桌面客户端、NAS/SMB/网盘连接器、公式复算仍未做。

### 5.4 集团租户模型（第 32 章，未实现）
层级 `tenant > dept > personal`，权限元数据已有 `tenant_id` 与跨租户过滤（第 18 章）；缺的是集团级策略下发、按租户配额/计费汇总、跨租户白名单授权、物理隔离部署。属规模化阶段，不阻塞首个试点。

### 5.5 AI 使用守则与免责声明（可直接交法务改）
- 产出归属：员工在职务范围内使用平台生成的内容归企业；**采用者对最终版本负责**。
- 责任边界：AI 输出不替代专业判断，金额、条款、合规结论必须人工复核；关键决策人机共签。
- 对外标注：对外发布内容建议注明「AI 辅助生成，请核实」。
- 使用禁令：禁止把机密、个人信息、密钥输入公网模型；禁止越权抓取或跨部门查询；违规纳入内部处罚。
- 数据合规：遵循个人信息保护法；使用境外模型需评估数据出境；员工可通过 `DELETE /ops/me/data` 申请导出/删除本人数据（级联范围以接口返回为准）。

### 5.6 非 LLM MLOps 落地步骤（第 38 章，骨架）
`/mlops/pipeline` 明确四项 `done=False`：特征存储 → 训练流水线 → 模型注册表（本轮有内存登记）→ 漂移检测（本轮有 PSI）→ 重训与灰度回滚。
验收线：至少 1 个传统 ML 模型走完训练→注册→serving→漂移→重训，模型版本可一键回滚。

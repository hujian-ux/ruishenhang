# M19 · 职业分类与岗位工作台

**一句话结论**：115 个技能包原来只能按行业找（制造业/零售/跨境/办公角色），
一个财务进来看到「制造业 21 个」不知道点哪个；现在多了一层**职业**入口——
选「财务」，先把报销预审、费用异常、账龄分析、经营周报这 4 个放到他面前，
剩下 13 个折叠在「其他」里。行业视角原样保留，给老板和售前用。

---

## 1. 问题：行业分法对岗位员工是噪音

| 谁 | 他想找的 | 旧目录给他的 |
|---|---|---|
| 财务专员 | 报销单怎么预审 | 制造业 21 / 零售 15 / 跨境 17 / 办公角色 62 |
| 人事 | 简历怎么筛 | 同上（他得先知道「办公角色」这个词） |
| 采购 | 缺料怎么跟 | 同上 |
| 老板 | 我这个行业能上什么 | ✅ 行业视角对他正好 |

结论：**行业视角不该删，但不该是默认入口**。员工认岗位，老板认行业。

## 2. 三个关键取舍

### 2.1 职业是横切标签，不替代行业
「对账与开票核对」既是制造业包，也是财务岗的包。所以一个包可挂多个职业，
但**主职业唯一**——否则 `17 + 20 + …` 会大于 115，客户会认为重复计数。
计数口径：各岗位 core 计数之和 == 技能包总数 == 115。

### 2.2 显式映射表，不做关键词推断
关键词会把「经营周报自动拼表」判成"运营"、把「异常指标归因分析」判成"数据"，
而它们实际是财务/经营分析岗的活。115 条写死在 `role_map.PACK_ROLES` 里，
可审计、可 review、不随描述文案改动而漂移。新包未登记时走回退（sub_function →
职业），不抛错、不丢包。

### 2.3 每个岗位只先给 4 个
一上来摊 20 个卡片，用户会挑花眼。`ROLE_CORE` 按「该岗最高频 + 不依赖额外数据」
选 4 个，作为开箱即用的默认配置；其余折叠成「其他 N 个」，用到再点。

要补齐优先级：采购 > 客服 > 品质。

### 技能库
顶部 `[按岗位] [按行业]` 切换。按岗位时：11 个胶囊（带数量）→
「XX 岗 · 开箱即用」4 张大卡（2×2）→「XX 岗 · 其他 N 个」网格。

### 侧栏
底部固定显示当前岗位（带颜色方块与数量），未选时显示「还没选岗位 · 去选」。

岗位存 `localStorage`（`wb.role.v1`），不上后端——这是「我怎么用这台机器」的偏好，
不是组织架构里的职位，不需要跨设备强一致。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/agents/roles` | 不传参：11 个岗位目录 + 各自数量 / core 数 |
| GET | `/api/v1/agents/roles?role=财务` | 该岗位的 `core`(4) + `rest`(N)，core 按优先级排序 |
| GET | `/api/v1/agents/catalog` | 双视角：`roles` + `categories`，两者都保留 |

`role` 同时接受 id（`finance`）和中文名（`财务`）；未知岗位返回 404。

## 8. 边界

1. **岗位不等于权限**。选「财务」不会让销售看到财务的包，可见域仍由 RBAC 决定；
   岗位只是在这层可见域里换个排列方式。
2. **不做岗位置信度推断**。没根据用户行为猜他是什么岗——猜错了比不问更烦。
3. **行业视角没有弱化**。`categories` 与 `total` 字段原样保留，老看板、老链接不受影响。
4. 岗位存在浏览器本地。换电脑要重选一次；将来接了组织架构（部门→岗位映射）
   可以改成服务端下发，届时 `role_map` 不用改。

## 9. 顺手修掉一个藏了三个月的 bug：员工看不到技能库

做 M19 时以员工身份验了一遍，发现技能库显示 **「0 个业务技能包 · 0 个岗位」**，
而管理员看到 115 个。

**根因**：M15 批量导入时写的是 `knowledge_scope="department"`，`dept_id` 落在导入人
（平台管理员，d_it）身上。`agent_store._visible()` 的规则是「global 可见 / 同部门可见 /
本人注册可见」，于是销售部员工 (d_sales) 一条都匹配不上——只能看到 scope=global 的内置
通用助手。之前所有演示都用管理员身份，所以这个问题一直没暴露。

**为什么不是"RBAC 坏了"**：权限逻辑本身是对的，错的是**导入时的归属设定**。115 个技能包
是从解决方案库导入的公司资产，不是某个部门的私有物。

**修法**（三处，缺一不可）：
1. `seed_live_demo.py` 导入 scope 改 `global`
2. `backfill_roles.py --scope global` 修存量（PG 模式用；内存模式重跑 seed 即可）
3. 前端空态从"白屏"改成说人话——「技能包没导入 / 未审批 / 不在可见范围」三选一

**同时加了反向测试** `test_department_scope_is_still_respected`：修 bug 不能顺手把
RBAC 放开，scope=department 的包对外部门仍然必须是 0。

教训：**只用管理员视角验收等于没验收**。后续每个界面功能都要先过一遍员工身份。

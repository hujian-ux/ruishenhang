## 二、关键发现：真模型来了也答不对的两个硬伤

M24 只证明了「`tool_calls` 里有 `rag_retrieve`、能拿到引用片段」。本轮准备语料时把链路打穿，发现证据根本没送到模型面前。

### 2.1 检索片段只拼了标题，正文没进 prompt

`agent_runtime.build_graph()` 与降级分支里都是：

```python
ctx = "；".join(h["title"] for h in hits)   # 只有文档名
```

「逐字引用并标出处」「冲突并列」「查不到说没查到」这些写在技能提示词里的要求，模型一个字都做不到——它只看得到三四个文档标题。

**修法**：新增 `compose_evidence(hits)`，输出带编号的证据块：

```
[1] 《差旅住宿标准（2023 版）》：部门经理…600 元/晚 / 超标…分管副总审批 / …
[2] 《差旅住宿标准（2026 修订版）》：…550 元/晚 / 一律报 CEO 审批 / 原 2023 版废止
```

- 编号 `[1][2]` 给模型稳定的引用锚点，也给验收脚本核对依据。
- 零命中时返回明确空信号（「本次没有任何可见的授权片段…回答未查到」），而不是空字符串。
- `grounded` 口径**只**对挂了 `llm_retrieval` 的技能生效：片段从「可选参考」升级为「必须逐条引用的依据」，并明令冲突并列、查不到直说。115 个业务包与默认助手保持原行为，不被带歪。

### 2.2 父子聚合同一篇文档只给一句话

`knowledge.retrieve()` 聚合时「同一 parent 取最高分 child 作为代表 snippet」。制度文档按句切块后，「部门经理限额」和「超标报 CEO 审批」是不同 child，只取前者，模型永远看不出审批人冲突。

**修法**：命中额外带 `snippets` 字段（旧 `snippet` 不变，向后兼容）：

- 每篇最多 5 句，**文档开头 2 句保底**（生效日期、废止声明、适用范围都在前面），再按相关度补足；
- `compose_evidence` 每篇按 600 字裁剪，多篇命中不撑爆上下文；
- `RetrieveHit` 与 `openapi.yaml` 同步加 `snippets` 字段。

> 调试中踩的坑：一开始按相关度取前 3 句，语料改一个词关键句就掉出前三；改成「开头保底」后，又发现保底取到的是 Markdown 标题和发文编号。最后把夹具首句写成自带版本、金额、审批人、废止状态的「制度要点」——真实制度的速查栏本来也这么写。

### 2.3 顺带修的 stub 摘要

`_stub_answer()` 原来硬截 prompt 前 80 字，改完后那段全是证据块，用户看到的占位答案变成系统提示词。现改为抽取「对话记忆 / 用户问题 / 本次任务输入」，M4 的会话记忆回归用例也恢复正常。

## 三、技能级硬规则（单一来源）

M23/M24 每条技能尾部都自己写了一段「硬规则」，「金额不许编」「缺料先问」抄了 24 遍。改一条红线要改 24 处，漏一处就是客户面前的口径不一致。

`public_skills.HARD_RULES` 七条，由 `compose_system_prompt()` 在 `build_agents()` 时统一注入：

1. **事实不许编造**：金额、日期、人名、编号、比例、制度条款，输入/附件/检索片段里没有的一律写「未提供」，举例须标「（示例）」。
2. **不替审批人拍板**：只给选项、依据、风险、推荐；不写「已批准」「应当通过」「符合规定」。
3. **依据可追溯**：引用标出处；多份依据冲突时并列各方与生效日期、标「待确认」，不自行选一个。
4. **缺料先问**：关键输入缺失先列清单，查不到写「未查到」。
5. **越权不猜**：看不到其他部门/租户数据就说「无权限查看」。
6. **产出物有「执行结论」首节**，按 `##` 分节、Markdown 表格承载数据。
7. 与本技能下方业务规则冲突时，以本段为准。

**两条格式约束**（已写进测试）：

- 硬规则里**不许出现 `## `** —— 下游渲染器按 `##` 切页，多一个标题产出物首页就多一张空白页；
- 幂等注入，业务提示词原样跟在后面；`hard_rules_version` 随启动刷新同步，改坏能被自愈。

**不抽走的**：各技能自己的业务干法（排期要有具体负责人、纪要分决议与待办、清洗不许删行）仍留在原提示词里。抽的是跨平台红线，不是专业判断。

## 五、RAG 答案质量验收（等真模型）

### 夹具：`backend/fixtures/rag_conflicts/`

| 文档 | 关键内容 |
|---|---|
| 差旅住宿标准（2023 版） | 部门经理一类城市 **600** 元/晚，超标经 **分管副总** 审批 |
| 差旅住宿标准（2026 修订版） | 部门经理一类城市 **550** 元/晚，超标一律报 **CEO**；**2026-03-01 起废止 2023 版** |
| 费用报销管理办法（2025 版） | 每月 **25 日**截止；**仍引用已废止的 2023 版**和分管副总审批 |

刻意制造两层冲突：新旧版数字/审批人不同；报销办法仍指向旧版。三份都标注「仅适用国内出差」，**没有海外条款**。

### 脚本：`backend/scripts/verify_rag_answers.py`

```bash
# 先起后端（普通模式即可）
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8080

# 灌语料 + 跑验收（stub 下会明确报「未验收」，退出码 2）
.venv/Scripts/python.exe scripts/verify_rag_answers.py
.venv/Scripts/python.exe scripts/verify_rag_answers.py --seed-only   # 只灌语料

# 充值后起真模型，重跑同一条命令
LLM_PROVIDER=direct LLM_VENDOR=siliconflow LLM_API_KEY=<key> \
LLM_DEFAULT_MODEL=zai-org/GLM-5.3 LLM_STRICT=1 \
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

三个用例分**检索层**（不依赖模型）与**语义层**（只在 `llm_real=True` 时判）：

| 用例 | 检索层检查 | 语义层判定 |
|---|---|---|
| `conflict` 新旧冲突 | 两版都召回，且证据含 600/550/分管副总/CEO/废止 | 金额两版都出现、标出冲突或待确认、两版审批人都出现、不替公司拍板、带出处编号 |
| `missing` 查不到 | 有命中（词重合）但片段无答案 —— 比零命中更严格 | 明确说未查到、不把国内标准当海外标准、点明片段只覆盖国内 |
| `citation` 有答案带出处 | 召回 2025 版报销办法 | 答出 25 日、给出处编号或文档名 |

脚本先按 title 清掉旧夹具再灌，保证语料改版后不残留同名旧文档。报告落 `backend/reports/rag_answer_quality.json`。

### 当前实测（2026-11-05）

```
语料灌入：3 份，scope=global
[conflict] 检索 PASS，6 条命中，冲突因子齐全
[missing]  检索 PASS
[citation] 检索 PASS
检索层：PASS（3/3）
结论：模型仍是占位，答案质量未验收，语义项 SKIP（不是 PASS）
退出码 2
```

`key` 复测结果：硅基流动 **402 有效但余额不足**（`check_key.py`）。所以「查不到会不会老实说」「冲突会不会并列」**仍未验证**，脚本不会把 SKIP 伪装成通过。

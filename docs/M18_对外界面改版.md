# M18 · 对外界面改版（从内部仪表盘到可用产品）

## 一句话

原来的界面是给开发者看的：深色侧栏、10 个技术标签平铺、标题写着「M4 多轮记忆 · M16 文件进出」。
员工打开不知道该点哪儿，客户第一眼看到的是调试面板。这一版按对外产品重做骨架，**员工端只剩两件事：聊、下载**。

## 改了什么

| 位置 | 之前 | 现在 |
|---|---|---|
| 导航 | 侧栏 10 个平铺标签（含「召回演示」） | 侧栏 = 对话历史；「技能库」「管理后台」收到底部 |
| 首页 | 目录卡片墙 | 欢迎区 + 4 个推荐技能 + 输入框，打开就能问 |
| 对话 | 表单式：下拉选智能体 + 按钮 | 消息流：用户气泡、助手正文、产出物卡片 |
| 输入 | 一行 input + 发送按钮 | 圆角输入卡：附件 / 技能包 / 输出格式 / 发送 |
| 管理功能 | 与员工功能同级 | 折进「管理后台」二级页，8 个页签 |
| 登录页 | 居中小卡片（写着技术配置） | 左品牌主张 + 右登录动作 |
| 文案 | `M4`/`M16`/`第35章红线` | 员工侧全部去掉；管理侧保留（那是给管理员看的） |

## 后端为此补的四件事

界面要的东西后端得先有，否则前端只能造假数据。

### 1. 会话标题（`title`）

侧栏要列历史对话，不能显示 `sess_9f3a8b2c1d`。改为取首条用户输入截断 26 字。
空会话回退「新对话」——否则侧栏会出现一条没有文字的空行。

### 2. 完整轮次（`turns`）

`GET /agent/sessions/{id}` 原来只回 `context_preview`（最近 6 轮的拼接文本，是给模型看的），
界面拿它没法还原对话。新增 `turns` 数组（role / content / ts / artifacts / llm_real）。

### 3. 产出物挂在轮次上

`append_turn` 在生成之前就落账（对话已经发生，不能因为渲染失败丢记忆），
而产出物是生成之后才有的 → 新增 `attach_meta()` 在生成后回填到该轮助手消息上。

**不这么做会怎样**：刷新一次页面，历史对话里的产出物全部消失，用户以为文件丢了。

### 4. `llm_real` 跟着轮次存

`llm.real` 原来只在当次响应里。刷新后红色提示条消失，第二天翻记录会把占位内容当成模型结论。
这是**安全问题不是体验问题**，所以和产出物一起持久化。

### 5. 内置通用助手

打开就能提问，不必先挑技能包。`ag_builtin_assistant`：

- `status=published`，不走评审（它是平台自带能力，不是交付物）
- `system_prompt` 留空，沿用 `agent_runtime.SYSTEM_PROMPT`，不维护第二份
- **不进 catalog**：技能库口径保持 115，不会变成 116

## 设计取舍

**为什么侧栏用浅灰不用深色**：深色侧栏是后台管理系统的语汇，AI 助手类产品的侧栏普遍是浅色，
让对话成为唯一的视觉重心。

**为什么助手消息不用气泡**：长文回答套气泡会显得局促，且气泡宽度限制会让表格类内容频繁换行。
用户消息用气泡（短、需要区分），助手消息直接排正文。

**为什么格式选择放输入框里**：产出格式是"这次任务的一部分"，跟附件同级；
放到设置页里会让用户永远找不到。

**为什么保留管理后台的技术文案**：管理员需要看到「第35章红线」这种制度锚点，
员工不需要。两类页面面向两类人，不强行统一。

## 顺手修的三个真 bug

1. **侧栏标题只显示一半**：`.rail-item span{flex:1}` 同时命中了删除按钮 `.x`，
   两个 flex:1 各占一半。加 `.rail-item .x{flex:none}`。
2. **`[stub|zai-org/GLM-5.3]` 前缀露到界面**：那是判真标记，不该给人看。
   展示层 `cleanAnswer()` 剥掉，是否真跑由红色提示条说明。
3. **产出物卡片名字被时间戳挤掉**：`费用异常波动分析_fei-yong-tai-zhang_20261105-1528.xlsx`
   在 212px 卡片里只剩「费用异常波动分析_fei-y...」。展示只留技能包名，
   完整名放 `title`，下载时仍用全名。

## 边界

- 移动端（≤860px）侧栏改为抽屉式，截图核对过 430px 宽无横向溢出。
- 历史对话恢复的是轮次文本 + 产出物，**不恢复当时的附件列表**（附件属于那一轮，但要重新上传才能再执行）。
- 技能库点卡片直接进对话；不在列表页做"即时执行"面板——同一个能力开两个入口会让人犹豫。
- 管理后台 8 个页签的页面本身没重写，只跟随新设计系统的 class 变好看了。

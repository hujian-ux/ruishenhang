# 真环境部署执行手册（企业 AI 智能体中台）

> 适用：把本平台从「本机演示」搬成「可上线的真环境」。
> 配套：身份/IM 凭据获取与配置见 `docs/身份与IM部署生效手册.md`（本手册只讲"怎么跑起来"）。
> 原则：所有能力默认关、零行为变更；本手册只给"打开与运行"的步骤。

---

## 0. 前提（必读）

1. **本机已安装并启动 Docker Desktop**（Windows/Mac 双击启动；Linux `systemctl start docker`）。
   本手册的 PostgreSQL / Qdrant / MinIO / Redis / Casdoor 全部由 Docker 编排。
   - 验证：`docker ps` 不报错、`docker compose version` 有输出。
2. 已 `git clone` 项目，`backend/` 与 `web/` 就绪，且 `backend/pyproject.toml` 依赖已就绪（容器构建时 `pip install -e .` 自动装，含 `pycryptodome`）。
3. 网络可达（拉镜像 + 访问 Casdoor/企微/钉钉网关）。
4. 本机 `curl` 调本地端口时若被代理拦截，加 `--noproxy '*'`（与 127.0.0.1 直连）。

---

## 1. 一键起外部依赖（PostgreSQL / Qdrant / MinIO / Redis）

```bash
cd <项目根>
docker compose up -d postgres qdrant minio redis
docker compose ps            # 等所有服务状态 healthy
```

- 账密见 `.env.example`：PG `app/dev`；MinIO `minioadmin/minioadmin`，桶 `kb-files`。
- 后端启动时若这些服务可达，会自动从内存兜底切到持久化（无需改代码）。
- 不想用容器？也可本机原生装 PG/Qdrant/MinIO/Redis，只要 `.env` 里的 `PG_HOST/QDRANT_HOST/MINIO_ENDPOINT/REDIS_URL` 指向它们即可。

---

## 2. 起 Casdoor（统一身份 OIDC 中间件）

```bash
docker compose -f docker-compose.casdoor.yml up -d
# 管理后台 http://127.0.0.1:8000  管理员 admin/123，首次登录务必改密码
```

### 2.1 在 Casdoor 里建 OIDC 应用
1. 左侧 **Applications → 新建**（`ruishen-ai`）。
2. 复制 **Client ID**（本系统目前只用 ID）。
3. **Redirect URLs** 加：`https://你的域名/callback`（本机联调填 `http://localhost:5173/callback`）。
4. 记下 **Client ID**（= 后端 `OIDC_AUDIENCE`）。

---

## 3. 配置后端环境变量

复制 `.env.example` 为 `.env`，至少补 OIDC 三件套（其余用默认值即可）：

```bash
# ── 统一身份（OIDC / Casdoor）──
OIDC_ENABLED=1
OIDC_ISSUER=http://127.0.0.1:8000      # 与 Casdoor 访问地址完全一致，末尾不要带 /
OIDC_CLIENT_ID=<第 2.1 步的 Client ID>
OIDC_AUDIENCE=<同上，通常等于 Client ID>

# ── 收口开关：先别开！验证可登录之后再开（否则全员登不进）──
AUTH_ENFORCE_OIDC=0

# ── 联网搜索 / 样例注入（按需）──
WEB_SEARCH_DECOMPOSE=0
FEWSHOT_ENABLED=0
```

> PG/Qdrant/MinIO/Redis 默认 `127.0.0.1`，与第 1 步容器一致；若后端也跑在容器里（见 5.2），则把这些 HOST 改成服务名（`postgres`/`qdrant`/`minio`/`redis`）并加 `depends_on`。

---

## 4. 构建并部署前端

```bash
cd web
npm install
npm run build                 # 产物输出到 web/dist/

# 方式 A（开发/演示）：vite 预览
npm run preview -- --host 0.0.0.0 --port 5173

# 方式 B（生产）：用 nginx 指到 web/dist/，或用任意静态服务器
#   nginx 示例：root /path/to/web/dist; try_files $uri /index.html;
```

`npm run build` = `tsc -b && vite build`，已验证通过（gzip ~95KB）。

---

## 5. 启动后端（二选一）

### 5.1 本地直接跑（推荐先验证）
```bash
cd backend
set -a; source ../.env; set +a     # Git Bash：把 .env 注入环境
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

### 5.2 容器化（生产）
```bash
docker compose --profile app up -d backend
# 镜像由 backend/Dockerfile 构建（已就绪，pip install -e . 含 pycryptodome）
```

## 6. 灌 115 业务包

- **有 PostgreSQL**（推荐）：seed 写入 PG，后端启动自动 `load_from_pg()` 读到，无需额外操作。
  ```bash
  cd backend && set -a; source ../.env; set +a
  python scripts/seed_live_demo.py     # 解析 115 个技能包 + 审批单
  ```
- **无 PG（内存模式）**：seed 与后端是不同进程、内存不共享 → 后端启动后是空目录。
  演示时要么先起 PG 再 seed，要么接受空目录（不影响其它功能）。

## 7. 验证（都过了才算部署成功）

```bash
# 健康
curl --noproxy '*' http://127.0.0.1:8080/healthz            # 200

# API 面（应 ≥110 个 path，含 /integrations/im/*、/ops/*）
curl --noproxy '*' http://127.0.0.1:8080/openapi.json | python -c "import sys,json;print(len(json.load(sys.stdin)['paths']))"

# OIDC 配置与可达性
curl --noproxy '*' http://127.0.0.1:8080/api/v1/auth/settings   # oidc_enabled:true
curl --noproxy '*' http://127.0.0.1:8080/api/v1/auth/oidc/health # ok:true（Casdoor 可达）

# dev 登录拿 token（验证鉴权链路）
curl --noproxy '*' -X POST http://127.0.0.1:8080/api/v1/auth/sso/callback \
  -H "Content-Type: application/json" \
  -d '{"provider":"wecom","code":"dev_admin","device_id":"x","state":null}'
```

前端：登录页点「使用企业身份登录」→ 跳 Casdoor → 授权 → 回首页。

### IM 管理端点鉴权（已加回归测试，这里给手测口径）
IM 管理端点**必须**带网关签名的 `X-Caller-Context`（不能把 role 当 query 参数传，那是已修掉的漏洞）：
```bash
CTX=$(python -c "from app.core import security; from app.models.caller import CallerContext; \
  print(security.encode_caller_context(CallerContext(userId='u1',deptId='d1',role='platform_admin',tenantId='t_demo')))")
curl --noproxy '*' http://127.0.0.1:8080/api/v1/integrations/im/config -H "X-Caller-Context: $CTX"   # 200
curl --noproxy '*' http://127.0.0.1:8080/api/v1/integrations/im/config                              # 401（无鉴权）
```

## 8. 接企微 / 钉钉（运行时，不改代码）

1. 登录后端 → 管理后台 → **身份与集成** → 消息接入（运行时）。
2. 选企微/钉钉，填 `corp_id/secret/agent_id/webhook_token/encoding_aes_key` → 保存（密钥不回显、列表脱敏）。
3. 点「测试下发消息」验证真收到；企微回调 URL 填 `https://你的域名/api/v1/integrations/im/wecom/callback`。
4. 企微消息体 AES 解密已落地（`pycryptodome`，`EncodingAESKey` 派生 32B key + AES-256-CBC）；填了 `encoding_aes_key` 即自动解密入站 XML。
- 详见 `docs/身份与IM部署生效手册.md` 第 1–3、7 节。

---

## 9. 收口（最后做！）

确认 OIDC 能正常登录后，把 `.env` 的 `AUTH_ENFORCE_OIDC=1` 并重启后端 → 演示入口消失、只能走真实 SSO。
**顺序错了会让所有人登不进**，所以必须在第 7 步验证通过之后再开。

## 10. 排错速查

| 现象 | 排查 |
|---|---|
| `docker ps` 报错 | Docker Desktop 没启动（本机双击启动，或 Linux `systemctl start docker`） |
| 后端连不上 PG | `.env` 的 `PG_HOST=127.0.0.1` 但后端在容器里 → 改 `host.docker.internal` 或服务名；本手册默认「后端也跑本机」 |
| OIDC 验签失败 | `OIDC_ISSUER` 末尾别带 `/`；`OIDC_AUDIENCE` 必须等于 Casdoor 应用 Client ID |
| 收口后登不进 | 确认 Casdoor 应用 Redirect URLs 含 `/callback`，且 `OIDC_ENABLED=1` + Issuer/ClientID 正确 |
| 115 包目录为空 | 无 PG 时 seed 与后端进程隔离；先起 PG 再 seed（第 6 节） |
| 本地 curl 502 | 被环境代理拦截，加 `--noproxy '*'` 直连 127.0.0.1 |

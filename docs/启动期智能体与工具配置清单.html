平台启动期智能体与工具配置清单 v1.0

核心结论：启动期分三层递进配置——L1 教学层预置"示范智能体"帮员工上手、L2 构建层提供"业务转智能体"工具让员工把部门业务变成智能体、L3 编排层提供"多智能体工作流"工具让他们把多个智能体串成自动化流程。L2 是承上启下的关键，L3 复用 L1/L2 的产物并闭环沉淀回模板库。

本清单与既有蓝图一致：知识库沿用全域/部门/个人三级分级（第 5 章），权限沿用 RBAC 三角色 + 召回单一过滤点（第 13、18 章），移动端复用同一过滤（第 16–18 章）。下方三类工具均构建在 Dify + LangGraph + Qdrant + PostgreSQL + MinIO + One API 私有化底座之上。

一、L1 教学层：预置"示范智能体"（帮员工学习使用）

目的：员工第一次进来不空手——有向导教操作、有教练帮拆解、有模板可一键克隆。这部分由平台管理员在启动期预置好，不是员工自己建。

预置智能体主要作用基于平台能力优先级
平台向导 Agent
（HelpDesk）		回答"怎么用平台"、把用户导航到正确智能体、解释权限模型（我能看什么、为什么看不到）知识库问答 RAG + 路由P0
业务梳理教练 Agent交互式引导员工拆解自己的业务流程，逐步输出一份"智能体草图"（步骤/所需知识/所需工具/权限范围）多轮对话 + 表单采集 + 提示词模板P0
部门模板中心
（Agent 模板库）		提供 3–5 个开箱即用模板（HR 入职助手 / 销售知识问答 / 客服话术库…），员工一键克隆再改模板市场 + 权限配置器P0
安全合规哨兵 Agent提示数据边界、拦截越权操作、做合规问答（什么能写库、什么要审批）权限校验 + RAGP1
最佳实践推荐 Agent给一个任务，推荐现成智能体/模板，避免重复造轮子检索 + 推荐P1

二、L2 构建层：业务转智能体的工具（让员工把公司业务整理成智能体）

目的：把"业务"变成"智能体"。核心是零代码编排器 + 知识接入 + 工具注册 + 权限配置四件套，员工不需要写代码即可完成。其中"业务梳理画布"直接对接 L1 的教练 Agent 产出的草图。

工具作用对应平台能力优先级
可视化 Agent 编排器零代码搭智能体：设人设、挂知识、绑工具、配变量、设开场白Dify Agent / StudioP0
业务梳理画布把业务拆成步骤/任务，每步映射为节点或子智能体，导出为编排草稿画布 + 模板P0
知识接入连接器上传文档 / 连数据库 / 文件夹同步，自动切片、向量化、打权限标签连接器 + Qdrant + PGP0
工具 / 插件注册中心把内部 API、函数注册成智能体可调用的工具（含鉴权、限流）Tool Registry / One APIP0
角色与可见范围配置器设 owner / dept / scope，绑定 RBAC，确保建出的智能体不越权权限元数据 + 召回过滤P0
提示词模板与变量库可复用提示块 + {{变量}}，降低写提示门槛Prompt 模板P1
试运行与评估台发布前测试、对比效果、留痕，避免直接上线翻车Sandbox / EvalP1

三、L3 编排层：多智能体工作流工具（把各智能体组成工作流程）

目的：单个智能体解决单点任务，工作流把它们串成端到端业务。核心是"编排器 + 节点库 + A2A 调用 + 人工审核"，让员工用拖拽而非写代码实现跨智能体协作。

工具作用对应平台能力优先级
工作流编排器拖拽节点把多个智能体/工具串成有向流程，可视化调试Dify Workflow / LangGraphP0
节点类型库触发器 / 条件分支 / 循环 / 并行 / LLM / 代码 / 知识检索 / HTTP 等开箱节点节点引擎P0
Agent-to-Agent 调用一个智能体作为节点调用另一个智能体，实现分工协作A2A 协议P0
人工审核节点敏感步骤加审批闸口（HITL），如越级共享、外部导出审批 APIP0
事件 / 消息总线解耦智能体、异步交接，支持长流程消息总线P1
定时调度器按 cron 周期跑工作流（日报、巡检、对账）SchedulerP1
执行监控与回放看链路、调试、回溯每一步输入输出Trace / 观测P1

四、启动期落地路线图（4 周）

W1 底座
私有化部署 Dify+Qdrant+PG+MinIO+One API，配置三级知识库与 RBAC，打通 SSO。
W2 教学层
预置 L1 三个 P0 智能体（向导 / 教练 / 模板中心），写好平台手册知识库。
W3 构建层
开放 L2 工具，选 1 个试点部门（建议行政部）做出 2–3 个业务智能体。
W4 编排层
用 L3 把试点部门智能体编成 1 条端到端工作流，复盘后沉淀为模板推广。
